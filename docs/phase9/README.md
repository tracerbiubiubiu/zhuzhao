# Phase 9 — 处置闭环深化 + 自研编排引擎 MVP（总纲）

> **阅读顺序**：先核状态与上一阶段出口，再看核心切片、可滑补全、外部输入和DoD。Phase9仍为规划总纲，“已拍”表示范围决定，未立项/未实施；细化稿须在前置输入到位后另立，不用当前代码名或示意API冒充已可用能力。

> **文档定位**：phase9 规划总纲（2026-10-29 建档）——**已拍决策汇编 + 范围索引**，蒸馏自愿景稿 [07-phased-plan §4.4](../proposal/secops-platform/07-phased-plan.md) 与 D 系拍板。细化设计稿随立项批拆建。

> **量级口径**：8–12 周（07 号 §3 原估 8–11 周；D25 校准——A5 引擎 MVP 4–6 周、阶段口径 8–12 周）。**Stage 2 起点**（D1 既定排期：引擎 MVP → phase10 迁移与 SOAR 退役）。

**阅读用语**：DAG是按依赖先后推进任务的无环图；它与工单状态机共用部分画布概念，执行语义仍分开。outbox指把待发布事件与业务数据写入同一数据库事务，再由后续消费者投递，不能用进程内派发代替；设计来源见[架构提案](../proposal/secops-platform/03-architecture-proposals.md)。DoD是阶段出口验收标准；D/A/F/X等来源短码见[术语与编号](../proposal/secops-platform/README.md#术语与编号)。

## 1. 定位与一句话

处置链全自动（告警→风险→工单无人工搬运）+ **自研轻 DAG 引擎 MVP**（先跑平台自有链路，不碰 SOAR playbook）+ outbox 事件持久化正式落地。

## 3. 核心切片（已确认模块）

1. **告警→风险→工单全自动路由**：phase7 路由规则成熟后开自动建单。
2. **值班表 + 升级链 + 通知聚合防轰炸**（F9；载体形态 = X4 立项前输入）——夜间告警可达值班人。
3. **runbook 绑定**（F10）：告警/风险类型 → 处置手册。
4. **证据中心**（F11；D26 合规映射同基座——触发驱动登记在案）。
5. **处置结论回传来源系统闭环**（F21）。
6. **自研轻 DAG 引擎 MVP**（03-A5）：六节点（action/script/approval/wait/branch/parallel）+ WorkflowEngine Port；**先承载平台自有巡检/处置链**（如 到期扫描→建单→通知→超时升级），**不碰 SOAR 现有 playbook**。
7. **outbox 事件持久化**（台账 C-20 收口批）：工作流推进 at-least-once 的前置件，本阶段正式落地（03-A3）。

## 4. 补全切片（可滑，不含outbox）

outbox是核心⑦和引擎工作流推进at-least-once的前置件，不能滑到引擎之后；若引擎提前，outbox只可同批或更早前移。

## 6. 出口标准（DoD，07 号 §3/§4.4）

典型告警端到端无人工搬运；夜间告警可达值班人；**一条平台自有链路在自研引擎上跑通并可审计**。

## 7. 边界

**不碰 SOAR 现有 playbook**（迁移 = phase10，按使用频率逐个重建+双跑对账；D23 检查点三指标——playbook 数量/复杂度分布/续费成本——phase10 立项前以 phase8 迁移期数据定"全迁 vs 长期双栈"）。
