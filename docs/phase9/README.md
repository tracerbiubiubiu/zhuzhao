# Phase9 — 持久业务协同与证据闭环

> 2026-11-11重规划；尚未实施。本阶段建议以适合当前规模的协同形式替代旧“自研通用DAG MVP，Phase10迁回退役SOAR”；保留业务效果，具体架构选择在E08定案。专业平台继续承担专业编排；唯一排期见[总账](../review/planning-backlog.md)。

## 1. 目标

R02完善本平台安全生命周期与FSM、TR、既有SOAR/Agent间的持久交接、取消、回传和人工接管；R05提供证据索引、手册引用与责任交接。消费现有值班/知识/专业平台，不再默认另建排班、通用runbook或证据数据湖。

不可丢的意图已由R01/P6.1先于消费者建设，本阶段按真实消费者扩可靠投递、幂等、毒事件、重放与观测；不能把早期尽力派发冒称已有outbox，也不能为等到P9而容忍前期不可丢动作无恢复。

## 2. 三类语义与单一权威

工单FSM管本地业务状态，TR管任务/attempt，SOAR管专业workflow，领域Agent管有限模型工具循环。统一能力合同、身份、批准、run/trace关联、结果和证据视图；不要求共用执行引擎或万能画布。回调/通知重投不重跑业务动作，未知远端效果进入对账。

人工批准绑定确切版本/输入/目标和有效期，恢复或新计划不能沿用旧批准；等待先登记，重复/乱序回执不重复推进。需要Agent的协同链消费A07，普通跨平台链不以完整Agent交付为前置。

## 3. 首期保留的用户效果

先一条可信告警→风险→工单→任务→结论回源的免搬运链。动作、脚本、批准、定时/事件等待、条件选择、并行汇合由本地/外部各自写主管；首期两分支/all-success汇合即可，未知效果先对账。专业流程可留SOAR运行，平台记录责任/run/证据与恢复，不要求先自研通用图引擎。

夜间接管用有效时段主备快照、停用/无人、接管回执、超时升级和交接验收；优先既有排班，无专用系统用薄责任表。通知汇总不能吞紧急升级，源回传失败不能当已送达。模板复用可先引用外部已审版本或有界配置，不先造市场。

## 4. 架构决策与退出项

E07基于P8出口的发布/容量/故障/权限证据评估服务拆分与插件边界；模块化单体是有效长期形态。E08在P7比较供给，P9定案：建议替代默认通用DAG自研、市场和强制SOAR迁回的技术形式，逐项保留/评审业务效果。确有专业供给无法承载的本地环节时，只为该缺口另立最小包，列成本、恢复和兼容验收；不以“平台完整度”为理由扩建。

## 5. 出口

一条本地生命周期链跨进程故障后可恢复、不丢意图、不重复副作用；受权人工接管与责任回执可见；专业来源收到结论或显示待回传；证据引用带来源/hash/权限/保留分类，缺件不能假装齐全。外部mock/contract通过与真实链路通过分列。

P10仅接收已经裁决的有限补充（E05等），不设全量迁移或专业平台退役目标。旧8–12周估算与六节点引擎设计保留为历史比较输入，不用于当前承诺。

## 双模式及企业授权继承

本阶段沿用[UAA与独立模式合同](../design/uaa-governance-integration.md)。独立模式不依赖公司UAA配置；企业模式按纳管来源和当前有效授权执行。Agent/知识/skill/专业执行、后台恢复及扩展不能用仍有效的配置或grant绕过已撤权/过期投影。各入口在本阶段开工和验收时复用合成反例，不反向成为P6.1双模式基础交付的前置，不另建UAA专属阶段。
