# 04 — P6-R4 度量与报表（设计稿）

> **文档定位**：段级设计稿（2026-10-26 建档）——[README](README.md) §2 R4 段整合展开；**登记级设计稿，可后置**。总纲与拍板状态 = [README](README.md)。
> **量级**：第一档 1–2 周；二三档触发驱动不占排期。

## 1. 定位与一句话

风险处置的度量出口：**看板 / 导出 / 临时问答（DSL）/ 周期成文报告**——四档演进；第一档轻装可用，二三档等真实诉求触发，不预建。

## 2. 现状基线（代码级事实，2026-10-26 核实）

- 工单域**零统计端点**（勘查实证——既有 panic 聚合/路由对账为运维面非业务统计）；R1 聚合端点（补全切片）将是平台第一块业务统计基建，R4 直接消费不另建。
- 导出先例 = P4-4 模式（excelize + L2 可见性约束）。

## 3. 范围条目（四档）

### 3.1 第一档：看板 + 导出

- 风险敞口看板（按级别/状态/来源/系统分布）、处置 MTTR、超期清单、接受单到期清单——**直接消费 R1 聚合端点**（不另建统计面防口径漂移，勘查处=外部平台聚合视图与报表两套端点的教训反向印证）。
- excelize 固定列导出（复用 P4-4 模式；**必须接 L2**——不可见行不出口）。

### 3.2 第二档：统计 DSL（触发 = 第一个"管理层看数"临时问答需求）

- 形态 = 单端点 `{api_code, group_by[], metrics[], time_range}` + **三层白名单**（api_code 枚举 → 该码允许分组字段 → 该码允许指标；白名单外一律 400，绝不拼接用户输入入 SQL）。
- **词表含工单域**（2026-10-26 所有者批准）：api_code 一并覆盖工单运营统计码（数量趋势/优先级分布/处理时长排行/超时排行/用时分布）——工单域无统计端点的缺口在此补齐，风险域与工单域共用同一套白名单基建不另造。
- **口径换算独立抽包+单测**（外部平台实锤 bug：'上月'用 `offsetYear(-1)` 算成去年同月、'去年'用 `lastMonth()` 归年——统计口径枚举 → start/end 换算表必须单独覆盖）。
- **apiCode/setCode 双编码**：一个能力服务多个数据集——"按状态/按 owner/按系统"是同一 api_code 的不同配置而非多个接口。

### 3.3 第三档：周期版式报告（安全周报/月报，2026-10-26 所有者批准登记）

- 报告模板 + 占位符灌数成文（封面/图表/结语）→ 导出 Word/PDF；报告任务**骑既有 cron** 定时生成；**事件驱动形态挂 R3 共享事件面**（处置终态→自动出报告，外部平台先例：流程办结自动产出报告）。
- 实现纪律：text/template + html→PDF 或 docx 模板灌数，**不引 Luckysheet/docx4j 类重渲染引擎**（勘查裁决：7535 行级渲染工程 ROI 严重不匹配；xlsx/docx 模板+占位符+表格区域扩展已覆盖绝大多数场景）。
- **水印/分享短链（外发防泄密）随本档触发评估**。

### 3.4 合规预留（零成本）

- D26：R4 预留「证据来源引用」字段（已拍——合规框架映射触发驱动时直接用）。
- D27：数据分类分级待 X5 资产平台契约（默认 risk_items 预留 classification 列）。

## 4. 启动拍板点

1. 看板载体：zhuzhao-ui 自建图表 vs 外部 BI——勘查参考口径 = 「BI 不自研 = 开源件独立部署 + Port 集成」（iframe 集成形态有外部平台实测先例，凭证应改短时 ticket 而非 URL token）；二档再议。
2. DSL/版式报告启动时点（触发驱动，无排期承诺）。

## 5. 边界（不做）

大屏设计器、Luckysheet/docx4j/Nashorn 类重引擎（勘查不采纳清单）；GRC 合规报表体系（D26 触发驱动）；实时大屏推送（SSE 触发登记，见 README §7 总账）。
