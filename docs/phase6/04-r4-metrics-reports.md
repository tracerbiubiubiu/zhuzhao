# 04 — P6-R4 度量与报表（设计稿）

> **文档定位**：段级设计稿（2026-10-26 建档）——[README](README.md) §2 R4 段整合展开；**登记级设计稿，可后置**。总纲与拍板状态 = [README](README.md)。
> **量级**：第一档 1–2 周；二三档触发驱动不占排期。

## 1. 定位与一句话

风险处置的度量出口：**看板 / 导出 / 临时问答（DSL）/ 周期成文报告**——四档演进；第一档轻装可用，二三档等真实诉求触发，不预建。

## 2. 现状基线（代码级事实，2026-10-26 核实）

- 工单域**零统计端点**（勘查实证——既有 panic 聚合/路由对账为运维面非业务统计）；R1 聚合端点（补全切片）将是平台第一块业务统计基建，R4 直接消费不另建。
- 导出先例 = P4-4 模式（excelize + L2 可见性约束）。

## 3. 范围条目（四档）

### 3.1 第一档：看板 + 导出

- 风险敞口看板（按级别/状态/来源/系统分布）、处置 MTTR、超期清单、接受单到期清单——**直接消费 R1 聚合端点**（不另建统计面防口径漂移，勘查处=外部平台聚合视图与报表两套端点的教训反向印证）。
- excelize 固定列导出（复用 P4-4 模式；**必须接 L2**——不可见行不出口）。
- **每日敞口快照表（2026-10-30 头脑风暴登记，建议随本档第一档）**：每天 EOD 对风险域/工单域各跑一次状态矩阵聚合（级别×状态/类型×优先级×状态 + 超期在办数），落快照表——**趋势/同比环比/净流入流出的唯一历史数据源**（主表状态被后续变更覆盖、events 有保留期；本表不做则历史趋势永久丢失，性质同审计归档）。骑既有 CronScheduler（audit_archive 同款形态），量级 0.5–1 天；第一档不加 owner/部门维度（需要时从主表按保留期窗口补查）。
- **工单侧第一档固定统计（2026-10-27 三方对标批登记，◆启动拍板 3）**：`GET /tickets/stats` 聚合端点——group_by 白名单枚举（status/priority/type_code）+ 指标（计数、超期在办数/率），**随 R1 聚合端点同批同模式落**（L2 同源=BK-21 三件套 buildTicketWhere 直接复用，导出先例在 `ticket_export.go`）；时长排行类留二档 DSL（无 closed_at 列硬算成本高）。蓝本=ficus dashboard（11 类计数+分布+排行+直方图，三方对标统计面最强）。**建议随批**——工单域零统计端点是「完善工单」最显性缺口，二档 DSL 触发驱动无排期承诺；件级设计在 [06 号](06-ticket-completeness.md) 件 11，两处同一决策。
- **首页工作台作为第一档消费形态（2026-10-30 登记，输入=zhuzhao-ui 首页改版走查诉求）**：首页按角色渐进的态势指标（admin 全局积压/任务失败率/效率卡——闭环时长/SLA 达成率/自动化率）直接消费 `GET /tickets/stats` 与每日敞口快照表，**R4 看板与首页同源同口径，不另建首页专用统计端点**；首页非工单指标（通知未读/任务 runs 聚合/PAT 临期）用各自现有端点不走统计面。设计稿：[08 号](08-home-workbench.md)（07 号 §3.4 同日登记，间隙小批窗口）。

### 3.2 第二档：统计 DSL（触发 = 第一个"管理层看数"临时问答需求）

- 形态 = 单端点 `{api_code, group_by[], metrics[], time_range}` + **三层白名单**（api_code 枚举 → 该码允许分组字段 → 该码允许指标；白名单外一律 400，绝不拼接用户输入入 SQL）。
- **词表含工单域**（2026-10-26 所有者批准）：api_code 一并覆盖工单运营统计码（数量趋势/优先级分布/处理时长排行/超时排行/用时分布）——工单域无统计端点的缺口在此补齐，风险域与工单域共用同一套白名单基建不另造。
- **口径换算独立抽包+单测**（外部平台实锤 bug：'上月'用 `offsetYear(-1)` 算成去年同月、'去年'用 `lastMonth()` 归年——统计口径枚举 → start/end 换算表必须单独覆盖）。
- **apiCode/setCode 双编码**：一个能力服务多个数据集——"按状态/按 owner/按系统"是同一 api_code 的不同配置而非多个接口。

### 3.3 第三档：周期版式报告（安全周报/月报，2026-10-26 所有者批准登记）

- 报告模板 + 占位符灌数成文（封面/图表/结语）→ 导出 Word/PDF；报告任务**骑既有 cron** 定时生成；**事件驱动形态挂 R3 共享事件面**（处置终态→自动出报告，外部平台先例：流程办结自动产出报告）。
- 实现纪律：text/template + html→PDF 或 docx 模板灌数，**不引 Luckysheet/docx4j 类重渲染引擎**（勘查裁决：7535 行级渲染工程 ROI 严重不匹配；xlsx/docx 模板+占位符+表格区域扩展已覆盖绝大多数场景）。
- **水印/分享短链（外发防泄密）随本档触发评估**。

### 3.4 合规预留（零成本）

- D26：R4 预留「证据来源引用」字段（已拍——合规框架映射触发驱动时直接用）。
- D27：数据分类分级待 X5 资产平台契约（默认 risk_items 预留 classification 列）。

## 4. 启动拍板点

1. 看板载体：**✅ 已拍（所有者 2026-10-27）自研**——zhuzhao-ui 现有 `echarts ^6.1.0` 依赖与 `Echart` 组件，零新依赖；外部 BI（独立部署+iframe）出局。触发时点=首个固定看板消费场景（如管理层周会投屏），数据源=R1 聚合端点 + 06 号件 11 工单统计，不另建统计面。**与 phase5 S8 数据大屏的边界（2026-10-28 所有者澄清「两者是两码事」）**：R4 看板=风险域专用（数据源 R1 聚合端点）；S8=通用运维大屏、**维持独立触发驱动**（phase5 README P5-S8，~1 周）——互不承接、数据不混用，哪边先有真实受众哪边先做。
2. DSL/版式报告启动时点：**✅ 维持触发驱动**——统计 DSL 触发=首个「管理层临时看数」需求（如「上季度哪些系统超期最多」：管理员在查询页选 api_code/group_by/metrics/time_range 即得，免开发专用端点）；版式报告触发=首份「安全周报/月报成文」需求（模板+占位符灌数→Word/PDF，骑 cron）。
3. 工单侧第一档固定统计：**✅ 已拍 随 R1 聚合端点同批**（§3.1；=06 号件 11，06 号拍板 2 同一决策）——`GET /tickets/stats`（状态/优先级/类型分布 + 超期在办数/率），BK-21 同源三件套，+1–2 天。

## 附录 A：跨模块指标目录（2026-10-28 所有者提出——「这些数据后面可能用于模块仪表盘展示」）

> **定位**：全模块计数/指标盘点目录（登记级不排期）——供未来模块仪表盘与统计 DSL 词表扩展取材。**三档分级**：P1 = 现成数据简单端点（随各域小批）；P2 = 依赖在建能力（C-21+ 件①等）；P3 = 统计 DSL 收编（趋势/排行/分布——DSL 立项时入词表）。
