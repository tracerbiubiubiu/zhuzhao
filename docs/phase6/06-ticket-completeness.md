- **方案（渲染器复用零后端）**：①先把发起页字段渲染段抽共享组件（DynamicFormField 落名——设计器注释预告载体）；②字段配置弹层加「预览」Tab（设计/专家/预览三 Tab 同框），`designer.serialize()` 输出经 defs 适配喂同一渲染组件（内存 schema 不落库）；formula 字段预览态显「提交时服务端计算」占位、file 字段预览态禁上传（或试传即弃）；与件 20 关系=容器无关（弹窗形态可先行，整页化落位后三 Tab 随新壳平移）。
- 蓝本：宜搭/简道云设计器内嵌预览通例；发起页渲染器即渲染 SSOT（预览与发起零漂移——件 18 求值端点落位后预览态显隐亦可接真求值）。

### 3.27 件 26 公式引用校验与提交重算

- **当前归属（2026-11-11，所有者最新安排）**。件 26 恢复 Phase6，公式引用与输入隔离问题保持开放。现有同类型 `formula → formula` 禁令及同名值位引用、请求或旧公式值进入求值的风险作为规划输入。先结合当前可达路径和重规划方案核对必要性，再确认修复与回归范围。发现记录见 [12 号 C1](../phase5/12-scenarios-and-tests.md)，下列保存、提交和回归描述作为候选，不冻结实现。

- **提交重算**。`internal/service/ticket/service.go` 的 `Service.Create` 和更新 `custom_data` 的 `Service.Update` 共用 `internal/service/ticket/type_admin.go` 的 `Service.validateCustomData` 与 `applyFormulas`。按当前 schema 从公式求值环境中剔除所有公式字段键，包括本次请求传入的值和更新时合并的旧值。公式字段以本次服务端重算结果写入。

- **提交路径回归**。通过建单和编辑提交伪造的公式值，断言普通字段正常写入、公式字段以服务端重算值落库，省略公式字段也能成功。另用测试夹具直接准备旧校验可放行的同名链式 schema，绕过新保存守卫验证提交侧隔离，断言求值失败且没有写入或覆盖工单数据。
