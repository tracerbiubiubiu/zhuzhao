## 3. 范围三件

### 3.1 设计器 v2（前端，B0-2/B0-5）

1. **向导式独立页**：类型信息（code/名称/描述/SLA）→ 流程画布 → 超时催办，三步整页切换（ecmdb Wizard 形态）；未保存离开拦截；视口锁定铁律照前端仓规范；动态菜单/权限码注册新路由页（`ticket:type:manage` 沿用）。JSON 源码模式保留为画布步内的兜底形态（对齐 S2「双模式共存」既定口径），不再与基本信息/超时表格挤同屏。
2. **节点注册表 + 属性抽屉**：FlowGraphDesigner 增注册表（节点类型/属性组件），点击节点弹右侧抽屉——transition_meta（超时/催办）收编进抽屉，表格形态退役；新增自动化能力仍走 ActionRegistry 外挂配置（§6 护栏③），画布不新增功能节点类型。
3. **出边条件构建器**（B0-5，随 B0-4 契约）：点边弹构建器——左值 = 同类型字段 schema 下拉（复用字段设计器元数据，禁手打）、操作符集（= ≠ > < in not in，expr 语法子集）、组内 && 组间 ‖、表达式预览；产出入边条件元数据。

### 3.2 引擎·定义快照版本化（B0-3，S3b 决议④前置抽出）

- ticket_types **编辑版/发布版分离**：新增部署端点（`deploy`，按 standards §3 公约 POST 形态）锁快照；快照表蓝本 = S3b workflow_* 五表族（§4.3）按 FSM 类型简化换算（类型级 states/transitions/transition_meta + version + published_at）。
- **快照范围：✅ 已拍含字段（2026-10-27 拍板 5）**——快照 = states/transitions/transition_meta + **ticket_type_fields 全量只读快照**（含 field_meta：formula/visible_when/fetch/布局）；在途单按自己版本的字段 schema 渲染与 G2 校验（渲染与 G2 两处读入口改道，+0.5–1 天），字段锁死守卫退为编辑期提示、FieldImpact 软告警退役。判据=「整改单活几周期间管理员要能改该类型字段」；对照系 eflow 快照仅含画布（其表单无版本化属缺口非设计）、ficus 两者皆无。迁移时字段语义见下十条之 6。
- tickets 钉**创建时快照版本**，运行时按实例版本取定义——`StateMachine`/`transition_service` 读定义入口改道（活读 → 按版本取快照；缺版本处置见下十条之 2：读路径降级展示、写路径 fail-closed）。
- **在途/存量边界十条（2026-10-27 第二组拍板落定；外审 ④⑤ 修正并入）**：
  1. **钉版本时点=建单时**：tickets 记录创建时类型的已发布版本；此后状态机/转换校验/超时催办/自动路由条件/字段 schema 全部按 `(type_code, version)` 取快照，不再活读。
  2. **存量一次性回填，兜底读写分向**：上线迁移把各类型当前活定义冻结为 v1 快照（复制现 `ticket_types` JSONB 行，+0.5 天），所有存量单打 v1——上线后不存在无版本单；兜底路径保留作防御：**只读展示**（历史单出图/时间线）缺版本可降级最新发布版，**写路径**（转换/校验/自动路由求值）缺版本 **fail-closed 报错**（静默按最新版执行转换是合规场景下更危险的错）。
  3. **编辑永不影响任何单**；deploy 产生 N+1；仅 deploy 之后新建的单用 N+1。
  4. **快照内全部钉住，不开「非结构性配置热修」口子**（超时分钟数等亦随版本）——修正在途单的配置错误走条款 6 迁移；开口子就要定义哪些算「非结构性」，边界会被持续试探。
  5. **活配置清单（永不入快照）**：message_rules/模板、assignment_rules（仅建单时用一次）、权限码与 L2、ticket_templates 预填（仅建单时用一次）、ActionRegistry（代码）、标签/抄送（数据）。
  6. **迁移工具两段**：最小档「同名直映批量迁移」**随 B0-3**——新版本未删除任何状态时，一键把某版本全部在途单迁至最新版（+0.5–1 天，覆盖「修配错超时」类 80% 需求），留痕 `version_migrated` 事件（payload 新旧版本）；迁移字段语义（含字段）：被删字段数据留 custom_data 不再渲染，新增必填不在迁移时校验、下次写入由 G2 拦（Jira 同款）。完整映射档（有状态被删时的人工映射+dry-run+分批）= [06 号件 15](06-ticket-completeness.md) 维持 P2 触发驱动（覆盖关系已在 06 号登记）。
  7. **版本删除守卫**：被**任一未删除工单**（含历史单——B0-2 只读图按版本出图）引用的版本删除返回 409（同今日「有单的类型不可删」口径）；类型 `is_active=false` 仅阻止新建；旧版本自然退役，无需独立禁用开关。
  8. **deploy 预检替代 stuckStates 在途告警**：lint 全绿方可 deploy；预检展示与当前发布版的 diff（状态增删/转换/字段变化）+ 各版本在途单计数 + 删状态时提示「迁移需映射」。
  9. **自动路由条件也在快照里**：每张单按自己版本的条件被评估——这是 B0-3 必须先于 B0-4 的根因（§4 顺序硬约束）。
  10. **导入导出包=快照同形**（06 号件 7）：导入永远走 deploy 语义产生新版本，绝不覆盖活定义。
- **业界对照（边界十条的依据）**：钉住旧版走完=Camunda/Flowable 默认、ServiceNow Flow Designer、钉钉/飞书审批、eflow；发布即迁移=Jira（发布草稿时强制映射被删状态、全量即时切换）；钉住+显式迁移计划=Camunda/Flowable Process Instance Migration；覆盖式热载=ficus 反例。本段取「钉住走完 + 最小迁移档随批、完整档触发」。
- **stuckStates 改图告警退位**：由边界十条之 8 的 deploy 预检替代（「未 deploy 的变更不影响任何单」+ diff + 在途计数）；管理端 version CAS 维持防并发编辑。前端消费：类型列表行加发布状态/版本列 + 部署操作。

### 3.3 引擎·自动路由执行器（B0-4）

- transition condition 从「拦人」升格「路由」：条件元数据挂到具体出边（from→to），命中即自动流转，无人值守。
- **条件左值词表（2026-10-27 增补）**：自定义字段（字段 schema 下拉）之外**必含系统字段与时间谓词**——`priority`/`status`/`assigned_to`/`created_at`/`status_changed_at`/`sla_due_at`/超期布尔/actor——由此「超时→自动转派」= 时间谓词条件路由，**吞并升级链形态**（与 [phase5/03 号](../phase5/03-s3-flow-semantics.md) 演进总表「升级链与 S3a 动作库结合不独立建」同口径）；06 号件 9 撤回的 validator `assigned_to == null` 亦依赖此词表注入。
- **condition roles 词表扩展（2026-10-27 第三组）**：在 assignee/creator/org_admin/admin 之外加 **`field:<user 字段 key>`**（字段取人——该字段当前指向的用户可执行此转换）；首例 = 整改单复核边绑 `risk_owner`（owner 交接时字段可改、created_by 冻结，复核权随当前 owner 走——[03 号 §3.1/拍板 6](03-r3-ticket-linkage.md)）；校验=字段须为 user 类型（06 号件 5）、保存期检查字段存在；B0-4 契约随批。
- **出边条件契约三语义（2026-10-27 增补）**：①**默认边**——有条件出边的状态须恰有一条无条件默认边；②**互斥优先级**——多条命中按配置序取首个（序在 meta 显式，不依赖 JSON 键序）；③**无命中禁静默**——全不命中走默认边，缺默认边的定义在 lint/保存期拒绝（ficus ErrNoBranchMatch 教训，§2.3）。
- **设计期 lint 三规则（随 B0-5）**：条件边无默认边 / 自动路由环（A↔B 互为条件路由——运行时链深防护之外的静态防线）/ 不可达状态；与既有 stuckStates 死路检测同层。
- **执行通道：✅ 已拍 C（2026-10-27 拍板 3）——commit 后独立事务即时推进 + 扫描器兜底对账**。定义三条：①触发源分三类共用同一求值函数——数据变化驱动（建单/字段写入/转换 commit 后，与 post_actions 同挂点即时推进）、时间驱动（超时/老化——扫描器主通道）、回调驱动（`run.succeeded`/`run.failed`——事件订阅形态 TransitionAction，B-8）；②**第二跳并发控制**：独立短事务内按「评估时假设的状态」做 CAS（复用 `UpdateStatusTx` 条件更新咽喉，CC1/CC2 同源），CAS 未命中=状态已被并发改写，放弃本跳交扫描器或下一事件重评——不基于过期状态执行转换；③扫描器同时兼任数据变化驱动类的崩溃窗口（commit 与回调之间）漏网兜底，与 R3 终态对账扫描同哲学。**头号论据=BK-11 嵌套取池先例**：B（同事务链式）要求链上每个求值器/Action 都 tx 感知（RowQuerier 模式），一处走池即复现 4 连接池循环等待（本仓有锤击回归记录）；C 天然把第二跳移出第一跳的连接持有窗口。A 的真实代价：默认 `timeout_scan_tick=5m`（`config.yaml:157`/`config.go:356`）、窗口内单停在语义非法中间态污染待办/metrics/SLA 时钟/通知/available 列表、且与 §8「≤5s 可见」验收不兼容。
- **循环防护**：链深限制复用 B3-3 post_actions 既有机制（防 A↔B 互为自动路由抖动）；**系统执行者身份入审计**（actor=system 语义，与人工流转可区分）；`available` 端点排除自动转换（人工可执行列表不出现）。
- 触发时点按触发源分三类（见执行通道定义①）：数据变化驱动走 commit 后即时推进；时间驱动走扫描器；回调驱动走事件订阅——三类共用同一求值函数，防两路漂移。

## 6. 边界（不做）

- **判断 = 自动路由（exclusive 分流），不是审批流**——S3b 审批流维持触发驱动（等首个真实审批场景，03 号 §4 既定）；本轮不捎带审批人/会签/驳回/多级审批。
- **不做并行/包容网关**——FSM 单态语义（一工单同一时刻一个状态）容不下并行分支；BPMN 全家桶 = 03 号明文红线。
- **引擎不内置功能节点类型**（easy-workflow 反面教训，03 号 §3.3 既定）——画布不出现通知/脚本/取数节点，自动化一律 ActionRegistry 外挂；本条直接约束 B0-2 属性抽屉设计。
- SLA 层 1 / automation_rules / S3b / 表单条件显隐等照旧触发驱动（03 号演进总表既定，本轮不入）。
- **运行态只读图**（详情页流程图当前态高亮+已走路径点亮）**已并入 B0-2**（2026-10-27 拍板 06-4，06 号件 2 销）；设计稿留 [06 号 §3.2](06-ticket-completeness.md) 供 B0-2 取用。

## 8. 验收口径（能力语言，走查式）

- **设计器**：独立页三步配完一个「带条件分支 + 状态超时」的类型，全程不出现 JSON 文本域；改图未保存刷新有离开拦截。
- **自动路由**：配 `open→closed（priority==1）/ open→assigned（默认）`，建 P1 单自动流转至 closed，审计可见 system 执行记录；非 P1 停在 assigned 等人工；自动转换不出现在 available 列表。**负向补两条（2026-10-27）**：条件出边全不命中→走默认边，缺默认边的定义在保存期/lint 被拒，**绝不静默办结**；多条命中→按配置优先级取首个且可在审计中看到命中边。
- **执行通道（C 已拍）**：建单后秒级可见自动流转（轮询 ≤5s 断言）；扫描器仅作漏网兜底——人为跳过 commit 后推进的单可被扫出补推；**第二跳并发**：在第一跳提交与第二跳执行之间并发改状态 → 第二跳 CAS 未命中放弃、交扫描器重评，审计中不出现基于过期状态的转换。
- **快照**：在途单流转中途 deploy 新定义——旧单按旧版本走完、新单走新版本；改图不 deploy 不影响任何单；存量回填后不存在无版本单；同名直映迁移一键把旧版本在途单迁至最新版且留痕（`version_migrated` 事件）；被任一工单（含历史单）引用的版本删除返回 409；历史单详情页按其版本出图。
- **负向必测（fail-closed）**：循环定义（A↔B 互为自动路由）被链深防护拦截且告警；**快照缺版本分向**——读路径（历史单出图/时间线）降级最新发布版展示、写路径（转换/校验/自动路由求值）fail-closed 报错；无 `ticket:type:manage` 账号不可见部署入口；validator 与自动路由叠加时校验冲突的语义（自动路由跳过人工 validator，仅拦人语义不适用——随 B0-4 设计定稿）。
