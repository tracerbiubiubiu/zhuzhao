# 首个核心可用版本：1月试用、2月1日前可用

日期：2026-11-14。所有者已确认目标为**2027年1月安排试用，2027年2月1日前有可用版本**；原单席×每周5工程日保留。真实UAA及公司消息HTTP联调时间尚未确定。本页是最新首版范围与阶梯方案，**范围/目标已定，单席按期可行性尚未证明，不是已经启动或完成研发的声明**。机器状态见[首版目标](../review/first-usable-release-target.json)。

## 1. 首版究竟要能用什么

旧→新、收益、基础项与后继增强先看[首版变化对照](../review/core-release-change-comparison.md)。首版必须有风险、工单、taskrunner、activelist和消息的实际联动，以及完整三层权限和可接公司治理的UAA公共实现。现有能力尽量复用；基础版可以简陋，但不能只交演示菜单或彼此独立的模块。

首条候选旅程固定为：**授权登录→接收/人工录入风险→评估和明确责任→受限派发整改工单→处理人处置/证据→获准任务经taskrunner调度→经API更新activelist→AL数据变化触发一次获权TR后继任务并按约定通知→工单显示原任务结果→风险负责人复核**。后继先选择只读复核等一个实际用途，不再写回触发它的AL字段；不是只发通知或刷新页面，不设计任意DAG，也不让同一变化反复触发自己。真实风险尚无接入时可人工录入实际风险，mock单独标识，不能拿mock数据证明真实来源已接通。

建议先限定一个结论源/规范化输入、一种整改流程、一个AL结构和字段组、少量固定获准动作、一种变化订阅、一条公司HTTP消息渠道。使用受审配置即可；这是待实施前用实际场景绑定的有限组合，不是已经批准真实类型/组织/收件人或所有自动动作。

可采用更小的受控首版画像：固定整改流程和基本字段，暂不启用公式或任意配置改写；监控AL类型先开放普通新增/更新，暂不允许它的replace/import及破坏性schema修改。限制必须由服务端执行并有清楚提示，不靠操作约定，也不退役其它AL类型已有功能。用源outbox→核心持久inbox/ACK完成一条变化推送，不先建设分页多消费者流平台；先用本地目录/批准映射，不等完整HR同步。若首批实际业务需要上述能力，补齐其安全合同后纳入该批，不能为赶日期静默弱化。

- **风险/工单**：列表、详情、评估/接受、责任、受权派单、处置证据、复核/逐风险结论；保留已有工单与有界N:1模型，不先做自动聚类、通用合并或完整设计器。
- **taskrunner/AL**：任务提交、运行和结果能关联原工单；所选AL写有当前行/字段权限、版本冲突和操作回执；AL变化能可靠交给所选后继。提交成功不等于业务完成，失败/待核实必须可见。
- **消息**：复用模板、消息中心、发送记录和ChannelSender端口，补真实HTTP通道及私有字段映射；受理/送达遵真实合同，超时不伪装成功。业务已提交但通知失败应显示待发/失败，不回滚成业务未发生。
- **权限/UAA**：本地独立模式仍完整可用；企业模式支持中央纳管账号、角色、菜单/按钮/API资源及适用范围。后台与页面都执行相同边界，不能只做SSO或隐藏菜单。
- **界面/运维**：正常首页、上述功能的薄UI、普通账号可完成旅程、必要业务/审计历史和失败处理、固定五仓组合/配置/启动/备份恢复。复用既有页面和组件，不等全站重设计。

AI、RAG、skill、MCP产品化、高级仪表盘、设备模块扩展、复杂通知策略台、全量插件治理、通用调度恢复台、多实例和微服务均不挡首版。保留其原路线与后继窗口，不在试用期继续塞入这些新范围。周期任务若首版实际启用，仍验其所需恢复/授权，不能用后置完整控制台免除基本正确性。

## 2. 现状重核：接口存在不等于已经接通

- 风险域当前没有实际model/service/迁移/路由或页面，是新增业务，不是只替换endpoint。
- 工单spawn_task已有提交路径，但字段映射、task与工单节点关联及结果回贴未完整接线；taskrunner是调度/签名回调服务，不是通用脚本执行平台。
- AL已有CRUD、CAS和导入能力，尚无本次需要的持久变化事实/订阅链。网关L1及AK/SK不能代替所选数据的行/字段授权。
- ChannelSender接口已有，普通业务当前装配UIPStubSender；release下即使配置endpoint仍返回真实发送未实现。现有真实webhook用于死信告警，不等于普通消息已经接公司渠道。
- 本地三层、JWT/RT和权限变更原语已有；真实SSO、三类企业feed和来源投影未实现。旧离线57例只证明合成合同，不代替产品/PG/浏览器/真实企业验收。

准确源码符号、端口及证据见[业务四链重核](../review/reports/core-release-chain-recheck-2026-11-14.md)、[UAA重核](../review/reports/core-release-uaa-recheck-2026-11-14.md)和[薄UI/试用](../review/reports/core-release-ui-trial-plan-2026-11-14.md)。

## 3. 三层权限是首版主线

认证先确定真实主体，再执行**L1路由/方法功能权限→L2资源可见范围→L3具体动作资格及业务条件**。UAA管已纳管的账号/角色/资源授撤；平台仍执行三层，中央功能许可不会自动让人读取任意票或变成处理人。中央提供数据属性时按确认规则映射/求交，不用本地范围扩大中央限制。

菜单、按钮和API使用稳定资源键并保持B案绑定；菜单不可见、接口不可调、按钮无权是相关而不互相替代的验证。来自UAA的同名admin/角色不能直接映成当前本地绕过L2/L3的系统管理员。直接角色、组织角色和继承来源都要收敛，撤权不能被另一条旧来源补回来。

首版验：普通处理人、风险组获授权管理者、只读成员、CC、同部门非参与人；分别覆盖列表/详情/计数/写操作/任务结果/AL读写/消息。角色或资源撤回后，策略重载、缓存和会话失效有可见结果；重载失败不得显示全链已生效。后台任务使用可停用的受限主体/委托并复验当前权限，不把AK/SK或服务账号当全权放行。

企业受管写入口只读/受控，非受管本地管理保留。失联不自动切回本地放权。业务历史和专门审计职责分开已定；两IAM高风险写的本地审计失败回滚仍按原待确认项，不借本次时间目标推定批准。

## 4. 阶梯与试用窗口

下列为**目标窗口和退出条件**，不是已经通过工日/依赖核算的单席承诺。UAA工作从第一步贯穿并行推进，不能等业务全做完才补权限。

1. **11月后半：固定首条组合与接入合同。** 固定五仓/入网试验包、普通用户落点、权限资源键、UAA三类feed/真实消息适配合同及合成HTTP服务。实际公司材料/测试条件在内网准备，私有SDK/映射不进入公共核心。
2. **12月逐步交风险→工单人工闭环。** 优先让所有者通过普通账号实际操作，先解决责任、可见性、派单和复核；不等高级自动化、全部来源或全站视觉。
3. **随后合上TR↔AL↔工单及消息。** 先交上面的一个有限组合，验证重复、并发、超时、重启、撤权、回贴/通知失败和AL变化持久交接。后台动作先具备必要的可靠意图/幂等/恢复，不等通用引擎。
4. **目标1月11日进入核心试用，最晚目标1月18日。** 公共版先完整真实后端＋合成企业服务/HTTP反例；企业试用另须真实UAA与公司消息联调通过及适用公司准入。缺真实条件时，只能明确称隔离环境试用，不能称公司纳管版可正式使用。
5. **1月试用冻结首批范围。** 推荐1月11–15日操作/反馈，18–22日修正和再试，25–29日稳定/回归；最晚18日开始也至少留两周。每周由所有者和少量代表角色安排数次30–60分钟实际任务，聚焦权限阻断、责任、结果和失败反馈；不要求读全部代码和文档。2月1日前验收的是上述闭环，界面可以朴素。

若最晚试用入口仍缺必需链，不能把全部试用时间吞成开发缓冲，也不能悄悄删UAA/三层/AL反向联动。须及时调整有效产能、具体动作组合或报告日期风险。此前B0/B1只是过程中的底座/接缝出口，不能再当本次2月目标达标版；Phase编号不是整包串行门，首版会提前消费所需P7子能力。

## 5. 日期可行性：现有单席没有可承诺余量

假设2026年11月16日开始，至2027年1月29日共有55个周一至五，未扣节假日、请假和其它投入，不能当55个已保证有效工程日。1月11日试用则此前40日、其后15日；1月18日试用则45＋10。版本PR/main收尾1–2日仍占这个窗口，不重复做已经验证的升级。

旧有界UAA C/P为27–42工程日，真实R另13–22且不含外部等待，共40–64；共享C04/D06/X02等前置不在这个UAA增量内。新增薄业务UI/浏览器工作负载16–26日明确不含UAA及其它后端。仅前两种互不重叠工作视图已经43–68日，**还不是首版总价**，不能把完整风险/互通后端、真实适配和试用返工默认为免费。因此现在不能承诺一席在40–45实现日完成全部核心闭环；只把AI后移并不足以解决。

首版功能边界应保留，实施前按上述有限组合对旧D/U/CE/P/R逐项拆出净工作、复用和验收，形成可派发切片；这些是旧价的分配/替代，不将本页UI视图再加到旧包总价。准确首版总价尚未冻结，不输出伪精确的按期甘特图。四链报告的后端59–91日是较宽保守候选，包含部分可合法收窄画像；它不是首版不可缩减最低工期。采用上面的固定配置/受限AL写画像后须独立重估，不能机械加UAA或与UI视图相加冒充新总价。

建议同时准备两条可独立实现和验收的工作线：一条UAA/权限/接入，一条风险/工单/任务/AL/薄UI，再按实际独立产能复算；这不是认定两个agent等于两席，也不是自行改变已确认单席。若仍只有一席，日期风险必须保留；应尽快用首个实现切片的实际速度校准，不凭AI生成速度保证上线。

## 6. 真实接入条件和所有者参与

真实联调时间目前**未定**，绝不能设置等待为0来证明2月可启用。内网至少需要：测试应用/认证合同；账号、用户角色、角色资源三类feed及完整性/顺序/空集规则；资源注册/回传权限；专属允许/拒绝测试角色和组织；消息HTTP鉴权、收件人、幂等/查询/受理或送达语义；网络/CA/凭据配置和执行测试的人。只需在内网持有这些，不要求导出公司文档、名称、地址或凭据。

需要所有者后续绑定的是一个首批业务组合及小范围试用人员、可实际提供的研发/评审/验收产能、真实接口何时可测。已确认的日期、三层权限、UAA统管和核心模块联动不重复询问；真实资源/人员/接管策略仍按既有批准窗口执行。

公共仓交规范端口、合成合同与可替换HTTP/传输接缝；公司协议、消息载荷、密钥和私有业务在adapter仓/进程侧。接通真实公司服务不应要求把私有代码并入主仓。同一承诺合同内以旧参考adapter对新核心的真实互操作证明核心更新后少改或不改私有侧；内部模型/数据库迁移不向adapter泄露，破坏性合同调整须明确列升级/转换方案。后续AI和仪表盘沿原路线渐进，不能倒回来阻塞本版。
