# 首个核心正式版本：本地账号先运行，UAA随后接管

日期：2026-11-14；2026-11-16补B0准入、试用绑定与稳定出口。**公司允许先使用本地账号正式运行；质量和实际可用性优先，不勉强1月日期。** 完整UAA在核心稳定后投入，约两个月只是期望窗口。旧“1月11/18日必须试用、2月1日前核心及完整UAA公共实现全部交付”不再作为当前要求。

本轮仍是设计/估算，未开始业务开发或实际部署。产能为1个有效研发席位×每周5工程日，T0未启动。状态见[机器目标](../planning/first-usable-release-target.json)；首版本地核心的唯一分项数字源为[净估候选](../planning/local-core-release-estimate.json)。旧76包长期预算与UAA C/P/R保留追溯，不把本页子范围再加到旧总价。

## 1. 分开两个正式出口

**本地核心正式版**：风险、工单、taskrunner、activelist和消息真实联动，本地账号/角色/菜单及完整L1/L2/L3可用，有薄UI、业务历史、必要审计/日志、失败处理及生产恢复能力。公司已允许这种模式正式运行，不以真实UAA或完整P/R为前置。正式启用的真实HTTP消息等渠道仍需实测，不用mock成功代验。

**UAA纳管正式版**：在本地版上追加真实认证、账号/用户角色/角色资源三类同步、目录/条件范围/回传、撤权/故障及批准接管；仍不缩为纯SSO。P/R与公司纳管准入约束这个后继切换，不再阻塞本地正式运行。

核心阶段先留好可信调用身份、稳定资源键、账号与授权source/写主边界和版本化公共端口；不提前实现全部SSO、企业feed及治理UI。私有SDK、字段和凭据留adapter，避免后续为UAA重做业务。

## 2. 必交业务与支持范围

首条旅程：**本地授权登录→接收/人工录入实际风险→评估及明确责任→受限整改票→处置/证据→TR获准动作→API更新AL→AL变化触发获权TR后继→消息与原票结果→风险负责人复核**。后继先选只读复核等实际用途，防写回循环；刷新列表或只发通知不能代验AL→TR。

- 风险列表/详情、评估/接受、责任/截止、受限派单、逐风险证据/复核及有界N:1；专业发现/研判取外部结果，不自建SOC。
- 工单现有创建/分派/处理/证据/评论与复核继续承接；**列表多选加标签纳入**，有限ID逐票复验并显示部分失败。新类型查看范围、CC可看和评论而无附送办理权、单主责等已定政策保持。
- TR复用队列/cron/回调，补operation/task/节点关联、稳定输入、业务receipt和结果投影；受理不等于完成，未知先对账，投影失败不重做效果。
- AL复用CRUD/CAS，补本批后台行/字段权限、持久源事实、单push→核心inbox/ACK→获权订阅；签名不代替业务资格。消息复用模板/规则/站内通知/记录，补公共HTTP sender及一条实际公司映射，区分受理、送达、失败和待核实。
- 正常首页、上述薄UI、关键里程碑/操作事实、必要去敏日志和恢复同批交。**消息仍是核心阶段，不随UAA后移。**

先选择少量真实动作、一整改流程、一AL结构/字段组/订阅和一HTTP渠道。固定字段/流程、暂不开放formula或监控类型import/replace等是候选画像；须服务端明确执行，不静默漏事件、不退役其它类型已有功能。**先验证真实日常任务可用；实际必需就补齐合同和估价，不能为日期交受限演示。**

AI/RAG/skill/MCP产品化、高级仪表盘、设备扩展、完整设计器/迁版/插件治理、通用流/恢复台、HA/微服务后继。原Phase6未交功能不删除；本地核心正式出口不等于扩展后的Phase6全包收官。

## 4. 按质量出口交付

2026-11-17所有者确认[存量修复前移](../planning/audit-repair-plan-2026-11-17.md)：先收口当前越权、授权来源丢失和必要可用性，再进入依赖该基线的新业务；设计细化可继续。目标账号接管保护新增合同见[第一包§3.7](iam-first-batch-design.md#37-目标账号接管保护cf-06本轮已确认待实现)。本次不要求全部IAM-A/B/C或审计P2/P3清零，实际启用所需子出口仍须先验；本页真实试用及正式门继续适用，未因方向确认而视为通过。

[权限差距动作](../design/authorization-model-and-engine-choice.md#8-差距补齐动作与实施计划所有者要求落档)纳入下述适用出口：AUTH-GAP-01–04先保证来源撤权、当前入口、对象/集合一致及独立预期/有限诊断，复用S1/R2/TD03/TD05/MH02与原薄UI、Q1整合；AUTH-GAP-05正式前交所选单实例基线。AUTH-GAP-06仅多副本启用前补专项，单实例已有失败恢复不能省；AUTH-GAP-07在首次试用反馈及P6.3/P7复评，不阻塞本地正式。当前不追通用策略/图引擎，已归包不表示免费；本次净分配已替换旧笼统IAM额度，实际开工仍以首批速度校准，有净增先改账再实施。

组织/角色/菜单与数据范围的[12项层级场景](../design/rbac-inheritance-and-cascade.md#83-首版代表场景测试设计不是已通过清单)随第1–3步实际消费纳入验收：S1先本地权限/撤权和必要薄IAM，D03/D06随工单/风险及所选来源交类型交集、多任职/生命周期。HIER-D01父停用整子树暂停已确认、按本批验收；不要求完整任职总控台、全站U06或真实UAA先完成。原S1/整版额度保留历史，当前IAM净28–46保持，全版因兼容回归补量更新为97–151工程候选；场景与原反例复用，不新增截止承诺。

0. **B0合成隔离预演**：固定五仓制品/目标架构，在专用测试主体、合成/mock数据和隔离资源中复现启动、登录、基础工单，核所选adapter开发依赖与已有参考接口的打包/配置；公共稳定接缝的业务验收仍归B1，不变成B0前置。记录已知限制，真实业务试用须另过下述§4.1，不以B0完成或测试环境可重建授权放行。 B0已完成资产与目标新增量的归属见[分配说明](../planning/local-core-release-estimate.json#/pre_core_rehearsal_allocation)：目标画像冻结后、预演开工前估净剩余，不反依后置Q2；当前97–151仅为已选核心WBS，不宣称含尚未估出的目标B0新增量。
1. **共用接缝与本地权限**：冻结本批输入/输出、写主、事务内当前授权/撤权失败收紧，补可靠意图与证据日志；UAA-C只留接口与来源，先交实际启用范围的P1修复或受控关闭证明。
2. **风险→工单试用**：普通账号能录风险、派票、办理和合法复核，尽早让代表角色操作。

### 4.1 B0预演与真实业务试用准入

B0只证明合成隔离技术预演。接真实业务身份/数据或开放业务操作前，实施方出具当前候选的P1处置表：`AUTH-01/02/07`在所选范围内已修复并验反例，或对应能力已由服务端完整关闭并验所有可达入口拒绝。`AUTH-07`含组织管理同源粗门，不只`BindOrgRole`；`AUTH-02`含提交、计划、触发、重试及最终执行，不只UI菜单。保留其它独立合法来源及受权业务功能；关闭一个入口后不能从内部调用或worker绕回。具体清单与源码归[基础版边界](../design/foundation-release-boundaries.md#1-先交哪一版)及[第一批IAM](iam-first-batch-design.md)，不要求所有IAM增强一并结案。

试用前沿Q12绑定一张受审运行卡：目标环境/网络与五仓版本、启用能力、代表角色和人员范围、数据来源/敏感性及保留策略、凭据边界、实施/支持联系人、故障停用与回退入口。未知值保持pending；纯合成预演与真实业务试用分别记录，不能把“公司允许本地账号”解释为任意环境/数据已经批准。真实业务试用产生的记录按运行卡保留/迁移，纯副本或合成数据清退也由画像明确，不能沿现测试数据可重建授权自动清空真实业务记录。公司名称、内部地址、真实账号及秘密留内网记录，公开仓只存去敏引用。

消息HTTP合同和联调窗口沿MH01/MR1发起：公共sender冻结前由所有者协调提供方提供字段/鉴权/受理、幂等、查询/送达及故障语义，实施方先用合成fixture验公共合同；MR1正式消息验收前在内网绑定实际映射、授权与测试窗口。真实材料未知不当零等待，阻塞的是对应真实消息/正式出口，不阻mock公共sender及其它独立能力开发。动作责任与证据见[现有议程执行动作](../planning/owner-decision-agenda.md#首版本地出口的执行动作)。

### 4.2 核心稳定的过渡出口

实施方以当前启用画像给出下列最小证据，业务所有者确认代表任务可用和反馈处置后，才能把主研发产能转入完整UAA-P/R：

- 本地三层权限下，风险维护者、普通工单办理者、受权复核者等代表角色完成§2的必交旅程；详情/列表/统计及受限字段同范围，越权有拒绝证据。
- 实际启用范围无未处置的P1、越权或数据损坏路径；尚未实现的能力明确关闭，已知限制有用途/责任/后继窗口，不以接受风险替代权限及数据正确性门。
- 重复提交、重启、撤权、冲突和未知效果有正常/拒绝/恢复证据；所选真实HTTP消息与本地正式制品、备份恢复/回退按适用门验收，mock不代替真实回执。
- 已完成一轮覆盖代表业务任务的试用反馈闭环：记录问题、修正及回归，剩余不阻塞事项有责任与排期。观察安排按真实使用画像确定，不预定“一周无故障”或任意性能/可用率数值。

这组判据是工程验收候选，不宣称现在产品已稳定。具体试用范围/用户与反馈接受由所有者确认，测试预期、故障注入和证据充分性由实施方负责；超出已价范围的新增工作先扣重补估。稳定后仍保留本地核心支持与回归产能，不能把同一席位全部投入UAA后无人维护；UAA资料联系不必等待此出口。

## 5. 真实业务后续接管与下一步

本地正式运行后，用户ID、风险/工单归属、附件/审计历史、receipt、未完成intent和在途任务均须保留，不能沿用“当前测试数据可重建”。认证subject与治理subject分开映射；工号/邮箱只作受审线索，不自动并号或删号重建。

UAA接管先做影子匹配和授权差异，批准映射/范围后切单一写主，收敛旧直接/组织/继承grant并核会话/待执行任务；同名admin不授系统权限。退出仍须批准有效本地基线，不恢复旧grant。中央角色/菜单不替代L2资源与L3动作检查。

首次本地正式消费者即登记合同并保护兼容；不等UAA后再保护。核心自带迁移，在承诺合同内用旧参考adapter验新核心，私有代码不跟内部表重构耦合。

按[模块交接](module-design-handoff.md)先做本地权限/接缝与风险/工单，随后TR/AL/消息；不等全项目或远期DTO冻结。实际流程/字段/动作/订阅、消息真实合同、部署资源及执行人员仍要绑定；UAA真实条件后续单列，不要求公司资料外传。两IAM高风险写本地审计失败回滚已由F017确认；外送失败补送，产品仍未实现。

上述绑定是现有Q12和MH01/MR1的执行动作，不增加正式决策组、不重问已确认的本地正式/UAA后置或mock政策。真实窗口暂未确定时，保留pending及阻塞出口，由责任角色在所列事件前推进，不能以“按窗口”无限挂账。
