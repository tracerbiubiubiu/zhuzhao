# 首个核心正式版本：本地账号先运行，UAA随后接管

日期：2026-11-14；按所有者后继澄清修订。**公司允许先使用本地账号正式运行；质量和实际可用性优先，不勉强1月日期。** 完整UAA在核心稳定后投入，约两个月只是期望窗口。旧“1月11/18日必须试用、2月1日前核心及完整UAA公共实现全部交付”不再作为当前要求。

本轮仍是设计/估算，未开始业务开发或实际部署。产能为1个有效研发席位×每周5工程日，T0未启动。状态见[机器目标](../review/first-usable-release-target.json)；首版本地核心的唯一分项数字源为[净估候选](../review/local-core-release-estimate.json)。旧76包长期预算与UAA C/P/R保留追溯，不把本页子范围再加到旧总价。

## 1. 分开两个正式出口

**本地核心正式版**：风险、工单、taskrunner、activelist和消息真实联动，本地账号/角色/菜单及完整L1/L2/L3可用，有薄UI、业务历史、必要审计/日志、失败处理及生产恢复能力。公司已允许这种模式正式运行，不以真实UAA或完整P/R为前置。正式启用的真实HTTP消息等渠道仍需实测，不用mock成功代验。

**UAA纳管正式版**：在本地版上追加真实认证、账号/用户角色/角色资源三类同步、目录/条件范围/回传、撤权/故障及批准接管；仍不缩为纯SSO。P/R与公司纳管准入约束这个后继切换，不再阻塞本地正式运行。

核心阶段先留好可信调用身份、稳定资源键、账号与授权source/写主边界和版本化公共端口；不提前实现全部SSO、企业feed及治理UI。私有SDK、字段和凭据留adapter，避免后续为UAA重做业务。

## 2. 必交业务与支持范围

首条旅程：**本地授权登录→接收/人工录入实际风险→评估及明确责任→受限整改票→处置/证据→TR获准动作→API更新AL→AL变化触发获权TR后继→消息与原票结果→风险负责人复核**。后继先选只读复核等实际用途，防写回循环；刷新列表或只发通知不能代验AL→TR。

- 风险列表/详情、评估/接受、责任/截止、受限派单、逐风险证据/复核及有界N:1；专业发现/研判取外部结果，不自建SOC。
- 工单现有创建/分派/处理/证据/评论与复核继续承接；**列表多选加标签纳入**，有限ID逐票复验并显示部分失败。新类型查看范围、CC可看和评论而无附送办理权、单主责等已定政策保持。
- TR复用队列/cron/回调，补operation/task/节点关联、稳定输入、业务receipt和结果投影；受理不等于完成，未知先对账，投影失败不重做效果。
- AL复用CRUD/CAS，补本批后台行/字段权限、持久源事实、单push→核心inbox/ACK→获权订阅；签名不代替业务资格。消息复用模板/规则/站内通知/记录，补公共HTTP sender及一条实际公司映射，区分受理、送达、失败和待核实。
- 正常首页、上述薄UI、关键里程碑/操作事实、必要去敏日志和恢复同批交。**消息仍是核心阶段，不随UAA后移。**

先选择少量真实动作、一整改流程、一AL结构/字段组/订阅和一HTTP渠道。固定字段/流程、暂不开放formula或监控类型import/replace等是候选画像；须服务端明确执行，不静默漏事件、不退役其它类型已有功能。**先验证真实日常任务可用；实际必需就补齐合同和估价，不能为日期交受限演示。**

AI/RAG/skill/MCP产品化、高级仪表盘、设备扩展、完整设计器/迁版/插件治理、通用流/恢复台、HA/微服务后继。原Phase6未交功能不删除；本地核心正式出口不等于扩展后的Phase6全包收官。

## 3. 净估与1月目标判断

当前源码的新增与复用见[四链重核](../review/reports/core-release-chain-recheck-2026-11-14.md)和[本次可行性](../review/reports/local-first-core-feasibility-2026-11-14.md)。旧报告保留当时范围，不再用完整UAA C/P的价格反证本地核心日期。按[分项候选](../review/local-core-release-estimate.json)去重：
- 共享本地授权/事务及必要UAA-C合同、operation/可靠意图、证据与日志：12–19工程日。
- 风险→整改人工闭环：11–17日。
- 工单→TR→结果/AL、AL→TR后继、公共HTTP消息：合27–40日。
- 一条公司消息HTTP真实映射/鉴权/验证：2–3日；外部等待另列。
- 薄UI、批量标签与浏览器旅程：10.5–16.5日。
- 共同回归、本地正式制品/配置/部署与恢复验收：5–8日。

合计原始67.5–103.5，约**68–104有效工程日，约14–21个有效研发周**。含本范围剩余详设、TDD、实现、专用测试、评审及正常修正；含UAA-C，不含完整P/R、额外提供方或外部等待。初稿63–96经独审补明并发撤权守卫、首次生产证据和真实消息映射后修订；置信中低，不代表必须耗满这些天，也不是按截止日倒推。

假设11月16日仅作参考T0，1月底前55个名义工作日未扣假日/其它投入。因此当前不宜承诺1月完成全部正式核心。建议争取**1月关键闭环可试用，完整本地正式版按后续约14–21有效周滚动**；纯工作日映射约2—4月，实际T0、假期、接口和业务绑定会改变日历，不另立硬截止。

旧“核心4–6周”不含完整准备批；旧05号另有R1前7–8周与R1–R4 5–8周分母。它们是历史相对估算，不否定所有者当时1月目标，也不能当含全部新增/补强的保证。用首批模块实际设计/实现/评审速度尽早校准，可能提前，也可能扩大区间。

## 4. 按质量出口交付

1. **共用接缝与本地权限**：冻结本批输入/输出、写主、事务内当前授权/撤权失败收紧，补可靠意图与证据日志；UAA-C只留接口与来源。
2. **风险→工单试用**：普通账号能录风险、派票、办理和合法复核，尽早让代表角色操作。
3. **TR/AL/消息闭环试用**：合上结果与真实后继，验重复、重启、撤权、冲突、未知效果及真实HTTP回执。
4. **本地正式部署**：所有必交及适用生产门通过再启用。末尾约2–3有效周由已价域/UI修正5–6.5日和RELEASE5–8日组成，不额外加一套缓冲，不塞新功能。
5. **UAA接管**：核心稳定后投入完整P/R，协议资料和公共准备可先行。约两个月是期望；旧P/R38–61工程日须按已实交共用成果扣重、真实条件和核心支持占用复估，不能把同一席位排满两条线。

生产门含适用完整测试/迁移、真实业务与消息、固定五仓制品/SBOM/整镜像漏洞、目标环境/TLS/秘密/会话网络、新业务备份恢复/回退与故障接管。复用已有工具，不强加全HA/PITR；允许本地正式只免去UAA前置，没有免去生产基本条件。

## 5. 真实业务后续接管与下一步

本地正式运行后，用户ID、风险/工单归属、附件/审计历史、receipt、未完成intent和在途任务均须保留，不能沿用“当前测试数据可重建”。认证subject与治理subject分开映射；工号/邮箱只作受审线索，不自动并号或删号重建。

UAA接管先做影子匹配和授权差异，批准映射/范围后切单一写主，收敛旧直接/组织/继承grant并核会话/待执行任务；同名admin不授系统权限。退出仍须批准有效本地基线，不恢复旧grant。中央角色/菜单不替代L2资源与L3动作检查。

首次本地正式消费者即登记合同并保护兼容；不等UAA后再保护。核心自带迁移，在承诺合同内用旧参考adapter验新核心，私有代码不跟内部表重构耦合。

按[模块交接](module-design-handoff.md)先做本地权限/接缝与风险/工单，随后TR/AL/消息；不等全项目或远期DTO冻结。实际流程/字段/动作/订阅、消息真实合同、部署资源及执行人员仍要绑定；UAA真实条件后续单列，不要求公司资料外传。两IAM高风险写的本地必需审计失败回滚仍待答，不由本次正式许可推定批准。
