# 02 — P6-R2 评估分级与处置策略（设计稿）

> **文档定位**：段级设计稿（2026-10-26 建档）——[README](README.md) §2 R2 段整合展开；**登记级设计稿，启动批细化**。总纲与拍板状态 = [README](README.md)。
> **量级**：1–2 周。主要风险：接受单的审批降级形态拍板。**迁移**：随 R1 表族同批（级别/deadline/处置策略列），不单立。

## 1. 定位与一句话

风险单的生命周期引擎：**评估定级 → 按级别配处置时限 → 四处置策略决策 → 风险接受单管理**。风险是"持续存在的事实"，生命周期（新增→已评估→整改中→(复核)→关闭/已接受）与工单状态机不同构；第一档 = Go 常量固定状态机（**不入 ticket_types 式配置体系**——"风险流程也可视化配置化"属范围蔓延，README §5 边界既定）。

## 2. 现状基线与既定拍板

- 级别第一档 = 手动四档（紧急/高/中/低）；评分模型（可能性×影响 5×5 矩阵、CVSS 映射）= 后续档（业界对标条 5）。
- **◆启动拍板 1：级别枚举载体**——字典 vs Go 常量（影响 R4 报表口径与筛选复用）。
- **◆启动拍板 2：deadline 语义**——自然日 vs 工作日（内网第一档建议自然日+显式登记）。
- **刻意不做 SLA 计时引擎**（dd §29 轻量版为准）——deadline 字段 + 超期提醒（走 S6）够用；超期扫描骑进程内 cron（`cron_scheduler.go` + advisory lock，既有设施零新增）；**升级触发信号清单**在 [phase5/10 号 §3.4](../phase5/10-s10-ticket-collaboration.md)（硬五条：对外承诺/停表语义/业务日历/达成率考核/自动升级链——信号出现即重开边界）。

## 3. 范围条目

### 3.1 评估与定级

- 新增 → 已评估流转：级别手动选定 + 评估备注落处置流水；级别变更落 risk_events（`level_changed`——"谁把高级改低"可追溯）。

### 3.2 按级别配处置时限

- deadline 字段 + 临期/超期提醒（走 S6 模板通知 owner）；超期扫描的**水位判定/抑止形态**与 S10 节点超时扫描器同源（interval ≥ 节流窗、observe 模式灰度可复用其经验）。

### 3.3 处置策略四选一（ISO 27001 risk treatment 标准模型）

- **整改**（mitigate）→ 派整改工单（执行桥 = R3）；
- **接受**（accept）→ 风险接受单（§3.4）；
- **转移**（transfer）/ **规避**（avoid）→ 第一档登记即可（字段记录决策，无专属流程）。
- 每次处置决策落处置流水 + risk_events（`accepted` 等事件）。

### 3.4 风险接受单

- **接受 ≠ 关闭**——独立状态「已接受」带**有效期**；到期**自动重开评估**并通知 owner（骑既有 cron）。
- 接受动作的**审批第一档 = superadmin/owner 确认制**（dd §29 降级既定——**◆启动拍板 3**：确认权限面收敛到谁）；S3b 审批引擎落地后可升级（触发登记，README §7 总账）。
- 到期重审的结果（续期/关闭/转整改）落处置流水。

## 4. 启动拍板点

1. 级别枚举载体：字典 vs Go 常量（§2）。
2. deadline 语义：自然日 vs 工作日（§2）。
3. 接受单确认制权限面（§3.4）。

## 5. 边界（不做）

SLA 计时引擎（升级信号清单见 §2）；评分模型（后续档）；GRC 条款库/法务/财务/经营风险；风险流程配置化。

## 7. 验收口径（能力语言）

四档级别与四处置策略全落库且每次决策可追溯（谁/何时/依据）；deadline 到期前 owner 收到临期提醒、超期收到升级提醒（频率按配置抑止不轰炸）；接受单带有效期、到期自动重开评估且 owner 被通知；转移/规避不派工单；整改策略经 R3 正确产出工单并双向可见。
