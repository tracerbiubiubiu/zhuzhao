## 1. 启动前固定什么

- 从已合入规划的最新五仓main核实际HEAD，再为每个写任务建独立worktree；不能继续把旧审计分支当未来实现基线。准确五仓SHA/公共库版本/协议/迁移/工具链写入候选manifest，缺companion revision不静默回落main。
- 每个PR声明唯一负责人、实际允许改动路径、源符号与不变量、领域/接口/数据/授权/配置影响、mock/contract/real出口。文档热点由集成者回填，其他agent不顺手提交控制台或他人文件。
- G01先建立可核的端口/PG/Redis/对象存储/账号/临时文件归属和私有验收入口；现有默认命令未隔离前不直接对共享dev/zt运行。E000001纪律仍按runbook；人工场景用专属账号。
- 迁移开工当天核磁盘与控制台下一编号，本文不预占000082或其它号码。up/down成对，遵B案回滚代码/DB耦合；接口/权限同步Swagger、目录绑定、UI生成物和模块说明。
- 先冻结本批实际启用能力所需的可信主体/服务/委托Context、稳定本地ID/资源键、local source/写主及受权调用边界；完整本地L1/L2/L3与当前撤权/事务守卫不能后移。后续UAA认证、三feed/企业资源/schema和治理投影的全量冻结只阻塞自身批次，不阻塞无关风险/工单/本地核心。模型/工具合同也按实际消费冻结，未启用AI不阻基础PR；D01/X01等不各自发明已共享协议。
- 公司消息HTTP从核心早期核验合同、映射和真实测试窗口，随TR/AL/消息闭环交付；不随UAA后移，合成HTTP用例不替代实际启用渠道验收。
- 本轮已有原则（mock保留、专业供给优先、模型仅API、内网只内部模型、私有adapter隔离、设备人工入口）不再重拍。owner当前决定只对其明确范围生效，不推定全部后期能力已批准。B06/B07已确认批准映射逐项自动交接、预览确认撤部plan后批量处理；具体映射/plan仍需合法批准，不代表已执行HR变更。

## 4. PR的完成证据

每个获准实施切片先遵[standards §11测试先行](../standards.md#11-开发工作流先框架--先测试--分批实现)：该批全量业务用例先写并因目标行为跑红，再实现到绿；红状态留在隔离工作树取证，不要求提交红测试，合入/交付仍须完整适用门禁。未来详设有新增行为时先补设计/红用例，不能拿工作包名称代替开工冻结。

| 证据 | 必须证明 | 不能替代 |
|---|---|---|
| 当前候选静态/生成检查 | lint、类型/生成物/目录/符号、commit窗口与来源、diff归属，绑定准确HEAD | “文件存在”不证明远端门禁生效 |
| 主仓既有门禁 | 按AGENTS执行lint/test-unit/test-integration/test-cover/acceptance；相关migrate-up/swag与新回归同步 | 原253/81快照不证明新代码；新增case不能为凑数或只镜像实现 |
| UI既有六件 | lint/typecheck/test/audit:prod/build/真实E2E，准确后端/上游组合 | 离线HTML截图不能证明Vue/权限/真实接口；不改原spec规避失败 |
| 兄弟仓验证 | 各仓实际lint/test/race及适用PG/Redis/HTTP合同，公共库最低版本/消费者矩阵 | 主仓绿色不证明AL/TR/private adapter实现正确 |
| 故障与回退 | 并发、提交断链、重复/乱序/撤权/unknown、恢复与不误清共享环境 | 成功路径不证明exactly-once、可回退或跨服务原子授权 |
| 文档与状态 | 三节变更说明、模块/阶段/总账/control同步，区分已实现/已验证/已部署 | 文档勾选、mock成功不替代真实待验 |

ENG-D01b已确认采用本提交独立文档/原型验证档，实施归G03；具体六条准入/排除见[工程候选](../design/engineering-execution-design.md)；现行全门禁未获豁免，不可把旧收据改标为新SHA实际运行。本批含治理文档，不自动归纯文档档。真正运行候选的代码/迁移/依赖/fixture/spec/工具或环境变化必须重新验证；文档检查通过不证明当前运行栈已重验。

### 单维护者短审阅卡

沿用规定三节，一份即可；常规变更以一页为目标，复杂风险不因页数限制省略，详情/原始证据按需展开：

- **改动摘要**：一个可演示行为的前后例子、关联原Phase模块/当前工作包/共同合同；复用何种用例，新增依赖或抽象的必要性。
- **影响面**：谁多/少了什么权限，哪些数据/状态/接口/迁移会变，恢复或回退边界；测试/断言/fixture/spec、skip/阈值/豁免、CI或协作规则是否改变及业务理由。
- **验证证据**：准确跨仓源码/运行组合、目标错误的红证据及修复后绿证据、一个成功及关键失败旅程/真实效果、当前适用完整门禁、独立审查与必要复验、首次失败/重试/NOT_RUN和仍待真实验证的提供方；最后列剩余风险及owner具体待选项，无则写无。

低风险不能自行跳过既有门禁；判级用于分配审查注意力。未来分档真正启用后，代码TDD、业务断言、变异和对应真实链义务保持。关键实现无法解释、验收积压或独立验证未收口时，先缩小后续交付范围，不能以更多生成代码替代。

## 5. 交接与失败出口

实施PR交付时列准确五仓候选、允许路径/提交stat、变更摘要/影响/证据、首次失败/修复/重试/skip、私有资源与清理收据、仍待真实验证的提供方。未通过门禁不称实现完成；依赖未就绪则保留该包阻断，不删除来源或把失败吞为skip。配置晋级补偿与数据库灾备分别演练。

回退先停止新副作用/提交，再按兼容reader/worker完成或对账在途；不删除unknown、业务历史或source身份，不用换旧镜像挂新PG卷假回滚。首次本地正式运行后，UID、风险/工单及附件/审计历史、receipt、未完成intent和在途任务均是正式数据，后续UAA不得删号重建或按测试数据清空。首次本地正式消费者即登记合同并保护兼容；不等UAA接管，也不能继续援引“尚未部署可直接替换”。旧随机任务无法对应时隙时不猜映射/全量重跑。共享资源与原main工作树保持可核归属，清理仅本任务清单。

已确认1个有效研发席位、每周5个工程日；质量和实际可用性优先，不勉强1月，实际T0尚未启动。所有者仍在补充场景，本次仅修订已讨论设计的交接，不进入开发或环境切换。UX01–03与B01–07等既定方向保留；B08真实通知配置在核心阶段核验，UAA-P01具体接管/失联/应急方案在后继窗口确认。未来准确合同、实现与真实验收按后续指令推进，不把文档交接当作全部功能实施批准。
