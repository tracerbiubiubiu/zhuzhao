## 背景

现状首页 = 6 张全工单统计卡（4 张全局状态 + 2 张我的待办/已办）+ 最近工单表。问题：

1. 视角混杂——全局态势数对普通成员信息量低，「我的」行动项才是每日刚需；
2. 域覆盖缺失——任务中心（自动化闭环执行器）与消息中心（通知到达）在首页零入口；
3. 无身份上下文——安全平台首页不回答「我是谁、我管哪个组织」，多组织/委托场景缺信任锚。

## 信息架构：两个问题 + 一条锚

首页只回答**「我今天要干什么」（行动项）+「平台现在怎么样」（态势）**，身份条作第三条锚（「你以什么身份在看」）。

### 布局（1440 基准）

```
┌─ 身份欢迎条：下午好，张三（E1234）· [研发中心] [部门负责人] ──────────────┐
├─────────────────── 工单 ──────────────────┬──── 任务中心 ────┬──── 消息 ────┤
│  97  我的待办（分派给我，未关闭）→点击跳列表 │  2  我发起·在途  │  5  未读消息 │
│  全局：待处理445·已分派239·进行中5·关闭125 │  ⚠ 失败/死信 1   │ →点击跳收件箱│
│  （四状态分段各自可点，沿用 URL 参数化）    │  （→runs?mine=1）│              │
├─────────────────── 最近工单（现有表格保留）──────────────────────────────┤
└──────────────────────────────────────────────────────────────────────────┘
```

### 角色渐进（同一张首页，按权限码渲染卡片——不做可配置仪表盘）

| 角色 | 可见卡片 | 依据 |
|---|---|---|
| 普通成员 | 身份条+工单合并卡（我的视角为主）+消息卡 | 全员端点 |
| 处理人/运维 | +任务卡（若有 task:read） | 权限码判定 |
| admin | 工单卡全局分段价值上升；任务卡含死信 | 现有码 |

「我发起的未闭环」（`created_by=me`+非关闭态）与「PAT 临期」（`listPatsApi` 30 天窗口）作为普通成员视角的补位副行——工单卡下半段并入或消息卡副行，实现时按密度取一。

## 数据源映射

| 指标 | 端点 | 可得性 | 权限口径 |
|---|---|---|---|
| 姓名/工号 | `GET /user/profile` | 【现有】 | 本人 |
| 组织列表/owner 标签 | `GET /user/orgs`（`org_member_role` 推导「部门负责人」） | 【现有】 | SelfService 全员 |
| 平台管理员标签 | 权限码特征推导（profile 无 roles 字段——后端补字段缓期） | 【现有】可推导 | — |
| 我的待办/全局状态 | 现有 6 请求权宜（聚合化随 `GET /tickets/stats`，04 号 §3.1 已登记随 R1） | 【现有】→【R4 优化】 | 全员（L2 内） |
| 任务在途/失败/死信 | `listRunsApi({ submitted_by: 'me', status })` | 【现有】 | **无 task:read 不渲染整卡**（FE4 口径——不是 403 静默兜底） |
| 消息未读 | `listNotificationsApi({ unread: true, page_size: 1 }).total`，请求带 `_silentError` | 【现有】 | 全员（铃铛对全员） |
| 我发起的未闭环 | `listTicketsApi({ created_by: 'me', status≠closed })` | 【现有】 | 全员（L2 内） |
| PAT 临期 | `listPatsApi`（自服务） | 【现有】 | 本人 |
| SLA 超期/效率卡/趋势 | `GET /tickets/stats` + 每日敞口快照表 | 【R4 第一档】 | 勿独立立项，随 R4 |

## 交互纪律（frontend-standard 在册条款）

- 统计卡可点=`cursor-pointer`+hover 反馈+URL 参数化跳转（展示惯例 5）；任务中心 runs 页需补 `?mine=1` 预填（现开关不在 URL 白名单——本批连带件）；
- 卡片点击语义=按该口径过滤跳列表，与首页统计卡→ticket/list 既有基建同构；
- 视口锁定铁律、空态引导三件照常适用。

## 测试与场景

### 验收口径（能力语言，走查式——06 号 §10 同款）

普通成员打开首页看到身份条（姓名/工号/所属组织标签）与自己的待办数；「我发起的未闭环」「消息未读」各自可点直达对应筛选面（工单列表 created_by=me / 消息中心 unread）；该成员无 task:read 时任务卡不渲染且浏览器**不发出任何任务请求**（渲染层门控，非 403 静默）；处理人看到任务卡「我发起·在途/失败死信」分段，点击落任务中心 runs 页且「只看我提交的」自动置位；owner 身份条出现「部门负责人」标签；admin 工单卡全局四状态分段各自可点、落列表页对应 status 过滤；存在 30 天内到期 PAT 时临期副行出现、无则不渲染（有数据才占位，防空态噪音）；各卡片点击后列表页 URL 预填口径与现有白名单一致、双击/重复点击不产生重复导航。

### E2E 落点（s2 改造为主，不新增 spec 文件——计数纪律轻）

| 场景 | 落点 | 断言要点 |
|---|---|---|
| admin 工作台 | `s2-home-smoke` **改造**（DOM 结构变化，原断言必适配） | 沿用现行模式：API 预造**临时类型**工单做数据锚点（tempTicketType 隔离自动分派规则—— incident 全量命中会把新单秒变 assigned 的既定坑）；身份条姓名/工号/组织标签在位；工单卡主数字加载后为数字态（`/^\d+$/`，loading '—' 免疫）；全局四分段点击各跳对应 `status` URL；最近表锚点行在位+状态 tag 一致；finally 清理不变 |
| 角色渐进负断言 | `s2` **拆第二用例**（operator+viewer 首页） | 任务卡 `toHaveCount(0)` 且 **`page.on('request')` 断言零 `/tasks` 请求发出**（请求侧强于 FE4 响应侧）；消息卡在位；身份条无 owner 标签 |
| 非 admin 卫生 | `fe4-nonadmin-hygiene` 自动覆盖（/home 已在 ROUTES） | operator/viewer 遍历零 4xx/5xx+零权限 toast——新卡片任何越权请求在此现形，属回归底线不另写 |
| owner 视角 | 随 S7（owner 账号 setup 在彼处）走查式核对，不进自动化 | 身份条「部门负责人」标签；不做强断言（S7 主域是名册/委托） |

**计数纪律**：s2 拆两用例 = E2E 27 spec / 34 用例 → **27 spec / 35 用例**，实现批同批更新 README+AGENTS 两处（AGENTS 计数口径条款）。

### 单测与哨兵连带

- `apiPaths` 网关前缀哨兵自动覆盖新请求面（storage 漏前缀类缺陷的唯一捕获层，新代码零额外动作）；
- `?mine=1` 预填走 URL 白名单键模式（对齐 ticket/list 既有白名单做法），tasks 页预填逻辑补一条 vitest（纯函数易测）；
- `uiConventions` placeholder ≤14 哨兵自动把关新文案（如「我发起·在途」8 字合规）；空态卡走「统计卡可点」惯例无需空态文案；
- 视口：双档自测 900 高/≥1440 高 + ≥2560 宽（frontend-standard checklist），任何页面 section 滚动量=0。

### 数据事实与断言纪律

- operator/viewer 可达 `/tasks`（FE4 ROUTES 在册）——任务卡渐进矩阵「处理人」行以实现时真实 `task:read` 下发面为准，设计表不锁死；
- 卡内数字**只断数字态与预造锚点 ≥1，不断具体值**（dev 栈数据漂移免疫——S2 断言加固批「坏数字也绿」的既定教训）；
- 全部场景走预造数据+finally 清理（幂等可无限重放，globalSetup 既有口径）。
