# 01 — P6-R1 风险汇聚与台账（设计稿）

> **文档定位**：段级设计稿（2026-10-26 建档）——整合 [README](README.md) §2 R1 段、2026-10-26 勘查回填与缺口对账的登记级展开；**登记级设计稿，启动批细化**。总纲与拍板状态 = [README](README.md)。
> **量级**：2–3 周（含上报 API+去重；聚合视图=补全切片可滑出）。**迁移**：risk_items / risk_events / 处置流水 / 每源镜像表族——编号启动时按 [11 号 §4 迁移地图](../review/11-project-control.md) 对账，不写死。

## 1. 定位与一句话

多数据源风险事件**汇聚 → 指纹去重 → 统一台账**（六组字段骨架）→ owner 指派与处置留痕；为 R2 评估分级、R3 整改工单联动供数。风险单 = 风险管理域自有实体（自己的生命周期：新增→已评估→整改中→(复核)→关闭/已接受），与工单状态机**不同构**（业界惯例：风险是持续存在的事实、工单是一次处置动作——与 S2「工单流程 vs 任务编排不同构」同一分界逻辑）。

## 2. 现状基线（代码级事实，2026-10-26 核实）

- **risk 域零代码**——本段为全新业务域。
- **可复用件已就绪**：tags 通用表（000063，entity_type 泛型——风险事件挂标签零改）；human_key 生成器（000057，`RISK-` 前缀同件复用）；assignment_rules 指派轴（000069 + axis 扩充 = Week 0 HR mock 件）；S6 通知全链（超期/状态通知，触发面域无关既定）；S9 情报缓存代理（R1 情报源之一）；BK-21 护栏泛化（Week 0 件——risk_items 接 L2 的哨兵）。
- **数据地基**：owner 解析/部门负责人轴依赖 M-HR 形数据——Week 0「HR 目录接口 mock 先行」件供给（[hr-directory-sync 前置件注记](../proposal/hr-directory-sync.md)）。

## 3. 范围条目

### 3.1 接入面（「镜像+流水」通用结构）

- **两档**：第一档 = 手动录入 + 上报 API（内部系统/脚本 POST，走既有鉴权 AK/SK 或用户 token + schema 白名单校验）；第二档触发驱动 = 扫描器/SIEM webhook 连接器。推/拉皆备从第一天按通用形态建（D11；拉 = http-pull / db-pull / file-pull + `ingest_sources` 水位表——端口行见 [phase5 README §6](../phase5/README.md)）。**愿景稿已拍决策对表（2026-10-28 外审补登——此前未吸收）**：**D14** 每源单模式、不做推拉对账（与「通用形态」不矛盾：形态通用、每源选一模式，禁做跨模式一致性机制）；**D19** 字段分归属 + `source_observed_at` 时间判优 + 每源稳定键优先级（详 README §2）；**D5** 原始告警/发现独立表、聚合实体复用风险单（findings 层级展示随 R1 立项批）；接入层流水线（`raw_ingest_events`→归一化 findings→资产解析→指纹→聚合）详愿景稿 07 §4.1。**mock 漏扫源适配器（2026-10-27 所有者：与 HR 同款，留接口、测试用模拟数据）**：`RiskSourceConnector` 首个实现 = mock adapter + 模拟数据集（覆盖指纹归并/重推/已关闭重报/级别与涉及系统分布/无 owner 场景），R1 开发与验收全用它；真实漏扫 adapter = 契约到位时换件（触发驱动）；件归 [Week 0](05-launch-batch.md) §1.2（~1 天）。
- **存储结构（核心设计）**：外部源数据落**可重建镜像表**、本地处置落 append-only 流水表；`(外部id, 来源)` 弱关联、**无外键**、孤儿镜像骑既有 cron 清理——源重推/回刷不冲掉本地处置事实（本地是 SSOT）。
- **◆启动拍板 1：状态口径二选一**——处置结论回写镜像侧 vs 本地只认流水（镜像状态仅参考）；不拍则两处状态漂移（外部平台实证踩坑：列表按镜像状态过滤、处置只写流水未回写）。
- **滥用防护二道**：rate_limit 桶 + body 上限（一道）；幂等栅栏（提交凭证形态，job_submissions 同款——二道，**✅ 启动拍板 5 已拍随批**）。
- **上报观测面（2026-10-28 核查补登，随 R1 批）**：上报量/限流拒绝量/指纹归并计数/重推计数出 `/metrics`，归并与重推落 risk_events——量级水位型挂账判据（C-6 同款教训：登记触发须回答信号由什么产生）自证可观测；对账扫描结果同源出审计行。
- **维度聚合视图（补全切片）**：按系统/类型/来源/级别/owner 分组聚合计数端点——管理层周会问答（"高危集中在哪几个系统、哪个部门整改最慢"）靠聚合而非逐条筛选；台账分组视图与 R4 看板**共用同一组端点**防口径漂移。
- **db-pull 安全边界（D12 已拍对表，2026-10-28 补登——愿景稿决策表原文此前未吸收，外审核出）**：只读账号 + 参数化 SQL 模板审批入库（禁自由 SQL）+ 水位列必填 + 行数/时长上限 + 每次拉取审计 + 网络白名单——随 db-pull adapter 实施批落地（首版 mock 源不涉及）。

### 3.2 指纹去重

- 指纹 = `SHA-256(涉及系统 + 类型 + 外部标识)` 落列 UNIQUE——去重判定 O(1)；重报提升计数/更新而非建新单。
- **启动拍板 2：已关闭单重报语义**——**✅ 定稿（2026-10-28 所有者，e4ea567）= 建新单+回归标记+回链老单**（已修复后真回归→建新单回归；「重开」仅保留接受到期未续期自动重开一种；详 §4 拍板 2）。
- **跨指纹人工合并（P1-5，2026-10-28 核查补登——capability-gap-audit 标 P1「待登记 phase6 R1」）**：指纹去重只管**同指纹**归并；多源同事件外部标识不同（多 CVE/多扫描器口径）须**人工合并**——形态 = `merged_into`/合并组模型 + 人工合并端点（主单保留、被合并单归档回链，复用重报回链语义），规则化合并可选；**登记为 R1 触发项**（触发 = 首个多源同事件诉求，量级 ~1–2 天），业界漏洞台账标配（Vulcan/Nucleus 同类）。
- **重报语义（2026-10-28 外审核出口径差，✅ 定稿=建新单+回归标记+回链老单）**：已关闭单重报→**建新单+回归标记+回链老单**（回归率口径——新事件可计数+links 行回链历史可溯）；「重开」仅保留**接受到期未续期自动重开**一种；**接受有效期内→计数不重开**（D13 原文维持）；与 03 号 N:1 关联表自洽（回链走 links 行，不破「每风险至多一张在办单」幂等）——早版「按关闭结论分流/重开原单」（a2ceb83）被本定稿取代。

### 3.3 台账

- **字段模型六组骨架**：基本信息 / 风险信息 / 评分与优先级 / 关联资产 / 生命周期与状态 / **归属组**（责任人·所属组织·协同处理人·**关联工单**（links 反查，含历史单——N:1 下一风险可有多条关联记录，2026-10-28 口径）——最后者即 R3 双向可见的字段位）；台账列显示、详情页分组、通知模板取词共用同一骨架，多来源灌入不散口径。
- **人读编号**：**✅ 已拍（2026-10-27 第四组）** `RISK-<年>-<6 位>`（如 `RISK-2026-000042`），年内重置——human_key 同件复用（000057 的「前缀+日期段+序列」改日期段为年段，CREATE SEQUENCE 幂等+冲突重试直接继承）；年度合规报告按年归档时编号连续，6 位容量 99 万/年。
- 台账页：按级别/状态/来源/涉及系统筛选、详情、**两级责任人**（风险 owner 先行，处置工单再指派处理人）；交互蓝本 = 成熟漏洞台账页（高级搜索条件树/批量编辑/标签/动态列/Excel 导出——勘查在档，实施时取用）。
- **风险证据附件**：弱依赖 S5（未交付则降级外链）。
- **批量导入（触发登记）**：Excel 模板下载 + 导入校验 + 部分成功行级报告——存量人工台账迁移；首源走 API 不依赖此项。
- **owner 离职接管「交接三件」**：名下风险清单告警 / 接管人批量改派+通知新 owner / 交接动作留痕（谁在何时把谁的哪些单交给谁）——已登记合规硬伤（用户禁用对风险零联动）的解法形态，随 M-HR 离职处置件对齐。
- **保留期/归档（触发登记）**：数据量级上来后启用，骑 intel_cleanup 同款 cron（外部平台有"N 天自动清理"先例）。
- **轻量系统台账（P0-5，✅ 已拍 2026-10-28 所有者——gap-audit 待拍板落定；P1-5 补登时同表对称漏项外审核出）**，**四件形态**：① `systems(code, name, owner_user_id, …)` 薄目录（seed+手工维护兜底；不做资产属性/依赖图——防 CMDB creep）② **预留 CMDB 查询端口**（所有者口径：公司侧后续提供 CMDB 查询接口——Port+Adapter，契约到位换 adapter，同 X1 漏扫 mock 先行模式，现以 seed 兜底）③ **自动查询+填充**（建单/派单按 system_code 自动解析负责人等字段——复用 C-2 auto_fill/prefill 同通道 external_http 适配器族）④ **工单字段人工可改**（预填=默认值建议值不锁字段——S1「自动填充+人工可改」同款语义）。承载 gap-audit Q3「发给对应系统负责人」（涉及系统=自由文本无映射的解法）；「涉及系统」升引用+自由文本兜底；**与 D29 边界**：CMDB 接口就绪后 systems 表保留本地兜底或被吸收，届时一句话拍。量级 3–5 天（随 R1 立项批）。

### 3.4 审计与事件

- **risk_events 审计事件表**（同 ticket_events 形态：created/status_changed/level_changed/accepted/…）——"谁把高级改低/谁做的接受/有效期谁改的"须可追溯（风险闭环=合规场景）；**◆启动拍板 4**：独立表 vs 显式降级复用 audit 中间件并说明取舍。
- **处置流水独立表+状态轨迹**（与 R2 共用）：处置动作 append-only 流水（动作类型/操作人/时间/备注）独立于风险主表，状态轨迹端点按单吐全历史；与 risk_events **相邻同构**（前者面向用户处置历史、后者面向审计领域事件），表结构同批设计。

## 4. 启动拍板点

1. 状态口径：**✅ 已拍（2026-10-27 第四组）本地只认流水**——本地状态由 append-only 流水驱动，镜像表的远端状态仅作参考列展示（「本地已关闭、远端仍 open」并存是特性：可配「已关闭但远端连续 N 期仍报」告警，提示误报或整改无效）；源重推只刷镜像+归并计数+流水追加 `source_repushed`，不动本地状态；**对外回写**（漏扫平台控制台要看本地状态）= RiskSourceConnector 回写 adapter + 06 号件 10 webhook，二档触发，不绑在本地关单流程上（否决理由：回写方案使关单依赖外部 API 可用、每源对齐状态机；单表直改方案=外部平台实证踩坑「重推即复活」）。
2. 已关闭单重报：**✅ 定稿（2026-10-28 所有者，e4ea567）= 建新单+回归标记+回链老单**——已修复后真回归→**建新单+回归标记+回链老单**（回归率口径：回归单/关闭单为标准质量指标，建新单臂可计数；links 行承载回链与结论）；「重开」仅保留**接受到期未续期自动重开**一种；接受有效期内→计数不重开（D13 维持）；早版「按关闭结论分流/重开原单」（a2ceb83）与第四组「一律建新单」均被本定稿取代；与 03 号 N:1 关联表配套（回链/幂等/复测结论五档见 03 号 §3.4/§3.5）。详 §3.2。
3. 人读编号：**✅ 已拍** `RISK-<年>-<6 位>` 年内重置（§3.3）。
4. risk_events：**✅ 已拍 独立表**（与 ticket_events 同构：action/from_value/to_value/actor/payload/request_id）——系统动作（到期重审自动重开、超期升级、归并）无 HTTP 请求，audit 中间件记不到；按单一条查询回放全生命周期。随 R1 表族同批，近零额外成本。
5. 幂等栅栏：**✅ 已拍 随批**（+0.5–1 天，job_submissions 同款：Idempotency-Key 唯一索引 + 窗口内回放首次响应）——解决网络抖动重发灌水重报计数、批量推送部分失败整批重发的 exact-once；与 R3 `source_ref` 派生幂等成对（入站幂等 + 派生幂等）；内容各异的垃圾风暴仍由 rate_limit + schema 白名单 + AK/SK 归因追责拦。
6. risk_items 落 L2 锚点：**✅ 已拍（所有者 2026-10-27：「两边部门应该都能看到」）双 org 可见**——主锚 `org_id` = 风险管理团队 org（底稿 SSOT 归属、不随 owner 交接漂移）+ 副锚 `affected_org_id` = 受影响业务系统所属 org（六组骨架「所属组织」字段位）；risk 域 GetFilter 可见条件 = 主锚标准 L2 判定 **OR** 副锚命中（业务 org 成员按其 scope 可见自家系统的风险，**只读**）**OR** `owner_user_id = 本人`（读写）。操作权（评估/接受/改派/关闭）= 风险团队 + owner，业务 org 其他成员只读+评论。实现=BK-21 泛化时 risk 域 GetFilter 多两个 OR 支（IW4 fail-closed 哨兵兼容，cc 读特例同模式），含在 BK-21 件内；逐条共享授权不做（组织级自动可见已覆盖）。

## 5. 边界（不做）

资产台账（D4——纯查询连接器 + 解析时快照，phase6 内解析可降级 `asset_ref=null`）；漏洞扫描能力本身；SIEM/SOAR 实时编排；评分模型（R2 后续档）；网盘式文件管理域（勘查判定不做——附件走 S5）；沙箱样本情报库独立台账（触发驱动，接沙箱源时按镜像表形态承载）。

## 7. 验收口径（能力语言）

同一风险重复上报只归并不建新单（指纹命中）；上报 API 越权/超限/重放被拒且留痕；源数据重推不冲掉本地处置状态；owner 离职后名下清单可告警、可一键接管、交接动作留痕；任意风险单可回放完整处置轨迹（谁在何时做了什么）；台账按六组字段筛选与导出正常；（补全切片）按维度聚合问答与 R4 看板数字一致。**验收数据源 = mock 漏扫源模拟数据集**（2026-10-27）；真实源接入另行触发验收（换 adapter 后跑同一套用例）。
