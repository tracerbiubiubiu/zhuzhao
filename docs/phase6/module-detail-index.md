## 2. 对比原来的设计，具体补了什么

1. **从接缝原则到可写测试的合同**：给出模块写主、请求/结果、唯一键/CAS、锁序、提交和恢复出口；六条链不再只各写一句“调用接口”。外部 API、按钮和内部用例走同一应用入口，内部无需绕HTTP。
2. **从“权限大体有”到当前状态可证明**：本地完整L1/L2/L3，公共授权代际守卫、策略加载与提交后恢复；停用/改权后旧缓存/AT/RT/PAT/排队任务不能继续借旧资格运行。UAA认证与账号/角色/菜单治理仍完整保留，但不挡公司已允许的本地正式先行。
3. **从草图到风险/工单责任闭环**：family/cycle分开、重复/乱序/回归、N:1每风险结论、接受制衡、逐项交接及失败恢复；旧票定义钉版、live权限、字段稳定身份和真值diff分别建模。
4. **从任务已受理到真实效果可查**：operation、invocation、attempt、event和receipt分开；unknown先查原效果，结果投影失败只补投影。AL源事务事实→持久收件ACK→TR实际只读后继，无票也可用；当前读取不冒充事件历史快照。
5. **从通知接口到应发/实发/未知的区别**：当前收件人和字段授权、稳定去重、HTTP受理/送达分列；公司真实消息仍是核心启用条件，不随UAA后移、不以mock送达代替。
6. **从视觉方向到页面状态合同**：安全首页、职责统计、统一布局/创建/搜索/筛选、列表批量标签、情报历史明确重查；新业务最小UI随批，全站推广不反向挡首版。
7. **从“留adapter”到可升级组合**：私有应用逐请求身份/范围与本域资源检查，mock/真实查询同合同；旧adapter×新核心做语义回归。设备保留人工登录；AI先只读/真人精确确认，持续自治后置。

这些以现有能力演进，未增加SOC、CMDB、通用DAG/消息平台或模型部署。技术复杂度只用于当前必需的授权、幂等、可靠交接与恢复；完整多消费者feed、任意插件宿主、通用Agent和复杂BI仍在原后续包。

2026-11-15复核后进一步收窄：资源L2变化不触发全站Casbin重载；只读私有应用ref不建永久表，纯取数connector不套用户交换；creator/assignee资格从原票字段计算；首版不建多维root/grant预算引擎或完整UAA治理表。必须保留当前授权、可靠交接、效果凭证和unknown恢复，它们解决单实例也会出现的真实故障。

## 3. 实施顺序与可独立验收出口

先交共同Context/当前授权/事务和最小稳定接缝，再风险→工单人工闭环，随后工单→TR→AL/结果及AL变化→TR只读后继，消息真实HTTP与薄UI贯穿。固定流程、一个AL监控类型/普通insert-update、一个订阅/动作和一个实际渠道构成首版有限组合；服务器显式拒绝监控类型尚不支持的其它写路径，其他已有能力不退役。

本期详细设计覆盖的功能不等于都进入首版本地核心：D05完整晋级、D16自动路由、全站U06、设备、AI和P6.E按各包推进。G05/E09适用正式生产硬门在首发前验，不等整个P7；完整UAA-P/R核心稳定后交，真实联调条件独立。原[68–104工程日历史净估候选](../review/local-core-release-estimate.json)待IAM扣重替换和长程包价未因细化自动增加/重排；实际范围发生变化时按来源与复用扣重复估，不承诺强赶1月。

**本期裁决、后期实现**也属于本期交接责任，不能因为包wave较晚就推迟询问：

| 条目 | 本期明确出口 | 后继实施边界 |
| --- | --- | --- |
| E02存储/细权限候选 | P6.3出口逐项定保留/小改/供给替代/退出，核容量与附件实际问题 | P7按获准子范围；没有问题不为专业化换一套存储 |
| E03审批/日历/队列候选 | P6.3出口定哪些类型需要轮询/认领、候选池、自然历时或日历；未定沿现合法主责 | P8及获准子窗交保留效果，不能到P8才作本期决策 |
| E04固定报告 | P6.E出口定第一套报告/受众/来源与最小供给 | P8固定模板/分发，不先造BI/DSL |
| E06通报/安全内容协作 | P6.E出口核专业来源和一个薄协作场景 | P8交保留效果，专业内容不复制成第二权威 |

## 4. 决策窗口与不能假定的事实

- 已确认：HIER-D01整子树暂停组织派生资格；SetRoles/AssignMenus本地成功审计写失败回滚、外送失败补送。见[第一包收口](iam-first-batch-design.md)，代码仍未实现；真实名单/保留参数后继绑定。
- 首条真实风险通知前：B08级别/组织锚点/负责人/频次/时区及公司HTTP受理、幂等、查询/送达能力；缺条件明确pending/unknown，不广播兜底。
- 对应真实启用前：批准的风险/工单类型、组织、字段和服务范围；真实目录/源身份映射；设备入口与可选用户名字段权；模型API能力/配额/数据区。公共mock设计不等待秘密资料导出。
- 正式运行前：真实制品/离线运行、TLS/秘密、备份恢复/接管、容量及各类保留值；UAA纳管时另确认真实映射、接管/失联/退出方案。首次本地正式数据保留，不能按测试数据删号重建。

已确认的mock长期保留、本地IAM、B01–B07/B09、设备人工登录、模型仅已有API、私有隔离及PR原则不重问。具体未定值按窗口绑定，不要求现在想全所有未来场景。

## 5. 完成的含义与验证

本次交付是候选详细设计及可执行参考Schema；业务实现仍必须按[standards §11](../standards.md#11-开发工作流先框架--先测试--分批实现)测试先行、有效红→绿、准确候选和完整适用门禁。Schema正/负样例只能证明协议约束，不能证明真实授权/网络/事务已经实现。主线既有绿色不代替新功能验收。

后继实施每批复核本页+对应模块合同+实际消费的共同DTO和具名用例即可；发现具体缺口再扩阅读，不继续要求每包重扫全仓。设计候选的覆盖证据和未冻结项归[设计深度机器表](../review/planning-design-status.json)，实现/运行状态归[项目控制台](../review/11-project-control.md)。
