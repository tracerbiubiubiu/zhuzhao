## 2. 对比原来的设计，具体补了什么

1. **从接缝原则到可写测试的合同**：给出模块写主、请求/结果、唯一键/CAS、锁序、提交和恢复出口；六条链不再只各写一句“调用接口”。外部 API、按钮和内部用例走同一应用入口，内部无需绕HTTP。
2. **从“权限大体有”到当前状态可证明**：本地完整L1/L2/L3，公共授权代际守卫、策略加载与提交后恢复；停用/改权后旧缓存/AT/RT/PAT/排队任务不能继续借旧资格运行。UAA认证与账号/角色/菜单治理仍完整保留，但不挡公司已允许的本地正式先行。
3. **风险与工单怎样一起办理。** 同一风险再次出现要区分是重复上报还是新的一次处置。派单人可以把多条风险放进一张工单，办理人逐项交证据，负责人逐项复测或交接；接受风险须另一位有资格的人确认。每张工单按创建时的规则办理，谁能操作仍按当前权限，历史按稳定字段编号记录真实变化。 [风险与工单示例](risk-module-detail.md#14-漏洞整改代表场景)
4. **任务失败怎样找到原结果。** 分别记录谁发起、实际调用、每次重试、事件和结果回执。远端结果不明时查原任务。若只差在工单里显示结果，补显示这个步骤。清单变化由核心保存收件记录后触发获准的只读任务，此过程无需工单。读取清单当前值时标明它是现值。
5. **消息处于哪一步。** 先查当前收件资格和能显示哪些字段，重试时用原发送记录识别同一次提醒。HTTP 接口已受理和收件人已收到分别记录，结果不明时提示待核实。正式运行用实际公司渠道验证消息。
6. **用户在页面上做什么。** 首页只显示用户有资格看的待办，能从列表多选加标签，搜索和筛选按统一方式操作。查询历史情报后可以明确发起重查。完成新业务所需的页面随功能交付，全站页面统一安排在后续。
7. **从“留adapter”到可升级组合**：私有应用逐请求身份/范围与本域资源检查，mock/真实查询同合同；旧adapter×新核心做语义回归。设备保留人工登录；AI先只读/真人精确确认，持续自治后置。

这些以现有能力演进，未增加SOC、CMDB、通用DAG/消息平台或模型部署。技术复杂度只用于当前必需的授权、幂等、可靠交接与恢复；完整多消费者feed、任意插件宿主、通用Agent和复杂BI仍在原后续包。

2026-11-15复核后进一步收窄：资源L2变化不触发全站Casbin重载；只读私有应用ref不建永久表，纯取数connector不套用户交换；creator/assignee资格从原票字段计算；首版不建多维root/grant预算引擎或完整UAA治理表。必须保留当前授权、可靠交接、效果凭证和unknown恢复，它们解决单实例也会出现的真实故障。

## 3. 实施顺序与可独立验收出口

当前先准备人工风险整改（B2）的工程与合成验收。[隔离入网预演（B0）](../design/foundation-release-boundaries.md#1-先交哪一版)按目标窗口后排，完整基础扩展版（B1）独立后排。实际业务试用另过[首版准入§4.1](first-usable-release-plan.md#41-b0预演与真实业务试用准入)，所选范围的AUTH-01/02/07须先修复或服务端完整关闭并有逐入口拒绝证明。首发与恢复、保留政策（Q12）的运行卡、MH01/MR1合同/真实测试窗与[核心稳定§4.2](first-usable-release-plan.md#42-核心稳定的过渡出口)分别约束试用、本地正式和完整UAA投入。

先做账号停用和保存时的权限检查，再让风险负责人从派单办到逐项复测。下一步验证工单发起任务、任务结果更新一项清单，以及清单发生变化后触发一个只读任务。首版只选一个固定工单流程、一种受监控的清单类型上的新增和修改、一个触发规则及动作、一条真实消息渠道。每步提供实际办理页面；服务端明确拒绝受监控类型暂不支持的其它写入，已有其它能力继续使用。

D05完整晋级、D16自动路由、全站U06、设备、AI和P6.E按各包推进。G05/E09中适用于首发的生产证据在首发前取得，完整UAA-P/R在核心稳定后交，真实联调条件独立。当前工程量、最早与保守情景见[交付排期](../planning/intranet-uaa-release-schedule.md#2-最早与保守排期)。原95–148和97–151保留为历史对账，旧参考adapter兼容、UI和首产分配见[发布对账](../planning/core-release-accounting-reconciliation-2026-11-16.md)。实际范围变化按启用能力和已验复用重新计价。

## 5. 完成的含义与验证

本次交付是候选详细设计及可执行参考Schema；业务实现仍必须按[standards §11](../standards.md#11-开发工作流先框架--先测试--分批实现)测试先行、有效红→绿、准确候选和完整适用门禁。Schema正/负样例只能证明协议约束，不能证明真实授权/网络/事务已经实现。主线既有绿色不代替新功能验收。

后继实施每批复核本页+对应模块合同+实际消费的共同DTO和具名用例即可；发现具体缺口再扩阅读，不继续要求每包重扫全仓。设计候选的覆盖证据和未冻结项归[设计深度机器表](../planning/planning-design-status.json)，实现/运行状态归[项目控制台](../review/11-project-control.md)。
