# 全项目排期与能力承接总账

日期：2026-11-12。当前为全项目路线方案，未实施新业务功能；G07A/G07B已按所有者要求前置完成本地候选，待PR/main承接。以原Phase6–9及更远规划、现有规模和新增要求为输入，尽可能承接业务价值、渐进优化，不照搬所有旧技术形式。机器总账为[唯一字段源](planning-backlog.json)，本页是同步阅读投影。

## 1. 怎样读排期

当前 **71个工作包、511个来源条目**。来源含复述/关闭历史，不等于同数新需求；[连续性审计](roadmap-capability-continuity.md)另有169个原功能来源原子，用于核业务效果，不重复估工。首轮67/501与更早61/494保留各自审计时点。

排期采用有依赖、归属、粗估和验收出口的波次。T0/投入未定，不沿旧固定周数或把区间上限相加承诺上线。研究可先行，实施依赖/真实待验分开；mock长期保留，真实接口只阻塞该provider放行。

## 依赖与估算的子出口语义

2026-11-12增加可验收子出口。`dependencies`要求完整包完成；`milestone_dependencies`只要求指定出口；子出口继承所属包外部依赖，完整包须全部子出口完成。子出口估算是包内分解，不另加总；不能以文档或SDK样例代替实现验收。推荐发布/PR顺序见[执行排期](execution-schedule.md)，新旧取舍见[对照](roadmap-change-comparison-2026-11-12.md)。
