## 需要确认的具体场景

1. **实际接管清单**：甲已有本地账号及历史工单，本地能派整改单，中央仅授查看。建议先审核映射/授权差异，保留ID及历史，纳管能力按批准中央结果变为只读。确认的是实际人员/组织/能力清单，既定来源原则不重问。
2. **同步故障时的可用性**：甲仍登录且grant有效，但已确认同步故障。公司允许窗口内，是先暂停受管写、保留获准只读，还是继续原受权读写？建议倾向前者；超过允许新鲜度后均停止受管能力。先核公司强制规则和可证明新鲜度机制，再确认具体动作/期限，不能把没有业务消息当故障。
3. **应急恢复入口**：企业认证不可用时，是否批准指定本地应急管理员恢复配置、核对同步？建议限定恢复用途、启停责任、有效期和审计。若希望其临时授业务权限，须另列具体范围与增量，不默认开放所有员工密码或建设PAM。

以上两项政策倾向尚未批准，公共实现可使用合成配置开发；真实激活必须取得具体批准。公司强制规则优先。资源和相对时间口径已由P-RESOURCE确认，不再反复询问严格日期；本页不要求提供内部地址、秘密或真实报文到公开会话。
