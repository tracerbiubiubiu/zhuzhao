## 已确定的原则与本轮新确认

平台聚焦数据聚合与安全全生命周期；不替代已有SOC/SIEM、SOAR、CMDB、情报、企业Agent/知识系统。保留大量mock，调用已有模型API，内网仅内部模型，支持外部Agent接入及本平台有限领域Agent。内部业务/SDK/字段通过独立私有扩展/connector接入，核心维护稳定公共能力。

本轮所有者另已确认：设备是异构无SSO，首期目录/状态/人工登录入口；取消公司旧组件版本对齐，可自行打包升级；当前未正式部署，允许协调替换旧合同，不设六个月保留；五仓统一PR，检查通过后单维护者可自行合入。确认的是方向/策略，本次未改远端保护、运行组件、账号或生产代码。

## 需要所有者参与的时点

[决策册](planning-decisions.json)保留推荐、备选、未决安全边界和截止，已确认不重问。技术锁序、DTO命名、文件模板等由实现者按合同评审，不要求所有者逐字段决策。当前按少量一轮处理：

1. **本批首先确认P6.0用户可见语义**：C02移除字段引用时是否自动删除附件（ENG-D02）、cron宕机错失补发策略（EXE-D02）。R01转派是异步可对账还是同事务失败整笔回滚（EXE-D01），也应在第一轮说明后定。
2. **D03/D06开工前确认业务授权/交接**：B01–B05类型可见、参与授予和风险代建范围；B06/B07离职/撤部策略。未决不启用扩大授权/自动交接的写开关，不阻塞安全禁用、mock和合同工作。
3. **看具体原型再确认体验**：默认壳层、首页待办口径、情报历史点选与重查（UX01–03）。这是对可操作样板的评审，不让所有者在抽象色号/布局名中猜结果。
4. **首规则/后期能力启用前**：B08通知时区/频次/临期窗；A04/A07自动化持续grant/写确认与预算；逐提供方真实合同、生产数据保留/RPO等只在真实场景具备时定，不预先假设公司接口或重建专业能力。
5. **第五步交接**：确认实施首批优先级/投入/T0。未确定日期不影响有依赖波次，但不能把工作日区间相加宣传为确定上线日期。

存在必须owner选择的分支时，只停相关实施/承诺；其它设计和交叉检查可继续。用户允许在拍板点停下不等于取消剩余审计，也不等于所有工作已经完成。
