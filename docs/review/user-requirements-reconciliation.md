## 1. 之前哪里确实没有做到

先前把“有文档/有承接包/有后续窗口”说得接近“已全部审完”，这个完成口径不准确。原65点只覆盖当时前32条输入；后续61条/92点对账也只是追溯快照。助手早期整体完成表述、随后才列出八组补研究，以及过早转向开工的建议，都不能作为已兑现全部原始要求的证据。

实际漏做或做得不足的动作有六组：

1. **全站前端**：此前是27路由库存与六类代表状态，缺全站角色、错误、长内容、缩放/键盘及真实Vue样板。现已逐路由实际审查，形成14项发现、逐页改造/验收及U02/U06/U07复估。产品缺陷尚未修复，尤其细粒度菜单命令呈现问题不应误称后端越权。
2. **全模块与统一通道**：此前16项耦合裁定和12家族骨架不是逐操作覆盖。现已清点18模块、176绑定、298导出service声明、135 UI HTTP调用及158能力候选；三链有精确Schema、收据/幂等/授权/水位/订阅/因果预算和最小UI运维。共同runtime尚未实现。
3. **Agent、skill、SOC职责**：此前只有窗口，缺同场景三路径比较、可信skill样包/生命周期和职责×动作×范围/撤权矩阵。现已增加可执行参考样例，并做跨文档反例复审；MCP另用真实官方SDK跑回环HTTP互操作。模型/AS/业务授权样例仍是合成供给，不能叫企业联调成功。
4. **完整净估与新排程**：此前UAA公共/最小UI/运维已补估，但CE及若干旧子范围未计清。现逐项补CE、常驻字段ACL、类型化检索、CmdK、真值diff、第二专业源及MCP生产身份桥，并复估六个既有包；父子、UAA、RP替换与复用不得重复加总。
5. **现行门禁**：批准分档并不等于它已经启用。之前文档批NOT_RUN提交不能证明符合当前全门禁要求；本次需完整适用门禁通过再提交，保留首失败/环境修正/重试，不能倒写历史。
6. **防止再次遗漏**：缺持续维护的原话—动作—产物—验证对照，摘要和机器表也出现漂移。现加结构/证据守卫和独立原话复读；守卫能拒绝证据未跑、漏来源、未估却报完成等矛盾，不能代替语义判断。

## 2. 原始主题和后续纠正怎样保留

工程与并行提交、目录/文档/命名、架构演进、五仓模块边界和一致性，都有对应现状审计、建议与实施包；使用独立worktree/环境、显式路径提交、单推送者，保留原测试先行和完整门禁。仓名/品牌尚未确定，按所有者要求先完成其他工作；本次不rename、push或合main。

平台仍以数据聚合和安全全生命周期为目标。SOC/SOAR/CMDB/TIP/知识等专业写主优先消费，不另造大而全平台；模型只接既有API，内网场景仅内部端点。平台领域Agent与外部Agent双轨保留，确定性步骤可满足的场景先采用简单实现，未证明需要通用智能体平台。

mock长期保留；公共核心＋私有adapter/模块隔离。独立模式的账号、角色、菜单、权限完整可用；企业模式通过UAA adapter投影身份与受管权限，来源/撤权/管理权分开。UAA公共C/P、真实R、最小前端和运维分别有价；真实环境合同/凭据/岗位编码/权限接管条件单列。未正式部署，允许协调替换旧合同，不保留无必要的六个月兼容承诺。

设备首期仅目录、状态/新鲜度、受权打开管理页，设备侧人工登录，不假定异构厂商支持SSO。Go/Node/PG/Redis等升级已有独立本地候选验证，PR/main和真实切换仍独立处理，不把开发机升级称所有部署都已更新。

工单文件上传是列表追加A、B，用户显式删除；替换字段引用不自动删A。调度支持忽略/最多补一次/逐次补齐，时间窗/数量/并发/失败/暂停/撤权与超限余项held细化，不能静默丢弃。状态转换成功后的独立转派失败保留状态并持久重试/对账，必需同成同败的本地责任变化仍走同事务。

新类型默认仅相关人员，旧类型保留范围；抄送给查看/评论，不附送处理权；查看全部范围不能绕类型限制，不另造“敏感”字段。扩大参与范围由独立获权业务管理者处理。虚拟风险组按职责授权管理风险并向配置类型/组织派单，不另要求通用建单权；事件岗位另按SOC职责授权。离职账号立即停用，批准映射后合法事项自动交接；撤部先预览确认，不复制原部门角色或改历史归属。

前端按全站规划：安全首页/Logo、统一创建与卡头文案、批量标签、搜索筛选及展开、字型/配色/比例/明暗/窄屏/键盘。情报左右栏，历史仅回填，明确重查才请求；按用户隔离本机元数据，不冒称结果快照。新增能力的配置、运行、结果、unknown与恢复反馈必须同批交最小UI。

统一通道是同一能力所有入口执行同一应用用例、领域权限与完成合同，不是全部HTTP回环或全部排队。工单→任务→结果、计划→AL更新、AL变化→订阅→任务分链验收；源事实、消息通知、执行成功和投影成功分开。CAS/幂等/lease/fence/当前授权/共享预算/异步恢复按规模逐步实施，远期可插拔与架构调整遵实际触发与固定复核窗。

路线覆盖P6–P10及更远，尽可能承接原功能价值；技术形式可因现有规模调整，不能用调查替代已保留业务效果。旧119触发来源、511计划来源及169功能原子保留可追溯处置，均不能直接当独立功能数或工日。后期准确DTO/DDL和提供方参数仍逐包冻结。

每轮新增/纠正先回填原话来源与核对点，并显式更新本轮范围截止；区分“已理解、已审计、已设计、已实现、已验证、已激活”。将助手公开承诺也纳入复核，不能只检查用户需求是否出现过关键词。
