## 1. 原话怎样承接

同一`capability_id/contract_version`的HTTP、内部、手动、工单、计划、事件与选定MCP入口汇入登记应用用例，再执行同一领域实现。adapter只处理协议、可信认证上下文、规范化和响应映射；不能复制业务策略、直库或对内部调用免检。本地短事务继续进程内调用并复用tx，不绕HTTP；查询不为格式统一排TR。异步的提交/执行是同一操作不同阶段，worker复验当前权限/版本/目标/预算，不能重新提交出第二任务。

当前生产快照已实际枚举18模块、176个Gin绑定、298导出service声明、218生产Go来源SHA及135 UI HTTP调用；去重后158个产品能力候选映射。构造器、纯函数、鉴权谓词、同事务步骤、审计写主及维护机制逐项有例外理由，不恢复退役菜单CRUD或开放任意SQL。全部映射的共同runtime验证仍为false；枚举完成不等于158个新API已经注册。

三条代表链分别覆盖不同断点：

- A：工单节点→持久意图/同一操作→TR执行→效果收据→工单结果。CE02-D交关联/阶段，D12交显示与白名单结果映射，不反依完整I01。
- B：唯一TR计划发生次→core受权AL命令→AL本库CAS/效果收据。不是全量replace冒充patch，TR不直写AL库；unknown按原operation对账，不换key盲重做。
- C：AL所有受支持写事务→源事实/feed→core持久收件/订阅版本→TR任务。事务型每流head提供完整提交水位，不能把nextval当提交顺序；规则取明确event-time值，变版/暂停/回放有连续水位和held出口。

源事实、任务受理、业务完成、结果投影和通知送达分别记账。数据“打通”的验收是三条真实旅程及故障恢复，不是共用JSON信封。MCP只薄适配审核后的能力，并不自动发布所有工具；公司UAA网页登录也不等于MCP OAuth AS。

## 3. 已做验证与没有证明的部分

本次实际执行router构造/Go AST/消费者匹配与来源哈希核对；精确Schema49项（16正33反）、规范化6项、原始JSON6项、独立语义oracle27项，以及隔离PG候选SQL8项。PG验证包括回滚无事实、16并发重复单效果、stage去重，以及plain sequence并非完整水位的实际反例；实验库已删除并核0。

这些是库存、候选合同与SQL算法的证据。没有把它们称为生产outbox、真实跨仓副作用、多实例流控或三链验收。现有Go门禁另行跑并绑定其输入；新增产品实现仍按测试先行，从本包正/负/边界/权限用例的行为红证据到全绿。
