不是所有能力都排进TR；同库短事务/查询保持进程内调用。不是所有功能都等待CE05；它限制新自动链的启用，独立mock、既有正确性和无关业务可继续。每个新API/本地/MCP入口仍需适用的有界profile，可复用现有机制，不让只读MCP等待完整CE05/I03。复杂持久协同留P9，但简单AL变更触发不拖到P9。CE新增能力的配置、运行/unknown、结果和恢复入口与业务同批计入增量复估，不自动算进旧U06。

旧C03/C04/R01/D12/I01/I02/I03的原责任继续保留；AL源凭证、AL任务adapter、订阅及跨入口准入是实质增量，应按复用扣重后补估。现有工程日/周次只覆盖补充前有限范围；**当前不提供把新增范围假定为零成本的“完整新日期”**。待场景收集和新增切片细化后，在相关编码排程前补估并重新生成依赖/日窗，无需今天穷尽远期参数。

## 3. 必须保持的边界

统一语义和接缝，不统一数据库、所有领域状态机或全部消息字节；不新造通用工作流、IAM、broker、CDC平台或专业SOC/SOAR替代品。AL拥有数据与源变化事实，主仓拥有订阅/业务策略，TR拥有调度和执行账本，专业平台拥有其事实和流程。

采用稳定操作身份、同键异参拒绝、未知效果先对账；跨服务网络不持本地DB锁。持久化事实、接受命令、业务完成、结果投影和通知已读分别记录。来自任务的AL更新仍是事实，触发被抑制时保留原因；不靠丢事件防循环，不保证跨系统exactly-once。

首期可单实例；真正扩副本前验证共享claim/lease/fence、重投和预算，不能只加副本数。用户、任务、事件、MCP、Agent及私有模块不得绕过当前权限与受控预算；事件来源认证不授予执行权。大量mock、完整本地IAM、私有UAA adapter、专业供给和现有前端组件继续保留。

## 4. 后续确认与细化时点

O13/O14仅确认所有者已明确提出的方向，不把本合同每个技术候选视为已批准参数。目前无需再问同一原则。CE01逐项列公开能力与受控例外；实现者负责schema、语言profile与锁序，编码前评审。若出现改变业务含义的选择，再用具体场景交所有者确认，例如：

- **AL订阅**：一次全量导入替换十万行，是“导入完成后跑一次核验”，还是需要每行执行动作？先按有界批次/manifest规划，逐行要求需另审容量与完整性。
- **结果回贴**：任务产出“扫描报告”，首期仅显示报告/状态；若要求自动写“复测结论”或关单，需要确定字段/状态允许集、当前授权和迟到处理，不能由返回JSON直接决定。
- **循环及积压**：规则更新AL又触发原规则，默认同链不反复重入；有合法递推需求再给有限步数和停止条件。大批积压采用hold/人工处置，不静默丢弃。

这些是对应能力启用前的具体窗口，不要求现在决定所有未来自动化规则。B08与UAA-P01继续各自窗口，不被本次新增愿景代替。设计与实现证据始终分列，三条链分别通过后才能分别宣称已打通。
