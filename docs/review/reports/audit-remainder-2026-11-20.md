## 起点已验证的修复

上一轮已交自助改密凭据条件写、现有工单 Update/Transition 的 HTTP 共同守卫、管理页面稳定目标、角色菜单原集合比较、字典备注省略保留、容器停止宽限、用量指标整体替换、任务提交凭证幂等读回、迟到取消清理及长期 running 的只读诊断。原复核中的对应反例由这些窄修覆盖，各自的测试与启用边界见[上一轮记录](audit-repair-followup-2026-11-20.md)。

## 本轮验收切片

- P2-1。只改工单图或重启用，校验当前组合后的图与元数据。处理服务器当前注册的动作与入参，历史行仍可停用或显式修复。校验失败不变更版本、有效图及启用状态。
- P2-1。通知写入核业务域与动作组合，偏好读取错误留证并阻止该收件人的发送，发送记录与告警失败可区分。验证范围是现行尽力链上的失败及成功处理。
- P2-2–4。平台查询按登录用户用独立令牌桶，默认 60 次/分钟的补充速率，显式路由覆盖优先，零值保留通用限流。启用超时扫描或验证码时拒绝负数或非法时长，保留零和空的缺省。情报 TTL 错值留证并使用服务端 7 天缺省。日志轮转拒绝负值。沿当前消费者核验存储范围、判定日志 `withDefaults`、常规归档构造与固定归档启动校验；应急 CLI 继续按既有配置装配。
- SIB-R02。凭证回读比对原 action 与语义等价的 JSON 参数。冲突及凭证暂无法确认各有结构化诊断；上游已受理的任务、原凭证及原有终态保留。
- U03/U04。关联候选依据真实菜单和双端更新范围，按目标过滤后取限。浏览器只回显当前查询，提交与回读绑定原始源和目标。后端仍重验建联请求。

- C04。现有业务写命令复核当前 HTTP 身份和授权，票行按 ID 顺序加锁，关系两端分别校验。资格写使用同一 IAM 排他键，事件事实随业务提交，外部工作在事务之外。
- 字典和组织。删除与既有字段规范写入共享同一字典行，并发两种顺序由 PostgreSQL 裁决，旧字段仍受保守保护。普通组织和虚拟组删除守卫计入停用角色的绑定。角色删除要求先解绑，并与新绑定互斥。合法删除组织时只清理该组织指向已软删角色的历史绑定。
- C02。当前头像使用已启用的当前桶和实际用户所有权。既有站内文件代理路径归一为头像键，历史两种表示均阻止回收。pending GC 先标墓碑再做对象 I/O，已确认的历史字段引用阻止回收。存量归属扫描与数据迁移继续登记。
- F2a。可解析但与账本身份、动作、业务参数或来源不一致的排队快照保留原行并隔离，使后面的正常任务继续推进。可验证为等价的现有同一 cron 发生次只推进时隙并保留原执行。失配升级提示具体字段，现有 `running` 维持只读观测。
- Taskrunner 的主线验证还发现，旧库补列会被同库另一 PostgreSQL schema 的同名表误导。启动现在按连接解析到的 `job_runs` 补列。双 schema 回归核对补列可重试，目标历史行和旁路投递均完整。
- P2-11/P2-12、P3-1/P3-2、U02–U06。活动历史与保存、通知列表和日志筛选、任务详情、Panic 分页、MyOrg、首页和消息中心、情报历史、工单组织与字典读取消除错序或假空。正常空集仍依照各页面已有业务口径展示。
