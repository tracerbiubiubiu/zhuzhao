# 五仓分档门禁实施

本批落实所有者再次确认的 ENG-D01b。纯说明文档仍走 CI，但只做轻量检查；登记的候选/隔离参考加针对验证，业务及工程规则改动保留完整适用门禁。代码测试先行保持。规则随本工程 PR 合入生效，不能据此追溯免掉本批完整验收。

## 变化与边界

- 五仓共用同版本分类器、文档和参考执行器；Make/pnpm 增加计划与轻量检查入口，原完整命令保留。
- 以完整 `base..head` Git 窗口、旧/新路径和模式判定；本地还包含暂存、工作树及未跟踪文件。初次 push 有 `origin/main` 时取实际 merge-base，无可靠基线则普通档。
- 常驻 `quality-gate` 汇总提交规则、文档及所有参考/产品/helper job 的实际结果，应跑项缺失、取消、失败或 skipped 均拒绝。不用顶层路径过滤隐去 workflow。
- 说明 Markdown 不凭扩展名全局豁免；嵌套 AGENTS、工程规则、正式 API/生成物、产品测试、运行输入及未知文件仍普通档。参考目录有固定 recipe，混合变化保留针对检查。
- 识别常见源码字面相对引用与 `go:embed`，动态消费仍须显式登记；不是万能依赖分析。文档检查仅检查本次新断链，历史无效链接不会因目录位置差异成为本次新增债；缺席跨仓、外链及非 Markdown 片段明确未核验。
- 参考使用固定命令校验规划、Schema 对应方言、向量、独立 MCP SDK 和离线 Chromium 交互。Ajv/Playwright 使用独立工具锁，不增加产品 Go 依赖；MCP 示例独立 Go 锁不引发产品/helper 重建。

`quality-check`只执行文档/参考检查，普通档随后明确要求在独占环境手工运行原完整命令并退出失败；它不会自动连接共享默认业务栈。远端 required checks/保护归 G02，本批不修改，也不将 G03 的双模式组合与可靠消费者装配守卫标为完成。

## 验证与限制

独立行为用例先在可运行旧行为/空守卫上取得红，再实现到绿；另以删除结果检查、缩小提交窗口、遗漏在途源码、错误解析文档消费、损坏参考向量等变异确认守卫能拒绝。文档检查覆盖增删改名、锚点和 JSON；参考校验覆盖真实固定 recipe，原型有正向旅程与精确反例。首次失败、环境装配问题及重试分别保留。

最终共享三套测试为 36/15/24，共 75 项通过；五仓六个共享脚本逐字节同 SHA，实际分类/文档检查与 workflow 静态接线检查通过。四个已知 Schema 另有真实矛盾变异：通用 Draft7 编译通过，但相应既有样本校验拒绝，证明定向语义检查确实执行；未知候选 Schema 的通用编译仅证明格式，不证明业务行为。

本批规则自身按普通档完整验收：主仓 lint/生成/单元/集成/覆盖率/迁移/四档验收；三 Go 兄弟的原完整适用测试及扫描；UI 原六件及独占真栈 E2E。具体命令与最终结果以本批五仓 PR/Actions 和本地原始收据为准，未运行或进行中的项目不能从本文推断为通过。主仓默认标签覆盖率维持 20.2%，没有以规则调整声称提升产品覆盖率。

本地结果：主仓 253 验收、81 对迁移往返通过；UI 244 单测、42 真栈 E2E 通过；TR 20 项真实投递/cron E2E及三兄弟原适用门禁通过。AL 源码扫描首次网络 EOF、原命令重试通过；UI 新独占 Vite 端口首次遗漏对象存储 CORS，保留完整 40 过/2 失败收据，补测试夹具允许源后从 globalSetup 完整重跑 42/42，无改断言或关闭浏览器安全。原型和产品真栈结果分列，既有构建提示不改写为零告警。

主仓运行夹具冻结后与当前 522 个产品输入逐项比对一致；离线原型、脚本自测和 CI 接线在最终候选单独核验。无业务 API、数据库迁移、权限语义或部署变化，也不证明真实 UAA/公司消息已接通。
