# 基础先行与各期能力边界复核

日期：2026-11-14。候选起点：主仓`2bcb994270e464b8c80f669af6086d298bfa8779`；隔离分支`codex/capability-interconnect-design`。本轮仅修设计、规划源及排程工具，不开始平台业务开发、共享切换或远端操作。

## 结论和调整

所有者明确要求先有基础能力、带入内网后编写私有adapter，再按实际使用演进；常见、常用、必然问题仍需覆盖。复核确认前版有几处前置过重，已实际修正，不能仅以“远期详设后置”概括。

- **现有底座先试验**：B0固定现有五仓组合，只准备一个目标平台/架构的运行包及必要二开依赖。独立IAM和现有工单可先使用；这不是已经完成入网打包、生产准入或公司UAA激活。
- **基础接缝要实跑**：B1先单实例、本地IAM、正常首页和基础工单，再用一个HTTP query adapter及一个参考私有应用证明接缝；不先做全套插件治理。仅有合同或离线模型不能验收这个出口。
- **后继按业务纵切**：风险人工闭环→常用体验/一条任务回贴/设备→固定统计/薄SOC协作→按提供方接入/API→所选AI与专业协同→实际规模和持久自动化。各期明确必交、非前置及验收出口，权威见[交付边界](../../design/foundation-release-boundaries.md)。
- **不以简化降低正确性**：当前授权/数据保护、附件正确性、必要的幂等和可靠交接、最小业务UI、原TDD和适用完整门禁保留。多实例在实际选择前验；单实例内并发写仍须事务/CAS。真实企业激活仍满足公司的认证及权限治理要求。

## 各期边界的正文同步

工程/版本文档不再要求首次入网就准备所有架构、全部浏览器/字体/工具和完整签名流水线；兼容矩阵先覆盖实际承诺的当前消费者及一个参考adapter/应用，第二支持代际出现前再扩。

日志/审计基础纵切先适用敏感面、本地可信事实、受权分页和原页面薄接线。大导出、快照artifact、外送和多worker按用途/拓扑分别交；原22–33日是完整有界候选，并非基础版必交价。业务历史与专门审计职责分开已确认；两IAM写的本地审计失败回滚仍待答，未借本轮原则确认升格为批准。

P7不再把脚本、知识、外部Agent和SOAR四类供给全部挡在P8前；P8按所选方向分别验收，不要求三轨首条纵切齐备。领域Agent和外部Agent可按场景分别推进，选RAG才消费相应知识ACL/引用。P9只有确需并行时才建设薄分支/汇合。

未盲删A05/A06/A07、U08/I03及E01的现行安全依赖。所选P7手动运行/provider、P8领域场景开工前，再按真实读写、持续委托和恢复消费拆子出口；这些是具名细化窗口，不是B0/B1的新统一前置。长期愿景保留，不要求今天冻结所有远期DTO/DDL或罕见情景。
