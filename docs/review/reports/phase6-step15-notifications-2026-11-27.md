## 新增路径

- 提交复测时，原业务事务还为实际进入待确认的风险项按当前责任人去重入箱。通知写失败会回滚业务提交，两条资产同一复核人只有一条通知，重放原命令读回同一业务回执。已无当前资格或已无待复核原项时，该提醒不计入收件箱和未读角标。原收件人仍具原票和风险读取资格时，可在复核完成后按原号查询投递状态。
- 模拟渠道冻结逐收件人载荷，发送前核资格和偏好。预览仅用合成变量。提供方收到消息后主动断开连接，Core 查询显示结果未知。停止并重启 Core 后，按原投递 ID 查得已受理，错误签名回调返回 401，正确签名的送达证据使原记录变为已送达。提供方一次发送、一次受理，原业务回执相同，站内仍为一条未读提醒。另一位具备本票办理资格的人查询该投递返回 404。
- 浏览器按键打开原投递，核对走同一 ID 的 GET 并展示已送达，站内未读状态保持。实际签名 HTTP 和 PostgreSQL 集成测试另外覆盖拒收、不支持查询、旧回执和首次 worker 在提供方受理后被终止的恢复。对旧回执失去重查及重启后重发的反向变异均使相应用例失败。
