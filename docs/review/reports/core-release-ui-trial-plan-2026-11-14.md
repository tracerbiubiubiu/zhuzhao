# 核心试用版UI、端到端验收与试用窗口

日期：2026-11-14。所有者已确认2027年1月试用、2月1日前可用；首版覆盖风险/工单/TR/AL/消息联动、三层鉴权及真实UAA，不等待AI和高级仪表盘。本报告是已核源码后的薄UI与验收计划，新增能力尚未实现，不构成单席按期交付承诺。

核读基线：主仓`48b2310a15defef1107feebf1f239523d9a0d13d`、UI`b4f5a1f1a9dc78e52374d50a1f25a587ecd8f996`。范围与总排程由集成者承接，沿[基础边界](../../design/foundation-release-boundaries.md)保留原业务默认和测试先行；本页不另立报价注册表。

## 已有页面怎样复用

UI的`src/views/`已有工单列表/创建/详情（`ticket/list`、`ticket/create`、`ticket/detail`）、任务（`task/list`）、AL（`al/data`）、消息中心（`message/center`）和通知管理（`system/notification`）；当前没有风险业务页。复用Vue、Element Plus、ProTable、筛选和表单，不先做全站U06、设备、情报或复杂配置台。

任务页已有运行记录/详情及按`task:manage`隐藏定义区；AL页已有行version和409反馈；消息中心已有通知/待办，通知管理页已有发送记录。这些实物不等于已有普通用户逐对象任务结果权、风险派单或AL可靠变化链。任务水位请求失败当前可能变0，首版相关入口须明确失败；不能授予普通用户全局管理权使演示通过。

## 一条首批核心旅程

真实UAA登录→获授权风险成员接收/录入风险→向批准类型/组织派整改单→普通处理人接单、提交证据→工单调用一个获准TR动作→更新一个AL结构的数据→变化触发约定后继/消息→原工单查看结果→当前风险负责人复核。

首批建议固定一个整改类型、一个AL结构及少量动作，以受审配置接线。若采用AL变化→TR反向触发，须交真实的持久交接和消费者回执，不能仅刷新AL页；先明确唯一触发链，避免自身回写无限再触发。mock长期保留，但不能替代企业UAA真实验收。

## 最小UI及关键验收

- 普通用户/风险派单：风险管理职责可受限派单，无须任意新建工单权；只读拒绝。处理人、CC与无关同部门人员分别验当前范围；CC可查看评论、不附送处理权，复核按当前`risk_owner`投影，不为待办数字强改AssignedTo。
- 工单/TR：原票显示已接收、运行、完成、失败和待核实；提交成功不当完成。响应丢失查原操作，迟到结果不覆盖新状态；本票结果读取不赠全局任务参数、日志或凭据权限。
- AL：版本/修改时间/关联结果可辨，冲突保留输入并提示重新读取；已提交但后继未完成显示待处理。重复事件不重复效果，失败写入不发假成功事实，当前type/row/field资格适用于查询、写、统计及下载。
- 消息：业务页给待发/失败摘要，管理页再查去敏详情；通知失败不回滚已提交业务，也不能冒称送达。发送时复验收件资格，标题/正文/深链不泄露无权数据。
- 企业权限：复用login/users/roles/menus，显示来源、同步/待生效和失败；受管只读、非受管按权限可写，后台同样拒绝绕过。撤权/换账号清旧路由与数据，故障不自动开放全员本地密码入口；独立模式原IAM另验。
- 真实端到端：专属普通账号跑成功链，以及无权、撤权、重复点击、超时、重启、通知失败和AL冲突。沿用原42条E2E作既有回归，不用旧绿色证明新链；新页面验加载/空/失败/无权、关键键盘和200%缩放。

## 薄UI工作负载视图

单位为有效工程日，含该项测试先行与正常修正；假设复用现有组件，后端提供本批冻结的规范化接口，不包含后端实现、提供方等待或整站视觉重做。

- 首页与权限落点：1–2日。
- 风险新列表/详情、评估及受限派单：4–6日。
- 工单节点/证据/任务结果及批量标签：3–5日。
- TR受权详情与回执：1–2日。
- AL变更、冲突和关联反馈：2–3日。
- 消息与业务失败摘要：2–3日。
- 新业务浏览器组合回归：3–5日，不重复收各项单位测试或UAA登录回归。

合计**16–26日，不含UAA**。它是D/U/CE所选工作的负载视图，不能再叠加到旧包预算；正式范围/扣重/依赖须由根方案统一落账。[UAA原估](../uaa-implementation-estimate.json)已含P前端5–8日、R真实前端1–2日，继续原价复用；合看前端相关负载为22–36日，不是另一项新增报价。

这已占40–45个理论构建日的大部分；单席还需承担风险、互通、UAA后端和接线，不能据此承诺1月完成。真实协议或当前权限模型超出该有限画像时，应明确变更，不压缩必要验证凑日期。

## 五个可演示阶梯

1. 固定入网试验组合、普通用户落点及首批业务配置；从此时启动真实UAA材料/网络/权限核验，不等末尾才联系提供方。
2. 风险→工单人工闭环和最小业务UI可用，先让owner用普通角色操作；人工业务不依赖模型。
3. TR→AL→消息与工单结果回贴联通，常见失败、幂等和恢复可解释；不要先造任意规则设计器。
4. 真实UAA、三层权限和完整适用门禁合并通过，才达到企业试用入口；前面本地/mock演示不能冒称此出口已过。
5. 冻结首批功能，按试用反馈修权限阻断、责任不清、结果难找和失败反馈，再回归；不再塞大功能。每阶验所选组合，不要求全站迁移。
