## 接入和来源

- 批次收件和业务应用分别提交。应用同事务提交观察、现势镜像、风险历史及批次结果。显式批次同号异参拒绝，旧单条重投继续逐事件读原接入号。应用和终态重读前复核配置和组织范围，交叠批次引用同一权威事件。
- PostgreSQL 竞态用例确认第一次提交落在待应用台账，应用阻塞时业务为零。事务取消后原批重投或消费者接续保留原号。重复执行交叠批、映射变动和中断场景，旧组织风险引用与业务效果均受当前来源范围限制。
- 真实 Core 在独占 PostgreSQL 中等待应用锁时被 SIGKILL，客户端未收到状态或正文。原批和两个预留接入号已持久化，业务计数为零。同一制品重启后，调度在任何人工重投前先完成一条应用和一条待核，并留下原逐项结果。另一次应用已提交且客户端丢弃成功正文，重启后同批重投读回原结果且零重复写入。
- 风险详情用镜像匹配的观察返回来源摘要。高序号携带更早观察时在基线重现摘要与镜像不一致，候选的摘要、严重性和派单依据取同一当前镜像。更低序号、不可判序和同号冲突沿用首批判定。
- 最终交叉复核补上同源事件及多家族的稳定锁序。多家族与改派使用相同的家族 ID 次序，之后才锁风险。显式批号异参保留 JSON 数字原词元的区别，收件时记录旧逐事件哈希以兼容 v102 的负零原事件。派生标题在创建时按列有界截取，长的稳定身份原样保存。

## 人工补核和目录

- 模拟情报给两条已知匹配及稳定证据引用。真实 Core 路由签名查询合成 CMDB，覆盖已命中、未知、陈旧、空结果、503、超时和恢复。风险仍需人工核实与确认责任，调用失败期间风险修订和责任事实没有业务写入。
- 主锚管理者在原风险补齐身份，CAS、证据和原操作号同行提交。非主锚、旧修订、不独立的证据及现有身份冲突被拒。曾复现后续源镜像的新引用可被当作独立证据，候选在风险锁内同时排除首报及现势源引用。期限过后同一稳定身份可续证，存量空白字段可补齐，非空字段精确比对。来源撤回、过期或身份冲突仍阻断派单。
- 模拟目录复用现有工具。半批中断保留已成功结果和旧水位，恢复送达缺失的部门、推进水位并按原批次读取原回执。现有人员关系与停用夹具检查本地现势资格。

## 处置

- 转移、规避和接受保留原策略与核实说明。新建整改票的预览及提交均要求整改策略。第 8 项逐项证据、复测、责任人申请、独立决定、未决项禁止关单，以及在办接受到期恢复直接复验。
- 主锚可按原操作号对无在办关联的风险确认误报及抑制期限。抑制原因受主锚权限和风险审计裁剪保护。同指纹在期限内只为原关闭周期增加来源观察。期满后真正新鲜的观察才开启新待评估周期。新周期开启后，落在旧窗口内的迟到观察仅留原接入回执。并发误报只成功一次，终止抑制独立留痕。
- `000103` 保存原接入与批次回执，`000104` 保存误报抑制并登记权限目录。存在业务历史的降级守卫拒绝删表。启用签名源时，先升级数据库再使用新 Core；发现待处理批次须保留台账，恢复获准的原源配置后可按原批续办。

接受到期全站自动重开、全站风险界面、生产提供方及后续排期条件项继续沿各自已定窗口。新入口及先前公开按钮均采用独立合成账号与实际权限校验。
