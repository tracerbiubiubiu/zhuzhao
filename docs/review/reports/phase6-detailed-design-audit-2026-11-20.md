## 1. 会改变开工顺序的发现

### 工单引擎升级必须进入第一条人工风险纵切

当前 `internal/model/ticket.go` 的 Ticket 只有类型和状态，`internal/service/ticket/transition_service.go` 的 Transition 与 ListAvailableTransitions、`internal/service/ticket/service.go` 的 Create 读当前 GetTicketType；转换已有状态、SLA、事件与评论事务，必需后继仍有提交后进程内 emit/post-actions。当前转换请求也没有受定义约束的字段补丁和独立票 revision。已交事务修复、状态机、字段验证和画布可复用。

发布定义、字段规范、带证据转换和受限参与权是风险闭环的产品依赖。原首版 S3 只计固定配置守卫，R4 只计所选派单和原用例接合，U4 的证据界面原在跨仓阶段，给这些行追加设计释义会漏工时。保留简单 FSM，按同一服务入口渐进替换。完整设计器、自动路由、跨环境晋级、删状态迁版各自后续。 [原流程设计](../../phase6/00-flow-engine-v2.md) · [工单详细合同](../../phase6/ticket-module-detail.md) · [原工单完善 26 件](../../phase6/06-ticket-completeness.md#26件当前对账2026-11-14)

### 首条风险纵切要按已启用输入与输出逐一冻结

总账 D08 完整包确实依 D01/D03/D06/D07/X02-F，D07 依 X02-Q，D09 依 D15，D10 依 D02/D08/D09/R01。首条人工画像可以消费本地稳定身份/目录写主的子出口和一种合成输入，暂不开真实提供方、通用预填查询和 feed。该子范围还要额外验撤权、受信主体、逐对象投影、可重试收件、可审业务历史和通知义务。任何被选真实来源若需要查权威目录、水位、完整集合或重放，先补并重估这些子出口。完整 D08 的依赖继续生效，完整基础扩展版后移会连带影响开放真实来源和设备分支。

- **同一锁序须在开工冻结**。`internal/service/ticket/iam_command.go` 的 withHTTPCommand 先锁所选票，转换再经 `internal/repository/ticket_transition_snapshot.go` 的 LockTransitionSnapshotTx 取活配置共享锁。目标合同把可变政策/发布指针排在业务对象之前。按共同授权守卫、组织及适用配置、group/family、risk、ticket、link 的次序逐个盘实当前写方、发布、迁版与扫描，所选路径验证两种提交次序。静态差异本身未证明运行死锁。
- **首条试用按真实钉版排产**。独立审计提出只做服务端固定配置的低价情景。该方案需冻结所有可改写定义的入口，而且无法证明发布 B 后旧票仍按 A。当前排期采用受控发布初版及第二版的可执行证据。同名状态最小迁版随 D01 定义交付。完整配置工作区后续推进，删状态完整迁版在 Phase 7，届时补准确映射 wire、权限、干跑、批次断点和字段/时钟处理。
- **复核条件要有受信的权威来源**。现有 TransitionMeta 使用四类角色词表，暂无 `field:risk_owner`。所选复核入口补可信风险字段和当前 owner/参与资格，普通自定义字段或客户端传值不能产生资格。交接只改当前受影响风险和来源，部分交接不得转走整票其他风险的复核权。普通关闭、转移、删除和后台路径共享同一桥不变量，或在本期按服务端明确封闭。
- **风险通知的意图和消息的幂等键采用既有写主合同**。风险事件携带域身份及规则身份，落投递以消息域的 `(source,source_event_id,rule_id,rule_version,recipient_user_id,channel,semantic_key)` 为准。解析时获准且送达前仍获准才发送，改派抑止旧投递，必要时新事实产生新投递。列表、未读、深链与证据分别在当前范围内裁剪。只交事务意图和受权最小站内提示时，界面只证明这些事实，真实频道按真实消息门验证。 [风险合同](../../phase6/risk-module-detail.md#6-d15通知与统一审计) · [消息写主](../../phase6/task-activelist-message-detail.md#3-候选逻辑数据约束与事务)
- **工程先静态核四个遗留边界**。字段配置将旧空值与默认行为分别回归，包括 F11 数字等旧形状及 F12 无法辨源的宽度。模板只用于建单默认，不能作为独立流程写主。若选定字段启用表达式，生产开放前验 C01 的新旧值角色及作用域；首条固定试用预算假设不需要新增通用表达式功能，冻结不成立时将适用余量单列。全站统计、超时扫描、显示已走路径凡被新类型实际消费均须读同一快照，旧历史缺事实标未知。 [工单类型与模板 ADR](../../adr/adr-004-ticket-type-template-flow.md) · [工程正确性详设](../../design/engineering-execution-design.md)

## 5. 设计取舍与验收收口

- 固定定义与显式迁版的设计方向成立。工单实例应能定位原始定义，有意迁移才改变实例指向；把流程图的内容版本和人的当前资格区分，保证重放和撤权可以分别证明。本项目保留小 FSM，不引入外部流程运行器。 [Camunda 实例迁移](https://docs.camunda.io/docs/components/concepts/process-instance-migration/)
- 业务事实和必须有后继的意图一起提交，接收和远端效果用稳定键回查；补强计划必须测试回滚、消息重复和有序约束，不能靠进程内 hook 或 HTTP 受理推定实效。 [AWS 事务发件箱](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)
- 动作预览、UI 显隐和发布时的配置校验只提供候选。实际提交、数据库结果回读和后台执行都沿本域当前资源授权，代表性 role×scope×action 的独立预期需要跨页面验证。 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
- 实施卡逐条注明写主、文件/符号、准确 wire、旧数据迁移/回退、权限矩阵、事务/后台状态、验收及配置开关。先有可观察的失败用例，再按实际变更档完成适用门禁；产品测试需固定同一五仓组合。真实试用另验 Q12，真实自动化和外部消息分别验 Q09 与 MH01/MR1，正式纳管另过真实测试、影子核对、批准与观察。

## 6. 漏洞整改代表场景增量审计

审计对象是[风险详设新增样例](../../phase6/risk-module-detail.md#14-漏洞整改代表场景)、其排期与 Q10 衔接，复用前文五仓源码基线。主会话负责文档写入和复算。直接派质量与交付审计者（DeepSeek）核业务覆盖、时钟和阶段估算，派防御性安全与权限审查者（Codex）核当前授权、mock 隔离及事项提交。两者均只读，并交叉核查首版与真实启用的分界。没有重启全量审计。

- **外部模拟边界**。开发、CI 与合成联调接可替换的情报、CMDB、HR 和外部消息模拟端。资产匹配依据在派单提交时仍须有效，模拟身份和主管关系不能授予业务权。真实联调使用显式选定的 provider，失联按实际合同报错或留待核。真实试用和正式渠道批准沿原准入。
- **时钟、复测与分支用例**。首条拆开接单截止、首次人工接单指标、闭环截止与最终确认时间，补闭环超期仍在办、接受制衡和通知分级/撤权测试预期。提醒重扫使用同一稳定身份，发送前核待接单与收件资格。部分通过不关整票、不触发闭环后动作，合法交接后旧资格、旧提案均不能提交。
- **延期期限与自动动作**。双签须共用同一申请版本并复验主管关系与当前职责。候选以风险项为粒度，批准后原子重算工单截止，保留历史超期。风险接受继续采用既有独立确认。闭环后动作只验所选变体，跨仓真实运行及无人值守准入保持原排期出口。
- **仍待确认**。CMDB 提供资产目录还是权威匹配（Q08），两侧实际角色、审批粒度、同人或缺员处置、待批计时及是否进真实试用（Q10），按现有议程绑定。新增接单提醒在开工冻结时核既有预算覆盖。完整定级、多源、双签及实际接入的变化按批复算。

本轮在文档中固化可执行验收条件。实际 mock 适配器、工单代码、运行配置和产品证据各归后续实施与启用窗口。

## 7. 三项设计确认与审计交接

质量与交付审计者（DeepSeek）和防御性安全与权限审查者（Codex）交叉核对了现行合同与主线 `42f83a1`。下列结论沿用既有工程归属和验收条件。

- **内网 adapter**。独立进程提供版本化接口，合成和真实 provider 实现同一已选合同。只读查询先验字段、范围和时效，目录或发现同步另验来源、顺序、持久回执和回放。主线可复用情报端口等基础。通用进程外接线与真实提供方分别验收。完整基础扩展版后排，首条业务先冻结所用公共接缝。真实试用需要的接口按实际范围前移。 [内网接入合同](../../design/intranet-adapter-migration.md#1-接入形态与责任)
- **数据与任务的共同通道**。同一登记能力由页面、工单、任务及订阅进入同一个受控用例。各领域保持本地数据写主，Taskrunner 调度业务任务，按持久意图、操作和实际效果回执关联。现有任务队列和回调可复用。所选跨仓链的统一接线、持久交接和未知效果恢复在组合阶段验证。 [共同调用](../../design/capability-invocation-contract.md#2-一个逻辑通道三种执行方式) · [跨仓接线](../../phase6/interconnect-source-wiring.md#1-一次装配共用内核)
- **权限适用性**。现有三层模型适用于已确认的漏洞整改职责，继续复用现有 IAM 和 Casbin。首条实际试用验证持久撤权、当前风险和复测职责、对象与字段范围及各读写入口一致。服务签名提供可信来源，当前用户、委托及资源动作资格仍按业务用例判定。HR 提供主管关系，后续 UAA 管理获准范围的账号及功能授权，本地负责对象判定。 [模型与接线余项](../../design/authorization-model-and-engine-choice.md#3-现有系统的价值与差距) · [当前债务](../11-project-control.md#6-当前健康状态遗留问题追踪)
