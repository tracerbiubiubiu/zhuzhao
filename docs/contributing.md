# 参与贡献

欢迎可复现问题、具体使用场景、文档改进和有界代码贡献。当前能力与未来方向分别见[README](../README.md)、[路线](roadmap.md)和[控制台](review/11-project-control.md)。

## 先确认范围

小文案修正可直接提PR。功能建议说明使用者、现有困难、输入/输出与最小验收场景；已有SOC、CMDB、SOAR或知识平台能提供的能力优先接入。大型模块、协议或依赖先讨论范围。

公开问题使用合成数据，移除真实身份、公司标识、内部地址和秘密；附版本/提交、复现步骤、预期、实际结果及脱敏日志。不要通过公开issue传播漏洞细节或凭据；正式私密安全报告渠道尚待单独配置和公布。

## 本地开发与PR

1. 阅读[开发指南](guides/development.md)与对应模块，安装当前worktree的`make hooks`。
2. 每个写任务使用独立分支/worktree和运行资源；本项目测试数据可重建，仍须核清项目与在途任务归属。
3. 遵守[工程公约](standards.md)：先写可验证预期和失败测试，再做最小修改，不弱化已有回归断言。
4. 使用显式文件路径提交，核对提交文件，不带其他任务的修改。
5. 通过适用检查后提交小PR；政策允许单维护者在必需检查通过后合入。

远端保护和完整组合CI仍在后续工程计划中，不能把文字当已启用机制。分档检查未生效时继续现行门禁，前置和命令见开发指南。

## 评审需要什么

PR包含改动摘要、影响面和验证证据；说明接口、迁移、权限、配置是否变化，实际执行结果及未覆盖路径。文档和截图区分当前产品、规划与合成示例，不把旧结果标成新候选执行。

公开能力描述同步中英README。详细文档以中文为主，不要求普通贡献翻译全部历史材料。兄弟仓按各自指南及同一生态公约执行。
