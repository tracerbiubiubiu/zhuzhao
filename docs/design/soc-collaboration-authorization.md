# SOC事实与本地事件协作的职责授权合同

> 日期：2026-11-13。用途：补FD08事件职责×动作×范围、撤权与接管反例；范围：D14/P6.E的SOC结论引用、岗位工单和证据协作。设计状态：候选；实施状态：46个合成授权例已运行，尚无事件模块/权限种子/真实SOC联调。
> 权威：风险组B05沿[生命周期合同§5](business-lifecycle-contracts.md#5-d03类型可见性参与人与创建范围)，新事件域复用[当前授权/公共调用](capability-invocation-contract.md)。候选资格码不表示现库已存在。

## 1. 三种事实分开

- **风险记录risk_item**：漏洞/隐患及其整改生命周期，原risk:manage＋资源范围不变。
- **SOC安全事件**：攻击/专业研判、关联发现、处置动作结果与专业终态，SOC/SIEM/SOAR为写主。
- **本地协作case**：对SOC事件/战役的稳定引用、经授权可见的必要快照、岗位职责、关联工单/任务/证据和本地协作状态。它不是第二SOC，不把“所有岗位已提交”写成“攻击已消除”。

首期有SOC引用则保留provider/external_id/source_revision/observed_at。暂无稳定SOC ID可用明确local_pending_reference轻分组组织协作，不编造专业事件或结论；映射确认后追加关联，不重写历史。专业原始日志/全量告警湖不导入本平台。

## 2. 资格、范围与主体

建议四类新增事件域L1资格：incident:read、incident:collaborate、incident:manage、incident:export；最小角色组合按职责配，不因“风险组成员”自动获得。它们是将来菜单/按钮注册的候选，尚未写迁移；GET页面与POST按钮仍遵standards。

| 业务职责 | 最小资格组合 | 实例范围 |
|---|---|---|
| 风险组只读/管理成员 | 沿risk权限，不自动加事件资格 | 仅原风险范围；风险页有事件链接也不授事件读权 |
| 事件观察者 | read | 当前获准的case/组织或明确共享范围 |
| 岗位办理者 | read＋collaborate | 当前case参与且本岗位；只能提交自己的办理/证据 |
| 事件协调者 | read＋collaborate＋manage | 当前获准case与配置目标组织/类型，可分派岗位和管理参与 |
| 复盘导出者 | read＋export | 仍按case及每个引用的当前可见性裁剪 |
| SOC connector | 绑定provider/scope的ingest服务许可 | 只写本源投影，不取得人工管理/任意建单或用户登录权 |
| Agent/后台任务 | 上述职责的受限服务主体＋显式grant | 当前人员/服务权限、case、动作、期限与grant交集 |
| 系统级管理员 | 保留平台既有本地管理例外 | 不因本地例外取得SOC凭据、改专业结论或冒签岗位结果 |

L1允许不替代资源范围；一个人可以兼任风险与事件职责，但授权来源分别可解释。复用C04/D06的直接/组织/继承角色当前有效展开，停组/离职即时撤销的目标合同不得被角色快照绕开。三个权源的真实撤销验收仍在对应实现包执行。

case参与/共享只影响实例范围，不附赠manage/export。协调者扩可见范围应预览新增接收者及引用分类，CAS提交参与集并同事务写审计；不能靠普通CC或创建者身份邀请任意人。现有工单CC读评论、处理权、受限类型策略仍各自判断。

风险组的受限风险派单规则不被取消：risk:manage管理者仍可依B05从风险创建配置好的整改票，无需通用ticket:create；事件协调者也复用共享建单用例，但以事件职责和case范围进入。两者不互相伪装身份，不新造“风险派单角色”，也不把源服务账号当业务操作者。

专业动作若后续经E02接SOAR/SOC，需要其单独执行能力、当前委托/目标/逐次确认和效果receipt，不是本期manage/ingest的隐含能力。表内“本期不可”只限定D14出口，未取消后续已有专业协同目标。

## 4. 关联资源与每个读取入口

最小判断为：当前主体有效＋L1资格＋case当前范围/管理员既有本地例外＋被引用对象当前权限＋数据分类/来源许可。case可见不意味着工单、附件、风险或情报全文都可见。不能因时间线聚合拿主仓服务密钥扩大查询。

详情、列表、计数、搜索、时间线、actor筛选、导出、看板和通知共用同一谓词；先按当前权限过滤再计算数量，只显示授权结果的计数。固定提示“结果按当前权限范围展示”无论是否存在隐藏项都可显示，不输出被裁掉的数量、ID、标题或隐藏项存在性；有隐藏引用与从未存在引用的输出应相同。已经获准查看的来源接入覆盖缺口可单独显示，不把未知、无权或被裁掉数据混计成来源缺口。完整导出事前计算授权行集/字段集，生成时及下载时重验；signed URL不替代下载授权。专业来源撤销的数据不可继续从本地缓存分享，按合同处理来源撤回，不伪造历史不存在。

时间线区分source_occurred_at、received_at和local_recorded_at。自动与人工补录明确origin/actor/evidence_ref，人工记录不冒充SOC事实；来源unknown/stale不能当fresh。恢复/补扫按provider+external_id+source_revision幂等，迟到旧revision不回退专业快照，删除/失联不等于事件解决。

## 5. 撤权、接管、失联与并发

- 受限grant、成员关系、角色/组织停用或权限epoch变化时，下一查询/执行/下载复验。已接受任务不等于仍可完成；既有效果保留审计，未来步骤暂停/拒绝，不能删历史伪装回滚。
- 岗位接管用预览plan：原岗位、继任者、当前资格/范围、在途任务及可见性差异；批准后逐项CAS。继任不自动继承原人的角色；无合法映射保持待处理，离职停用先行，沿B06/B07。
- 管理参与/重分派带expected_case_revision/expected_scope_revision及操作幂等键；同事务改本地状态/关联/审计，外部通知经R01，网络期间不持DB锁。未知效果先receipt，不靠重复新建岗位票“恢复”。
- SOC事实源失联与UAA授权源失联分开。前者可读当前仍有权的历史并标stale，继续本地评论、证据和已有岗位办理；自动按旧专业状态新增派单hold。
- **已确认的人工本地协作政策（B09，2026-11-13）**：SOC暂时不能刷新事件，但用户当前权限仍有效时，获授权事件协调者确认“数据已陈旧”并填写理由后，可以在已配置类型/组织范围内手工创建本地协作任务，如催部门补证据；自动依据旧状态新增派单保持held。记录manual/source_gap_ack、理由、所见来源revision和实际操作者，不伪称SOC当前研判。manual_source_gap_enabled是服务端受控配置，调用者不能用body字段开启；D14实现后按此政策开放，配置关闭仍hold。缺确认/缺理由、撤权、越范围均不能执行，原型S37–S40保留正负例。该确认不授予隔离、封禁等专业处置权，不豁免UAA/权限新鲜度；公司强制规则可收紧，不能借来源失联放宽授权。当前仅设计确认，产品未实施或实际启用。
- UAA/权限新鲜度不满足时，仍按UAA-S02限制受管写；用户给“来源缺口确认”不能绕过身份/授权失效。专业源恢复追加新revision与对账记录，不直接改本地工单终态。

## 6. 最小DTO、界面与运维接线

目标case记录为local_case_id、source_ref/状态、source_revision/observed_at、本地责任与scope revision、local_status及受权关联引用；来源原文最小化，保留缺口。角色/菜单码、HTTP具体路由及迁移编号在D14编码前依统一目录注册，不预占迁移号。仅GET/POST，POST业务对象在body，不另外建立跨库写通道。

最小前端同批交：case来源/时间/陈旧提示；本地/来源时间线及actor过滤；当前岗位与证据；受控派单/参与预览；导出裁剪结果；pending/failed/unknown及对账入口。disabled按钮不是后端授权。人工来源缺口协作入口同批显示来源陈旧时间/状态、确认勾选、必填理由和本地协作范围，清楚提示自动派单暂停；提交与真正执行前均核当前权限/范围，操作审计保留所见来源版本。运维需看本源水位/延迟、投影/intent失败、撤权/订阅积压、待接管和未接专业覆盖，不展示来源密钥或原始日志湖。
