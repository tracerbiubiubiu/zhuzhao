# 五仓工程治理与目录演进计划

日期：2026-11-11。状态：规划已落档，配置和代码变更尚未实施；本轮没有开启远端保护或修改CI。工作项编号、依赖、工作量与窗口以[总账](../review/planning-backlog.md)为唯一排期。

## 1. 基线判断

五仓已有同核提交策略、三钩、离线反例、CI事件窗口检查；主仓已有分层/权限/秘密守卫、Swagger/Wire检查、单测和集成；UI已有lint/typecheck/build/audit/Vitest；兄弟Go仓已有race与部分真PG链路。继续保留这些能力。

本轮五仓GitHub只读API实证：main未受保护，required checks为空，rulesets为空；secret scanning/push protection均启用；vulnerability alerts与Dependabot security updates关闭。主仓完整acceptance和UI Playwright没有作为现有CI自动链路执行；主仓安全工作流仍偏向旧阶段分支/历史revision。源码证据分别位于各仓`.github/workflows/`、`scripts/commit-policy.py`、`.githooks/`；这是一份时点审查，后续启用必须另留准确配置收据。

## 2. 并行协作：隔离先行

G01在P6.0实施：每个写任务独立worktree和短分支，跨仓任务用一份准确base/head清单关联。多个只读审查可以共享；控制台、路线、公约等热点由一个集成者维护。串行合流后在固定组合上验收，避免所有agent在main同一工作树抢写。

保留路径提交、索引核对和提交后复核；它们不能识别同文件行的作者归属。现有`zz-commit.sh`路径校验还需检查精确成员关系、空格/目录/通配符边界。worktree的refs/部分配置仍共享，amend/rebase/reset不可并发；不自动清理他人worktree。

环境也按任务隔离：端口、PG库/容器、Redis、合成账号、临时文件、构建输出、对象存储bucket/前缀及owner标签。测试账号依runbook，E000001禁止人工改密。验收只精确清理本任务资源，前后核共享容器/卷/进程；不以reset共享栈收尾。

依据：[Git worktree](https://git-scm.com/docs/git-worktree)。当前执行方法与台账见[开发指南](../guides/development.md)和[runbook](../ops/runbook.md)，G01实施时再更新机械守卫，不能提前宣称隔离自动完成。

## 3. CI与合入

- G02/P6.0：短分支/PR、准确required checks、禁止强推/删除main、有限紧急通道。单人维护不制造第二个人形式审批；所有者已确认统一PR/单维护者可合；当前直推约定与目标策略在G02实施时一起迁移，尚未改远端。
- UI分支名经env作为数据传入shell，清查`${{ }}`在脚本中的不可信插值；不把只读token当成无注入风险。依据：[GitHub脚本注入防护](https://docs.github.com/en/actions/concepts/security/script-injections)。
- G03/P6.0：将历史审计安全流与main/PR持续扫描分开；扫描绑定实际revision与工具。检查不可达模块提示和可达漏洞，失败/不完整不得伪绿。
- 固定五仓SHA、utils版本、API/schema与迁移版本的组合清单；PR声明companion revision，缺失明确失败或明确兼容策略，不静默依赖任意最新main。UI codegen新鲜度与实际消费范围分别验证。
- PR先跑廉价检查和关键合同；完整acceptance/E2E在隔离组合上作为合入/发布所需检查或受控候选检查。先量耗时与flaky，再决定触发频率；每周至少一轮完整组合和漏洞复核，每月固定依赖窗口。

仓库保护、CI权限和服务端规则必须检查实际设置，不能由YAML存在推断生效。必要证据包含准确head、未通过反例、失败尝试、跳过与重试情况。

## 4. mock、测试与质量度量

大量合成mock是开发/演示/异常覆盖的长期能力。UI可优先复用Playwright请求拦截，是否引MSW由收益与维护成本决定；外部Provider、MCP、时钟、HR/CMDB/SOC/知识/Agent均可有确定性实现。各模式显式开关，界面和结果标来源，生产错误不能静默回退成mock成功。

验证分三层：mock场景验证业务/UI行为；契约验证Schema、错误和状态语义；真实提供方验证认证、授权、时延/限流及实际效果。缺少提供方环境不阻塞mock开发，不关闭真实待验；不要求所有测试联网或消费模型费用。[Playwright官方mock](https://playwright.dev/docs/mock)可作为现有工具内的轻量实现。

G04/P6.1先建立风险—测试对应表：鉴权拒绝/可见集一致、事务回滚、并发转换、重复与迟到、计划时隙、配置往返、对象归属、跨仓结果语义、撤权及恢复。高风险改动须有能抓住历史错误的回归；不堆实现镜像测试。

覆盖率分开报告默认tag单测、integration、UI逻辑/组件与E2E旅程。历史20.3%仅默认主仓单测口径；不混分母、不先设全仓80%。新改高风险模块先设否定路径和差异覆盖，基线实测后再定合理阈值。

首批fuzz评估签名解析/规范化、表达式/Schema/流程配置、AL导入与ID、TR参数/cron；性质包括不panic、篡改拒绝、往返不变和非法输入无写效果。PR跑语料和短预算，定时跑较长预算，固化失败样本。性能基线明确数据规模、P95、连接/内存/积压恢复，基准不由工具入口存在来证明。[Go fuzz](https://go.dev/doc/security/fuzz/)、[漏洞治理](https://go.dev/doc/security/vuln/)为一手依据。

U07同时排视觉样例、DOM交互、基础键盘与对比度；关键真实栈仍验证L1/L2/L3、迁移、存储和跨服务链路。视觉基线不能以“有合规诉求才做”无限挂账。

## 5. 供应链、发布与运维

G07A/P6.0先升级受支持工具链/Node与基础镜像，G07B/P6.1交PG/Redis等候选组合与恢复演练，取消公司旧版本对齐，见[版本现代化](dependency-modernization.md)。G05/P7补持续受控依赖更新PR、SBOM/制品来源、固定镜像/运行制品、最小CI权限和发版兼容矩阵；保留已有秘密扫描，补依赖告警，不自动合并升级。外部脚本/skill也要版本、来源、依赖锁和批准，运行期不任意下载执行。

迁移up/down成对、编号双核和B案回滚耦合继续有效。配置晋级D05与DB灾备分别验收；恢复前提、归档真实目的地、HTTPS/cookie/CORS、容量与HA按E09核实际部署需求，不能拿开发默认值证明生产就绪。这里不涉及模型部署。

执行结果、日志、原始快照、运行数据和不可变证据按类别制定保留/预算。当前永久运行记录约定不得被新默认值覆盖。连接秘密只引用既有凭据设施，不造新的通用密钥产品；params、日志、模型输入输出与审计分别做最小化和脱敏。

## 6. 目录与新仓一致性

当前五仓分类已较完整，按[文档维护约定](../documentation.md)继续各仓维护docs；不建立空目录。目标是职责一致和检查可重复，不要求Go服务、UI和库物理同构。

| 规格 | 必须有实际职责的内容 | 不强制 |
|---|---|---|
| 所有仓 | README、协作入口、工具链/依赖锁、检查入口、文档入口、忽略规则、CI、所有权/发布说明 | 空ADR/空阶段/空部署目录 |
| Go服务 | cmd入口、internal领域/机制边界、实际配置与迁移/测试、部署和恢复说明 | 为凑层级建立无用interface或空pkg |
| 公共Go库 | 包契约、版本与兼容、最小依赖、单测/fuzz与消费者验证 | 业务service/repository/迁移目录 |
| UI | 路由/页面/组件/请求/状态/样式token边界、契约生成、mock/视觉/E2E | 更换框架或复制多个同义组件层 |

G06/P6.1交付一个轻量模板及版本清单：提交策略等机械公共文件以一个维护源和摘要同步，生成差异PR；规范正文以主仓SSOT引用，不复制整篇。各仓保留语言适配与必要例外登记，CI检查版本漂移、链接、生成物和关键依赖方向。初期可由脚本同步或固定revision reusable workflow实现；不为此立刻改monorepo或新建治理服务。

新领域按职责小步归位；工单领域现有隔离可复用，IAM扁平文件不是必须先重排的缺陷。跨域只能调用明确用例/查询端口，不能为目录美观先大量搬文件。新增仓库先写独立交付理由和数据/协议边界，模型/MCP/RAG名词本身不是建仓理由。

## 7. 验收与未决

各包在总账规定窗口交付具体反例和收据；五仓组合、hooks实际安装、required checks生效、真实提供方验证、故障恢复分别验。自动化只能证明已编码的约定；设计审查、权限与产品任务仍需实质评审。

尚需实施前确认的技术选项：组合清单格式、完整门禁触发频率、UI mock实现、测试阈值、产物签名与发布方式。每项归G02–G06相应开工窗口，默认优先现有工具的最小扩展，不新增整个平台。
