# AI查询、确认建单与有界运行合同

日期：2026-11-11。状态：设计候选，未实现。补充[AI总纲](ai-capabilities.md)，服务于A01/A02早期实施，并为A03–A07提供共同边界。后期SDK、协议传输和真实提供方仍在各包开工前冻结，本文不冒充完整Agent产品详设。

## 1. 最早的两个可交付场景

**A01受权查询**：当前登录者提出“本周我负责的高风险工单”，模型只能选择已登记的Query及schema内参数；服务端校验后调用现有受权用例，返回行/聚合与可验证引用。查询不需要先建完整Agent或MCP。模型不生成SQL，不使用全局管理员服务账号读完后再靠提示词过滤。

**A02确认建单**：用户描述需求→生成结构化草稿→服务端校验类型/字段/目标/授权并预览→用户确认精确计划→一次业务提交。首期仅当前用户交互，不产生长期grant、不后台自主派生任务；提交仍走工单Service，可靠后继交给R01。一段自然语言不能直接成为后台定时授权。

平台特有的领域Agent是后续A05–A07：复用上述工具和既有模型，持有有限步骤、检查点、预算和人工确认，不增加另一套风险/工单状态。外部企业Agent仍可调用同一受权工具；其内部提示与运行图由提供方维护，不同步复制进本平台。

## 2. Provider连接与数据区

| 对象 | 最小字段 | 不得混入 |
|---|---|---|
| ModelConnection | connection_id、alias、provider_kind、endpoint_ref、secret_ref、data_zone、模型ID、capability set、timeout/并发/配额、config_revision | GPU/部署/训练配置、明文密钥 |
| ScenarioDefinition | scene_id、不可变版本、可信模板摘要、输入/输出schema、Query/Action允许集、模型能力、预算/确认政策 | 任意用户上传的可执行脚本 |
| ToolDefinition | capability_id、合同版本、operation_id、参数schema、read/write、资源范围、幂等/效果查询能力、结果schema | 在model参数里自报角色/权限 |
| Invocation | invocation_id、场景版本、actor/delegation、数据区、资源范围、计划hash、状态、结果引用、预算事实、trace | 可复用的浏览器token、无期限管理员权限 |

同一个生成端口可由企业模型网关/原生API/兼容API adapter实现。首期只依赖生成与结构化输出；不支持工具调用则仅允许固定只读摘要，不能通过解析自由文本放开任意工具。内网data_zone强制只路由内部服务，fallback必须在同一数据区与能力要求内；连接故障不能转发外部模型求成功。

策略先裁剪再出站：只传完成当前受权场景所需的最小字段，附件/知识原文按来源ACL另取。模型输出、工具返回和检索文档都作为不可信输入；其中的“请忽略规则/执行命令”不会改变工具允许集或授权。日志默认记录模板/配置摘要、用量与受权结果引用，不收集完整敏感prompt；真实usage缺失须标estimated/unknown。

## 3. 调用层共同协议

以下为逻辑operation候选，尚非已注册路由。实施时遵GET/POST、公用错误信封和目录B案，维持现有业务REST兼容；MCP adapter在其协议专用入口映射同一用例，不把JSON-RPC强装进业务信封。

| operation | 输入 | 结果与授权 |
|---|---|---|
| `ai.query.preview` | 场景/问题、可选上下文资源引用 | 允许的Query计划、补充问题或拒绝；不读未授权上下文 |
| `ai.query.execute` | 计划引用/参数、当前主体 | 执行前实时鉴权，结果行/聚合/引用与取数时间；查询计划不赋权 |
| `ai.ticket.draft` | 需求、目标类型/组织候选 | 结构化字段草稿、缺失/冲突、来源；不建单 |
| `ai.ticket.preview` | 草稿修订、目标、definition/schema版本 | 确定性校验，plan_id/hash/expiry和授权范围；必要业务澄清 |
| `ai.ticket.confirm` | plan_id/hash、幂等key、expected_revision | 当前用户复验后创建；成功业务receipt，失败原因/需重新预览 |
| `invocation.get/result/cancel` | invocation引用、当前主体 | 受权状态/结果；取消请求与效果已取消分别表达 |
| `ai.schedule.preview/confirm` | 结构化schedule、动作/目标、批准政策 | 仅A04/I02/I03后开放，持续grant与TR定义/时隙receipt；非A02功能 |

通用关联字段用request_id/trace_id、invocation_id、plan_id、operation_id、TR task/execution/delivery ID各自职责，不拿一次HTTP request_id当跨重试幂等身份。请求写侧严格schema；不能从任意JSON键映射业务字段。API版本、场景发布版本、工单definition版本、实例revision和授权epoch分别保存。

Query catalog首期只列工单列表/详情/允许聚合与已就绪风险查询，响应按原资源权限过滤；capability说明应明确排序/时区/分页/最大行数/是否完整。跨页合计必须用受权聚合接口或明确“当前页”，不能让模型把前20行当总体。无访问权与来源不可用分别返回，无法确认的数据回答“不足”，不得给出假造计数。

## 4. 精确确认与并发

预览保存规范化命令、主体、资源/目标集合、类型发布版本、字段schema/参数摘要、配置版本、过期时刻和hash。确认页显示将创建的工单、组织/责任范围、关键字段、后继效果与来源，不仅展示一段模型解释。修改目标、参数、definition、关联资源或效果会使旧批准失效。

确认请求的授权必须在副作用前再次判断；用户刚看到preview不等于以后持续有权。当前权限撤销或关键依赖变更返回需重新预览，不自动“修正”目标继续执行。模型改写计划后也必须重新确认。前端按钮禁用只是体验，服务端按稳定幂等key与command hash建唯一receipt：同key同命令返回原结果，同key不同命令冲突；响应丢失先查receipt，不能让模型生成新key重复建单。

A02可直接以用户会话调用同一工单用例，token仅在服务器可信链路内使用，不交给模型/外部Agent。本页AI外部Agent代用户、后台持续委托和无人值守写必须使用I02短期委托/grant；X01同步身份接缝只承载已批准的最小交互能力，不授长期grant。授权声明限定subject、audience、operation/resource、scope、期限、批准政策与撤销。无grant时不靠“由服务调用”当作管理员操作。

**双模式授权来源**按[UAA合同](uaa-governance-integration.md)统一处理。独立模式使用本地IAM，不检查不存在的UAA状态；企业模式的纳管能力还须检查本地受管授权投影及其已批准的新鲜度/故障政策。MCP AS令牌、scope、持续grant、Agent配置或旧确认仍有效，都不能代替当前有效业务授权。投影的撤销/范围收紧复用C04守卫，不能只更新同步表而绕开本地授权失效；不要求每个工具请求同步远程查询UAA。

默认首发所有业务写均逐次精确确认。批量/高风险动作、无人值守和预算上限的业务取舍在A04/A07开工前给出样例再决；当前用户已经提出AI方向不等于已经授权AI自动执行任意动作。

### 4.1 跨入口的合成撤权与新鲜度反例

合成企业用户甲只有一条中央认可的工单读取授权；09:00已取得有效MCP AS令牌、相应scope及一个持续查询grant，09:05这条授权在本地投影中被撤销。预期：MCP `tools/list`不再列该能力，`tools/call`拒绝；Agent下一次取数停止；尚未开始的计划发生次hold；私有扩展的同一用户调用也被拒绝。token/grant未过期不能继续使用旧角色，草稿/结果引用按当前权限读取，已提交业务receipt不因此重做或伪装撤销。

同一用例再把“明确撤权”替换为“纳管投影超过已批准新鲜度阈值”，样例政策固定为暂停受管访问，仍应出现上述拒绝/hold；具体生产阈值和允许的有限降级须按UAA合同批准，不由样例决定。若另有当前有效且中央认可的独立授权链，按完整来源重算，不把撤一条绑定误做全局deny。最后用独立模式本地账号重跑：无UAA配置/投影不构成失败，但本地角色撤销、MCP自身认证及grant约束仍正常生效。

此例由E01-UAA-P交公共投影/双模式基础证据，后续A03、A04、A05–A07及X01在各自交付时复用入口反例；不让未来完整Agent或MCP实现反向成为P6.1硬前置，也不把未执行的文档样例标为验收通过。

## 5. 状态、恢复与取消

首期状态：`created → planning → needs_input/ready_for_confirmation → executing → succeeded/failed/canceled`；外部效果未知独立为`outcome_unknown`，进入对账，不当作普通失败重跑。纯只读调用也需区分来源超时、权限拒绝与模型格式错误，错误不能写成空结果成功。

后续领域host每步先保存稳定step_id、输入摘要、场景/模型配置版本，再执行；工具效果有独立operation receipt，收到结果后存检查点。恢复时读到已完成receipt只续下一步，不重做副作用。模型输出可能不确定：已保存计划继续使用保存值；未执行模型步骤可重试但不复用旧批准；外部效果未明先query/reconcile。checkpoint只保存运行进度，不代替业务事务。

每个run只有一个推进主，TR只有一个schedule/动作重试主；外部Agent、SOAR与本地host不能同时各自重试同一动作。工具超时若可能生效，禁止模型自主再试；需先查询效果。取消只阻止尚未开始的步骤，正在执行的外部效果须实际提供方确认；界面显示“请求取消/结果待核实”，不能假绿。

技术起始预算建议：每轮Query默认最大100行、模型请求60秒/有界输出，领域run最多8步/5分钟、连续工具失败2次即停；均为可调技术候选，不是对真实提供方延迟的承诺。写工具首发保持逐次确认，预算耗尽保留进度/已有效果并转人工，不清空记录后从头跑。每用户/组织/连接的并发与用量需同设上限，防单个Agent耗尽共享连接池。

## 6. 知识、skill与界面

结构化业务状态直接查业务Query，知识API只用于已有知识服务的受权检索/引用。服务账号不能代替用户ACL；不具备逐主体检索的提供方先限已批准共享集合或受权深链。引用带source/version/observed_at，读取时复验权限/撤销；不可见引用不显示内容摘要。无引用的模型生成不能作为专业复测/接受证据。

skill首期仅受信版本库指令/资产，记录owner、摘要、兼容工具集与评测；allowed-tools不是授权。安装/启用是配置管理，执行工具仍走本合同。脚本由已有专业执行平台承载，当前计划不在主进程执行任意skill脚本或建市场。

UI将“模型连接”“外部Agent接入”“平台领域Agent/场景”区分配置，给出能力/数据区/当前状态；只选当前允许连接。运行页展示计划、待确认步骤、来源/取数时间、实际工具效果及暂停/取消入口；设备工具只允许查状态或打开受权入口，不能默认获得设备口令/会话/自动登录能力。具体交互参见UI仓施工合同与离线原型。

## 7. 验收分层和待定范围

mock黄金集至少覆盖：同义查询/必要澄清、无权资源/跨组织计数、分页不完整、无数据/不可用分离、恶意文档、schema非法、provider无tool能力、重复confirm/响应丢失、preview后撤权/改定义、陈旧计划、tool重复/unknown、预算耗尽和取消竞争。安全反例必须全通过；语义准确率/延迟阈值在A01首个合成集基线后定，不能事先编造100%正确。
