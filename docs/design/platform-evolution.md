# 平台边界与演进设计

日期：2026-11-11。状态：本轮授权的规划修订；本文描述目标合同，未实施能力仍以[控制台](../review/11-project-control.md)和[总账](../review/planning-backlog.md)为准。现状架构见[architecture](architecture.md)。

## 1. 首要目标与必须保留的前提

zhuzhao负责**数据聚合与安全全生命周期管控**：连接发现、研判结论、责任人、整改、复测、接受、应急协作和证据；专业工具负责专业的发现、分析和执行。不能把“提供统一入口”扩展为重新建设SOC、CMDB、TIP、SOAR或知识平台。

本轮必须保留的前提与明确建议：

- SOC/SIEM、SOAR、CMDB、威胁情报、企业智能体与知识平台均已有。确认的是供给类别存在，具体API、字段、权限、速率与可用测试环境仍须逐项核验。
- 大量mock接口必须保留。外部接口未具备可联调条件时，继续通过Port/Adapter、合成数据和契约测试开发；真实集成的待验只阻塞对应能力的真实放行。
- 大模型使用已有服务，通过OpenAPI/兼容接口或其它提供方协议调用；不建设模型训练、部署、GPU或推理集群。内网只允许内部模型，其他环境按数据政策配置允许的服务。
- 针对所有者提出的本平台自建智能体问题，本轮建议同时支持接入已有智能体，以及利用平台特有业务能力配置和运行领域智能体。领域Agent不扩展为通用智能体开发、知识库运营或模型平台。
- 三层授权、可追溯审计、存量兼容、专属测试账号和共享环境保护继续有效。本轮允许重审旧阶段顺序、技术预设与范围，但不借规划绕过现行代码的安全边界。

## 2. 能力供给与数据写主

每个新需求先登记其权威提供方，再决定本平台需要的最小能力。

| 能力 | 专业平台负责 | zhuzhao负责 | 本轮处置 |
|---|---|---|---|
| 发现、告警关联、检测规则、狩猎 | SOC/SIEM | 接收结论、关联来源ID、派责与跟踪、处置结论回传 | 接入；不复制分析引擎/规则中心/日志湖 |
| 资产、系统、责任人权威 | CMDB及身份目录 | 查询、稳定引用、有界快照、未解析标记及人工临时兜底 | 接入；本地薄映射不成为第二资产账本 |
| 情报评分、IOC关系与专业标签 | 威胁情报平台/SOC | 查询缓存、来源/时效、关联工单与证据 | 接入；旧本地TIP/IOC权威清单方向退出默认范围 |
| 专业安全动作与跨系统复杂编排 | EDR/防火墙/专业执行端、SOAR | 受权请求、执行投影、人工接管、失败对账 | 接入；taskrunner仅做现有平台调度和有界胶水 |
| 风险与整改、接受和复测 | 本平台领域层 | 本地生命周期、责任、关联与审计 | 有界自建；来源严重性与本地处置优先级分开 |
| 事件响应 | SOC发现与研判，专业工具处置 | 跨岗位协作、工单、时间线索引、证据与战后整理 | 协同；不建第二SOC事件分析台 |
| 模型、知识与通用智能体能力 | 既有模型/知识/Agent平台 | 连接配置、上下文、授权工具、本地领域Agent及运行证据 | 双轨；不复制模型基础设施和知识运营 |
| 报表与态势 | SOC/BI等提供专业统计 | 本地流程口径、跨域关联摘要、来源深链 | 限界；不建通用统计DSL/BI/态势产品 |
| 值班、通告、合规资料与手册 | 优先核现有责任载体/知识与消息服务；专用值班/通告/演练平台是否存在未确认 | 引用、待办和证据回执 | 先消费；不默认另造排班、发布或合规引擎 |

外部观测事实以来源为权威，本地处置事实以领域服务为权威；同步失败、字段未映射、陈旧和未知必须显式呈现。引用至少保留source、external_id、observed_at/received_at、版本或摘要、访问范围和深链。深链不携带秘密，点击后的访问仍由目标平台鉴权。来源删除/撤权、重报/乱序和本地保留要求在适配契约中定义，不能靠复制整份源数据逃避。

新增的本地兜底字段必须有来源标记、允许覆盖者与冲突策略；真实CMDB接入后保留必要人工处置上下文，禁止将人工建议值回写为资产权威。

## 3. 五仓与领域边界

| 边界 | 当前职责与应保留资产 | 目标接口与禁止混入 |
|---|---|---|
| zhuzhao | IAM、三层授权、工单、消息、网关、对象资源与情报代理；风险为计划 | 领域用例拥有数据/事务/授权；AI、MCP和适配器调用用例，不直写领域表 |
| zhuzhao-ui | 本平台受权事实的呈现、配置、任务交互 | 统一主仓入口；不保管提供方秘密、不自行访问内部专业服务 |
| taskrunner | DB-first受理、任务/attempt执行、调度与重试 | 执行终态与路由权威；不拥有工单/风险生命周期，不成为SOAR |
| activelist | PostgreSQL动态类型与清单、导入导出 | 只存合适的本地业务清单/映射；不持有IAM决策、资产权威、风险正本或证据正本 |
| utils | 签名、错误、日志与其它纯机制 | 可版本化协议机制；不下沉Action业务定义、领域权限、模型政策和运行状态 |

主仓模块还应逐一明确：认证负责凭证有效性；用户/组织/角色维护身份与授权事实；菜单是导航与路由目录而非业务全部权限；工单拥有状态与逐项操作不变量；消息拥有投递与偏好而不替代业务状态；对象服务拥有用途/归属/引用生命周期；情报代理不创造专业评分；风险、AI与集成分别持有未来的本地业务、调用策略与提供方映射。上述边界见各模块当前说明和[AI设计](ai-capabilities.md)，不把未来目录当成已经实现。

## 4. 流程统一的范围

统一的是稳定能力引用、版本、输入输出、身份委托、批准、审计、关联ID和运行视图；三类状态各有权威：

- 工单FSM管理本地业务状态、转换采集和不变量。
- taskrunner管理一次任务受理、attempt、执行结果及计划时隙。
- 智能体管理目标、模型决策、工具建议、确认和有界运行；外部Agent与SOAR的内部状态由提供方掌握。

一条链只能有一个编排主、一个动作重试主；结果投递失败不重新执行动作。共用画布只在交互任务确实相同时复用，不强求一张万能图，也不以画布统一为由合并执行内核。

优先消费现有SOAR/Agent/工作流服务。需要本地持久的是不可丢的业务意图、人工批准、等待回执与恢复索引；可以用有限状态/待办实现时不建通用DAG。P7完成供给比较，P9处理E08：建议以更小方案替代“必须自研六节点通用引擎、模板市场、Phase10全量迁回退役SOAR”的旧实现安排，保留动作/脚本/批准/等待/条件/并行等效行为与模板复用；拟取消业务项须列价值/影响供审阅；只有列出既有平台不能满足的本地场景、成本和恢复证据后，才为明确缺口另立有限实施包。

## 5. 可靠性先于自动化承诺

当前`domainevent.HookRegistry`是进程内尽力派发；`ticket_events`业务留痕不是可靠投递回执。taskrunner的DB-first与execution栅栏也不证明跨仓业务完成。

C03先核清受理、执行、响应和记账，D12再接结果与白名单映射；R01为不可丢消费者补事务内意图或可证明的重建对账。稳定event_id、execution、attempt、delivery、时隙键各司其职。权限撤销和审批输入漂移在副作用前复验；远端效果未知进入对账，不能自动重做不可幂等动作。

完整事件投递能力按承诺前置，不再固定等到Phase9。重试预算、毒事件、确认、迟到结果、回放、人工补偿与告警有固定出口；无恢复证据的自动化仅允许低风险观察或人工确认。现有永久运行记录/日志与其它保留类别不悄悄互相覆盖，实施前按资料类别确认归档和累计容量。

## 6. 可插拔与服务拆分

先在模块化单体内建立Port/Adapter、显式装配、Schema/version、配置与生命周期边界。新增仓库应对应独立交付/部署/权限或清晰公共库职责；不为AI/MCP/RAG每个名词单独建仓。

每个能力包应声明：输入输出与兼容版本、资源/权限、必要配置和secret_ref、超时/限流/预算、启动检查、健康、停用/在途政策、失败恢复、观测和数据清理。核心领域仍按编译期装配和配置启停；内网私有模块采用进程外稳定合同、受信声明注册与通用导航/网关接缝，详见[扩展兼容](extension-compatibility.md)与[内网适配](intranet-adapter-migration.md)。X01/X02前置P6.1而非等待P9拆分；不引Go动态plugin或通用插件商店。

拆服务只在独立发布、故障隔离、扩缩容、安全边界或维护责任的证据成立时评估。先隔离数据写主、消除跨域直查/直写，再设计远程协议、幂等、观测、迁移和回退；不把IAM提取、K8s、Kafka或CQRS预设为阶段必达。E07在P8出口取证、P9定案；不拆也必须有结论和下一次架构复核窗口。
