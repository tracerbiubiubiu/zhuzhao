# 生态一致性合同 — 统一语义、允许差异与渐进验证

日期：2026-11-13。状态：**设计落档，新增机制待实施**。适用于五仓与后续公共模块、私有connector；不启动开发、不改变既有发布状态。工程规则权威见[standards](../standards.md)，执行接缝见[能力调用合同](capability-invocation-contract.md)，唯一排期、依赖、投入与状态见[规划总账](../review/planning-backlog.md)。本页不是第二份规范全集或第二张排期表。

## 1. 目标与统一边界

用户从页面、工单节点、计划、活动列表触发器、Agent、MCP或私有扩展调用同一能力时，应得到一致的输入校验、授权范围、幂等含义、成功定义、结果与错误语义。各入口适配后进入同一受控领域用例；新增入口不能复制一份权限判断或绕过业务校验。对外接口指平台与扩展的产品能力合同，不要求把repository、内部辅助函数、秘密或管理绕过全部暴露。

统一的是语义、稳定接缝及可以复验的验收标准。Go服务、公共库、Vue页面、专业平台adapter不需要相同目录树、相同排版或同一个状态机。事件与动作可以关联，不能因数据打通就共享数据库、任意递归回调或允许无权限的自由调用。能力按需要选择进程内Port、受权HTTP或可靠命令/事件投递，不强迫每次本地调用绕网络，也不先建一个可调用任意代码的通用`invoke`入口。

保留大量合成mock、独立完整IAM与企业adapter双模式、现有Vue/Element Plus、专业平台供给边界。mock与真实提供方遵相同公共合同，来源必须可辨；真实失败不能伪装为mock成功。内部私有域代码、厂商字段、企业秘密与公共核心隔离，不因“统一”复制到开源仓。

## 3. 标识、消息与调用的最小共同词表

| 标识 | 含义与稳定范围 | 禁止混用 |
|---|---|---|
| `capability_id` + `contract_version` | 静态能力与其合同版本；决定输入/输出、权限及效果语义 | 不能当某次执行的去重键；能力版本不等于资源revision或计划版本 |
| OpenAPI `operationId` | API定义元数据，在HTTP适配层关联能力；是否存在一对多路由由目录明确 | 不沿用为动态业务`operation_id`；不因相似拼写认为同一字段 |
| `operation_id` | 一次动态业务意图/效果的幂等身份；重试和恢复保持，参数digest与目标范围须匹配 | 不是静态能力名、HTTP请求ID或每轮投递的新UUID；查询无需伪造写效果 |
| `invocation_id` | 一次逻辑能力调用的观察身份；同一调用的HTTP重试/重投不能因此变成新的逻辑调用 | 不是一次HTTP attempt；与业务效果不强制全域一对一，组合动作的子operation需显式关联 |
| `request_id` / `delivery_id` | 分别定位一次传输请求和一次消息投递尝试；关联到逻辑调用与业务操作 | 不用于跨重试业务去重，不替代任务execution或cron occurrence身份 |
| `event_id` / 因果关联 | 稳定已发生事实及其来源、关联与因果链；可靠投递中重复送达保留原事实身份 | 新业务事实不能复用旧event_id；本地无稳定ID的现状不冒称可跨仓重放 |

这是目标词表，不是本批已上线字段。已有调用、API别名与manifest须在消费者清点后显式迁移或映射；不能静默改线上的字段含义。`schema_version`、能力`contract_version`、API主版本、消息协议版本、业务定义revision、实例revision、授权epoch各管自己的兼容边界，不用一个`version`承载所有语义。

统一消息是按kind选取最小字段profile：共同定义字段名、归因、版本和错误/结果含义，领域payload继续由发布者的schema拥有；不要求本地Hook、HTTP响应、MCP消息和外部专业平台原报文逐字相同。进程内`DomainEvent.ActorID`等既有类型可保留；跨边界时由adapter映射为约定的公开表示。外部原始数据先规范化、标来源/观测时刻，再生成可订阅的领域变化事实；不是将任意JSON透传成有执行权限的消息。

## 4. 同一能力跨入口的验收切片

**2026-11-13明确约束**：接口、内部、手动、工单、计划、数据事件、MCP/Agent调用同一能力时，必须汇入同一登记应用层执行入口和领域实现；入口adapter只处理协议与可信上下文，不复制业务逻辑或绕过授权。同步与异步分阶段、同事务窄Port及跨入口反例以[调用合同§2.1–2.3](capability-invocation-contract.md#21-同一能力只有一套受控执行路径)为准；统一格式不足以验收，仍须核实际执行路径及效果。当前为设计约束，未改造现有调用代码。

每个新增核心或插件能力先列出所属领域、数据所有者、可用入口、输入/输出、读写性质、资源授权、幂等/效果查询、并发版本、同步/异步、取消/恢复、限额、来源和UI归属。没有实际用户或调用方的入口可以明确为不适用；不能靠“以后统一平台”留下无负责人占位。

首批按[能力调用合同](capability-invocation-contract.md)选薄闭环验证工单节点→任务→结果展示、计划→活动数据更新、活动数据变化→受权动作。公共接缝复用，但每条链的业务效果、触发去重、结果归属和前端状态分别验收；不能因为第一条成功就宣布全部数据已打通。新增触发、回写与跨入口覆盖若超出既有工作包，必须显式进入[增量范围册](../review/capability-interconnect-supplement.json)及总账的估算/依赖，不能吞入G06、R01或U06原估算。

入口一致性反例至少包含：未授权入口拒绝且无写效果、重复提交一次效果、同幂等键不同参数拒绝、响应丢失可查询、源事务后宕机可恢复、双实例不会重复拥有同一执行、撤权/旧版本/迟到结果不覆盖当前数据。异步能力还需验证有界队列/并发、429/退避、积压/死信、取消边界及人工处置入口；具体阈值由用例/实际容量决定，不在此承诺全域统一数字。

前端与能力同批交付最小可用的按钮/表单、权限反馈、运行/未知效果/失败状态、关联结果与恢复入口。可复用现有页面或受权深链，不为每个能力先建新整页；已接收不提示已完成，业务成功但读刷新失败不鼓励再次执行。公共视觉增强可以渐进，业务成功含义不能靠后续美化补齐。

## 5. 证据、例外与渐进收口

1. **先声明适用范围。** PR列适用profile、影响合同/入口、旧消费者和所用SSOT。无实际影响的全仓统一检查不额外添加；新规则先用具体反例说明收益。
2. **再交机械证据。** 使用实际候选组合检查格式、解析、schema/生成物、依赖方向、稳定标识及公共bundle漂移；检查只能证明其编码的范围。例外记录领域理由、影响消费者、负责人、复核窗口与退出/保留结论，不用永久“后续看情况”挂账。
3. **再交真实旅程与故障证据。** mock长期保留，真实权限/事务/副作用与Vue实际渲染分别验；记录失败尝试和未覆盖，不用合同或原型存在抵消缺失验证。
4. **按阶段扩展。** P6.0先词表、候选组合、事务/可靠性前置；P6.1以G06和U02/U07建立最小profile/页面样板；P6.3以U03–U06迁移现有页，同时新增业务随批接UI；P7以I01/R07形成受权发现、HTTP/MCP等标准消费者与兼容矩阵；P8/P9按已验证需求扩展长流程和专业平台协同。精确窗口与本次新增工作量以总账为准，未实现项不能只靠进入阶段视为完成。

截至本设计，G06的版本化bundle/lock、EditorConfig与UI独立formatter检查仍待实施；现有token不等于推荐token已推广，六类离线原型不等于Vue样板或27页真实迁移。新能力目录、统一调用接缝、R01可靠交接与MCP封装也不能由本页推断已具备。实施应优先已有组件和已确认场景，不新造设计系统、规范服务、通用工作流产品或专业安全平台。
