# 能力互通、统一调用与渐进演进合同

日期：2026-11-13。状态：**最终愿景及有界详设候选；未实现产品共同runtime**。[三链详设](capability-interconnect-detail.md)已有首批准确DTO/Schema、持久状态和参考验证；未来新增操作、产品DDL、真实容量及提供方参数仍逐包冻结。所有者继续补充场景，T0未启动。[增量范围册](../review/capability-interconnect-supplement.json)区分原计划承接与新增范围，CE净估已进入现行总账，不把早期骨架状态沿用为当前全局结论。

## 1. 最终目标与产品范围

所有可复用的产品业务及管理能力，不论核心还是可插拔模块，都应有受权、可描述、可版本化的外部接口，并通过同一逻辑调用合同组合使用。页面、工单节点、手动任务、定时任务、变更订阅、外部系统和MCP/Agent只是入口不同；同一业务效果由同一领域用例及写主提交，不各做一套实现。

“对外”指模块/仓库外的受信消费者能够按合同调用，不意味着开放公网或默认授权。“自由调用”指可发现、可配置组合、可查询结果；当前主体、数据范围、参数、版本、幂等与执行预算仍需成立。受权能力目录不因模型请求就暴露全部管理员功能。

范围覆盖用户/组织/授权、工单/风险、任务定义/运行/结果、活动列表Schema和数据、附件控制、通知、受权查询/报表、连接器及已接入的专业能力。内部工具函数、任意SQL、数据库直连和离线恢复入口不强行变成业务API；确需特殊通道时登记理由、维护方和调用限制，不用“internal”标签隐藏本应复用的产品功能。

最终覆盖率是愿景，不要求本期一次把全部存量端点迁移。每项能力按“盘点→合同/写主明确→受权API可用→跨入口同例→可组合→按需MCP发布”推进；声明元数据不等于实现完成。

## 2. 一个逻辑通道，三种执行方式

共同通道由能力描述、调用门面、执行适配和结果/事件合同组成，不要求所有调用通过同一个物理进程、HTTP端点、数据库或队列。

| 执行方式 | 适用场景 | 必须保留 |
|---|---|---|
| 进程内领域Port | 同库短事务、受权查询、必需同时成立的业务状态变化 | handler→service→repository、领域授权、事务/锁序；不为了统一而HTTP绕回自己 |
| 受控跨服务HTTP | 核心与私有扩展/AL等独立写主、已有专业平台 | 精确能力/路由映射、服务身份和业务主体分开、超时/幂等/完成回执；不共享数据库 |
| 可靠异步执行 | 长耗时、外部副作用、定时/延迟任务、不可丢后继 | C03/R01意图/receipt、TR调度、恢复/对账/取消；受理成功与效果完成不同 |

现有REST端点继续保留；新增或本批触及的能力，其REST及其他入口必须映射到相同能力描述和受控领域执行路径，存量按清单分批接入。不先改成万能`/invoke`，也不把所有CRUD排成后台任务。统一调用门面是授权、schema、版本、限流和结果关联的共同接缝，不掌管所有领域事务。核心与插件遵同一准入规则，供应商差异留adapter。

平台长期目录覆盖Query、Command、Action和订阅管理；它描述“能做什么”。TR负责何时执行已获准任务，领域属主负责怎么执行及事实提交，结果投影负责在哪里展示。业务工作流、任务执行和Agent循环共用能力与证据，不强行合成同一个状态机或通用DAG引擎。

### 2.1 同一能力只有一套受控执行路径

**架构约束：同一能力及其合同版本，所有触发入口必须汇入登记的共同应用层执行入口和领域实现。** 不能只统一字段/名字，再让HTTP handler、手动按钮、工单Action、cron或MCP adapter分别实现同一业务动作。版本化兼容adapter可规范化旧输入；确需并存的版本实现须在目录登记语义、消费者和退出/保留政策，不能伪装成同一合同的入口特例。

同一受控用例可按登记的provider/策略选择不同adapter或兼容实现，但须满足同一合同语义和验收，不能因触发入口不同而换一套业务规则。受理时固定能力/合同版本和受控路由；排队、恢复或升级不得静默改用最新版，未知/不兼容版本明确拒绝。不同能力及不兼容主版本可有各自领域用例，不要求共用一个函数。

入口adapter负责协议解析、认证和可信上下文构造、参数规范化及响应映射；业务参数/版本校验、能力权限和当前资源/动作授权、幂等/并发、适用预算、执行记录、结果和错误语义在共同路径执行。HTTP路由L1继续保留，内部路径提供等价的能力资格校验并复用领域L2/L3，不依赖“经过网页中间件”这个假设。不同入口可使用不同主体或受限grant，授权范围以各自可信上下文计算；共用路径不意味着权限或结果可见范围自动相同。

例如AL更新能力：手动页面经API adapter、工单节点经内部Action adapter、计划/数据变化经可靠命令、MCP经协议adapter，最终调用同一登记能力；该能力再调用AL公开数据API，由AL领域服务提交自身数据。任何入口都不得直写repository/数据库，不能复制“简化版”校验、默认管理员身份或设置可由调用方控制的`skip_auth`。领域实现内部正常调用其repository/纯辅助函数；这些内部步骤不要求逐个公开或再次进入门面。

### 2.2 同步、异步与事务中的调用

- **同步本地调用**直接进入共同应用层门面/受控用例，无需HTTP回环。必需同事务完成的组合操作由明确事务所有者通过窄Port协调，共用同一事务和可信上下文，保持既有锁序；不重新排队，不在持锁时调用外部网络，也不重复获取同一不可重入锁。
- **异步调用**将准入与执行分成两个明确阶段。提交时验证并持久绑定能力/合同版本、目标、规范化参数、可信主体/委托、稳定操作身份及预算；worker取得执行资格后进入同一能力的执行阶段，按当前授权、资源范围、版本/状态/revision、期限、claim/fence和效果凭证重新核验，再执行登记领域实现。提交获准不能代替执行获准；已提交效果按原receipt处理，返回旧结果仍复验当前读取权限。执行阶段不能回到“提交新任务”入口造成无限排队；重投保留原操作/逻辑调用身份，结果查询或投递不重新执行业务。
- **预算与记录**按一次操作的阶段区分预留、实际开始、执行与投递；不能因入口转换重置额度，也不能在两层重复收取同一预算。跨服务各自负责其本地配额和数据事务，共享预算以登记的预算属主为准，不承诺一笔分布式事务。来源入口、真实操作者、执行主体和父调用继续可追溯，不用统一身份抹掉归因。

同事务复用已有上下文不另开可独立提交的事务、不对同一次逻辑调用重复入口限流；目标资源授权与领域不变量仍在适当事务位置复验。新增独立子能力须声明组合/预算，不在持锁时等待远端准入。逻辑调用计数、实际attempt、provider开始速率及inflight分别核算；外部重试或异步真正开始仍取得该阶段有效额度，不能把“不重复计取”解释成无限重试或永久复用旧许可。

“唯一执行路径”是每项能力的职责约束，可以由门面、公共策略组件和领域用例组合完成；不要求一个巨型函数/全局服务，更不把所有领域状态机合并。准确接口签名及同步/异步阶段的字段在CE02编码前冻结，本轮不指定新wire协议。

### 2.3 跨入口验收及渐进范围

CE01列能力/版本与实际支持的入口、唯一受控执行入口、领域实现和legacy例外；CE02交最小公共接线，后续每项能力随批扩展。新入口不得新增旁路；已有存量按实际消费清单迁移，不要求本期全量重写。

验收同时检查调用归属和实际业务效果：在同一可信主体/目标/规范化输入下，经HTTP、内部、工单或手动入口得到一致的业务校验与效果语义；不同主体仍执行其各自权限。反例覆盖内部入口无权拒绝且零写入、跨入口重投同一合法操作仅一次效果、同号异参拒绝、排队后撤权/改状态被挡、并发CAS冲突、限额不因换入口重置、结果丢失可查询且不重做动作、同事务失败无半套提交、预算不重复消费、队列恢复不漂移版本。还须检查adapter没有旁路repository或重复业务实现；仅字段schema一致、mock返回一样或静态import通过，不能证明已经走同一路径。

## 3. 先消除同名异义

| 标识 | 目标含义 | 不能代替 |
|---|---|---|
| `capability_id` + `contract_version` | 一个可调用业务操作及合同版本的静态身份 | 某次执行或幂等键 |
| OpenAPI `operationId` | HTTP接口定义元数据，映射到能力 | 动态业务效果ID |
| `operation_id` | 一次业务意图/效果的跨重试幂等身份；同键不同命令拒绝 | 能力名称、HTTP请求号 |
| `invocation_id` | 一次逻辑能力调用的运行关联；同调用重投保持，子调用有各自ID及父引用 | 单次网络attempt或授权凭据 |
| `request_id` / `trace_id` | 一次传输请求及追踪关联 | 可跨重试去重的业务身份 |
| `event_id` + `producer/source` | 已提交事实的稳定身份，重放不换号 | 命令授权或任务发生次 |
| `delivery_id`、TR task/execution/occurrence | 投递、执行和计划时隙各自身份，沿C03/I03细化 | 一套混用的“任务ID” |

例如文档中的`risk.dispatch.v1`若表示能力定义，应映射到能力键/合同版本；不得拿该常量充当所有派单的幂等身份。已有`action_id`和既有wire字段先登记别名、版本及迁移映射，不能全局替换字符串、改历史数据或破坏签名。[OpenAPI对operationId的定义](https://spec.openapis.org/oas/v3.1.1.html#operation-object)支持其作为接口定义标识；本项目仍需区分动态效果身份。

## 4. 能力描述与消息骨架

近期先冻结最小可表达合同，再在实施窗口写准确schema，不提前假称全部定义完毕：

- 能力归属：静态身份、维护方/写主、可用版本、普通API与可选MCP映射、同步/异步支持、读写及副作用分类。
- 输入输出：参数schema及限制、目标资源/字段允许集、结果schema/摘要/工件引用、可查询receipt和取消/对账方式。
- 安全：用户/服务/受限委托的允许入口、当前权限及数据范围、审批/持续grant、出站目标和凭据引用；配置不授执行权。
- 运行：幂等/版本冲突、deadline、重试分类、并发/队列预算、事件来源/结果及恢复责任。

| 消息种类 | 含义 | 完成/确认边界 |
|---|---|---|
| 执行请求command | 要求能力属主执行已获准命令 | 持久受理、执行中、效果已确认分别返回；不是任意body即授权 |
| 事实event | 数据属主已提交的变化 | 收件/投递ACK不等于消费者业务效果成功；事实不能直接当命令执行 |
| 结果result/receipt | 对某操作效果、状态和结果引用的确认 | 来源认证、输入/版本绑定、重复/迟到检查后用于展示或受权投影 |
| 通知notification | 向用户说明事件或待办 | 渠道投递、已读与业务完成分别记录，不作为源事实写主 |

公共元数据按类型复用协议/schema版本、消息ID、能力或事件类型、主体归因、操作/调用/关联/因果ID、时间和结果引用；领域payload继续由属主管理。HTTP沿现有`code/message/data/request_id`，事件不套一个“HTTP成功码”冒充事实，通知正文也不等于执行命令。不同消息版本和存量协议由adapter映射，重放保留事实/操作身份，不传用户长期token、秘密或任意原始对象。

跨系统事件可映射[CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)的`source/id/type/specversion`等元数据；这是互操作参考，不要求首期安装新broker或全量改写现有payload。统一的是语义和可检查映射，不是所有消息字节完全相同。

## 5. 三条代表链分别验收

### 链A：工单节点配置任务，结果在工单展示

发布的节点配置绑定能力/版本、受权参数映射和结果展示/写回策略；转换提交时对不可丢执行落稳定意图。任务通过共同门面提交TR，保存工单与operation/task/发生次关联。执行属主提交效果和receipt，结果投递只更新该关联的状态/结果投影；重复结果不重做动作。

工单展示有限摘要、状态及受权结果引用。展示结果、回写字段、推进状态是三种不同能力：写回需要字段白名单、原定义/实例版本、当前权限和状态条件，不能收到任意JSON就写票。失败、unknown、取消请求和投递失败分别可解释；结果展示失败不重新执行远端副作用。

**当前**：`internal/service/ticket/actions_builtin.go`的`SpawnTaskAction.Execute`已提交任务，但未保留完整运行/结果回贴；`internal/service/jobs_callback.go`的`JobsCallbackService.Execute`是执行请求入口。C03/R01/D12已有承接，目标未交付。先交该纵切，不要求D12等待依赖D12的完整I01，避免环。

### 链B：定时任务受权更新活动列表

计划绑定获准能力、目标list/type、允许字段、输入版本/预期revision、错失/重试策略及持续授权。TR是业务调度唯一主；每个发生次走同一受权门面，调用AL公开数据API，AL提交自身数据及操作凭证，主仓/TR按receipt判效果并展示结果。

不得让TR直写AL数据库；`dept/actor`只是现有标签/归因，不是持续授权。新增、patch、upsert、删除各有明确合同；全量replace import不能充当普通字段更新。并发冲突用CAS/revision及幂等返回原结果，unknown先对账。首条自动写仅在选定目标/主体/授权/效果保证可验时启用；普通用户自由创建无人值守写依I02/A04，不借内部SK临时放宽。

**当前**：TR调度、AL CRUD/CAS/import已有；AL写任务Action及完整业务授权/效果链尚无，属于新增适配范围，不由原R06数字自动包干。

新消费须先有R06选定类型/行/字段范围及并发/恢复保证；CE03整包当前以R06为前置，后续如拆最小可验子出口需显式改图和复估，不能只把R06列作参考。自动计划链还须I03恢复与CE05适用准入出口，准备合同或只读用例可先行。

### 链C：活动列表变化触发后续任务

AL数据写主在Insert/Update/SoftDelete/Restore/Import的事务内写最小变更凭证/outbox，或交可证明覆盖全部支持写入口的完整变更feed。主仓拥有受控订阅、规则/版本、过滤和任务路由；AL不依赖TR、不实现另一套业务编排或IAM。只在主仓网关HTTP成功后补发、轮询当前值或监听前端不能证明没有漏事实。

单条事实至少定位源/list/type/文档、revision/世代、稳定事件ID和因果引用；默认最小摘要，消费者按当前权限取数据。删除/恢复保留可判身份与版本，不能用当前状态假装历史快照。批量replace/import先交有界批次/完成事件和可查询manifest，不无条件放大成逐行海量任务；需要逐行语义时另冻完整性/容量合同。支持写入口外的直库修改不在默认保证内，必须受控或用经过核验的变更源承接。

订阅消费按`subscription_id/version + event_id + action_index`幂等地产生稳定操作意图，再走TR执行；重复/乱序/失效引用不能生成新命令。订阅/任务/结果回贴的写权限各自复验，事件签名只证明来源，不授业务执行权。实际业务值无变化时不产生业务changed事件的目标语义须随AL实施批定义，不能仅靠该优化防循环。被规则过滤或因回环抑制的触发保留原因和事实关联，不删除已提交事实来掩盖循环。

**当前**：AL无源变更发布器。旧“AL不感知事件”的表述只适用于不引入业务路由的边界，不应禁止写主记录自身事实；本轮按此修订设计，未新增迁移或实现。

## 6. 并发、异步、多实例与反压骨架

| 风险 | 首批要求 | 逐步增强/实测窗口 |
|---|---|---|
| 并发写/重复/迟到 | C04授权/领域锁、expected_revision、效果receipt；同键同命令返回原效果，同键异命令拒绝 | 热点对象/批量锁序和性能按G04实测细化 |
| 跨库提交 | 本地短事务保存事实/意图；网络不持DB锁，远端按幂等/查询合同执行 | 不声称本地锁保证跨系统即时撤权或分布式原子性；高风险无保证不自动写 |
| 多实例执行/派发 | 使用共享持久claim/lease/fence与逐consumer凭证，不用进程内锁或goroutine当唯一主 | 首期可单副本；实际多副本启用前验旧worker/租约接管/策略收敛，不提前建设完整HA |
| 流控/队列积压 | 不只按HTTP路由限流；共同入口按主体/能力/目标/provider控制开始速率、inflight、批量/大小及队列预算，明确拒绝/held/恢复入口 | 全局与本地预算分别登记；阈值按实测，不编造当前QPS/SLA；任何入口不能绕过同一逻辑预算 |
| 自触发/风暴 | 可信root/causation、规则版本去重、最大深度/总步数/fanout/时间预算；发布时检查静态回路，运行时可暂停 | 默认不让同一订阅在同一因果链反复重入；合法有限链显式允许，不能一刀切丢掉所有任务来源事件 |
| 结果未知/取消 | accepted不当success，unknown先对账；running取消是请求，确认无效果/终止后才canceled | 复用C03/I03恢复与人工处置，不发明exactly-once承诺 |
| 回调/事件入口 | 可信发送方、精确用途、重放/版本/大小检查，受审目的地和凭据引用；统一平台路由 | 不把外部URL、role或新root当可信输入，不允许自行重置链预算或任意反代 |

源事务不可丢凭证写失败时，按领域合同失败/暂停，不能成功后静默漏事件；外部事实接收先可靠stage，再推进游标。队列满、期限到、权限撤销和预算耗尽必须有可定位状态，不无限重试、不阻塞全部worker。限流不能只保护网页而放过进程内、MCP、订阅或定时入口。

每个新入口先交本能力适用的deadline、大小、速率/inflight及可观察有界profile，可复用已有组件。CE05再扩跨入口共享/目标/provider预算和自动链循环保护；不能把该后续完整包机械变成P6查询或只读MCP的前置，也不能在推广前完全无界。订阅生效水位、改版/停启与回放政策，以及谓词取事件时值或当前值，在CE04编码前通过代表例细化，不把当前值查询当历史事实。

## 7. MCP、专业平台与双模式

MCP把选定能力映射为tools/resources等协议表面，继续调用共同门面、当前授权及原receipt；不会生成另一套业务实现或把工具注解当授权。HTTP普通消费者继续可用，能力可对外API化不等于自动公开全部MCP工具。[MCP tools规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)提供发现/调用schema，业务写授权和完成语义仍由平台合同承担。

核心、私有扩展、专业连接器共用能力准入和因果合同，专业SOC/SOAR/CMDB/知识服务仍负责其业务。复杂持久协同优先消费已有专业供给，不因能力互通重建一套万能工作流、检测引擎或数据湖。

独立模式仍完整本地IAM；企业模式纳管来源走UAA当前投影/新鲜度和受限委托，配置/事件/grant不恢复已撤权限。UAA网页登录不等于MCP AS。mock长期保留，同套合成链正反例用于各入口，不用mock宣称真实互通成功。

## 8. 渐进范围和下一步详设门

P6.0先交能力家族库存和标识/消息/完成语义；P6.1交最小逻辑门面及C03/C04/R01/X01接缝；P6.3用D12交链A。P7逐能力扩I01/I02，补链B/C、共同准入和循环防护，再由A03发布选定MCP适配。P8/P9逐步扩专业执行、Agent和复杂持久协同，按证据决定拆分，不把简单AL变化触发拖到P9。

每期仅要求新增/触及能力服从共同合同，存量用映射/适配器渐进迁移；全量覆盖、容量、多实例和更复杂数据范围留明确窗口。当前准确schema、变更事件粒度、订阅UI/配置形态和SLA未全定；这些在对应编码前用代表链细化，不一开始造完整平台。

新AL来源凭证、AL任务adapter、订阅和共同准入属于实质增量，不能免费塞进原I01/R06预算。补充前排期保留历史基线；[增量范围册](../review/capability-interconnect-supplement.json)的CE01–05有界范围已净估52–80工程日，与LS及六包替价扣重后进入[现行完整排程](../review/execution-schedule.md)。它不覆盖任意未来厂商/场景，获选新范围仍需补估及依赖核验；参考验证不是产品三链或共享流控已实现。
