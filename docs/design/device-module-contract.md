# 内部设备目录、状态看板与访问入口

日期：2026-11-11。状态：新增X03目标设计；设备来自多个厂商，**不假设设备支持SSO**。本文替换本轮早期把统一入口近似单点登录的建议；与平台自身登录对接企业SSO是两件事。

## 1. 首期提供什么

所有者已确认首期在私有扩展中提供设备目录、状态仪表盘/大屏，以及有权限用户可见的“打开管理页”，设备侧人工登录。设备页面仍使用各厂商自己的账号/口令、MFA、验证码或其它实际认证方式。平台不保证点击入口就完成设备登录。

CMDB已确认存在，优先引用其设备ID/属性/责任人；运行状态从实际具备接口的设备管理系统、SOC或监控取数，监控平台具体供给尚未确认。若没有状态源，显示未知或人工维护的状态与时间，不自建轮询扫描/探针/NMS；如只提供厂商API，可在私有adapter做有界取数，另估单厂商工作量。

模块用于统一查看和进入现有设备，不成为第二套CMDB，不复制设备配置中心、固件管理、PAM或远程会话系统。台账中必要本地补充（展示分类、收藏、入口配置）有字段归属与覆盖规则，不反写为CMDB权威。

## 2. 受控信息模型

| 对象 | 主要字段 | 约束 |
|---|---|---|
| DeviceReference | 本地扩展ID、source_id/external_id、名称、厂商/型号/固件、所属组织/责任引用、类别/标签 | 来源稳定ID；真实IP/名称不进入公开mock |
| StatusObservation | status=healthy/degraded/down/unknown、observed_at、received_at、stale_after、来源与原因 | 无数据/过期与故障不同；不能用入口HTTP200推定设备健康 |
| AccessEntry | endpoint_ref、方式web/专业访问平台、认证类型、适用网络、状态、维护者、最后验证时间 | 地址在私有配置，列表仅展示脱敏目标；不存口令/token/cookie |
| AccessCapability | 可查看/可打开、目标侧授权责任、已验证方式、厂商适用范围 | 查看状态不自动允许访问入口；入口允许也不代表目标侧登录授权 |
| LaunchReceipt | 谁、何时、哪个设备/入口、允许或拒绝、目标引用、关联ID | 普通链接只证明打开请求；不能记为“设备登录成功”或完整会话审计 |

仪表盘按授权后的设备集合统计，显示正常/异常/未知/陈旧的数量和口径，分母、筛选及最后更新时间可见。大屏使用专门的只读会话/范围，隐藏入口和敏感定位字段，不能通过公开URL获得整公司设备状态。自动刷新有失败/陈旧提示，不将失败归零。

## 3. 访问分层与现实限制

| 层级 | 用户体验 | 实施条件与本轮处置 |
|---|---|---|
| L0 目录入口 | 点击“打开管理页”，随后按厂商方式登录 | 首期推荐；配置允许的HTTPS目标，校验证书/网络连通由实际环境解决 |
| L1 专业访问平台入口 | 点击已纳管资产的应用/会话入口 | 可选；先确认是否有PAM/堡垒机、应用发布能力、许可证及API，不能假定已有 |
| L2 逐厂商辅助登录 | 专业平台代填账号/发布远程浏览器，或厂商明确支持令牌会话 | 单厂商/固件实测通过后启用；不做通用保证，失败回到人工登录 |

业界对不支持SSO的Web资产，确有通过远程应用与页面元素定位/多步脚本填充的方案。例如[JumpServer Web资产文档](https://www.jumpserver.com/docs/v4/assets/create-web)要求RemoteApp或VirtualApp承载，并区分基础与脚本填充。这说明它需要应用和登录流程适配，不意味着本项目或任意设备已具备自动登录；具体版本/版别/授权/凭据责任还须确认。

首期不自建密码库、浏览器注入口令扩展、SSH/RDP代理或会话录屏。若选择L2，优先由专业平台托管/轮换凭据、记录会话，本平台只发受权启动请求/接回执；没有成熟提供方时维持L0。验证码、MFA、硬件证书、动态DOM、iframe、厂商升级都可能使自动填充不可用；不能绕过厂商认证措施。

设备兼容清单至少按厂商、产品/型号、固件版本、入口协议、认证方式、是否有API、授权方式、是否支持代填/发布、MFA人工步骤、验证日期和维护者记录。未测=未支持，已测旧版不能覆盖所有新版；固件更新后只停用受影响的辅助登录，状态展示和人工入口可继续。

## 4. 打开入口的合同

目录GET仅返回当前用户允许看到的入口元数据。打开动作由受权POST请求完成，服务端重新检查设备范围、入口权限和当前配置版本，生成短期启动回执；普通链接返回预配置允许地址，专业平台方式返回其受控handoff引用。仅网关服务端使用secret_ref，浏览器不能提交任意URL让服务端访问。

普通浏览器打开不需要平台抓取设备登录页。目标协议/主机/端口由受审配置允许，不接受 `javascript:`、用户信息段、携带凭据的query或任意重定向；外链采用noopener/noreferrer并在跳转前明确目标网络。设备实际网络不可达时提示其访问条件，不由核心反代所有厂商Web管理流量。

未来handoff必须绑定用户、目标、操作、有效期和单次nonce，供应方消费后不可重放；没有供应方可验证消费/登录回执，就只记“启动已提交”。普通直链同样不能防止用户在地址栏自行进入，真正设备访问权限由目标/专业平台控制，平台隐藏按钮不替代设备侧授权。

## 5. 可插拔验证与排期

X01先提供稳定注册、权限、网关/导航/身份接缝；X02提供来源adapter合同。X03在P6.3用独立私有参考模块完成mock目录/看板/L0入口，核心不出现厂商字段或新业务表。UI首期可统一导航到受信独立应用；只有明确要嵌入相同壳层才增加页面承载方案，不先建任意远程微前端。

X03估算只包括薄模块和一个合成来源，不包括厂商逐个对接或自动登录。P7核验真实CMDB/状态源并另立厂商子包；L1/L2本轮不立实施包，P7记录是否有专业供给/明确收益，缺失则明确维持L0并关闭本轮候选，不无限挂“未来SSO”。将来提出辅助登录需求时按独立范围重估，不成为首期验收前置。

验收覆盖：范围隔离、计数/导出同授权、未知/陈旧/部分来源失败、多个厂商且认证方式不同、入口隐藏与打开复验、恶意目标/过期handoff、无SSO仍可人工登录的明确交互。真实设备登录成功只在逐设备真实验收记录，不用mock原型或浏览器跳转代替。
