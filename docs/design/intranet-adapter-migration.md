# 从 mock 到内网提供方的适配与切换

日期：2026-11-11；2026-11-14按本地正式核心先行、质量优先同步交付。状态：X02目标设计，真实接口仍待核验。与[扩展兼容](extension-compatibility.md)、[领域合同](business-lifecycle-contracts.md)共同使用。保留mock是长期要求，接入真实接口后也不删除mock场景。

首个核心版以[最新计划](../phase6/first-usable-release-plan.md)为准；本公司已允许先用本地账号正式运行，质量和完整验收优先，1月不强承诺。B1只交过程接缝，不能代替全部核心联动与适用公共生产门；完整UAA-P/R在核心后接入，约两个月只是未证明的目标窗口。真实UAA和公司消息联调时间未定；本地正式运行、合成供给成功和公司UAA纳管激活分别取证。

## 1. 接入形态与责任

推荐链路：核心领域用例 → 稳定公共端口 → mock connector / 私有真实 connector → HR、风险来源、CMDB、SOC等提供方。私有 connector 是协议/语义转换服务；真实 SDK、URL、字段名、消息中间件和凭据只在内网私有仓/配置。核心升级不需要合并私有字段代码，供应商变更只影响对应 connector。

同一公共端口的mock与真实实现必须通过同套合成契约用例；只替换endpoint/secret/profile即可切换实例，profile是环境选择，不能把adapter实现版本塞进业务身份键。现有情报 `internal/pkg/threatintel/threatintel.go` 的 `Provider` / `NewProvider` 已有桩/HTTP分支，但 HTTP 响应映射仍在核心；不能由此宣称全项目私有适配已完成。HR当前不是一个已可替换的完整同步模块，D06/X02需从公共合同补齐。

这类语义隔离对应业界的[Anti-corruption Layer](https://learn.microsoft.com/en-us/azure/architecture/patterns/anti-corruption-layer)。可借鉴[Airbyte协议](https://docs.airbyte.com/platform/understanding-airbyte/airbyte-protocol)的connector声明、读取与状态交接思想；本项目只实现所需目录/发现feed，不引入一套通用ELT平台。SCIM/MQ/厂商REST均可由私有侧适配，核心业务API仍遵工程公约的GET/POST，不能据此改造外部厂商协议。

## 2. 公共数据合同

按启用能力选合同：X02-Q只读查询先有source/query引用、输入输出、当前授权、来源/时效、超时与错误，不要求feed游标或双边outbox。以下记录/批次、身份/幂等/完整性要求在启用对应同步feed时交付，不把所有来源形态压入首个query connector。

本地正式核心先保留公共C的稳定本地ID、可信主体/服务/委托上下文、资源键和source界面。人工录入的真实业务标明local来源、写主与稳定记录身份；合成mock另分信任域，不能在接真实feed时把本地事实当测试数据清空。后续认证主体、治理主体与目录实体分别受审映射；不要求先实现全部远期feed或UAA投影表。

| 公共对象 | 必须携带 | 领域所有者 |
|---|---|---|
| 来源实例 | 稳定 `source_id`、数据区、合同版本、能力、权威字段、完整快照/增量能力 | 核心登记；环境地址另存 |
| 记录信封 | source_id、entity_kind、external_id、source_revision/序号、observed_at、received_at、schema_version、payload_hash、operation | connector规范化；核心验证 |
| HR人员/组织 | 稳定来源ID、工号等可变别名、状态、组织/主管引用、生效时间；引用未解析可表达 | 核心用户/组织服务提交 |
| 发现事实 | 稳定来源发现ID、对象引用、类别、来源严重性、证据引用/摘要、观测时间、来源状态 | 来源事实与本地风险处置分离 |
| 资产查询 | 稳定来源资产ID、允许展示的名称/类别/责任信息、来源/时效 | CMDB权威；核心只做薄映射 |
| 批次回执 | batch_id、逐行accepted/rejected/conflict、错误原因、已提交checkpoint、完整性标记 | 接收端提交后生成 |

时间统一带时区，未知值用明确unknown，不把空串/0/缺字段解释为“撤权”或“风险消失”。字典映射保留原值和映射版本；未知枚举入隔离区。核心只接受schema白名单，不把厂商任意对象透传给模型或界面。原文若为调查所需，放有授权/保留周期的证据存储，不无限写入常规日志。

身份主键为 `(source_id, entity_kind, external_id)`，source_id与领域合同provider_ref为同一来源登记映射，entity_kind至少区分user/org/finding/asset；来源ID可重用时另加经过核验的identity_generation。匹配、去重、回执、墓碑和删除均使用同一实体命名空间，不能因人员和部门恰好同号而串号。账号/组织本地ID由核心持有；工号、姓名、邮箱不是永久唯一键。来源版本若不可排序，不能伪造为数字比较。仅来源明确保证的revision/事件序列/完整快照水位可证明事实新旧；connector串行接收序号只能排序交付，不能把迟到旧事件变成新事实。相同身份/hash可判重复；冲突且无可信freshness时先查来源当前值/完整快照，仍不能判断则隔离待核验，不自动覆盖或触发停用/风险回归。回放不覆盖已更新版本。feed协议主版本不是人员状态版本。

## 3. 一个连接只有一个游标与重试主

纯查询无提交游标。启用同步feed时，同一数据集只选一个采集主和重试主，connector隐藏上游鉴权/翻页，核心按领域提交确认；每一跳的来源游标与提交水位独立命名，不混成“同步成功”。

首个feed可采用**直通核心提交后才推进游标**：上游须可重读/重投，核心持久提交领域变更和接收记录后ACK，connector才推进来源checkpoint；超时重投原身份/版本。不强制connector与核心各造一套outbox。

只有需要在核心提交前确认上游、异步缓冲或脱离来源重放时，connector才须先持久保存来源版本/游标、规范化批次及可重投payload，再推进读取checkpoint/上游ACK；批次保留到核心提交ACK及安全回放窗口届满。可用现有可靠收件或write-ahead receipt恢复，不限定必须同时使用inbox和outbox。checkpoint不得领先可恢复数据。

如提供方只支持MQ/推送，不能因收到消息就声称核心提交：可等核心提交再确认上游，或先按上述要求可靠保存后确认。发送端不能在网络200或“已排队”时推进业务提交游标；异步202必须带可查receipt，终态后推进。

全量同步至少包含 snapshot_id、start/end、complete、预期数量/校验或来源完成证明；分页中断/过滤/429/超时都不得形成“完整缺失集合”。先stage并验证完整性，再按领域政策启用缺失处理。大批次分块提交需要可恢复进度，禁止一半失败却将整个checkpoint标成成功。

幂等以来源记录/版本和批次为键，收件去重与领域变更同事务。外部副作用未知不靠重放补偿；checkpoint回退也不等于业务回滚。查询、采集、回传是独立操作与凭据授权，默认只开取数。

## 4. HR迁移的特殊约束

人员/组织事实与企业账号/功能授权分开登记写主：HR通常管理目录任职，UAA管理应用账号及受管授权，具体字段先过E01-UAA-C来源矩阵；同字段不允许两路竞争覆盖。平台保留非受管的本地业务授权、工单参与和审计，企业模式应急按批准政策处理。真实同步通过用户/组织服务执行，不能私有adapter直写users或角色表。离职/停用首先关闭登录与委托；工单与历史证据保留，根据已确认的交接政策转派或进入待认领，不能静默全部转给超级管理员。

组织撤销、主管缺失、环/重复工号、回聘、跨组织迁移和先人后组织均为必备mock场景。局部数据缺失不能推断离职；只有明确停用事件或已验证完整快照及批准的缺失政策可以触发。HR源不能借同步角色字段获得管理员权限。具体active检查、组织生命周期和交接矩阵见[领域合同](business-lifecycle-contracts.md)。

首批真实导入先运行身份匹配报告：新增/匹配/冲突/待人工映射，再只读影子比较并批准实际映射。已有合成账号与真实员工默认隔离，禁止按相同工号或邮箱自动合并。本地先正式运行的真实账号UID、工单、风险、附件归属及审计历史继续保留；不能删号重建业务或重置归属。UAA接管另预览角色/资源和直接/组织/继承来源差异，批准后切为单一写主、关闭受管旧入口并收敛旧grant；不把外部同名admin映成内置管理员，不把新旧授权无条件取并集。

## 5. 风险来源迁移的特殊约束

来源发现与本地风险episode分别建模。来源严重性/活跃/最后发现是外部事实，本地处置优先级、接受到期、整改/复测是本地事实；connector不得用上游 `closed` 直接关闭本地风险或工单。来源暂时不再返回、账号读不到、源记录删除均不等于已复测通过。

重复/乱序/批次重放不新建重复风险；回归是否新episode按D08的family+cycle规则。来源ID若会复用，必须先定义实体指纹/来源代际，不在接入时临时拼字符串。回传结论带本地decision/evidence引用和幂等键，只回写对方明确允许的字段；无回传能力是合法配置。

## 6. 真实切换步骤与退出条件

以下影子、writer切换和checkpoint步骤用于实际启用的有状态feed；只读query来源只验选定输入输出、授权、时效/限额和失败边界，不强行套入全量迁移流程。

1. **合同核验**：只在内网确认协议/权限/速率/字段/删除/排序/回放/沙箱；公开文档仅保存去敏结构，不保存内网地址或SDK。
2. **共同契约**：用同一合成样本跑mock与真实adapter映射测试；断网、429、重复、乱序、字段漂移及撤权均有预期结果。此时可以继续开发核心，不等待真实沙箱。
3. **只读影子**：真实来源读到隔离stage，生成差异与身份映射报告；不触发通知、停用、工单、自动执行或回传。
4. **有限试点**：固定来源/组织白名单、单一writer与checkpoint、速率和总量上限。人工核对新增/更新/隔离数量，包含失败重启、撤权和删除事件。
5. **切换与观察**：冻结旧writer、记录最后已提交水位与未决批次、启新writer；重复窗口靠稳定身份/版本去重。不是简单把 `stub=false` 就宣告迁移成功。
6. **回退**：关闭新writer/自动后继消费者，导出差异和待对账列表；恢复旧adapter时从已证实提交水位继续。已发生业务决策/通知/外部动作按补偿政策处理，不能还原旧游标再无条件重放，也不能以回mock掩盖真实数据丢失。

放行回执绑定核心/adapter制品摘要、合同、映射、来源实例、字段白名单、mock/contract/real层别、批次/水位和操作者；授权撤销与失败恢复演练通过后才开启相关真实能力。真实接口不具备时状态为 `contract_ready_real_pending`，并在P7逐提供方包复核，不能清除原排期。

## 7. 私有交付和验收

内网部署包包含私有connector镜像、合同摘要、配置模板、密钥引用、CA/代理配置和迁移/回退步骤。固定OCI摘要、Go/npm缓存与许可证清单，见[版本现代化](dependency-modernization.md)。私有CI可以导入真实SDK，公共CI只验证合成fixture/参考实现；不把内部源码/接口数据上传外部模型或仓库。

X02-Q为2–3日的独立合成HTTP query connector，与mock同例；只依X01-C，不等D06或X02-F。X02-F为3–5日的目录/发现feed稳定身份、完整性、持久提交ACK/水位与恢复参考，供D08及真实HR feed启用。原X02父价5–8日不变，不另加总。

B1基础出口实际跑通X02-Q加一个X01-B参考私有应用，验证换endpoint/profile、身份/资源授权和禁用无需修改核心供应商代码；接口文档或UAA57例离线合同不代替接线验收。首版受审配置+重启生效即可。X03只依X01-B、X02-Q、U02，不等待完整X01-H安装治理或同步feed。

首条真实纵切选择HR目录与风险发现两类中的一个实际可联调来源，另一个先mock+契约；D06/D08各自领域实现仍按原波次。任何提供方新接入都单独估算、实测和登记，不能用“完成connector框架”声称SOC/CMDB/HR全量迁移完成。实际调用/事务裁定见[当前模块边界](current-module-boundaries.md)，子出口依赖见[执行排期](../review/execution-schedule.md)。

### 7.1 私有adapter随核心升级的最小操作路径

按[升级承诺](extension-compatibility.md#61-首版可验的核心升级承诺)，同受支持主合同内只改变核心实现时，私有adapter应继续使用稳定wire/语义，不依赖核心model/DB。厂商协议变更由私有映射处理，新增业务语义或破坏性合同仍可能需要适配。

1. 固定当前adapter制品/合同和目标核心版本，核对核心升级差异与迁移说明；保存所选数据备份及私有配置，私有代码/SDK/数据留独立仓与进程，不直库或导入`internal/`。
2. 更新并构建核心，执行核心自带、已审的迁移；私有配置和secretRef从独立目录/部署挂载读取，不被pull覆盖。不要求私有侧复制核心迁移或因内部表变更修改adapter。
3. 以保留的旧参考adapter对新核心实际跑合成HTTP契约和所选权限/结果反例，记录双方摘要；私有环境另跑真实供应方映射验证，不外传真实数据。首期只要求这一组旧adapter×新core，不先建完整多代矩阵。
4. 通过后按受审配置重启/切换并核对在途及原receipt；失败按已验代码/DB兼容步骤回退或恢复，不能只回退endpoint重放副作用或恢复旧grant。
5. 发现破坏性变更时停止无条件升级，按显式新合同、字段/语义转换和消费者清单协调；首次正式部署前可按原决定协调替换，首次本地正式部署就登记合同/消费者并承担兼容迁移责任，不等UAA接管，也不承诺永久零改或固定月数。

该步骤与稳定端口属于首个核心版必需接缝，不等待全插件治理；真实公司UAA/消息可用性及激活审批仍独立验收。

## 9. 企业UAA是企业模式首次正式激活门

[UAA接入合同](uaa-governance-integration.md)明确不只认证：公司要求纳管的目录、账号/角色/资源、条件范围、回传及撤权须按实际供给核验。所有者已确认本公司允许本地账号先正式运行，E01-UAA-C及本地三层/可信上下文/稳定资源/source合同先交，完整公共P和私有R接在核心之后。**R.pre_apply是从本地模式切入公司纳管企业模式的附加门，不是首次本地正式部署门**；纳管激活仍不能由真实风险、HR或mock验证代替。私有adapter不能直写核心角色表或发送任意Casbin规则，只走来源受限的领域投影入口。

未知真实契约只阻断对应真实激活，mock仍可开发，也不把已允许的本地正式运行泛化成仅隔离试用。本地首次正式运行仍须通过IAM/三层、TLS/边界、备份恢复、制品与适用完整门禁；两IAM高风险写的本地审计失败回滚仍按[统一日志/审计合同](unified-observability-audit.md)待答，本次不批准。企业模式不自动回退mock或全员本地账密。退出UAA需要受审的授权/凭据接管及明确批准的本地权限基线，不能切endpoint恢复旧grant；完整退出迁移工具不作B1前提。C/P/R保留原范围和估算基线，按选定纵切再净估，不因窗口后移直接砍价；原M-UAA工作量不能隐含并入X02/E01粗估，核心后约两个月的UAA目标也不等于已证明的工期。
