# 基础版与后续各期的交付边界

> **2026-11-14 F013后继边界**：公司允许本地账号先正式运行，质量和实际可用优先，不勉强1月。最新[首版阶梯](../phase6/first-usable-release-plan.md)要求风险/工单/taskrunner/activelist/消息实际联动及完整本地三层权限，UAA-C接缝先留、完整P/R核心稳定后交。下文B0/B1仅为过程出口，不代表已满足首版本地正式门；UAA真实接管另验，消息真实HTTP仍属核心。

> 日期：2026-11-14。用途：本轮渐进交付边界的权威说明；面向所有者和实施者。
> 设计状态：承接“先带现有底座入网开发试验，再补稳定接缝，常用先交、复杂按使用增强”的调整；新增产品尚未实现。
> 本页管发布边界；业务与安全语义仍归对应合同，价格和依赖归[总账](../review/planning-backlog.json)。B0/B1是近期出口，不是另建两套产品或增加两个Phase。

## 1. 先交哪一版

平台继续聚合专业平台的数据、承接安全生命周期。先让现有能力和一个扩展真实可用，再沿原路线增强；不按同类产品最完整形态逐项补齐。mock长期保留，内网私有字段、SDK和凭据留在adapter侧。独立模式与企业模式共用公共核心。

**B0：现有Phase5底座可以打包带入内网试验。**

- 必交：固定五仓组合、制品/配置说明、启动和原有能力验证步骤；不接UAA也保留本地账号、角色、菜单授权和权限管理，说明当前功能与限制。
- 只选择一个实际入网目标平台/架构，准备运行制品、校验值和所选adapter开发需要的依赖；是否需要前端开发工具按实际二开范围决定，不先打包全部语言/架构的离线工具闭包。已验收版本维护候选仍按原PR/main收尾，不将本页当已在公司环境跑通。
- 不作前置：新增风险域、UAA产品接线、通用插件宿主、统一调用层全面迁移、全站重设计和完整观测平台。
- 退出验收：在隔离环境复现现有启动、登录和基础工单旅程；说明mock及尚未接通的来源。这是开发/试验交付，不能称生产就绪或真实企业接入通过；公司规定的接入限制仍须遵守。

**B1：最小可扩展基础版，在P6.0/P6.1按所需纵切交付。**

- 必交：单实例、本地IAM、正常首页、基础工单创建/分派/处理/证据/复核，以及本批触及的版本、权限和数据正确性修复；业务最小UI与能力同批。
- 必交：一个进程外query adapter和一个参考私有应用，经稳定合同、可信身份、当前资源授权和受控导航接入；私有侧拥有自己的代码和数据，不改核心源码接厂商特例。
- 接缝采用X01-B基础出口与X02-Q；X01-H承接后续完整宿主。先受审配置和精确登记，不先建设任意插件市场、动态代码加载或完整声明包管理台。
- 不作前置：整个P6.1包全部结案、完整X01-H、所有feed种类、全部UAA-P、完整调度恢复台、所有页面的U06迁移及远期统计。
- 退出验收：无UAA配置仍独立可用；mock与参考HTTP adapter跑同一合同，换endpoint配置不改core；参考应用可登记、访问和停用，伪造用户/越权被拒；同合同的核心升级候选与原参考客户端组合可验。

已有基础业务无需等B1所有新接缝完成才试用；B1也不以“保留接缝”为由只交接口文档。当前[UAA离线57例](examples/uaa-reference-mock/README.md)是合成合同参考，不是上述产品出口已经验收。

## 2. 其后各期交什么

**P6.2：风险人工闭环。**

- 必交：一个合成专业结论来源、风险列表/详情、评估/接受、明确责任、受权派单、整改/复核及逐风险结论；保留有界N:1和最小风险通知。人工业务不依赖AI可用。
- 不作前置：全部真实来源、全套设计器、复杂自动路由、完整统计和全站视觉推广。
- 退出验收：来源进入→风险处置→整改票→证据/复核可由普通业务角色操作；重复不误建、无权不泄露、失败有明确待处理；mock/contract/real分别说明。

**P6.3：常用体验和一条任务回贴。**

- 必交：批量标签、常用搜索筛选、本地草稿及按已选范围交常用批量分派；情报左右栏、明确重查；薄流程通知配置；一项获准任务从工单触发并回贴结果；设备目录/状态/人工登录入口。
- 不作前置：全功能批量操作、任意规则/映射编辑器、完整积压恢复台、全站页面一次迁完、PAM或设备SSO。U06逐页推广，不能整包挡住业务UI。
- 退出验收：逐项权限和部分失败可理解；任务完成/失败/未知有原回执可查；设备来源/新鲜度可辨，管理页由设备侧人工登录；新增功能有实际可用界面。

**P6.E：固定统计与薄事件协作。**

- 必交：获权范围的数量、积压和选定时长投影；必要的SOC事件引用、相关工单及证据视图。里程碑事实随原写路径保存，缺历史不倒算。
- 不作前置：复杂分组/P90等完整分析、大屏设计器、全套战役操作台和通用导入/合并产品。
- 退出验收：数字与明细同范围、口径和来源明确；四类已确认时长分别解释，固定投影逐项交付；有真实存量才启用已选有限导入及逐行报告，另列净估。

**P7：标准API和按首个提供方接入。**

- 必交：所选能力的标准API/目录、受权手动运行与所需身份/结果；按实际选定来源或执行方完成一条真实adapter纵切，再扩后续来源；MCP沿已有分期的薄出口消费同一能力。
- 不作前置：所有提供方、所有能力迁移、全语言SDK和完整调度恢复产品一齐完成；只读数据adapter不机械等待模型或无人值守身份包。
- 退出验收：外部消费者与内部用例得到一致受权结果；所选真实来源/执行方有独立回执；周期/后台委托启用时再验其持续授权和恢复出口。

**P8：按选定场景扩AI与专业协同。**

- 必交：选一个领域Agent或专业执行/协作场景，复用既有模型、知识及执行供给，交可用入口、批准/结果与证据；已有P6/P7 AI查询或MCP入口可以先用。
- 不作前置：全套Agent平台、知识运营、脚本市场、通用审批和报告设计器；固定报告/通报按具体受众逐项交。
- 退出验收：选定任务可演示、权限和引用可核，有人工接管；不以模型声称完成代替业务效果。

**P9：规模和持久自动化。**

- 必交：选定跨平台自动链及接管/回源；按实际运行需要交多实例、容量或架构调整，不预定全面微服务化。
- 不作前置：通用DAG画布、任意并行/回路、强制退役外部SOAR和所有高可用拓扑。
- 退出验收：所选链在重试/重启后不丢必要意图、不重复效果；实际启用多实例前完成其claim/fence及撤权一致性验证，未选形态保持明确支持边界。

**P10及更远：有明确使用需求的增强。**

- 必交：对已保留的具体增量给用途、提供方/有限实现、子估和交付窗口；继续承接原路线效果。
- 不作前置：跨端草稿、Office预览、外部门户或复杂会签整套预建；先用本地草稿、授权下载、专业预览和内部人员承接。
- 退出验收：获选增量逐项交效果，未选候选有结论；不把调查完成等同功能实现，不默删已确认业务效果。

## 3. 哪些门随启用生效

首次新增业务写先满足当前授权、版本/并发、校验及本地事务正确性；首次不可丢的自动/异步动作先满足持久意图、幂等、当前授权、结果及恢复。它们按实际纵切复用C04/R01/CE，不要求先建齐全部共同平台；已存在的数据损坏或越权问题不能以“基础版”放行。

公司UAA纳管企业模式首次正式激活前仍须实际协议、身份/授权映射、撤权、新鲜度/故障、受限恢复和接管验收；不能只接认证、用mock顶替或故障自动转本地放权。独立模式不被真实UAA等待阻塞。首次生产另过适用TLS/边界、备份恢复与运行证据门，不等同B0入网试验。

十一组已确认方向与B/UX/K2保持：单主责、明确业务管理范围、接单/时长、流程通知和设备人工入口先做薄版本；实际使用共享池才交已定轮询/认领；完整策略台、复杂日历和运营分析后续增强。确认方向不等于首批实现全部配置、统计或例外；两IAM写的审计失败回滚仍依[最新确认状态](../review/planning-followups.json)，不从本页推定批准。

实施继续[standards §11](../standards.md#11-开发工作流先框架--先测试--分批实现)：本批先冻结预期、正负/边界/权限用例并取得真实红例，再实现到绿及跑适用完整门禁；少做一批功能不等于少验该批数据与安全。
