# 工单运营、时长度量与数据权限补充

日期：2026-11-13。来源：后继输入F004。状态：现态审计与官方对照已归档，业务方案仍是候选解释与待确认设计，尚未逐项批准/计价或实施；不因F005的README授权推定本页已批准。既有B01–B09、UX及K2方向保持。权威仍归[生命周期合同](business-lifecycle-contracts.md)、[工程公约](../standards.md)和对应包，本文记录需并入的增量。

## 责任与范围派单

原句有笔误，按后半句候选理解为“唯一当前主责处理人＋多人知会”；现AssignedTo单值、CC多人已存在，协作/复核职责另列，不直接数组化处理人。待分派时个人可空，但需明确管理责任。

已有规则仅匹配固定target_user，未实现组织队列/随机/轮询/认领。建议已知资产或风险owner直派；同质共享任务配置合格候选池后轮询；指定类型可选主动认领及超时处置。轮询须当前资格、固定派单幂等和多实例游标；认领须单赢家CAS。无候选显式待处理，不猜人；紧急兜底应是预配置合格对象。

候选池、组织负责人和类型业务管理员不天然穿透participants_only。受限票默认合法单人直派，认领者须有相应读取资格；要向未参与者开放队列摘要，显式调整类型查看范围/指定角色并预览影响，不能自动给全池加参与人。

## 类型业务管理员

区分类型配置权与实例业务管理权。建议组织/虚拟组织承载职责，再限定类型和作用组织；允许补描述/白名单字段、协调、转派及合法流程操作，记录原因、操作者、前后值与revision。不直接改来源正本、公式或历史时间，不绕业务validator和发布版本。

实例读取/统计仍遵守类型查看策略；配置管理员不自动取得所有实例。是否在指定类型的查看策略中显式增加受组织范围约束的业务管理职责、允许其读取/统计未参与的票，须授权并预览影响，这是当前待确认问题；不能借本页改变B01/B03默认。

类型/字段Schema编辑权也不自动包含修改数据可见范围或字段安全策略的权力，后者须有独立授权和影响预览，避免通过改定义间接放宽自己的权限。

## 响应、节点与整单时长

建议明确名称而非混用“响应/处置”：首次接单响应=创建到首次人工接单；分派后等待=该责任轮次分派到确认；节点驻留=每次入态到离态；处理历时=开始到提交结果，不等于人工工时；整单闭环=创建到最终业务确认；独立技术归档另计。

简单类型可一键确认并开始；需要观察排队者再拆接单/开始。系统自动分派、页面查看、机器人留言不算人工响应。K2继续入态即起算，分派入态也算，接单不能延后原节点SLA；同节点转派不重置节点/整单时钟。

示例：09:00建单、09:05分派入待处理、09:12接单、09:20转处理中、10:00提交入复核、10:20闭环、10:30技术归档。首次接单响应12分，分派后确认7分；待分派5分、待处理15分、处理中40分、复核20分，整单闭环80分，归档90分。自然历时、工作日历/获准暂停分开；重开保留首闭环并新增周期，重入节点有发生次；并行分支不能相加当整单历时。

现有status_changed_at和轻量SLA不能重放全部历史，Transition等持久事件尚需统一。应在D02相关写路径开工前冻结所需最小事实和净估，随D02补同事务里程碑；首组指标投影口径可在P6.1出口前冻结，再由D13交获选投影，展示类型/优先级/流程版本、样本数、均值/中位数/P90、超时率和未完结积压。不能等写路径交付后才决定是否保存事实；缺历史标不可计算，不用updated_at倒算，不为首批指标先建通用BI/DSL。

## 通知、AL、设备与仪表盘

通知复用D11，以事件×类型/流程/节点×角色配置：入节点当前处理人、提交复核给复核人、闭环按类型选发起/责任/知会、超时到配置升级对象。站内与外发须统一规则/预览/去重，发送时复验当前可见性；通知不赠读取权。

AL现有AK/SK与路由权限不能替代用户type/row/field权限。核心统一鉴权，AL执行受限请求；旧裸反代收紧，列表/详情/写入/导出/统计/Agent沿同规则。设备状态、管理入口和可选登录账号分层授权；密码/token/私钥不作为普通AL字段，需集中管理时优先专业凭据供给，是否接入仍待答复。

当前utils `aksk.Sign/Verify`的canonical不覆盖URL query，不能把用户/行/列约束放进任意可改query便称已安全传递。核心须确定当前范围与允许列；若委托AL执行过滤，约束须通过签名绑定的body/过滤摘要或等价可信合同传递并在接收侧验证，不能只在核心拼好未受保护的query。若核心负责最终过滤/投影，分页与计数也须沿同一授权谓词。合同须覆盖旧通配反代、导出、元数据和任务入口；准确wire及反例在相应包冻结，不在本页悄悄升级签名协议。AL不因此复制IAM。

当前`Sensitive`标记不是字段访问控制，启用访问日志时会记录query及body前4KiB；真实敏感数据纵切须同时防止日志泄露。详情、软删记录、导出/异步下载、统计、缓存和Agent沿相同范围；无权字段不能用于筛选/分组侧信道，也不能以已有快照绕过撤权。

个人首页维持当前处理/明确复核责任，发起/知会另列；业务管理者增加合法类型/组织范围的运营视图，全局态势另授。先过滤后聚合，数字与列表同源，不由前端裁剪全库统计。

AL现有`DataService.List`是cursor分页且无total，尚无可直接复用的受权聚合接口。首批运营数字须选有限统计投影或受权COUNT，记录范围、口径与新鲜度并补净估；不能让浏览器全量翻页计数，也不把所有新增台账/工单统计默塞进D13原风险指标或R06旧价。

## 业界对照与本项目取舍

2026-11-13后继复核：此前聊天的定向调研在本节补齐可追溯依据。以下是官方文档对照与本项目建议，不是产品实测、供应商适配验收或所有者批准，也不能证明存在适合所有场景的唯一最优解。

- **主责与共享派单**：Jira自动化支持指定人员、随机、轮询和按工作量分配，JSM也支持从未分派队列分配给自己。[自动分派选项](https://support.atlassian.com/cloud-automation/docs/jira-automation-actions/)、[主动认领入口](https://support.atlassian.com/jira-service-management-cloud/docs/assign-yourself-to-a-customers-request/)。本项目保留单值当前主责及多人知会；已有owner直派，共享同质池先建议轮询，特定类型允许认领。轮询较容易解释与重放；认领需要合法队列可见性、单赢家及无人接单兜底；按负荷分配另需可信容量口径，首期不为此建设通用路由产品。选择仍待按类型冻结，不把随机视为业界唯一方案。
- **类型业务管理员**：NetBox将对象类型、用户/组、动作和对象约束组合授权，其Custom Objects也将类型定义权限与对象数据权限分开。[对象权限](https://netboxlabs.com/docs/netbox/v4.4/administration/permissions/)、[自定义对象权限](https://netboxlabs.com/docs/custom-objects/permissions/)。本项目复用既有组织/虚拟组与B03/B04，建议显式授予某类型和组织内的业务管理范围、字段白名单及合法流程操作；不因为能配置类型便拥有全部实例。这个业务角色和干预边界是本项目设计选择，不能由外部产品权限模型直接推定已经批准。
- **响应、节点与整单指标**：Zendesk的首次回复通常指创建至第一次公开客服回复，渠道/SLA例外另行处理，不能直接等同接单；JSM允许分别设置SLA开始、暂停和结束条件。[首次回复定义](https://support.zendesk.com/hc/en-us/articles/4408821871642-Understanding-ticket-reply-time)、[SLA条件](https://support.atlassian.com/jira-service-management-cloud/docs/set-up-sla-conditions/)。本项目是内部协同，建议明确命名“首次接单响应”，简单类型一键确认并开始；有真实排队分析需要再拆两步。接单是持久业务事实，不要求所有类型额外增加一个状态。首批固定口径先于通用报表；独立归档仅在确有独立步骤时另计，不制造重复流程。K2入态计时保持不变，获准暂停和工作日历须另有配置，不能因接单指标而默改既有SLA。
- **逐流程通知**：Jira通知方案以事件和收件对象配置，接收通知仍受资源访问条件约束。[通知方案](https://support.atlassian.com/jira-cloud-administration/docs/configure-notification-schemes/)。本项目建议在已有D11上增加有限的类型/流程/节点条件，先给当前责任人及明确复核人所需待办，再按类型决定哪些普通事件通知知会人；既有风险抄送和其他强制通知义务不被普通偏好覆盖。站内、外发复用同一选择规则，差异只留在渠道投递，不另造通知中心产品。
- **AL和设备权限**：NetBox在对象查询中应用授权约束；OWASP建议秘密采用细粒度权限、集中管理、审计和避免明文日志。[对象范围](https://netboxlabs.com/docs/netbox/v4.4/administration/permissions/)、[秘密管理](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。本项目建议type/row/field资格贯穿数据入口，设备首期仍是目录、状态、人工登录入口；地址和可选账号分层，普通AL不存口令、token或私钥。是否需要专业凭据供给是另一个业务范围，不推定各厂商具备SSO，也不自建密码库。
- **按职责仪表盘**：Grafana明确说明可见的仪表盘不等于数据源查询已被限制。[数据源与展示权限边界](https://grafana.com/docs/grafana/latest/setup-grafana/configure-security/)。本项目采用服务端先过滤再聚合、明细和数字同一谓词；个人、类型运营和全局视图复用界面框架，资格分别授予。这里借鉴数据授权边界，不引入Grafana、不以页面隐藏替代数据权限。

这些取舍优先复用现有AssignedTo/CC、组织授权、D02事件、D11通知、D13投影和U02界面。真实人员负荷、专业凭据平台与内网接口尚未验证，仍保留mock；“已有行业依据”不等于真实接入通过。

## 当前确认与补估边界

两项**已提问但未答**仍为设备地址/可选账号与专业凭据的范围、业务管理员对未参与受限票的显式实例范围。其余候选须在下方具名窗口冻结：共享池轮询/认领、管理员干预白名单、接单/开始及首组指标、流程事件与知会矩阵；不把未回答或后继README授权当同意。品牌、公开体验和安全报告渠道另归[展示方案](../guides/open-source-presentation.md)，更早未决归[剩余议程](../review/owner-decision-agenda.md)，不重问既定原则。

X03原本可用私有独立存储与mock交付，不需要无条件等待整个R06/P7。若选在P6.3或更早启用真实AL敏感台账，应先拆出所需最小授权纵切、补净估并接入正式依赖/排程；完成前继续合成数据或关闭该真实入口。不能把本页安全前提视为已经完成拆价和排程，也不把整个R06强行前移。实现方负责存储/协议选择，所有者确认真实数据和业务启用范围。
