# 公共核心、私有扩展与兼容合同

日期：2026-11-11；2026-11-14按基础版先行细分交付。状态：目标设计，尚未实现。适用 X01/X02；本页具体化[平台演进](platform-evolution.md)，不把当前编译期注册描述为已支持免改核心的插件。

2027年1月试用、2月1日前的首个核心版按[最新首版计划](../phase6/first-usable-release-plan.md)交付；B1只是过程接缝出口，不代替风险/工单/TR/AL/消息联动及UAA公共实现。真实企业接入时间未定，合成兼容回归不等于公司激活获验。

## 1. 要达成的更新方式

公共核心保留 IAM、资源授权、工单/风险生命周期、能力入口和审计。公司内的设备模块、专有流程、供应商 SDK 和字段映射放在独立私有仓/进程，通过版本化合同调用核心。核心兼容升级时，私有模块无需跟着修改；确有不兼容时，由核心维护旧合同的兼容实现或显式新主版本，私有模块按约定窗口迁移。

这是一项可验证的兼容承诺，不是“任何未来版本永远不改”。核心能力的新业务语义不能由一个适配器自动猜出；安全漏洞修复也不要求保留错误行为。支持窗口与例外处理见§6。

当前实际接点：`internal/app/wire.go` 的 `InitializeApp` 及生成装配、`internal/router/router.go` 的 `New`、`internal/router/catalog.go` 的 `AuditRouteCatalog` / `AuditPageWriteBindings`、`internal/pkg/resource/registry.go` 的 `Register`；UI `src/store/modules/permissionRoutes.ts` 的 `resolveViewComponent` 只解析构建时已有视图。新资源通常还要改装配、路由、目录种子与 UI，并非现成的外置模块平台。

## 2. 四种扩展及默认选项

| 情形 | 承载 | 与核心的合同 | 更新责任 |
|---|---|---|---|
| HR/风险等上游协议不同 | 私有 connector 服务 | 标准目录/发现 feed 或公开业务 API | 私有侧维护上游映射；核心维护公共 DTO |
| 内部新增业务模块 | 私有扩展服务及自己的存储 | 核心能力 API、身份委托、受控导航/网关目录 | 各自升级；核心不导入私有仓 |
| 需要复用平台页面壳 | 标准页面配置，或单独构建的受信内部应用 | 导航、上下文、跳转/授权启动合同 | 首期允许新窗口/独立应用，不预设任意 JS 动态加载 |
| 核心业务自身扩展 | 核心代码评审内的模块 | handler→service→repository、内部 Port | 仍属于核心发布，不能叫零改核心插件 |

默认采用进程外 HTTP 合同，不采用 Go `.so` 热插拔。Go 官方记录动态插件的工具链、编译参数及公共依赖一致性限制，这与私有模块独立更新目标相冲突。[Go plugin 文档](https://pkg.go.dev/plugin)

不为每个 connector 必建独立仓：同一所有者、发布节奏及信任区可共用私有 integration 仓并分目录；独立凭据/发布/维护团队才拆仓。私有扩展模板沿用公共文档分类、格式检查和任务隔离，但不复制整份核心源码。

## 3. 核心一次性建设的接缝

X01在原8–12日内拆为三个出口，见[执行排期](../review/execution-schedule.md)：

- **X01-C，2–3日**：公共connector合同、可信服务/业务主体边界、出站和停用规则。
- **X01-B，P6.1，3–4日**：配置式受信应用、精确API/权限目录、最小同步身份接缝、导航和禁用。首版采用受审配置、启动校验及重启生效，不要求安装审批CLI或热切换。
- **X01-H，P7，3–5日**：完整声明包安装/审批CLI、活动版本切换和治理；按实际消费者完善多代兼容。

基础版B1必须实际跑通一个进程外合成query connector和一个参考私有应用，验证当前授权、配置替换/禁用以及**换endpoint/profile不改核心代码**。文档、类型声明或UAA离线模型不能代替端到端接线。新增合规模块只增私有制品及已支持的配置；确需新公共语义仍经核心合同演进，不能承诺任意未来模块零改动。

X02-Q可独立为D07等消费者提供只读接缝，不等完整导航宿主或D06/feed；D08启用发现feed才依X02-F。X03设备参考应用依X01-B、X02-Q和U02，不等X01-H或完整X02。

基础配置与后继声明包共用以下字段合同；首版只启用所需项，签名安装与多版本治理在X01-H完成：

| 字段组 | 最小内容/约束 |
|---|---|
| 标识 | `manifest_version`、命名空间 `extension_id`、制品版本/摘要、维护方、合同主版本范围 |
| 依赖 | 必需/可选 `capability_id`、合同版本；不能只凭核心程序版本判兼容 |
| API | 精确方法与路由模板、静态capability_id/contract_version与OpenAPI operationId映射、输入/输出schema摘要、读写/幂等分类、body/timeout限额；动态operation_id仅为业务效果身份 |
| 权限 | 独立页面与按钮权限；资源类型及数据所有者；默认不授予任何用户/角色 |
| 导航 | 名称、图标白名单、位置、受信应用引用；不允许内嵌脚本、任意 URL 或复用核心菜单码 |
| 环境 | `endpoint_ref`、`secret_ref`、数据区、网络出站允许项；声明包不含真实地址、口令或用户数据 |
| 生命周期 | 健康检查、停用策略、在途处理、保留/导出与删除规则、告警责任人 |

X01-B先审配置差异，启动时校验命名空间、依赖、路由/目录冲突和受信目的地；无效配置拒绝启用，不部分开放。X01-H的 `extension apply` CLI再增加签名/摘要、批准及基线CAS，同事务写目录与成功审计；活动配置成功后切换，失败保持旧版本。分进程切换用版本回执和对账，不声称一笔数据库事务覆盖所有进程。

当前目录主要由 SQL 迁移维护。引入声明式目录前必须补“目录来源归属”：核心迁移只修改核心拥有的行，私有包只修改自己的行；每项绑定保留来源键，卸载只撤自己的绑定，不能按 path 粗删共享授权。页面只挂 GET、写操作挂按钮的 B 案守卫同样适用。CLI是受审管理通道，不开放让普通请求注册任意反代/权限的接口。

已有`/api/v1`业务端点继续保留，capability_id/contract_version是静态能力引用，OpenAPI operationId映射接口定义，operation_id只标一次业务意图/效果。旧文档/线协议把这些混名的地方须按[共同合同](capability-invocation-contract.md)登记兼容映射，不能直接改历史字段；不要求客户端全改成`/invoke`。新扩展网关只路由已登记模板，规范化后拒绝穿越、任意上游、方法漂移、重复敏感头和超限输入，不能宽泛豁免L1。

## 4. 身份与资源授权

网关认证调用者并做 L1；数据所有者的服务负责 L2资源范围和L3动作条件。核心工单资源授权不自动覆盖私有设备资源。X01交付最小同步身份/逐请求授权接缝，X03在设备纵切中实现私有资源过滤/逐项检查与负例；X02只负责提供方数据适配。导出、计数、批量与深链须使用同一范围。

服务身份只能说明“哪个服务”。代表用户执行时，另外携带短期、签名、限定 audience/操作/资源/有效期的委托引用；扩展不得提交一个任意 `user_id` 请求核心信任。核心业务写入最终仍以当前权限、业务状态和确认/授权 grant 复验。凭据和当前会话不在浏览器、URL、消息或普通日志间透传。

第一条用户同步调用在 X01 内提供最小可验证的身份交换/逐请求授权，不依赖真实HR供给，也不等待完整 I02 才能做设备目录；可先选择回调核心授权检查，失联拒绝敏感操作。后台持续委托、无人值守写和凭据代用须等 I02。任何缓存都不延长被撤销授权的实际可用期；若将来为离线读引入有限缓存，必须另定撤销时限并明确退出敏感操作。

扩展拥有自己的库、迁移和数据责任，不导入核心 `internal/`，不共享表、跨库 FK 或直接查核心 PG。以核心公开 ID 关联，但撤销/删除/不可见需要事件或受权查询复核；外部引用不能反向授予核心资源访问。

## 5. 兼容边界与合同版本

| 版本 | 改变什么 | 不替代什么 |
|---|---|---|
| 程序/镜像版本 | 一个实现与制品 | API兼容判断 |
| API/事件/connector合同主版本 | 输入输出、语义、授权、错误与时序承诺 | 工单定义版本 |
| schema/能力目录修订 | 可兼容新增、可选能力、字段限制 | 数据库版本 |
| 工单发布定义/实例 revision | 业务规则与单个实例并发 | 网络协议版本 |
| 委托/授权 epoch | 当前授权有效性 | 能力或模型版本 |

兼容检查覆盖字段、默认值、枚举、时间/单位、排序/分页、错误、鉴权要求、幂等和完成语义。响应新增可选字段可兼容；客户端应忽略未知响应字段，但未知枚举需明确降级；请求写侧继续严格验证。新增必填字段、改变默认行为、把受理成功改成完成成功均不能冒充小版本兼容。参考[Google AIP-180](https://google.aip.dev/180)，本项目仍需语义场景测试，不能仅靠 OpenAPI diff。

事件消费者按稳定 event_id 幂等；schema 不认识应隔离并报告，不能成功 ACK 后丢弃；字段删除先有显式新主版本与双读/转换计划。公共 SDK只提供类型/签名/错误/分页与客户端，不含核心 repository、私有 SDK 或业务授权政策；HTTP实现允许非Go语言。utils 的最低 Go 版本变化和 HTTP合同兼容是两件事。

## 6. 部署前替换与部署后兼容验证

所有者已确认：目前未正式部署，允许协调直接替换旧合同，**不采纳本轮曾建议的6个月/两次发布保留承诺**。本轮变更要同步更新五仓候选、mock、SDK/生成物和文档并核验已有开发数据，不为不存在的正式消费者建设长期桥接。若发现仍在使用的私有消费者/不可丢在途数据，先清点和协调切换，不能假定无影响。

稳定公共端口与私有隔离仍是目标。首次正式部署（独立或企业模式）时登记对外合同/消费者及最低兼容基线；同主版本保持语义兼容，确需新主版本时按实际消费者给出迁移/退役窗口，不预先承诺固定月数。当前没有正式消费者不等于未来每次升级都强迫私有模块重写。安全例外有影响清单和替代/禁用措施，不为兼容保留漏洞。

基础版固定当前合同摘要及参考消费者，实测mock/HTTP connector同例和配置替换；不为尚不存在的正式消费者先建多代兼容平台。正式消费者登记后，发布矩阵覆盖支持窗口内旧扩展/adapter对新核心、当前扩展、最低与当前合同；N/N−1不能代替更长支持窗口。公共CI只运行合成fixture与参考扩展，私有CI运行真实SDK/字段测试并输出去敏回执。

X01-B验收：参考应用按受审配置/重启接入和禁用，无供应商核心差异；权限撤销、伪造用户和路径越权默认拒绝。X01-H再验声明包apply失败不部分生效、升级及支持窗口内兼容。X02/X03各验其connector/设备纵切；合成证据不能替代真实供应商认证成功。

### 6.1 首版可验的核心升级承诺

外部wire及业务语义合同独立于核心内部model、包结构和数据库版本；核心重构或自带迁移不向私有adapter暴露表结构。私有侧保持独立仓/进程/数据，不导入`internal/`、直查核心库或把公司SDK并入主仓。

在已登记、受支持的合同主版本内，旧输入、默认值、错误、权限判定接口及受理/完成语义保持兼容；新增能力/字段须可选且不改变旧调用含义。兼容不冻结当前授权，真实撤权和安全修复仍须生效。

首版必须固定一套旧参考adapter制品及合同，用**未修改的旧adapter对新核心实际HTTP运行合成契约回归**，验证查询/所选写、权限拒绝、错误和适用幂等结果。记录双方摘要及合同版本，不重新生成旧客户端来掩盖不兼容；这是一组可复跑组合，不是全代际支持矩阵，也不证明真实公司接口已通。

核心提供自身迁移和升级说明；私有配置/secretRef存于checkout之外或独立私有配置目录，公共仓只留模板，`git pull`不覆盖它们。操作者仍须按说明构建、备份、迁移、启动及验证；目标是少改或不改adapter源码，不保证任意未来pull只编译就能完成所有升级。

破坏性变化须显式新合同及受影响消费者/配置/数据转换清单，给出兼容转换或协调升级步骤；继续遵守当前未正式部署可协调替换的决定，不新增固定6个月或无限兼容承诺。首个核心版先交这条稳定接缝与回归，完整插件治理留X01-H。

[Microsoft API指南](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md)支持版本合同下既有消费者继续运行，[防腐层模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/anti-corruption-layer)支持内外模型语义隔离；本项目采用这两点，不照搬Azure路由、云组件或审批期限。

## 7. 排期与仍需裁决

X01在P6.0冻结合同，P6.1交X01-B基础接缝，P7交X01-H完整治理；X02-Q先交独立查询参考，X02-F在启用同步feed时交可靠提交/恢复。X03设备薄模块在P6.3交mock纵切；真实provider按选定顺序接入。服务拆分仍按E07取证，不能把进程外适配等同全部模块微服务化。

## 8. 企业统一认证与中央授权的附加约束

企业模式按[UAA合同](uaa-governance-integration.md)注册扩展资源，目录所有者定义稳定语义，中央负责其纳管角色/分配，本地/私有服务执行实际资源判断。外部身份或同名角色不能直接获得核心admin/superadmin语义；扩展默认不获授权，安装manifest不等于中央完成批准。

涉及身份/功能授权的X01-C设计先过E01-UAA-C的来源、稳定编码与撤权合同门，无关mock能力继续。B1可带入内网进行独立模式开发/试验，不等待完整UAA-P25–39日；通用身份接缝和服务间HMAC都不等于企业SSO或用户授权。选首个真实UAA供给时补公共P及私有R，中央撤权须传到已启用的策略/会话/扩展入口，失联不得由缓存无限延权。公司要求纳管的正式企业激活必须通过对应验收，不能用B1或参考扩展替代。

AI/MCP/RAG/skill不是B1前置。后继按实际消费的Query、身份、ACL及恢复子出口细分；A05/A06/A07现行整包依赖在正式排程调整前继续保留，不在本页直接删依赖。
