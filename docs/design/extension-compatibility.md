# 公共核心、私有扩展与兼容合同

日期：2026-11-11。状态：目标设计，尚未实现。适用 X01/X02；本页具体化[平台演进](platform-evolution.md)，不把当前编译期注册描述为已支持免改核心的插件。

## 1. 要达成的更新方式

公共核心保留 IAM、资源授权、工单/风险生命周期、能力入口和审计。公司内的设备模块、专有流程、供应商 SDK 和字段映射放在独立私有仓/进程，通过版本化合同调用核心。核心兼容升级时，私有模块无需跟着修改；确有不兼容时，由核心维护旧合同的兼容实现或显式新主版本，私有模块按约定窗口迁移。

这是一项可验证的兼容承诺，不是“任何未来版本永远不改”。核心能力的新业务语义不能由一个适配器自动猜出；安全漏洞修复也不要求保留错误行为。支持窗口与例外处理见§6。

当前实际接点：`internal/app/wire.go` 的 `InitializeApp` 及生成装配、`internal/router/router.go` 的 `New`、`internal/router/catalog.go` 的 `AuditRouteCatalog` / `AuditPageWriteBindings`、`internal/pkg/resource/registry.go` 的 `Register`；UI `src/store/modules/permissionRoutes.ts` 的 `resolveViewComponent` 只解析构建时已有视图。新资源通常还要改装配、路由、目录种子与 UI，并非现成的外置模块平台。

## 2. 四种扩展及默认选项

| 情形 | 承载 | 与核心的合同 | 更新责任 |
|---|---|---|---|
| HR/风险等上游协议不同 | 私有 connector 服务 | 标准目录/发现 feed 或公开业务 API | 私有侧维护上游映射；核心维护公共 DTO |
| 内部新增业务模块 | 私有扩展服务及自己的存储 | 核心能力 API、身份委托、受控导航/网关目录 | 各自升级；核心不导入私有仓 |
| 需要复用平台页面壳 | 标准页面配置，或单独构建的受信内部应用 | 导航、上下文、跳转/授权启动合同 | 首期允许新窗口/独立应用，不预设任意 JS 动态加载 |
| 核心业务自身扩展 | 核心代码评审内的模块 | handler→service→repository、内部 Port | 仍属于核心发布，不能叫零改核心插件 |

默认采用进程外 HTTP 合同，不采用 Go `.so` 热插拔。Go 官方记录动态插件的工具链、编译参数及公共依赖一致性限制，这与私有模块独立更新目标相冲突。[Go plugin 文档](https://pkg.go.dev/plugin)

不为每个 connector 必建独立仓：同一所有者、发布节奏及信任区可共用私有 integration 仓并分目录；独立凭据/发布/维护团队才拆仓。私有扩展模板沿用公共文档分类、格式检查和任务隔离，但不复制整份核心源码。

## 3. 核心一次性建设的接缝

X01-C先交公共connector合同、可信服务/业务主体边界、出站和停用的可验参考；X01-H再交通用注册/撤销、受控网关、身份传递、导航与兼容检查。完整X01完成后，新增合规模块只增加私有制品、环境配置与声明包；不能再为每个模块向核心增加一组供应商switch。D07的只读查询不要求整个导航宿主，依X02-Q；D08的发现接入依X02-F，二者仍须公共合同和真实HTTP参考负例，不能只凭文档存在开工。子出口继承包外部依赖，估算在原8–12日内分解，见[执行排期](../review/execution-schedule.md)。

建议声明包字段：

| 字段组 | 最小内容/约束 |
|---|---|
| 标识 | `manifest_version`、命名空间 `extension_id`、制品版本/摘要、维护方、合同主版本范围 |
| 依赖 | 必需/可选 `capability_id`、合同版本；不能只凭核心程序版本判兼容 |
| API | 精确方法与路由模板、稳定 operation_id、输入/输出 schema 摘要、读写/幂等分类、body/timeout 限额 |
| 权限 | 独立页面与按钮权限；资源类型及数据所有者；默认不授予任何用户/角色 |
| 导航 | 名称、图标白名单、位置、受信应用引用；不允许内嵌脚本、任意 URL 或复用核心菜单码 |
| 环境 | `endpoint_ref`、`secret_ref`、数据区、网络出站允许项；声明包不含真实地址、口令或用户数据 |
| 生命周期 | 健康检查、停用策略、在途处理、保留/导出与删除规则、告警责任人 |

计划中的 `extension apply` 管理 CLI 先校验签名/摘要、命名空间、依赖、路由与目录冲突，输出权限/导航差异和兼容结果。受权操作者确认后，以基线版本 CAS 同事务写目录与成功审计；受信网关仅在应用成功后切换活动配置。失败保持旧活动版本，分进程切换用版本回执和对账，不声称一笔数据库事务覆盖所有进程。

当前目录主要由 SQL 迁移维护。引入声明式目录前必须补“目录来源归属”：核心迁移只修改核心拥有的行，私有包只修改自己的行；每项绑定保留来源键，卸载只撤自己的绑定，不能按 path 粗删共享授权。页面只挂 GET、写操作挂按钮的 B 案守卫同样适用。CLI是受审管理通道，不开放让普通请求注册任意反代/权限的接口。

已有 `/api/v1` 业务端点继续保留，operation_id 是稳定能力目录的引用，不要求现有客户端改成统一 `/invoke`。新的扩展网关只路由已登记模板；解码/规范化路径后匹配，拒绝穿越、任意上游、方法漂移、重复敏感头和超限输入。不能靠宽泛前缀豁免跳过 L1。

## 4. 身份与资源授权

网关认证调用者并做 L1；数据所有者的服务负责 L2资源范围和L3动作条件。核心工单资源授权不自动覆盖私有设备资源。X01交付最小同步身份/逐请求授权接缝，X03在设备纵切中实现私有资源过滤/逐项检查与负例；X02只负责提供方数据适配。导出、计数、批量与深链须使用同一范围。

服务身份只能说明“哪个服务”。代表用户执行时，另外携带短期、签名、限定 audience/操作/资源/有效期的委托引用；扩展不得提交一个任意 `user_id` 请求核心信任。核心业务写入最终仍以当前权限、业务状态和确认/授权 grant 复验。凭据和当前会话不在浏览器、URL、消息或普通日志间透传。

第一条用户同步调用在 X01 内提供最小可验证的身份交换/逐请求授权，不依赖真实HR供给，也不等待完整 I02 才能做设备目录；可先选择回调核心授权检查，失联拒绝敏感操作。后台持续委托、无人值守写和凭据代用须等 I02。任何缓存都不延长被撤销授权的实际可用期；若将来为离线读引入有限缓存，必须另定撤销时限并明确退出敏感操作。

扩展拥有自己的库、迁移和数据责任，不导入核心 `internal/`，不共享表、跨库 FK 或直接查核心 PG。以核心公开 ID 关联，但撤销/删除/不可见需要事件或受权查询复核；外部引用不能反向授予核心资源访问。

## 5. 兼容边界与合同版本

| 版本 | 改变什么 | 不替代什么 |
|---|---|---|
| 程序/镜像版本 | 一个实现与制品 | API兼容判断 |
| API/事件/connector合同主版本 | 输入输出、语义、授权、错误与时序承诺 | 工单定义版本 |
| schema/能力目录修订 | 可兼容新增、可选能力、字段限制 | 数据库版本 |
| 工单发布定义/实例 revision | 业务规则与单个实例并发 | 网络协议版本 |
| 委托/授权 epoch | 当前授权有效性 | 能力或模型版本 |

兼容检查覆盖字段、默认值、枚举、时间/单位、排序/分页、错误、鉴权要求、幂等和完成语义。响应新增可选字段可兼容；客户端应忽略未知响应字段，但未知枚举需明确降级；请求写侧继续严格验证。新增必填字段、改变默认行为、把受理成功改成完成成功均不能冒充小版本兼容。参考[Google AIP-180](https://google.aip.dev/180)，本项目仍需语义场景测试，不能仅靠 OpenAPI diff。

事件消费者按稳定 event_id 幂等；schema 不认识应隔离并报告，不能成功 ACK 后丢弃；字段删除先有显式新主版本与双读/转换计划。公共 SDK只提供类型/签名/错误/分页与客户端，不含核心 repository、私有 SDK 或业务授权政策；HTTP实现允许非Go语言。utils 的最低 Go 版本变化和 HTTP合同兼容是两件事。

## 6. 部署前替换与部署后兼容验证

所有者已确认：目前未正式部署，允许协调直接替换旧合同，**不采纳本轮曾建议的6个月/两次发布保留承诺**。本轮变更要同步更新五仓候选、mock、SDK/生成物和文档并核验已有开发数据，不为不存在的正式消费者建设长期桥接。若发现仍在使用的私有消费者/不可丢在途数据，先清点和协调切换，不能假定无影响。

稳定公共端口与私有隔离仍是目标。首次正式内网交付时登记对外合同/消费者及最低兼容基线；同主版本保持语义兼容，确需新主版本时按实际消费者给出迁移/退役窗口，不预先承诺固定月数。当前没有正式消费者不等于未来每次升级都强迫私有模块重写。安全例外有影响清单和替代/禁用措施，不为兼容保留漏洞。

每个声明包发布时固定合同摘要与合成样例。发布矩阵至少覆盖：旧扩展/旧adapter对新核心、当前扩展对新核心、核心最低合同与当前合同、mock与connector同例的语义结果；N/N−1只是候选实现组合，若支持窗口包含更多版本就增加组合，不能以测试两版代替整个支持承诺。公共 CI只运行合成fixture与参考扩展；私有 CI运行真实 SDK/字段测试并输出去敏合同回执。

X01验收：新参考扩展无核心差异地登记/禁用；相同合同的核心升级后旧客户端无需重编译；破坏性修改被协议/语义测试拦截，部署前经协调的替换有显式新基线；权限撤销、伪造用户、路径越权和部分apply失败均默认拒绝。X02用内网connector、X03用设备纵切分别验证，mock证据不能替代真实供应商认证成功。

## 7. 排期与仍需裁决

X01在P6.0冻结合同，P6.1实现最小接缝；X02在P6.1先做HR/发现feed参考connector，P7逐提供方切实接入；X03设备薄模块在P6.3交付mock纵切。服务拆分仍按E07取证，不能把进程外适配等同全部模块微服务化。

部署前可直接替换已确认；私有扩展交付优先级及受信内部应用接入方式在对应实施窗口裁决。实际字段、签名、路由细节由实现包评审冻结。当前没有声明包管理器、外置页面加载器或跨版本回执，不得用本设计宣称已有能力。
