# 07 — P5-S7 AI 助手（概要登记——已拍整段后置）

> **段属性**：**已拍后置（2026-10-09 所有者）**——形态与 LLM 供给均未清楚，先登记不做、不超前建设；**不计入 phase5 基线段**，无量级、无迁移、无排期。
> **文档定位**：薄设计稿（2026-10-15 建档，phase5 分支）——登记定位/演进设想/重启条件/预留接口，**细节启动批（重启立项时）定**。立项 = dd §27（2026-10-08 第五轮）。

## 1. 定位（概要）

平台内嵌 AI 对话助手——用户在平台内与 AI 对话；长线设想 = **AI 参与并协助业务工作**，而非纯聊天窗。

## 2. 演进路径（设想，未定）

- **第一档**：平台内对话（产品使用/数据问答）。
- **第二档**：**AI 协助业务操作**——所有者示例场景：AI 协助风险员工对风险事件做**定性分析**、自动**关联资产系统**、找出**责任人**并**自动下发工单**（function-calling 代操作形态）。场景载体 = [phase6 风险模块](../phase6/README.md)。

## 3. 启动批拍板点（仅登记方向，重启时逐项拍）

1. **LLM 供给与接入方式**：企业内网可用模型 / 公司统一 AI 网关 / 外部 API——内网环境敏感项（与 M-Mig 背景相关）。
2. **交互载体**：参考 fastclaw 的平台内对话形态。
3. **AI 代操作权限边界**：必须**收敛于操作者自身权限**（AI 不得成为越权通道）+ 操作留痕审计。
4. **工具调用面**：哪些 API 开放给 AI。

## 4. 重启条件

待**业务数据/场景明确**（如 phase6 风险模块跑起来后的 AI 协助诉求）**+ LLM 供给落地**后，重启立项（另立立项登记，本文件届时扩为设计稿）。

## 5. 预留接口

接入层 = **`LLMProvider` 端口**（Chat/Complete/Tools；外部 API 起步，内网模型/公司 AI 网关 = 换 adapter——[README §6](./README.md) 清单第 5 行）。选型预置（建议值）：自写轻量 `LLMProvider` 接口 + **OpenAI-compatible HTTP 实现起步**（多数网关/模型兼容），不引 langchaingo 类重框架（绑定度高）。

## 6. 边界（不做）

后置期间**零投入**：不建对话壳、不接模型、不做工具注册——防"形态未定先铺基建"（与 S3b"无消费者不建引擎"同一纪律）。
