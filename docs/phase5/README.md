## 0. 一句话

把工单域与任务域的"配置面"从手填/JSON 源码兜底升级为前端可视化，并补齐富媒体、消息通知、情报缓存与工单协作底座，十段递进：**表单可视化设计与字段自动化（S1）→ 流程状态图可视化设计（S2）→ 流程运行语义配置化（S3，**已解冻**拆 S3a/S3b——S3a 2026-10-19 升格排期 W13–15）→ 管理面配置人性化（S4：taskrunner 任务面）→ 对象存储底座与富媒体（S5，RustFS）→ 消息通知（S6：统一消息平台 + 模板 + 工单触发）→ AI 助手（S7，形态未定）→ 数据大屏（S8，🚦 后置）→ 威胁情报缓存代理（S9）→ 工单协作与提醒（S10：抄送/标签/角标/节点超时/导出）**。S2/S4 前端为主、存储契约零破坏；S1 前端为主 + 字段求值器小后端件；S5 为公共底座段（IW2 收编）；S6/S9/S10 后端为主（S6 = P4-2 通知通道的能力延伸；S9 = 外部限流 API 缓存代理通用件；S10 = 2026-10-09 场景差距分析产出）；S3 后端为主（**已解冻**拆 S3a/S3b——S3a 2026-10-19 升格排期 W13–15 纳入收官；S3b 等首个真实审批场景）；S8 触发驱动后置。

## 2. 范围：十段递进

### P5-S1 动态表单可视化设计器与字段自动化（前端为主 + 求值器后端件）

- **渲染器已在位，设计器选型已拍**：工单发起=自研七类型轻量渲染器（W4 交付；form-create 库引入决策顺延至设计器批，`views/ticket/create/index.vue` 头注释）——**设计器选型已拍（2026-10-15 所有者）：自研设计器**（sortablejs 拖拽排序 + 属性面板，产物即 field schema 零映射；选型论证深化详录 [01 号 §3.1](./01-s1-form-designer.md)——view model ≠ domain model 正论/业界对标/四路线代价账；form-create designer 半天 spike 降为**对称验证**——其 rules/options 组件树 JSON 与规范化 schema 不同构，引入需双向映射器+面板裁剪到七类型，高级布局能力用不上，模型税大于成熟度收益；form-create runtime 作渲染引擎备选在案，触发驱动）。[12-frontend「阶段 2（远期可选）」](../phase3/12-frontend.md) 随本段转正。
- **后端存储不变**：产物仍是 `ticket_type_fields` 字段 schema；字段类型基线七种（input/textarea/number/date/select/multi_select/tips）+ **richtext 第八种随 S5 扩入**（设计器调色板预留，见 [05-s5 §6](./05-s5-object-storage-richmedia.md)）。
- **select/multi_select 选项引用 P4-3 字典**（已随 P4 交付，`/dicts` + `/dict-items` 各四端点已核）：设计器选项支持挂字典键而非死枚举，选项变更全系统生效。**人员/部门类字段自动补全（2026-10-09 场景补充）**：指派/抄送/参与人选人走既有用户搜索端点；M-HR 对接后（HRFetcher）组织人员数据入本地表，补全零额外对接——依赖 M-HR 触发，不阻塞本段。
- **字段自动计算/联动（2026-10-08 所有者场景补充）**：① **计算字段**——按已填字段公式自动算出派生字段，落点=字段 schema 扩展（**新列 `field_meta` JSONB 增 formula**——01 号附录 A.2 方案 b，2026-10-16 对齐）+ **服务端求值为 SSOT**（提交时后端算入 `custom_data`，前端仅预览展示——防篡改与现有哲学一致）；② **提交时条件取数回写**——按字段值判断后从数据源取数自动写入字段，落点=字段联动规则（数据层自动化，非流程层），取数走 `DataFetcher` 端口（按 source 类型注册 fetcher——见 §6 对接预留清单）。**求值器统一为白名单 Go 侧表达式求值器**（phase3/10 §4.2 既定路线；easy-workflow 表达式拼 SQL + 黑名单防注入为反面教材），字段公式（本段）与网关条件（S3）共用一件。**两个启动拍板点**：取数数据源白名单（内部资源/activelist/外部 HTTP——外部回到 §26.6 出站决策树）；取数身份（系统身份 vs 发起人代理——L2 可见性边界）。量级 +3–5 天（求值器为公共件）。
- **编辑时预填 auto_fill（2026-10-16 所有者场景登记——phase6 实际场景驱动；触发驱动挂账不入基线，消费者 = phase6 R3）**：formula 之外的第二种联动语义——**建议预填**：编辑时按已填字段实时带出（如填 IP → 查 CMDB 带出责任人）、UI 标注"自动带出可修改"、提交信任用户值（区别于 formula 服务端强制覆盖）。承载 = `field_meta` 新列扩 auto_fill 元数据（触发字段 key + fetcher 类型 + 字段映射，与 formula 同列——附录 A.2 方案 b，**执行时机双态预留**——本段实现只做提交时取数，编辑时预填留 phase6 R3 启动消费）；CMDB 登记 DataFetcher 白名单实例（拍板点覆盖，零新拍板）。业界同型 = ServiceNow auto-population / Salesforce lookup 带出 / 低代码「数据联动」。详录 [01 号 §3.3③](./01-s1-form-designer.md)。
- 新字段类型 = 另立后端批：渲染器 + `validateFieldInputs`/G2 schema 校验同步扩，遵守"只增不改"兼容纪律，不混入 S1。
- 现 ticket/type 页表格模式保留为**专家模式/兜底**（phase4 深水区降级决策的形态直接复用）。
- **字段变更在途影响分析（2026-10-09 隐藏需求核查补遗，与 S2 改图告警对齐）**：字段保存=全量替换（`ReplaceTypeFields` DELETE+重插，对存量 `custom_data` 零检查——`ticket_repo.go:780-792`）；本段引入 formula（计算字段引用其他字段 key）与 S6 模板变量引用后，**保存前须做影响面告警**：被 formula/模板引用的字段、存量单含该字段数据 → 告警确认（半天级，防"引用字段被删/改 key → 公式与模板静默失效"）。
- **详情页 custom_data 回显收编本段（同日补遗）**：现状 zhuzhao-ui 仅 create 页提交 custom_data，detail/list 页**零渲染**（代码核实）——自定义字段"填了看不见"，与"keyword 仅搜标题"同级的台账硬伤；随本段渲染器批补详情页按 schema 回显（≤1 天）。
- **字典引用守卫（同日补遗）**：select 挂字典键后需注意 dict_types/dict_items 现为**无守卫硬删**（`dict_repo.go:90-99`）——挂接批补守卫（存在引用 schema → 拦截或告警）或拍"禁用不删"使用纪律；org 删守卫不查 org_roles 教训同型。

### P5-S2 流程状态图可视化设计器（纯前端为主）

- **采用现成拖拽画布组件，不自研画布**：✅ **已拍（2026-10-15 所有者）：LogicFlow 优先**——spike 仍跑（vue-flow 同日对照，各 0.5 天同一 PoC：拖节点/连线/序列化回 transitions/回显）作**对称验证**，按映射成本+交互手感+包体终定实现；AntV X6 备选（能力过剩）；bpmn.js 排除（BPMN 2.0 标准模型与 transitions JSONB 不匹配且过重）。数据面：状态=节点、转换=边，与 `transitions` JSONB **天然同构**，映射器为浅层翻译。
- states/transitions 画布化：节点=状态、连线=合法转换，产物序列化回现有 transitions JSONB，**后端零改动**；中文化与交互打磨计入量级。
- **分层要求（2026-10-08 所有者问询后定）**：画布层（LogicFlow/vue-flow 封装+交互）与 schema 适配层（transitions 映射器）**分离**——任务域将来若立流程设计器可复用画布层、只换适配器；但**引擎与数据模型不合并**：工单流程=人触发的实体状态图，任务流程=完成事件驱动的执行编排，不同构——任务侧编排维持 16 号红线（不做通用流程引擎，轻编排走 zhuzhao 回调串联、重编排走外部 DAG [phase3/15](../phase3/15-script-platform-dagu-vs-inhouse.md) GPL 法务前置），不得为复用而把两者捏成一个"通用流程模块"。
- 可选校验增强批（纯增量、向后兼容）：`validateTypeGraph` 现只查端点在 states 内，可加 lint 级检查——终态可达性/孤立状态/无出边死锁告警（是否阻断保存待启动拍板）；**改图影响在途单告警（业界轻量实践，2026-10-08 对标 Jira 在途迁移后的取舍——迁移向导过重不取；2026-10-09 第四线建议升级为必做，采纳——成本半天、防"改图后在途单僵死"实险）**：保存图时扫描在途工单状态分布，存在将脱离新图的状态（改后 AssertTransition 恒拒=工单僵死）→ 告警确认。
- **工单高级搜索（触发驱动，2026-10-09 第四线登记）**：keyword 现为 title ILIKE+纯数字 ID 精确匹配（ticket_repo.go:145-154），custom_data 自定义字段筛选缺失是台账类使用的硬伤，诉求出现时启用（PG JSONB 谓词，量级与检索形态启动批评估）。

- **触发层**：工单状态流转/待办 → 选模板 → 字段值填参 → 解析收件人 → 经统一消息平台发送。**启动拍板点：挂接机制**——a) 显式 emit（状态变更 service 层调用，C10 风格，推荐起步）；b) ticket_events 消费面（phase3/10 原设计——但事件表无 processed 列/无消费面，P4-2 交付时未含，选 b 需补迁移）。**触发面须域无关（2026-10-08 phase6 复核回写的要求）**：触发源与收件人声明不得焊死工单域——phase6 风险事件（新增/指派/超期/关闭，收件人 = risk owner 非工单字段）将复用同一模板/通道/触发面；若选 emit 须做成**可订阅内部钩子**（工单状态变更事件面 = S6 与 phase6 的共享基础设施，一次变更多订阅者，见 [phase6/README §3](../phase6/README.md)）。**投递语义（2026-10-09 隐藏需求核查补遗）**：触发挂接须**异步投递**（状态变更事务外；发送失败不阻塞、不回滚工单事务——通知无状态可补发，同步阻塞反拖累主路径）+ 同单短时多变更的节流/去重（防通知风暴）。**人读编号前置（同日补遗）**：工单当前唯一对外标识=字符串化自增 id（`model/ticket.go:10`）——通知正文"哪张单"无可引用、跨团队核对困难；建议本段随批落 `TK-yyyymmdd-NNNN` 形态编号（新列+Create 时生成，存量单维持 id；若不随批，模板先只引用链接不引用编号）。
- **发送记录**：`message_log` 表（模板/收件人/状态/错误/重试）+ 管理页；失败复用既有死信告警链。
- **三条设计约束（2026-10-09 隐藏需求核查）**：① 模板默认保守——预置种子模板只含工单编号+标题+平台链接，**不含越 L2 才可见的字段**（防模板内容泄漏越权信息；更丰富模板由管理员自担）；② 投递异步+**节流去重**（同工单同事件窗口去重，防状态翻转通知风暴）；③ 人读编号（TK-… 形态，可选随批——列表/通知/导出统一用人读号）。

### P5-S9 威胁情报缓存代理（概要登记——通用件，细节启动批定）

- **定位**：对**已有威胁情报 web 应用做能力补全**（应用本体不动）——解决其每日/每小时查询配额限制。技术形态 = **外部限流 API 的缓存代理**（通用件），威胁情报是首个消费者；**消费方 = phase6 风险模块 R1**（风险事件情报源之一）。
- **查询流程**：查询 → 先查本地缓存库（命中直接返回）→ 未命中调上游接口 → 结果入库带 TTL。
- **缓存设计要点**：缓存键 = 情报类型（IP/域名/hash 等）+ 查询值；**TTL 双档 7 天/30 天**（按指标衰减特性配置）；**配额耗尽降级策略**（返回过期缓存标记陈旧 vs 明确报错——启动拍板点）；可选第二档 = 高危指标后台批量刷新。
- **依赖**：上游应用 API 契约（查询接口/认证/限流数值）由企业方提供；调用凭据入配置管理。查询走 `ThreatIntelProvider` 端口（接口 + 通用 HTTP 实现 + config 挂点——§24 SSOProvider 同款预留模式：契约到位填配置即用）。
- 量级 ≈ 1 周（缓存表 + 查询代理 + TTL 管理）。

### P5-S10 工单协作与提醒能力（2026-10-09 真实场景差距分析产出）

**「角色壳」落地方案（2026-10-09 所有者"套壳"问询后设计——形式 b 的具体实现，谈判首选）**：UAA 配 3–5 个**粗粒度应用角色**并在其界面做用户分配（满足其权限管理存在感，非糊弄——Keycloak role mapping/Okta app roles/Azure AD app roles 同款业界标准）；zhuzhao 登录 callback 按角色 claims **覆盖式同步**本地绑定（`uaa_roles → 本地角色` 映射表，单向收敛——本地特有细角色不反向暴露），之后 L1/L2/L3 照常。**四个实现拍板点**：①映射方向单向收敛；②fail 策略 = AT 有效期内不重查、仅登录/刷新时同步（天然降级，UAA 故障不断已有会话）；③审计 = 登录同步落角色变更记录 + 可选定时对账任务（防长期未登录用户角色漂移）；④壳厚度分级——**L0 壳**（UAA 只管应用准入/scope，角色平台自算）起谈，UAA 要存在感升 **L1 壳**（粗角色）。代码影响：`getRoles` 数据源接映射结果，Casbin/L2/L3/菜单渲染零改动（角色绑定进数据、判定在本地——接缝天然存在）。
