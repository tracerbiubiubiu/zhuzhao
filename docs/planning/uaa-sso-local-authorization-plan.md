# 公司仅 SSO、本地授权实施计划

> 用途：按 2026-11-26 所有者确认，B4 本地账密正式运行稳定后，UAA 开发优先交付公司认证、本地授权。
> 状态：已纳入设计，待实施、单独净估和真实认证验收。实施取证按当前开发指南及独立工作树分工执行。
> 权威：[UAA 接入合同 §5.2](../design/uaa-governance-integration.md#52-公司仅负责-sso应用管理权限与菜单) · [首发和现场顺序](intranet-uaa-release-schedule.md#进内网后按什么顺序做)

## 当前证据与实施范围

早期 M-SSO 已提出公司认证后由本地签发会话、沿用三层鉴权。现行合同也保留认证与治理两个接缝，但此前只为本地独立运行和完整纳管定义了启用路径。当前 `internal/router/router.go` 的认证路由仍接本地 `AuthService.Login` 和 `Refresh`，没有 SSO 入口。既有治理参考 mock 使用合成的授权数据和逻辑时钟，覆盖投影与故障政策，产品登录和本地菜单权限回归由本计划另验。 [历史目标设计](../design/design-decisions.md#24-公司-sso-对接oauth20-授权码模式预留接口版2026-09-02-所有者拍板) · [参考 mock 的覆盖边界](../design/examples/uaa-reference-mock/README.md)

员工经公司认证，Core 按受审绑定查询既有本地用户并签发本地会话。业务请求继续使用本地角色、组织、菜单、资源与动作规则。复用现有会话和鉴权链，共享认证接缝供未来 B5 使用。B4 继续本地账密首发，完整 B5 保留治理、同步和接管门，当前合成合同和冻结估算沿各自原范围。

按本地核心稳定出口转入主研发交付。协议联系、公共合同和合成用例准备可先行。核心阶段只承接已确认业务及公共认证/授权接缝。仅 SSO 的实施依赖 B4 候选中实际使用的 C05 会话撤权、C04 当前授权及本地主体接缝；HR/三类权限 feed、X02-F、完整治理 P/R、企业 MCP AS、全站 U06 各按自己使用的范围排期。完整 B5 仅在公司要求纳管或所有者另行批准后立项。若公司只批准完整纳管，从 B4 按完整 B5 条件联调及切换；已验的认证成果可按实际兼容范围复用，权限接管须独立取证。 [主研发产能与放行](owner-decision-agenda.md#核心稳定证据与业务接受q12-执行动作)

## 1. 公共认证合同与身份绑定

主责 **需求与架构设计师（GLM）**，交叉复核 **防御性安全与权限审查者（Codex）**。先完成本项，Core 与 UI 按其契约并行。

- [ ] 写定 Core 与私有认证适配器交换的最小已验证身份、来源和错误；冻结浏览器登录发起、回调、错误和会话交付合同及后端入口开关。公司实际协议留给内网核验；合成画像按现行合同的授权码方向选一条流程。
- [ ] 明确预建号、绑定、解绑、改绑的审批、审计、唯一性、凭据生效顺序与回退；标明账号、目录属性及权限的本地写主。按绑定和撤权所需的最小持久状态评估 DDL，实施时才按迁移地图编号。
- [ ] 交付合成合同用例：相同工号或邮箱的不同外部身份不自动绑定；同一外部键的并发绑定只能有一个成功；未知、冲突、改绑未生效和停用账号均不得签发凭据。Core、UI 和内网实施方用同一份验收契约。

## 2. Core 登录、会话与本地鉴权

主责 **工程实现者（Codex）**，交叉复核 **验证与验收者（DeepSeek）**。依赖第 1 项约定及 B4 候选中的当前账号与撤权能力。

- [ ] 先把身份交换、登录失败、改绑或停用与会话签发/刷新交错的预期加到候选自动化测试；断言撤销后访问和刷新被拒，缓存投影失败也可安全收敛。认证侧覆盖回调事务过期、一次性消费、来源不匹配及回跳目标限制。
- [ ] 接入受限认证端口与已批准绑定，复用 `internal/service/auth_service.go` 的 `issueTokenPair`、`Refresh`、`Logout` 所在会话链及 `internal/middleware/jwt.go` 的 `JWT`。复用 `internal/service/session_security.go` 的 `CheckProjectionReadiness` 检查，并用绑定版本、本地状态与会话代际保护签发，签发与刷新均携带或能查到原认证来源和绑定版本，用于审计、解绑、改绑和停接撤销。断言解绑、改绑生效后，旧访问、刷新及派生文件会话全都拒绝。切换为仅 SSO 时，证明试点账号原账密会话失效。停用同样验证访问、刷新和文件会话。永久离职或凭据失陷时按政策显式吊销 PAT，核验实际启用的委托和后台入口。试点登录策略由后端按目标账号执行。
- [ ] 用固定合成身份改本地角色和角色菜单，确认现有会话按当前策略生效。覆盖 `UserService.SetRoles`、`RBACService.AssignMenus`、`MenuService.GetUserMenus` 和代表工单的 L1/L2/L3。外部角色声明对权限没有影响，未开启 SSO 时本地登录和鉴权可独立运行。真实 UAA 不可达时用合成 IdP 验新登录及既有会话策略。

## 3. UI 登录、导航和浏览器回归

主责 **工程实现者（GLM）**，交叉复核 **产品体验设计者（Codex）**。依赖第 1 项约定；和第 2 项独立开发，之后用同一 Core/UI 候选联验。

- [ ] 用 `zhuzhao-ui/src/api/auth/index.ts` 的现有认证调用边界，以及 `zhuzhao-ui/src/store/modules/user.ts` 的 `loadSession` 和 `resetState`，接入公司登录按钮、回跳、取消和可重试错误；继续从本地目录加载菜单和按钮权限。服务端消费认证回调后再回跳 UI，回跳不携带公司授权码、公司令牌或本地 AT/RT。日志与用户提示只保留获准的错误分类及关联号。Core 对 `internal/middleware/logger.go` 的 `AccessLogger` 回调查询串和入口代理日志做脱敏回归，覆盖成功、失败和异常。
- [ ] 浏览器验同一已绑定账号由公司登录后看到原菜单和工单；改一个本地角色菜单，刷新后界面与接口结果一致。另验无权限 API 拒绝、过期会话、本地登出、错误回跳和试点账号密码入口限制。同一浏览器切换账号时清理原会话、动态路由和用户缓存。未启用时确认本地密码登录与首发业务旅程可用。
- [ ] 对第 2、3 项固定 Core、UI 与合成 IdP 制品或版本，隔离运行质量门、适用普通档全量验收和浏览器专项。记录本地模式、合成 SSO 和本地权限改动各自证据。

## 4. 内网认证联调、试点和回退

主责 **发布与运维评审者（GLM）**，交叉复核 **验证与验收者（DeepSeek）**。依赖第 2、3 项隔离验收以及本地核心稳定出口和获准内网测试窗口。

- [ ] **进入联调**。确认公司允许仅接认证；获取测试应用、协议、可信稳定身份键、回调、网络与证书，逐项核验中央注销、停用信号和测得的传播时效。实际配置、身份材料和原始证据留在批准的内网环境。
- [ ] **批准并产生试点证据**。私有适配器只交已验证身份，生成只读绑定预览，隔离冲突。首批真实账号启用前，所有者批准试点名单、时效、停用、应急及回退方案。实际提供可信注销信号时，验证信号关联的 SSO 会话及旧访问、刷新和派生文件凭据失效；实际提供可信停用信号时，验证本地停用按时生效并阻断已启用的 PAT、委托和后台入口。缺少可信信号时，先演练获批会话总寿命（含刷新）和离职本地停用流程。试点同时验证本地角色与菜单改动、公司服务故障和回退，核原用户 ID、工单归属与审计历史。
- [ ] **放行或停止**。身份错误、会话超出批准期限、授权结果偏离本地事实或回退失败时停止扩批。所有者在试点通过后另行批准正式启用范围和窗口，并确认会话及离职撤权政策、预备维护入口和回退清单。回退先关 SSO 和撤销该批 SSO 会话，再按批准清单恢复本地密码入口或凭据，核获准保留的本地会话仍可用。B4 本地正式验收、真实 SSO 试点/启用、完整 B5 接管分别保存证据。

## 验收与净估

- **身份与会话**。未知账号、冲突和失效绑定均拒绝且无写入；身份交换失败没有本地会话；本地停用、登出、改绑、SSO 停接分别验证有效凭据的结果；真实环境核验公司端可兑现的注销和停用语义。
- **权限与菜单**。用无角色、仅可读和可办理三种本地账号对照，验证菜单、按钮、直接 API、资源范围与动作执行。撤角色或角色菜单后检查既有会话，确认该撤的权限生效且合法独立授权仍可求值。
- **部署与退出**。无 UAA 配置、私有适配器禁用及 UAA 不可达分别验证 B4 能启动、能本地登录。仅 SSO 首批用真实认证接口和获准样本验关闭、撤销、恢复。公司要求治理时按完整 B5 的真实条件验收。 [完整纳管的真实条件](uaa-real-integration-conditions.md)
- **复用与计价**。按本页四项分别登记工程预期、适用的共用成果和验收证据。实际开工前按选定协议、身份和撤权供给净估；额度仍待定。后续若启动完整治理，从 P/R 对照基线扣除已验证可复用的认证、绑定、最小 UI、会话回归或运维演练，只计治理净增。外部等待另列。
