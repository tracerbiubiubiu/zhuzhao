> 本页供桌面走查和实施后的验收使用。按约一人产能和两条合成风险准备。实际开工日 T0、实施授权及真实试用另在对应窗口确认。
> 以[人工风险整改（B2）与持久撤权（C05）开工计划](phase6-b2-kickoff-plan.md)及其规划基线为依据。实跑时重新绑定候选 SHA、制品和隔离资源。所有者待确认事项统一见[决策议程](owner-decision-agenda.md#详设审计后的排产选择)。

「通过」须证实预期动作、落库及回读。「拒绝」须证实指定的终态或业务拒绝原因，目标业务无额外效果。「待核查」指提交结果未知，须用原标识核实。「待恢复」指已知的业务事实尚有后继待完成，依原意图恢复。缺证据、配置串栈或故障未命中时，该轮无效。拒绝留痕按既有合同核对。

卡一验证[账号停用与投影恢复](#卡一-c05-停用已提交而撤销投影失败)，属于会话终结与认证增强收敛（工作包 C05）。卡二验证[两条风险共票并逐项复测](#卡二-b2-两条合成风险共票并逐项复测)，对应人工漏洞整改（发布验收点 B2）。真实试用的环境、角色、数据与停止办法按首发与恢复、保留政策（议程 Q12）确认。 [常见编号怎么读](README.md#常见编号怎么读)

卡一可沿现有的停用、刷新、受保护读和文件代理准备隔离检查。管理员查原操作 K 的回执属于 C05 候选，故障注入由 G04 隔离装配提供。卡二可用现有工单分派和字段编辑理解旅程，风险台账、派单和逐项复测仍是候选。正式执行两卡前，按实际候选绑定入口、输入和可观察的拒绝原因。 [风险接口候选](../phase6/risk-module-detail.md#2-写主模块端口和公共类型)

## 卡一 C05 停用已提交而撤销投影失败

**要验的断点**是账号停用已在 PG 提交，旧 Redis 会话状态仍可读，目标撤销投影暂时写不成。使用实际停用 `POST /api/v1/users/status`、刷新 `POST /api/v1/auth/refresh`、文件代理 `GET /api/v1/files/*key`，另选同候选内可核当前权限的受保护读入口用于 Bearer/PAT。复核四种凭据的 HTTP 拒绝，以及重启和恢复后的原回执。[C05 合同与 SESSION 用例](../phase6/foundation-iam-module-detail.md#43-c05切换恢复与独立验收)

### 前置与有效性检查

- 使用独占真 PG、Redis、应用和文件对象夹具，固定实际 API 与代理目标。用专属合成账号分别承担停用管理员、目标账号和同线路仍获权的控制账号。目标与控制账号的凭据在测试窗口内有效，角色和目标资源范围在用例期间固定。每次操作沿[开工计划的隔离装备](phase6-b2-kickoff-plan.md#3-隔离装备与验收交接)校验归属。
- 停用前目标旧 Bearer 和仅 cookie 的文件请求都应成功。PAT 用符合当前业务权限的受保护入口确认成功。预留有效 RT 槽给停用后的探针，刷新正向控制使用独立设备槽，避免预先消费试验 RT。候选上的凭据须在停用前由本候选按当前 schema 签发。基线红例用基线自己签发的有效凭据。
- 记录目标账号启用状态、候选当前代际和投影水位、稳定操作引用 K、原有会话状态和资源读回摘要。冻结服务端实际判定原因的观测点。全程只记录引用、状态与差量，凭据及文件内容使用合成夹具并留在隔离环境。
- 仅阻断目标账号的撤销投影写，保留旧 Redis 值可读。记录注入点的实际命中及读回。在同一服务和路由用仍获权的控制账号证实正常。逐凭据记录校验、实际进入当前账号判定及读取 PG 停用事实的请求关联证据。到期、签名或 schema 错误、资源无权、限流 429、整库不可用及通用 503 均使本轮撤权断言无效，另开对应变体。
- 实跑前将逻辑回读绑定实际存储、唯一键、受权查询入口、响应原因和 UI 提示。由仍获权的管理员用 K 查询原命令、目标、已提交事实、结果代际和投影状态。独立读回唯一 `session_projection` 意图、目标、`expected_epoch`、`desired_active=false`、租约/fence 和完成状态。PG 回执证明本地提交，实际确认与水位共同证明投影恢复。[持久安全事实与回执](../phase6/foundation-iam-module-detail.md#42-c05的有限持久方案)

### 顺序、判据与证据

| 顺序与动作 | 判据 | 需要回读的证据 |
| --- | --- | --- |
| 1. 固定 K 提交停用，持续阻断目标投影 | **通过本地提交，投影待恢复。** PG 原子保存停用、新一代、原回执及唯一投影意图。投影水位仍落后，旧 Redis 状态可读。管理端表达已提交、清理待恢复。 | 从独立 PG 观察连接读已提交事实和差量。记录 K、意图身份、命中和旧 Redis 摘要。若丢失首次响应，通过已知 K 受权查原结果。 |
| 2. 保持故障，尝试用旧 Bearer 读受保护资源，再走仅 cookie 的有效文件路径 | **终态拒绝。** 当前账号已停用。请求无受保护数据或文件内容输出。 | 真实 HTTP 响应、认证原因、目标业务读回及同线路控制账号成功。分别验证 Bearer 与无 Authorization header 的 cookie 请求。 |
| 3. 用预留旧 RT 刷新，用原有效 PAT 请求受保护入口 | **终态拒绝。** 旧 RT 无新 TokenPair 或会话 cookie，原槽未被请求消费或替换，无新代槽。PAT 因账号状态拒绝，保持其自身生命周期账。 | 按候选的账号/代际/设备定位原刷新槽，比对前后存在状态和不含秘密的差量。独立设备槽刷新正对照成功。用启用账号的到期 PAT、已撤 PAT 和仅数据库不可用三个变体验实际原因，结合冻结的响应合同与认证分支取证。 |
| 4. 保持投影失败，由当前获准管理员尝试再次启用，再受控重启应用 | **拒绝启用，原操作仍待恢复。** 启用请求有常规权限且单独绑定操作号。账号继续停用，重启后从原 K/意图看到未完成事实。以同一 K 重交原停用命令，只回原结果或原待恢复状态。 | 启用前后 PG 账号/代际差量、重启后原回执/意图和拒绝读回。确认故障覆盖重启后的目标重试。重交停用命令后无新增代际、成功回执或意图。 |
| 5. 解除目标投影故障，受权重投原意图 | **通过恢复。** 唯一原意图确认，投影水位收敛到本次停用代际。账号仍停用，旧凭据继续拒绝。 | K 与原意图可查。恢复只补原意图及确认水位，安全写次数、代际和成功回执数量保持。保持同一受信 Redis 存储。 |
| 6. 当前获权者重新启用，待启用的新代就绪后新登录 | **通过新会话，旧 JWT 继续拒绝。** 新 AT、RT 与文件会话可在权限内使用。仍有效且未撤的 PAT 按当前账号和业务资格恢复，已撤或到期 PAT 继续拒绝。 | 新代、原停用及启用事件的回读，旧代 AT/RT/cookie 负例。独立核 PAT 的当前有效性和授权。 |

**恢复分支。** 数据库未提交时按原合同核安全写零差量。提交结果未知时先查原 K，未确认期间留待核查。数据库读不可用、账号有效且当前代投影不可证分别验依赖故障。已从数据库证实停用的账号走终态拒绝。Redis 整体不可信的恢复及轮签留给 SESSION 专项。

**验收出口。** 当前基线的红例重点辨别旧 AT/文件 cookie 的许可缺口，旧 RT/PAT 已有账号状态检查。候选绿例须覆盖顺序 1–6，保留首次失败、重跑及去掉关键保护后的可辨识红例。拒绝与待恢复的准确 wire 由实施方按 C05 合同冻结。同一个通用 HTTP 错误不足以判定通过。[C05 当前行为和目标合同](../phase6/foundation-iam-module-detail.md#41-c05现有wire与尚未持久化的部分)

## 卡二 B2 两条合成风险共票并逐项复测

**画像。** 在同一合成管理范围、目标组织和同一启用复核的固定工单定义下，两条风险 R1/R2 由同一风险负责人 U 管理。M 有主锚批派资格，P 是合法办理人，U 有当前复测权。X 具有复测入口所需的粗粒度功能权限和目标读权，当前复测职责仅属 U。R1 为高、D 日 17:00 截止，R2 为中、D+1 日 17:00 截止。D 为固定 UTC 样例业务日。[风险代表场景](../phase6/risk-module-detail.md#14-漏洞整改代表场景)

**证据输入。** R1 提交逐项整改说明和可核的合成变更/复测引用，只用引用。R2 提交逐项整改说明与有效的合成附件引用。引用能定位稳定对象和版本，当前复测人可以按实际权限回读。附件另核归属和有效性。每次提交把引用绑定具体关联和当前版本，与对应业务变更同事务。复测按项记录依据、结果、复测人和时间，打回记录原因。初始提交和重提保留各自证据。

**复测设置与证据要求。** 本卡主路径启用复核。验证关闭复核的设计变体时，使用另一份已通过发布预检的合成定义，沿合法完成边检查逐项字段、措施、证据及当前资格。缺证据须拒绝。 [复核开关与逐项证据](../phase6/risk-module-detail.md#52-逐风险结论与review-gate)

### 主路径

| 顺序与动作 | 判据 | 需要回读的证据 |
| --- | --- | --- |
| 1. M 核实、定级、预览及提交派单 | **通过。** 09:00 只建一票 T 和两条有效关联。记录派单操作者 M、当前负责人 U 与初始 creator 的合同映射。票取最高等级及最早业务截止。 | `group_key` 完整组分维度（风险负责人、管理组织、目标组织、类型、定义及获准范围）、`plan_id/plan_hash/operation_id`、两个风险及其依据、票/关联/历史/必要意图差量。 |
| 2. P 被分派、提醒与接单 | **通过。** 09:05 分派，09:35 接单截止，09:36 一次应发，09:40 人工接单。首响 40 分钟，分派到接单 35 分钟。未发的旧提醒被抑止，已发或原超期事实可查。 | 分派发生次、接单时间、去重键和提醒状态。工单业务截止与接单时钟分别回读。 |
| 3. P 提交方案与两项证据 | **通过提交，进入待复测。** R1 仅用可核引用可以提交，R2 文件归属与访问核验后绑定。逐项保存 proposal/证据，相关风险及整票未成为终态。17:01 回读逾期在办。 | 当次定义、票/风险/关联版本、逐项证据、文件引用和历史。首页仅 U 有该票当前待复测职责且同票去重。 |
| 4. U 确认 R1 通过，R2 有理由打回 | **通过逐项处理。** R1 为已核实修复 `fixed`，对应关联结论生效。R2 原证据和打回理由可查并回到合法整改态。整票继续在办，无整票闭环后继。 | 分别读两条风险、关联、状态、历史与意图。接单、原期限与已发生超期均留下事实。 |
| 5. P 仅重提 R2，U 复测通过 | **通过闭环。** 17:20 回读 R1、R2 均已基于各自复测落实 `fixed` 结论，关联均已解决，票才进入终态。整单闭环 8 小时 20 分钟，R1 未被重做，先前超期仍可查。 | 逐项版本与回执、同事务的终态/历史/必要意图、UI 按当前权限回读。站内应发、入箱、失败分别留证。 |

本卡两项都走已核实修复。风险接受有独立的本人申请、另一位获权主锚管理者批准及到期重评流程。存在待批准的接受申请时，整票仍受终态守卫约束。[风险复核与接受合同](../phase6/risk-module-detail.md#52-逐风险结论与review-gate)

### 拒绝和待恢复变体

| 独立变体 | 预期判据 |
| --- | --- |
| 先以 X 回读目标票和本来可见的关联，再用当前票、风险和关联版本及合法证据尝试复测。另用 U 在同前置夹具作正对照 | **拒绝。** X 缺当前复测职责，两个风险、关联、票、必要业务历史和意图均无新增效果，U 的相应操作通过。证据全文按对象权限单独回读。若另做负责人交接，旧 U 的手工抄送可见来源和已经撤掉的复测资格分别回读。 |
| R1 已通过，P 重提 R2 时仅缺本项证据。另开变体仅使附件无权或失效 | **拒绝。** 分别核缺证据与附件校验原因。R2 的字段、状态、关联、文件引用和必要业务意图无新增效果，R1 原结论可查。 |
| 提交旧版本。另开变体在预览后仅撤派单权 | **版本冲突或授权拒绝，分两轮归因。** 旧版本零相应业务差量。预览后撤权整组零建票和零新增关联。 |
| R1 已通过且 R2 待办，用符合入口常规资格的主体及请求逐个尝试普通 Close、风险关闭、转换及已启用的自动边或任务回贴 | **拒绝。** 开放入口的拒绝原因指向未完成的风险复核。T 和 R2 保持原业务事实，R1 保留已生效结论，零整票闭环意图。计划关闭的入口逐个验服务器拒绝。 |
| 以新派单操作再次选择已有关联的风险 | **原票回读或明确冲突。** 仅在仍获权时给原票引用。按原 `group_key`、风险及实际目标回读，零新增票、有效关联及派单成功意图。 |
| 在 PG 证实派单或复测及原回执已提交后丢弃首次响应 | **待核查。** 客户端按原号受权核查，回读原操作回执、票、两关联和历史。同号同输入只收敛原结果，业务与必要意图各一次。回执不可判定时保持待核并停止自动重做。 |
| 业务已提交，站内投递暂失败或执行过程重启 | **业务已通过，通知待恢复。** 以同一投递键恢复并重验当前收件资格。用相同前置分别回读资格仍在时只入箱一次、已撤权时有尝试记录和指定抑止原因且零新增入箱。未执行或缺证据不能记为抑止通过。回读失败须明确可见，正常空态单独验。 |

投递键按 `(source,source_event_id,rule_id,rule_version,recipient_user_id,channel,semantic_key)` 回读。同一源事件重试用原键，分别检查历史、投递和入箱差量。实跑前按候选登记开放及关闭的实际路由或动作，以及预期拒绝原因。[风险通知与去重合同](../phase6/risk-module-detail.md#6-d15通知与统一审计)

**验收出口。** 主路径按角色独立回读，拒绝分支检查指定原因和零相应业务差量，恢复分支从原引用闭环。待复测属于正常业务状态。真实试用只收新票，旧票回填、同类型 A/B 发布钉版与缺可信快照停写按[隔离旧票验收](phase6-b2-kickoff-plan.md#旧票范围与定向验收)另验。试用具体团队、样本、真实渠道和留存按 Q12 确认。
