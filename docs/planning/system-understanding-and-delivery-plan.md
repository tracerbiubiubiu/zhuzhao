## 2. 首次Phase6实际开工前的最小补齐

只补足首批工作能够被理解、评审和承接所需内容。资料由协作者依据仓库提炼，所有者参与判断和练习；不要求所有者逐文件重读全部源码。以下完成标准是本计划的交接标准，不新增一套自动化技术门禁。

先做一份可完整走读的最小样例：短基线卡、一页能力地图、同一旅程的成功/拒绝纵切及首批启动讲解。首选`audit_archive`：具备所需任务权限和有效独立维护资格的主体成功，仅有任务权限而无维护资格的主体收到403。沿用[pass8补修记录](../review/reports/audit-pass8-followup-2026-11-17.md)中的正向链和拒绝证据，整理时核对应源码；未重新执行时明确标为历史实跑，不冒称当前候选演示。样例本身不授权再开维护任务或切换运行环境。

### 2.1 基线卡

- **目标**：所有讲解都能回答“讲的是哪份实现，证据证明到哪里”。
- **输出**：一份短基线卡，列实际参与仓库的准确HEAD、候选/工作树状态、运行来源、相关收据和已知边界；统计附日期、口径及固定来源。
- **完成标准**：区分已实现、已验证、已合入及已部署；区分当前候选与历史收据。待核事实保留待核，不把主仓测试数与UI/TR测试数相加，也不把默认单测覆盖率说成全部路径覆盖率。
- **参与者**：协作者采集，独立评审者点检来源，所有者确认本次要介绍或继续开发的基线。

### 2.2 一页能力地图

- **目标**：从接口清单转为能够解释的问题域及模块关系。
- **输出**：覆盖8–10个域的一页地图，每域说明解决什么问题、关键模型、最难的取舍、当前状态及一个源码/文档入口；优先复用现有控制台和模块说明。
- **完成标准**：每个域有可追溯来源；现有产品、在途候选及未来设计分清。所有者能够按域介绍系统并指出首批工作的位置；不要求背接口、字段或历史数量。
- **参与者**：协作者提炼，独立评审者核事实，所有者试讲并标出仍不熟悉的域。

### 2.3 一条成功纵切与一条拒绝纵切

- **目标**：能够从入口解释数据、授权、事务和副作用怎样流动，以及系统在哪里拒绝非法操作。
- **输出**：围绕同一真实旅程，给出一条正常成功路径和一条越权或不合法状态拒绝路径，按“文件路径 + 符号名”连接路由、中间件、service、repository及已有验证入口；审计、事件、通知分别说明可靠性边界。
- **完成标准**：每个关键跳转能定位源码；能解释拒绝原因、期望错误及业务写入/外部副作用是否发生，预期零业务效果时给出对应证据，拒绝审计等留痕另行说明。引用旧测试应注明准确候选；尚未重跑的演示不写成已复现，不因图上有箭头就承诺原子性或必达。
- **参与者**：协作者追链并准备现有证据，独立评审者核成功/拒绝预期，所有者沿路径讲解并回答关键追问。

### 2.4 首批启动讲解

- **目标**：在首次实际获准Phase6小批开工前，共同理解本批为什么做、改哪里、怎样证明结果。
- **输出**：复用以上材料和既有[三节短审阅卡](../phase6/implementation-handoff.md#单维护者短审阅卡)，讲清本批输入/输出、模型、不变量、主要取舍、失败路径、预期验证及后继边界；记录剩余理解疑问及处理人。
- **完成标准**：所有者能用自己的话说明本批模型、一个取舍和一个拒绝反例，并知道从哪里核验。无法确认的理解状态保持待确认；影响本批正确授权或评审的疑问先澄清，其它域的知识缺口按模块滚动补齐。
- **参与者**：实现协作者讲解，所有者复述及追问，独立评审者检查解释与技术证据是否一致。

复述后取一个与本批有关的条件变化，先由所有者预测结果，再一起对照源码及已有证据核验，例如“保留任务权限、撤去维护资格，哪一步拒绝、会不会产生业务效果”。允许查资料，记录实际回答、使用的AI提示范围、核验结果和仍待补的理解点；AI补出的答案不算本人已理解。不评分，不新增考试或技术门禁；未实际执行的变体只记推演，不写成测试通过。

## 3. 后续按模块滚动补齐

完成上述最小交接后，不继续扩大为全生态阅读工程。每个实际获准模块在开工准备时补自身模型与边界，交付时更新现有模块文档、必要决策及地图入口，复用已有验收材料；遇到跨模块改变时更新共同合同及相应索引，不复制第二套规则。

三层鉴权、连接池耗尽、路由与权限对账三个主故事的提纲和共同历史时间线，移到前三个实际交付小批中逐步整理；先选一个与当前批次有关的案例，再按相关性补齐其余题目，不要求开工前一次写完。每个故事包含背景/约束、候选选择、实际动作、验证、结果及保留边界，重要事实指向源码、决策或固定收据。协作者提取事实，独立评审者核证据，所有者确认实际参与和可承担的解释深度；没有证据的迭代顺序及个人行为留待确认，不能把AI或协作者的工作自动写成所有者亲手完成。若前三批没有适合某题的场景，第三批复盘时明确保留或替换及原因，不为了凑数补写未经核验的故事。

额外故事候选包括：对象引用与GC、迁移往返及其盲区、字段与模板往返保真、通知可靠性取舍、多会话提交与工作树治理。它们是待选择的题目，不代表历史已经核验或所有者具有相同贡献。优先处理当前模块真实遇到且已有证据的案例，不要求每个模块都产出STAR故事或独立ADR。

时间线只收能解释重要变化的节点。每节点说明**当时能力、暴露问题、采用选择、放弃的替代、当时验证、当前由何处承接**，并指向原来源。文档日期、决策日期、代码提交、候选验收、合入main、部署分别标记；未知日期留未知，不能从文档建档日倒推实现或部署。旧问题及失败保留当时原意，当前变化由后继节点解释。

模型、不变量、授权、状态转换或恢复边界改变时，随相应模块交付同步受影响的地图、纵切和讲解入口；旧故事保留历史基线并链接当前承接说明。只更新受影响的解释与事实，不因纯文字勘误重做全部知识交接。

## 4. 首三个实际获准交付小批试行

从Phase6首批实际获准实施开始，在前三个交付小批中试行；本次计划落档不计入试行。不预先指定三个新业务包，也不把一次交付人为拆分凑数。各批沿原授权、候选冻结和适用技术门禁推进，使用[能力交付评审空白模板](../toolkit/templates/capability-delivery-review.md)；填写实例不回写空白模板。与本批无关的提示栏可直接省略，无需逐栏填“不适用”；适用但未跑、失败、取消或跳过的检查必须保留并说明原因、影响及后续，不能靠裁剪免除门禁。引用已有解释与证据，保持短审阅卡可读，不为每批另写长报告。

在既有“改动摘要、影响面、验证证据”三节中分别复用以下信息，不新增第四个强制节：摘要说明模型和取舍；影响面说明调用链、不变量、失败及后继边界；验证证据说明有效红例、修后正反例、适用门禁及理解/贡献/收尾状态。无法取得有效红例或不适用某检查时按原规则说明，不为故事效果编造失败。

每批分开记录四类事实，不能合成一个“完成”勾选：

- **技术验证**：本批准确候选、适用检查、真实红绿及原失败/重试、尚未覆盖路径；依旧由原门禁决定交付资格。
- **理解状态**：所有者是否参加解释、能否本人复述模型/取舍/反例，以及条件变化的预测、查证和仍需澄清的点。未参加或未确认保持待确认，不从“代码已合并”推断理解通过。
- **个人贡献**：由谁定边界、提出反例、实现、定位、评审和批准，证据能支持到哪里。所有者确认自身实际行为，未知事项待确认，不预写第一人称功劳。
- **Git与运行收尾**：准确提交/PR/main承接、工作树和索引归属、临时分支/资源去向、材料ID；部署和共享环境更新另记，按实际授权处理，不自动升级为全局清理或部署。

实现协作者负责解释及证据准备；独立评审者核对模型、反例和结果；所有者参与复述并确认个人贡献。每批解释只覆盖该批及必要依赖，不要求所有者当场掌握无关模块；影响决策的未知点明确处理后再作相应决定。

第三批结束后共同复盘材料是否真的帮助评审、理解疑问是否减少、哪些内容重复以及实际投入。再决定保留、简化或调整；若需要成为正式协作规范、自动守卫或AGENTS/standards变更，另准备具体候选并按原规则执行适用门禁。本次试行不提前宣布正式规范已经改变。

## 5. 资料归属与交付边界

Git范围依[文档维护约定](../documentation.md#2-什么应进入-git)及[材料目录](../materials.md)执行，本页只说明本计划产物如何归属，不另立保留规则：本计划及空白模板继续跟踪；稳定能力地图、已核验的成功/拒绝纵切、有效决策、项目故事和时间线中的长期事实随Git维护，归现有控制台、模块文档、ADR或正式结论，不另建第二套长期知识库。地图是这些权威入口的阅读投影，不能另维护一套能力或缺陷状态；故事涉及个人贡献仍须本人实际确认。

填写后的练习/评审实例、原始讲解与问答记录、日志、截图、探针和备份归本地档案；需要长期保留的独有结论提炼回原文档属主，引用稳定材料ID，不把整份执行实例或原始材料纳管。原始问答与个人贡献待确认内容不包装成公共工程事实。与模块有关的解释随该模块PR更新；系统性文档整理使用独立短分支/PR，保留正常审阅和适用检查。

执行实例可先放ignored工作区，收尾按既有规则归本地档案或正式结论；不在src下再建报告目录，不把受限本机资料、凭据或真实私有地址纳入上述产物或外部渠道。下一步只按本计划准备知识交接产物，不因计划落档顺带实施业务、修改工程门禁、推送、合并或部署。
