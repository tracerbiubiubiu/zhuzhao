## 1. 接下来怎么做

**用同一张票看前三段交付**。第一段，管理员停用办理人的账号，即便会话撤销投影失败，业务提交也要按当前凭据和授权拒绝旧请求。第二段，管理员发布新版整改类型，已经创建的票仍按创建时的定义办理，提交沿用第一段的守卫。第三段，办理人提交两项整改证据，当前负责人逐项通过或打回，等该处理的项都具备生效结论才可以终结这张票。可以用合成数据走读这组目标，实际试用准入见 §5。 [开工计划与反例](phase6-b2-kickoff-plan.md)

同一单席产能先完成第 1–3 段，再走第 4–7 段。第 1–3 段的终点是候选可验，实际开放试用还要过运行准入。代表性业务用于冻结职责、状态、字段和完成条件。选同一负责人下两条风险，由受权派单人合成一张整改票，办理人提交证据，当前风险负责人逐项验证。

首条候选采用[漏洞整改代表场景](../phase6/risk-module-detail.md#14-漏洞整改代表场景)。开发、CI 与合成联调使用情报、CMDB、HR 和外部消息 mock。手工定级、接单与闭环超期、一次站内提醒及逐项复测按启用范围核现有分项。Q12 实际试用建议采用本地真实角色和获准可核的人工风险/资产依据。双主管延期已确认留后，多源实接、定级策略和自动动作按对应窗口冻结。实际试用若要求前移，逐项扣重后复算。

1. **冻结代表业务与可信底座。** 固定五仓组合、工作树和隔离资源，确认一个风险范围、一种类型及角色、证据、失败和回退。先完成会话持久撤权，再收本批当前授权与本地强审计。公式、附件、日志按实际证据字段验。开工可并行准备现有接口、测试夹具、消息合同及外部窗口。闭环验收包括数据库停用已提交而投影失败、旧凭据拒绝、可恢复且不复活；配置或撤权在先时写业务零副作用。两条角色/菜单变更的本地强审计写失败时业务回滚，外送失败可补送。 [底座详设](../phase6/foundation-iam-module-detail.md) · [工程与隔离](../design/engineering-execution-design.md)
2. **升级工单引擎的首条纵切。** 建立受控发布、快照、工单钉版与旧票安全回填。处理人和复核人用同一个字段/动作服务，证据字段、状态、时间、附件引用、事件及必要可靠后继同事务。先交发布 A 后建单、再发布 B、旧票留 A 新票用 B；两版都服从当前权限。验坏配置拒发、遗失快照停止写、半途失败不留字段或状态、旧入口经同一限权；证据转换接入前核最低类型可见性和参与资格。第 2 段先验资格接口，实际风险负责人及交接后的资格在第 3 段联验。薄 UI 和并发/浏览器用例随实际入口提交。完整画布、自动边和配置晋级留到对应增强。 [工单详细设计](../phase6/ticket-module-detail.md) · [本轮关键发现](../review/reports/phase6-detailed-design-audit-2026-11-20.md#1-会改变开工顺序的发现)
3. **打通人工风险整改。** 先风险台账/受权读与计数，再评估、责任、接受制衡，再预览/提交有界共票，最后按风险提交、驳回和复核。源采用人工与一种合成规范输入，启用最小本地目录/权限及持久收件。业务事实和必要通知意图一起提交。站内只提供受权最小提示和可查失败状态，完整送达回执随后交。首页待复核只计当下具名风险负责人并对同票去重。角色空态/无权、重复/乱序、部分成功与回读、票删或关联移除、原结果恢复逐项验。真实开放前在 Q12 运行卡核目标、人员、数据/留存与回退，记录所选范围的 AUTH-01/02/07 反例通过或对应能力经服务端关闭后各入口均拒绝的证据。任何关键通知的实际渠道先验。 **发布验收点 B2**。 [风险详细设计](../phase6/risk-module-detail.md) · [试用准入](../phase6/first-usable-release-plan.md#41-b0预演与真实业务试用准入)
4. **打通自动任务、活动清单及公共消息。** 先当前对象/字段权限与受信服务范围，再票节点→原任务→结果和一次受权 AL 更新，再 AL 变化→持久 ACK→一个受权只读后继。公共 HTTP 通知、状态页和失败对账并行准备。合成环境能证明重复、撤权、迟到、进程恢复、unknown 不做重复效果；实际启用无人值守前另验授权，真实消息合同/测试窗按提供方结果绑定。 **发布验收点 B3**。 [跨仓详细设计](../phase6/task-activelist-message-detail.md)
5. **本地账号正式可用并确认核心稳定。** 交本地三层权限、代表旅程、薄 UI、批量标签、真实 HTTP 消息和选定接缝兼容。验新业务准确制品、升级/回退、TLS/秘密、实际编排排空与接管、备份恢复。Q12 收一轮反馈、修正与回归，所有者接受后才转主产能。 **发布验收点 B4**。 [首版验收与稳定](../phase6/first-usable-release-plan.md#42-核心稳定的过渡出口)
6. **交付公共 UAA 双模式。** 补公共扩展接口、适用目录与三类持久 feed。验本地模式独立、来源只读和非纳管范围可写、当前撤权、公开安装/退出、四页必要 UI 及共同故障恢复。公共产品完成可进入真实联调；真实测试环境和协议准备可在此前并行。 [公共产品工作分解](uaa-implementation-estimate.md)
7. **真实 UAA 联调、获批接管、切换与观察。** 验批准范围下真实认证、账号/角色/资源同步、授权范围、失联时停受管写、撤权时限、影子差异、有效退出基线。正式切换后核本地 UID、历史归属、在途业务与原回执，代表人员可完成同一业务并可受控退出。 **发布验收点 B5**。 [真实四道门](uaa-real-integration-conditions.md)

### 按实际窗口增排的两项

- **隔离入网预演（发布验收点 B0）**。沿现有底座与合成数据测批准的目标、离线导入、登录/基础工单、升级回退与重启，给制品摘要、限制和停止入口。旧情景示例为 **2.5–5 日**。目标画像冻结后再复估实际净额，并确认预演窗口。真实试用所需环境证据在开门前取得；共享安装/恢复证据与正式发布只计一次。若这项必须用同一席位且排在真实试用前，主线相应增加尚未复用的工日。
- **完整基础扩展版（发布验收点 B1）**。参考私有应用、进程外查询 adapter 及其当前授权、替换、禁用和兼容，仍是独立产品交付。共用扩展接口已验时剩 **5–7 日**，接口未交时合 **7–10 日**。本地正式版只验实际接缝和已登记旧协议消费者。没有可执行的真实旧消费者时，须先具名冻结已有最小参考组合或选择前移相应接线并复估；纯 mock 不能结兼容门。完整风险真实源/设备能力保留这些接缝的实际依赖。

## 5. 外部依赖和需要拍板的事

- **开工前**，T0、实施授权和实际可用时段集中见[所有者议程](owner-decision-agenda.md#详设审计后的排产选择)。已确认按两条合成风险预备，真实试用只收新票，逐项证据必填且附件按需，旧票在隔离环境验证。技术方冻结启用写集、存量回填、旧配置写端切换、引用/锁序和验收用例。真实业务启用由以下窗口决定。
- **试用与正式本地**，环境/运维与所有者确认 Q12 环境准入、样本类别、代表角色、数据保留、停止/回退，以及是否需要 B0。正式前给准确制品、备份和恢复目标、人员、证据和实际试用接受。
- **自动动作与消息**，业务方给 Q09 授权和适用边界，提供方给 MH01 协议、MR1 测试窗口、接纳/送达/查询能力。唯一关键渠道需要可验证送达或获批替代处置。合成链可先建，真实动作/消息按各自门放行。
- **研发优先级**，B2 优先已确认，按环境窗口和业务依赖另排 B0 与完整 B1。所有者在人工试用反馈后选择贯通主线先行或优先做完整工单引擎/风险增强；如争取并行两条关键线，先确认新的有效研发席位及隔离能力。异地等待可提前预约。
