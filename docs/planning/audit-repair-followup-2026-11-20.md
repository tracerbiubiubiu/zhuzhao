## 基线和分工

主仓 `eef9bfe`、Taskrunner `1a2d4ab`、前端 `8051448e`、ActiveList `d2fd455`、Utils `661f465`。前三仓各建独立短分支。后两仓以消费依赖的方式参与组合验证。

1. **F2a/E09 任务取消与运行对账。** 工程实现者负责 Taskrunner。测试先钉住取消清理出域后迟到投递，及 Redis 删除失败后再次进入清理；保持终态守卫和正常重试。对长期 `running` 与队列的终态差异补有界可见性和人工核对入口，效果未知由原 C03/F2b 处置，保留任务身份和重试预算。
2. **工单配置、字典与角色菜单。** 工程实现者（Codex）负责相关主仓代码及 UI。钉住旧记录和同码重建后的零误写、字典父对象、备注省略和显式清空、两个客户端同角色保存。权威检测与保存共享事务。新的 UI 请求携带必要的稳定标识，现网旧调用的兼容边界随合同和测试记录。
3. **C04 和 C05。** 总设计师给共同屏障、事务内新鲜授权和写方矩阵，DeepSeek 架构设计师做独立复核。自助改密必须在锁内核原凭据与启用状态，以现有错误和合法强改流程验收。工单授权按已枚举的入口核撤权提交顺序、连接复用和领域写零效果，副作用放在提交后。完整会话投影、可靠意图和多副本机制各自沿原工作包验收。
4. **F0/C-6。** 两仓容器的停止宽限覆盖自己的排空预算。存储用量按用途和总量发布同一份实时快照，补用途中最后一行移除后的指标反例。发布与运维评审者独立核容器停止路径和全量门禁的隔离条件。

## 验证与接收

- 每个并发修复先以确定性时序证明失败，再以相同断言复验。至少 8 轮变异按工程公约执行。拒绝后核真实持久值、新旧目标、相关副作用和草稿。
- 不同底层助手复核关键不变量。独立集成复核核跨仓兼容、测试覆盖、准确提交树、门禁与分支清理边界。
- 每仓先 `make quality-plan` 与 `make quality-check`（前端使用本仓等价命令）。普通档在专属 PG/Redis 与合成生态栈跑受影响仓的完整门禁，包括主仓 lint、单测、集成、覆盖、迁移与四档验收，UI 真实浏览器，以及 Taskrunner 实际 PG/Redis 与定时链。通过后按后端先于 UI 的顺序合入，分别验证分支、PR 和合并提交的适用主线 CI。
- 报告记录每个已交切片及剩余条件。真实数据、部署和未选工作包沿各自批准口径。清理前核非主线祖先、未提交内容、部署资源占用及证据归属。
