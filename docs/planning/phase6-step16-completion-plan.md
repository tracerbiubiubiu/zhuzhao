# Phase 6 第 16 项完成计划

> 范围为第 16 项已选定的外部合成验收。基线为 Core `6835f273`，承接首批 `03e6d715`。权威为[交付排期](intranet-uaa-release-schedule.md#剩余开发顺序与验收)、[风险模块详细设计](../phase6/risk-module-detail.md)及[处置决定](../phase6/02-r2-assessment-treatment.md)。

## 交付顺序

1. **接入先收件，再应用。** 规范输入、原批号、来源组织/映射及处理结果持久化。显式批号同输入找回原回执，异输入拒绝。单条仍按原事件去重。应用复用原有锁、事务和序号水位。首报和重试走同一应用路径。受信源失去配置或组织授权时阻断应用与回执重投。验证相同/交叠批并发，事务间中断、处理提交响应丢失、进程重启和原号接续。
2. **来源镜像和补核。** 详情和派单从同一条现势来源记录取证，核对序号和观察时间异序。已有风险经主锚管理者用原评估命令补齐缺失的稳定身份，以证据、有效期、CAS 和原操作号留痕。来源撤回、过期或身份冲突继续阻断派单。用明确合成情报匹配接入两个已知资产，再由 Core 签名读合成资产目录，验未知、陈旧、空结果、超时和恢复。模拟目录验半批缺项补收、回执读回以及当前人员资格。
3. **处置。** 直接复验第 8 项逐资产证据、复测、接受申请、另一人决定和关单约束。转移、规避只登记处置依据，派单视图和提交均不能以此创建整改票。按已选误报合同补主锚确认、限期按指纹抑制及过期后对真正新观察的待评估。跨指纹合并、工作日日历和双主管延期归原决策窗口。
4. **固定候选及主线核验。** 源码与验收由不同助手交叉复核，现有页面以固定 UI 基线复跑。运行普通档完整门禁，记录 SHA、适用检查和合成证据。通过受保护主线的 PR 合并，跟踪合入 SHA 的适用 CI，并用合入源码复验重点旅程。

真实提供方、内网接线、生产部署和其它排期项目按原准入处理。第 8 项已签收的在办接受到期恢复继续复验，接受到期自动重开、全站风险界面和条件项沿各自排期。
