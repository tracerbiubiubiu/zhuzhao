# Phase 6 D06 模拟目录主部门调动实施计划

Core 从已合入的 `af40abae` 开工。只处理一名预登记合成员工从实体部门 A 调至实体部门 B。设计以 [D06 写主合同](../design/business-lifecycle-contracts.md#72-写主映射与发布) 为准。

## 写入边界

固定模拟来源通过显式作用域、合成员工外部标识及身份世代，解析预登记的用户与新旧部门绑定。合成身份和合成实体部门均须启用、非系统且同租户。目录只移除原有的受管主任职，在目标新建默认成员主任职，并推进来源修订。目标已有任职或会继承功能角色，或原主任职含额外角色、范围、时效、负责人事实或功能角色绑定时，保留原业务状态并记录待处理结果。本地直接角色、其他任职、历史工单及派单归属保持原事实。人工成员入口继续处理本地任职，受管主任职的主标记和删除由模拟来源控制。

`transfer-primary` 读取一条合成调动，`transfer-receipt <scope_ref> <operation_id>` 查询已提交回执。以规范化内容识别同号重放与冲突，用户来源修订与任职更新及回执同事务提交。目标无法解析时仅保存待处理回执，修正后用新操作号。既有部门批次沿用独立的水位和回执。

## 任务分工与验收

- 边界核对。独立助手核对 IAM 写入入口、有效组织条件以及当前与历史归属的读取路径。
- 测试先行。验收助手使用真实命令与独占 PostgreSQL，先确认尚无人员调动出口，再覆盖 A 到 B、直接角色和其他任职、当前授权、历史归属以及未解析目标时零业务写入和独立回执查询。
- 实现。主会话负责受管来源检查、原子写入和回执、迁移、命令以及合同和能力矩阵。复用 IAM 写锁和现有可见性读取。
- 独立复核与门禁。另一助手使用固定候选复核写边界、事务与证据。执行专项真实数据库验收、普通档四阶段验收及迁移往返，并记录候选和剩余边界。
