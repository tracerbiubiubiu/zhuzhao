# Phase 6 第 16 项模拟扫描与人工补核计划

> 用途是落实第 16 项首批的接入与复核。基线是 Core 远端 main `6835f2738adbb303c61b721de927a3b1639a24d0`。范围依据[总排期第 16 项](intranet-uaa-release-schedule.md#剩余开发顺序与验收)和[风险接入处理合同](../phase6/risk-module-detail.md#4-接入处理事务和并发)。

只使用虚构扫描结果和专属测试账号。以一套 Core、独占 PostgreSQL 和 Redis 验证真实 HTTP 写读链。来源身份由既有 AK/SK 绑定，人工按现有风险权限核实。一个稳定来源事件对应一个接入号，人工评估沿用原操作号和风险修订。

## 分工与通过条件

- [x] 接入盘点与基线验收（`source_audit`、`journey_acceptance`）。使用已签名的同源观察，验证重复、等序冲突、旧序号、默认关闭和错源拒绝。以风险、观察和历史记录计数及现势镜像确认零重复业务效果。
- [x] 无可比序号（主会话）。在 `internal/service/risk` 集成用例重现旧观察覆盖现势镜像。仍使用锁内现势记录。两边都有规范序号时沿用数值序，其余按持久化精度比较观察时间。旧观察记为 stale，等时或缺少比较基线记为 held。验证后一条可确认的新观察正常推进。
- [x] 资料不足和原号恢复（`receipt_audit`、`journey_acceptance` 与主会话）。缺少有序源必需的序号时保存待核回执，无风险效果。已有稳定身份与组织归属而欠缺结论时，由获权人员评估同一风险并留独立核实说明。来源丢响应后按原事件和原内容重签重投取得原接入号，重复响应保留原持久原因。人工丢响应后直接按自留操作号核查原修订。真实 Core 重启后复核无权主体和已撤资格主体的读回边界。修复未指派风险授权判定的空值分支，使越权首写及同号重投返回 404。
- [x] 固定候选和独立验证。根会话统一接线及回填，另一助手核实锁内比较、持久读回与实测断言。执行分类门禁、lint、单测、集成、覆盖率、升级迁移、四档验收、往返和 Swagger。全量验收使用独占栈。记录各检查根据与覆盖边界。

评估说明保留在本地风险历史，来源观察继续保留自身的内容和有效期。无稳定漏洞或资产身份的风险仍受派单依据守卫。首批接入恢复以逐事件接入号为单位。

## 后续批次

1. 模拟情报与资产匹配。对账现有资产查询和来源依据，复验命中、无命中、资料陈旧、超时与恢复后的人工核实。确认查找结果没有自动改写责任人或关闭风险。
2. 模拟目录与同步恢复。检查当前人员资格与目录事实的绑定，验证同步中断、补送和读回。持久批回执及独立收件消费者先按接入合同盘点，再按缺口补齐。
3. 其余选定处置。直接复验第 8 项已交付的风险接受制衡，并按总排期核对其它选定处置的资格、证据和终态条件。
