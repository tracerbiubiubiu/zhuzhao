## 实施切片

### 1. 普通编辑保真

- [ ] AL 的 UI 普通编辑保留未修改的数组、可选文本和值的缺省语义。只将变更字段作为 patch 发送。编辑存量文本数组时保留逐项输入的边界、空白、空项和换行。批量粘贴写入入口保持原契约。可选文本从已有值被显式清空时提交该清空。当前读取目标的版本继续随请求送出。
- [ ] 在 UI 的真实页面逻辑测试及真实栈 E2E 证明仅改标量后数组逐项相等、原样保存保持、显式编辑有读回、普通创建仍可用。选择未改字段与显式清空、旧版本拒绝的对照。
- [ ] 字典启停保留原备注。明确缺省更新和显式清空的区别，保留现有版本保护。验证类型与条目启停后回读非空备注，明确清空仍可操作。

### 2. 当前目标与数据生命周期

- [ ] 字典和 AL 的过期确认由服务端按当前稳定标识和已见版本核对。单批锁定兼容 wire，保留已登记旧消费者。验同号重建、状态改变、正常确认和服务端的受限入口。AL 全量导入在提交前验证整份 JSON 输入，失败时原集合和 revision 保留，同时保留尾随空白及现有体积错误。
- [ ] C02 对仍被当前工单文件字段引用的普通附件拒删。保护工单、对象和关联的现有锁序。解绑和逻辑删除同事务，清理对象在提交后可恢复。验有效/无效引用、合并、两字段同对象、旧对象兼容及持久效果。创建与更新的文件用途验证对齐。

### 3. 任务及工单当前边界

- [ ] F2a 修初投/补投撤销依据。只在确认取消或拥有该投递语义时撤销。验数据库账本与 Redis 合法重试保持，及坏行、取消、重复时隙与终态失败的对应复核。人工重试是否给新预算和对账动作沿实际契约及执行代次验证。
- [ ] 工单关联集合按双端当前读权；发给处理人的修改通知以同一提交版本和当前资格为准；自动首派不得覆写已生效的人工分派。有影响的 C04 业务写必须以同套事务内当前授权为前提。复用 C04/C05 的现行设计；只关闭通过逐入口核验的切片。
- [ ] 归并配置枚举、失败状态及首版 Q09/F0/S1 口径后继。维护缺项和已交切片沿原总账，预算在实际范围确定后去重。B0 合成预演、真实业务试用、本地正式与完整 UAA 的验收分别登记。

## 复核、门禁和合入

- [ ] 独立评审对应修复、行为边界和测试牙齿，高影响项使用不同底层 Agent 交叉复核。每仓明确文件和执行权归属，统筹统一处理最终候选及反馈。
- [ ] 先执行各仓适用 `quality-plan` 和 `quality-check`，普通档在独占栈跑主仓 lint、单测、集成、覆盖、四档验收、迁移及 Swagger。前端跑 lint、类型、单测、依赖审计、构建和真实栈 Playwright 全量。Taskrunner 与 AL 跑各自普通档检查及真实 PG/Redis 或 PG，并核公共库消费版本和固定组合。
- [ ] 按兼容性顺序合并后端再合 UI，精确核 PR、merge SHA 和适用 main CI。通过适用验证前保持候选待验。G02 远端规则操作与真实接入按单独的实际准备和权限处理。
- [ ] 收尾回填控制台和审计结论，归档需要保留的全部证据。清理经证实已经合入且无单独贡献、无未提交文件或在途依赖的分支及本批资源；有独立材料的工作树先归档并核可恢复性。

## 独立验收边界

- **C04 工单写侧**。总设计师与独立权限审查确认，撤权提交顺序须由共同屏障、事务内有效授权和所有已启用写源一起保证。先登记入口和写方清单，再按权威合同接同连接、当前策略代际、领域锁和失败处置。仅完成其中某个入口的局部锁定时，对应授权保证仍保持开放。顺序关联读取、附件字段生命周期和事件快照可单独证明自己的不变量。
- **F2a 任务干预**。人工重试沿用当前队列预算，重置持久状态仅适用于读到的执行代次。所有者确认数据库优先取消：仅在账本持久化取消后清理 Redis，清理未完成进入现有对账域；前置查证不可用时复核未交付条件。最后一次写终态失败的结果对账仍沿现有运行合同。若增加自动预算、重放结果未知的执行、改变取消 HTTP 口径或处理旧计划时隙冲突，应先明确对应行为和证据。
- **保护与试用**。沿 G02 跟踪当前远端强制检查。Q09 只约束实际无人值守动作和包含该链路的正式出口。风险试用所需权限切片和总工期仍按首版权威规划核对。
