## 1. 首条人工漏洞整改旅程

### 画像与角色

首轮准备使用两个合成资产，各有一条人工核实风险。合成样例取同一风险负责人、风险管理组织、目标组织、固定整改类型和定义版本，合成一张票并逐项人工复核。开发和隔离联调使用人工录入及一种显式合成来源。真实试用只收新建整改票，实际团队、具名角色与获准的风险和资产依据随 Q12 绑定。首批双主管延期已确认留后，现场制度确有强制要求时按 Q10 提范围变更。生产日历、真实多源和自动动作按各自窗口决定。[风险代表场景](../phase6/risk-module-detail.md#14-漏洞整改代表场景)

| 代表角色 | 本旅程中的职责与边界 |
| --- | --- |
| 风险团队管理者 | 在主锚获权范围核实、定级、批量预览和派单。风险接受变体由另一位有主锚资格者处理审批，禁止自批。使用风险派单受限用例，保留真实操作者。 |

### 旧票范围与定向验收

- **真实试用只收新票。** 从所选 B2 类型新建整改票。旧票兼容使用隔离环境的合成样本验证。
- **隔离验收照常覆盖旧票。** 用可信旧定义回填同类型合成在办票，验证可重入并保留 ID、历史、有效引用、节点时间和期限。定义来源无法证明时拒绝推断回填，定义不能解析时停写并明确降级只读。若只有部分历史来源不明，标为未知，关票仍按实际生效结论判定。发布 A 后建票，再发布 B，A 票继续按 A、新票按 B，两版都以当前身份判权。批次还核旁路类型、终态历史、未选票和旧配置写客户端。[旧票隔离走查](#53-旧票兼容单独核对)
- **入口与失败反例。** 主锚写、办理及复核分别验无权、失权、陈旧版本、关系交接和缺证据；隐藏对象同不存在一致。预览后变更依据或撤权，提交依原分类拒绝且无新业务事实。关单、普通转换、删票及后台入口经同一桥校验，暂不支持的入口由服务端关闭。对同号重试、丢响应和重启查原回执，已完成项不重复。验非本人接受批准、待批准阻止票终态；验已接单、改派和撤权抑止旧待发送提醒。权限反例核票、字段、时间、关联、附件、业务历史和必要意图的差量，允许设计要求的拒绝留痕。
- **薄 UI 与开放出口。** 以具名角色在真实浏览器检查待办深链及刷新、同票去重、复测、部分失败和当前无权态。真实开放前，Q12 运行卡要绑定制品、人员、数据留存、故障停用与回退，并记录实际范围内 AUTH-01/02/07 通过或相关入口服务端关闭的证据。关键提醒渠道须实测，或走业务已批准并验证的备用处置。[工单存量和发布](../phase6/ticket-module-detail.md#33-发布迁版与配置晋级) · [真实试用门](../phase6/first-usable-release-plan.md#41-b0预演与真实业务试用准入)

## 2. C05 首批开工计划

**目标**为账号停用或密码安全写提交后，用数据库中的当前账号状态和会话代际判定旧凭据。安全状态、代际、可查回执和投影意图同事务，Redis 投影可恢复。PAT 沿独立生命周期核当前账号、令牌和业务资格。复用现行自助改密条件写及 F021 已确认的重复操作语义。[底座 C05 合同](../phase6/foundation-iam-module-detail.md#4-c05账号atrtpat-与停用恢复) · [F021 行为决定](owner-decision-agenda.md#本轮规划修订的独立确认)

### 按顺序交付的审阅单元

1. **先固化入口和故障红例。** 盘点 `internal/service/user_service.go` 的 `Create/UpdateStatus/Delete/ResetPassword`、`internal/service/auth_service.go` 的 `Login/Refresh/UpdatePassword`、`internal/middleware/jwt.go` 的 `JWT`、`internal/middleware/fileauth.go` 的 `FileAuth`、PAT repo 与 `internal/pkg/admincli/reset_password.go` 的 `ResetSuperadminPassword`。冻结当前/目标响应、获权回执查询和 UI 结果矩阵。第一条红例在真实 PG/Redis 验停用写已提交、只让撤销投影写失败、会话读仍可见旧 Redis 值的分支；用仍合法的旁路账户证明探针并未被通用故障截断。
2. **交数据库安全事实和操作原子性。** 先给创建、存量初始化、停用/启用、删除、管理重置和自助改密写失败零提交及并发断言。实现成对扩列迁移、`session_epoch ≥ 1` 与 `0 ≤ session_projection_epoch ≤ session_epoch`、初始 `1/0`、可重入初始化及共用私有 operation/intent 存储，按仓内实际实现核可复用性。新迁移同步到 `internal/testutil/testdb_integration.go` 的集成装配。安全写在当前守卫和目标行锁内重验状态/hash/代际，并同事务写状态或口令、代际、回执和意图。应急 CLI 保留恢复能力，先冻结清楚受权目标及撤销确认后启用的安全顺序，另测 HTTP 重置保留停用。
3. **接通真实认证入口与投影恢复。** Utils 用增量签发接口提供 `session_schema=db_epoch_v1` 和规范正整数字符串 `session_epoch`，维持旧消费者接口。主仓 JWT AT/RT 与文件 cookie 读当前 DB 安全快照，再核投影/会话槽。校验登录不借用新代际，refresh 按原代际和设备隔离且一个赢家。投影在 DB 锁外执行，单调写 Redis，按 DB 当前代际与 lease/fence 确认结果。失败只重投原意图，旧确认或清理不得覆盖新代。PAT 继续其独立分支，登录和启用均不能清除待恢复安全屏障。由 C04 再把具体凭据事实接入实际业务提交守卫。
4. **交付客户端、受控恢复和准确候选组合。** UI 接线核 `src/common/request/src/index.ts` 和 `src/store/modules/user.ts`，明确当前会话终态退出、可恢复故障、改密已提交以及结果待核查。保留单飞刷新，迟到结果按会话世代隔离。完成投影长期失败的告警和受权重投，验新旧 JWT 切换、可信单项恢复及不可信 Redis 恢复。业务代码、测试或迁移候选走普通档，局部审阅单元只作集成输入，须等适用的全量门禁和独立故障验收通过后才能宣布 C05 交付。

存量用户保留主体 ID、账号状态及业务归属。切换采用扩展、回填校验、受控切读写和重登。纯 Redis 旧代际不可作为可信迁移源；降版前须能拒绝旧会话，不能仅删安全列或按旧代继续接受。具体迁移编号、错误码和接口联动由实施方依基线冻结。C05 沿用已有 **6–10 单席工程日候选**，按首批实耗校准；G04 和共用存储/验收按现有净估扣重。[底座切换与验收](../phase6/foundation-iam-module-detail.md#43-c05切换恢复与独立验收) · [运维恢复合同](../ops/runbook.md#62-c05会话投影长期失败的受控恢复设计候选未实现)

### 撤权故障回归

以下映射底座 `SESSION-01–10`，由实际 HTTP、数据库、Redis、进程和必要浏览器回读给证据。旧 AT 指旧访问令牌，RT 指对应的旧刷新令牌。

| 断点或并发条件 | 通过标准 |
| --- | --- |
| DB 写回执/意图失败，或当前资格拒绝 | 状态、口令、epoch、成功回执、投影意图及会话槽无业务变化。断言失败发生在预设断点。 |
| 停用提交，投影写持续失败，Redis 保留可读的旧值 | DB 停用事实与原回执/意图仍在。旧 AT、RT 和仅带文件 cookie 的请求终态拒绝，不签发新令牌或读文件；PAT 因账号停用也拒绝。记录管理员看得到的已提交与待恢复状态。移除 DB 门时，红例须在当前仍可读旧 Redis 的同分支暴露。 |
| 管理重置、自助改密、删除，以及依赖不可用 | 旧代 JWT/RT/cookie 拒绝。活跃账号密码改变或投影 pending 时独立有效 PAT 的资格保留，删除/停用、PAT 自身撤销或到期均拒绝。DB 无法确认或当前 JWT 代投影不可证，验证可恢复故障和零受保护效果。PAT DB 错误现为 401，若调整须同步兼容检查，路由级 Redis 限流故障单列。去掉 PAT 生成固定回退，注入随机源失败时零落库、零 secret 回包。 |
| commit 回执丢失、提交后杀进程、Redis 写后丢确认 | 重启从原 operation/intent 收敛。受权可查原回执；同号并发或口令内容不同均最多执行一次，非秘密绑定冲突或异主体拒绝。不复发 TokenPair、无第二次代际推进，不在结果未知时换号自动重做。 |
| 启用与投影未完成、迟到 clear/确认及新停用交错 | 待撤销时启用拒绝且保持停用。确认后只有受权启用可推进新代；旧 worker 的清理、完成回写和重复确认无权覆盖。重新启用后未撤且未过期的 PAT 按既有策略恢复；旧 JWT/RT/cookie 继续拒绝。 |
| Login/Refresh 自身并发、登录和安全写交错 | 用屏障固定读到旧凭据后再提交改密/停用，签发不得借用新代。两个相同 RT 只一笔消费成功，旧刷新不覆盖新登录或删除较新会话槽。保留单设备/单 AT 登出语义。 |
| 单项投影缺失、Redis 全量不可信、长期失败 | 单项仅在其余库可信时修复当前代。整体不可信继续关闭会话服务、轮 JWT key 后重登，验证曾登出 AT 和旧 RT 都无法复活。超过恢复预算后待办/升级可见，未授权干预、伪造就绪和超时自动启用均拒绝。 |
| 首次创建、存量初始化、CLI、旧 claims 和 UI | 初始化可重入，停用用户不被激活。CLI/HTTP 差异正确。旧 schema 按受控重登拒绝，畸形新 schema 不回落。核文件 cookie 单独入口与既有 header 优先级，授权范围仍由文件路径核验。浏览器区分终态、普通 403/503、已提交待恢复和未知响应，新账号不被旧请求的迟到清理影响。 |

复用 `auth_epoch_race_integration_test.go` 的 `TestAuthEpoch_ChangePasswordUsesCurrentCredential`、`TestAuthEpoch_LoginCannotBorrowPostResetEpoch`、`TestAuthEpoch_RefreshBindsConsumptionEpoch`、`TestAuthEpoch_UserLifecycleCannotReviveOldAT`，以及 `jwt_epoch_test.go` 的 `TestJWT_PasswordEpoch`、`TestFileSession_PasswordEpoch`。新增断言先红后绿，关键并发反例使用可控屏障至少八轮，并在临时测试候选去掉对应保护确认反例仍能红。原集成用例中的 Redis 模拟适合作为快测，另用真实 Redis 验进程中断、投影丢失和恢复。G04 用同画像对照 Bearer、Refresh、文件与 PAT 的 QPS、p50/p95、每请求 DB/Redis 查询数和连接池占用，记录结果供评审。[C05 原验收目录](../phase6/foundation-iam-module-detail.md#43-c05切换恢复与独立验收)

## 3. 隔离装备与验收交接

## 5. 桌面联审与开工就绪

### 5.1 C05 撤权故障

先按 `user_service.go` 的 `UpdateStatus`、`jwt.go` 的 `JWT`、`fileauth.go` 的 `FileAuth` 与 `auth_service.go` 的 `Refresh` 核静态入口。基线停用后的 Redis 撤销由 `AfterIAMCommit` 执行，红例重点辨别 AT 和仅文件 cookie；RT 与 PAT 已有账号状态检查。候选须额外证明 PG 当前账号事实、回执和持久意图。四种凭据分别记录判定原因。基线和候选各用自身签发的合成凭据。[认证与恢复合同](../phase6/foundation-iam-module-detail.md#43-c05切换恢复与独立验收) · [C05 验收卡](phase6-b2-acceptance-cards.md#卡一-c05-停用已提交而撤销投影失败)

1. **前置通过。** 从实际候选签发可用凭据，独立记录账号启用、代际、投影水位、请求关联引用及故障前资源读取结果。独立回读预留 RT 槽存在、匹配停用前代际和设备、未过期且未消费，正常刷新用独立设备槽。同线路控制账号在故障前后均须成功，确认走到本轮要看的服务和校验路径。
2. **停用已提交，投影待恢复。** 提交前已有稳定操作引用 K。独立 PG 读回同时看到账号停用、新代际、原回执和唯一投影意图，Redis 旧值仍可读，定向写故障有命中证据，水位尚未收敛。客户端丢响应且尚未读到提交证据时先按 K 受权核查，结果保持待核查。明确回滚则核账号、代际、成功回执与意图零变化。
3. **旧凭据终态拒绝。** 逐个回读实际响应、请求关联证据、预期账号判定原因及目标业务差量。AT 和仅 cookie 请求无受保护内容，RT 无新令牌或 cookie 且无槽替换，PAT 因账号停用拒绝且保留自身生命周期。到期、签名或 schema 无效、业务对象无权、限流或依赖故障须各自归因。对活跃账号的当前代投影不可证或 DB 无法确认，另按依赖故障合同核可恢复结果与零受保护效果，PAT 沿自己的数据库分支。
4. **启用拒绝，重启后仍待恢复。** 故障保持期间，由仍获权管理员用不同操作号尝试启用。回读账号仍停用、无启用代际或成功回执。预先登记故障如何跨重启维持，重启后确认原意图仍待处理、旧水位未变及目标重试再次命中。重复停用只回读原操作，代际、成功回执和意图数量不增。启用所见状态和管理员可查的待恢复原因分别记录。
5. **原意图恢复通过。** 在同一可信 Redis 存储中解除故障并获权恢复原意图。回读原目标代际、同一意图的确认和水位，核确认使用当前代际及有效租约/fence。原停用事实、代际推进次数和安全成功回执不变，旧凭据仍拒绝。查回执、重投、启用和 CLI 应急续办各核适用授权与目标范围。Redis 整体不可信归 SESSION 专项，单项恢复所得证据只覆盖本卡。
6. **恢复后启用通过。** 另行获准启用，待启用新代投影就绪后新登录。对照启用回执、新旧代和实际读回，新 AT、RT、文件会话在权限内可用，旧 JWT 仍拒绝。仍有效且未撤的 PAT 按当前业务资格可用，到期或已撤 PAT 仍拒绝。

**结果与客户端映射。** 实施方按原 K 的完成、待恢复、尚不可判定三类读回，分别绑定独立 PG 事实、认证原因、响应和 UI。另排首次响应丢失且暂查不到 K、明确回滚、已提交待恢复三轮。查不到 K 时维持待核查，明确回滚须有零提交证据，终态拒绝须有对应授权或凭据原因。B2 丢响应沿同一判别原则，使用业务自己的操作引用。

### 5.2 B2 两条合成风险

按固定 UTC 时钟推演一张新票、R1 和 R2。M 派单，P 办理，U 逐项复测。R1 仅用可核引用，R2 用合成附件。用仍具常规入口资格的对照主体分别验证缺证据、失权、版本冲突及复核门；给每个变体独立还原前置，避免前一次状态或修订号先挡请求。[两风险验收卡](phase6-b2-acceptance-cards.md#卡二-b2-两条合成风险共票并逐项复测) · [逐风险复核合同](../phase6/risk-module-detail.md#52-逐风险结论与review-gate)

3. **办理提交通过。** 回读 P 的方案及计划、票/风险/关联修订号、钉版和两项各自的措施与证据。U 按实际对象权限可核引用，附件的对象归属、权限和业务绑定分别可查。此时只形成待复测事项，首页仅当前具名 U 计同票一次；17:01 仍显示逾期在办。缺单项证据或附件失效时从对应守卫拒绝，零相关字段、关联、状态及必要意图变化。

5. **只重提 R2 后闭环通过。** R2 提新证据，经当前负责人复测通过后核两条有效关联都已有生效结论，票于 17:20 到终态。回读 R1 未重做、曾逾期可查、17:20 与建单相隔 8 小时 20 分，以及终态、历史和必要意图的提交证据。核通知失败能回读，浏览器准确显示当前角色所见结果。

**C05 到 C04 的提交边界。** 从首批实际开放且纳入 C04 的写入口中绑定一条业务样例。第一轮在初步认证通过后、业务提交前先完成凭据撤销，保持动作职责、对象及业务版本可用，回读事务内当前凭据拒绝与零业务差量。第二轮让合法业务先提交，再完成撤权，分别查原业务回执和后续拒绝。按各凭据自己的失效合同选条件，密码变更与 PAT 自身撤销分开。与上面的复测职责交接用例分别归因。

**待核查与待恢复。** 首个响应丢失时，调用方按原操作号受权查询，先从待核查收敛到原回执，再回读票、关联及历史。通知故障变体先独立在 PG 证实业务回执和必要投递意图已提交，再查失败记录。后继投递失败按原投递键恢复，重验当前收件资格及消息条件。获权时只入箱一次，已入箱但确认丢失时回读原入箱记录，未发且已失权或条件失效则须有尝试记录、指定抑止原因和零新增入箱。重试或恢复后业务结论、历史及意图次数均不增。正常空态和回读失败另各取一次证据。

### 5.3 旧票兼容单独核对

3. **缺可信定义的写入拒绝，获权只读降级。** 先验无可证来源时不绑定猜测版本，再独立验缺对应定义时写入返回 503、动作停用、`definition_resolution=degraded`，票和证据历史仍在且按当前权限读取。无权读仍拒绝，浏览器区分降级和空结果。若只有历史结论缺出处，该结论记未知，关票仍仅计可证的已生效结论。隔离夹具以独立证据复原对应原版后，只重试合法的新请求或查询原回执，复查原历史和期限。

### 6.2 C05 首轮取证清单

3. **四种凭据各自终态拒绝。** 静态可列预期账号原因和各入口应保持的业务事实。绑定候选时登记实际 HTTP 状态/原因、客户端显示及诊断关联。候选实跑在同次已提交停用且投影仍滞后的窗口逐凭据留响应及当前账号判定。核 AT/仅 cookie 不回保护内容，文件请求确以仅 cookie 进入，RT 无新令牌或 cookie 且原槽无消费/替换，PAT 因账号停用拒绝且自身有效性未改变。依赖故障、凭据过期或格式、限流及资源无权给出各自证据，发生提前拦截的路径本轮无效。基线按自身已有状态和响应取证，红例只计目标保护差异，既有 RT/PAT 拒绝和局部 mock 证据单列。
4. **重启与重复操作。** 静态可定原 K、意图、目标代际及水位的比较关系，和另号启用被拒的判据。绑定时登记同一故障能否跨进程、重启所涉制品和资源、恢复及请求观察点。实跑核重启前后原意图身份与待恢复状态、目标重试命中、重复停用零新增代际/回执/意图，以及另号启用拒绝和账号仍停用。若重启后无法证明原故障仍在，该步无有效结论。
5. **恢复及启用。** 静态可定获权重投原意图和代际、水位、租约/fence 的收敛关系。绑定时确定受权查询、重投和启用的各自角色与出口。实跑在可信同一 Redis 下恢复，核原 K 可查、同一意图完成、水位收敛、原停用仍在且无第二次安全写。之后另号获权启用，新代就绪后新会话方可使用，旧 JWT 仍拒绝，PAT 按其自身状态和当前权限判定。Redis 整体不可信时停止本卡单项恢复，沿 SESSION 专项。[C05 恢复与独立验收](../phase6/foundation-iam-module-detail.md#43-c05切换恢复与独立验收)
6. **服务端状态与界面证据。** 静态可列 §5.1 的待核查、已提交待恢复、恢复完成、明确回滚及终态拒绝。绑定实际响应、判定原因与 UI 映射后执行首个实跑动作。实跑按 K 将同一操作的 PG 事实、HTTP 与界面提示逐项对上，未证实提交、已落库但投影未追平、已恢复三类状态须明确可区分。明确回滚核零提交，拒绝核实际守卫。单个通用错误不足以证明结果或原因。

### 6.3 取证就绪与待确认

- **可先完成的工作。** 保留源码入口、变量消费者、候选字段及证据清单。约一人产能先绑定 G04，再准备 C05 首轮实跑。实际环境归属、正常对照和目标故障观察都通过才开始对应故障轮。候选回执、角色和原因映射未定时，暂停相应接口消费或取证。本节沿 §5.4 的阻断分工。
