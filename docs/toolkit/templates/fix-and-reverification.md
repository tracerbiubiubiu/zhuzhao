# 修复提交与复验模板

> 用途：填写已授权修复的提交正文及提交后的独立复验；读者：修复者与复验者。输入：已确认发现、准确修复窗口与实跑证据；输出：提交说明和复验记录。状态：空白原件，不证明修复或发现关闭。权威：[工程公约§12-9](../../standards.md)与[审计方法§9.1](../../review/audit-playbook.md#91-修复提交与复验记录)。

提交结构从原审计指南提取；替换占位符，遵实际提交策略，不虚造发现号。完整日志属于本地证据；必要正式复验归review/reports，有修复提交先记待复验。“准确窗口”指修复前后各仓的明确版本范围；“稳定红证据”指在记录的条件下可重复观察到原失败，不表示修复后仍失败。

```text
fix(<模块>): <中文摘要，≤50 字，结尾无句号>

改动摘要：
① <根因与修复方式；单条不编，多条连续编号>
同类扫描：<实际扫描入口、结果及残留>

影响面：
<模块、路由、权限、依赖与存量兼容、配置或迁移影响>

验证证据：
<修复前基线与复现；修复后回归/同类/边界结果>
<并发修复的变异验证和必要检查的实际结果；未覆盖项与原因>

Refs: <审计发现编号；非审计修复不虚造编号>
```

提交后另填复验记录，避免提交正文循环引用自己的SHA：

```markdown
# <主题>修复复验 — <YYYY-MM-DD>

## 发现与准确窗口
<原报告/稳定发现号、修复前基线、修复后各仓完整SHA、实际依赖/构建/运行产物>

## 复现与回归
<原失败及触发条件、修复后复现、同类扫描、正负/边界回归；命令、退出码与结果>
<并发修复的变异记录和稳定红证据；不适用时写明理由>

## 门禁与限制
<本候选适用门禁、实际结果、首次失败/重试/跳过（skip）/未运行及影响，材料ID与必要校验值>

## 结论与交接
<逐发现待复验/复验关闭及依据，残余风险、台账回填和下一步>
<本地提交、远端CI、main合入、发布、部署状态分别列明>
```
