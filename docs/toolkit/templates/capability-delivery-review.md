# 能力交付评审模板

> 用途：把一次已授权交付的模型、取舍、证据和收尾讲清楚；读者：所有者、实现者与评审者。输入：任务授权、准确候选、现行设计及实跑证据；输出：本地评审实例。状态：配合[系统理解与交付计划](../../planning/system-understanding-and-delivery-plan.md)的前三批试行空白原件，不是正式新门禁，不替代AGENTS要求的三节变更评审说明或既有验证。权威：[文档维护约定](../../documentation.md#6-可复用工作资料与执行生命周期)、[工程公约](../../standards.md)及对应模块合同；本模板不是新的设计或状态权威。

复制后替换占位符，未知写待核及影响；“不适用”须给理由，不能默认绿色。填写后的实例归本地过程材料；正式模型和决策回填现有模块/ADR，必要长期结论按文档约定归档，不回填模板。原始日志、截图、账号、凭据和个人路径不放原件或受控结论。

按本批实际影响裁剪栏目并引用已有材料；常规交付沿既有三节短审阅卡组织，复杂证据按需展开，不要求每批另写长报告。三个试行小批从Phase6实际获准实施开始计算，本次计划落档不计入。收尾范围为本批参与仓库、工作树及资源，保留与清理按现有授权及归属执行，不从模板推导扩大操作权限。

```markdown
# <任务主题>能力交付评审

**本地准备栏：基线、范围与事实来源。** 这里用于准备和链接证据，交付回复仍按下列三节组织。

- 授权与边界：<用户要求及来源；允许操作、排除项、待确认事项>
- 任务目标：<谁在什么场景遇到什么问题；本批可观察的结果>
- 准确候选：<逐仓分支、完整SHA；未提交差异、归属及候选冻结位置>
- 对照基线：<修复前/变更前准确组合；各仓消费者pin、锁文件和必要配置>
- 运行组合：<二进制/前端产物/镜像与源码绑定；环境属主和隔离边界>
- 当前事实：<源码文件路径＋符号；对应配置、迁移和真实消费者>
- 设计依据：<现行模块/合同/ADR；有效决定与被替代内容分别标明>
- 历史与候选：<报告时点/准确基线；后继规划尚未实施的部分>
- 证据位置：<本地过程实例位置、稳定材料ID、必要校验值；未知项及补核方式>

## 1. 改动摘要

<交付时本节合计不超过10行，用人话说明文件、原因和核心逻辑，不贴代码。>

- 解决的问题：<触发条件、原行为与本批行为；涉及文件及符号>
- 模型与主链：<输入→关键状态/数据→授权→事务→副作用→输出；各层职责>
- 关键不变量：<必须持续成立的约束；由哪些符号/约束/守卫维护>
- 取舍与理由：<可行替代、所选方案、成本及明确保留的可靠性/兼容边界>
- 例外与失败：<至少一个拒绝或失败反例；谁拒绝、何时回滚、调用方看到什么>
- 同类与剩余：<扫描边界、已处理同类路径、仍未处理部分及承接入口>

## 2. 影响面

- 模块与消费者：<主仓及兄弟仓受影响的入口、装配和调用方>
- 接口与协议：<签名、字段/序列化、API路由、错误语义；破坏性与升级要求>
- 授权与身份：<权限码、L1/L2/L3、来源/撤权、豁免及管理员分支>
- 数据与迁移：<表/索引/迁移编号、存量兼容、up/down与代码回滚耦合>
- 配置与依赖：<新增/改变项、默认值、必要理由及替代方案>
- 运行与体验：<并发、失败恢复、外部服务、UI状态和部署条件>
- 文档与台账：<现有模块/ADR/控制台回填位置；已同步/待同步与影响>
- 明确限制：<尚未实现、未获授权或需另批处理的内容及原因>

## 3. 验证证据

- 验证分类：<quality-plan/quality-check的候选范围、档位和适用检查；结果依据>
- 反例设计：<预期拒绝/失败、触发控制、正向对照；为何能检验关键不变量>
- 原始红：<准确旧组合、命令、退出码、断言及材料ID；未复现则如实说明>
- 修复后绿：<准确新组合、同条件结果、次数/统计口径；不可借用别的候选>
- 变异/故障：<必要时移除修复、并发交错或故障注入及结果；不适用给理由>
- 完整检查：<逐项命令、退出码、结果与证据；按适用门禁填写，不以分类替代>
- 覆盖率：<基线/候选的同口径范围与变化；未测或不可比的原因>
- 首次失败与重试：<原失败、环境/产品归因证据、修正点及重跑范围>
- 未覆盖路径：<缺失/失败/取消/跳过项、原因、失去的保证与下一步>
- 结论边界：<静态确认/专项通过/组合通过分别说明；发布、部署另记>

### 所有者讲解与追问

讲解状态可选“待讲 / 已讲待核 / 待补讲 / 本人确认”，由实际讲解与核对决定。
AI只能记录已发生内容，不能代所有者勾选、宣布掌握，或从“可以”推导已经理解。

- 讲解范围：<模型、主链、不变量、取舍、拒绝/失败及证据入口>
- 当前状态及来源：<状态、谁确认、原话/记录位置；未发生保持待讲>
- 所有者复述：<本人实际讲述的内容；未提供留待本人补充>
- 追问与回答：<实际问题、本人回答、待核事实及对应源码符号>
- 待补项与复核：<哪里仍讲不清、下一次如何验证；不以AI补答案充当本人掌握>

### 个人贡献核对

下列各项分别由本人补充；仓库存在实现或测试，不证明是谁提出、拍板或完成。

- 提出问题/需求：<本人 / AI辅助 / 其他；实际参与及来源，待本人补>
- 设计与拍板：<候选由谁提出、本人实际决定什么、沿用什么；待本人补>
- 实现与审查：<本人亲写/审查/AI辅助的范围；未参与部分，待本人补>
- 定位与修复：<本人做过的排查、判断和操作；与工具/AI贡献分开，待本人补>
- 验证与验收：<谁定义预期、谁执行、谁判断；本人可独立解释的证据，待本人补>

### 收尾与交接

每项记录“实际状态＋对象/归属＋证据＋保全或未决处置”；不适用须说明理由。
main干净不证明其它副本已清理。运行中的旧main可明确保留，记录用途、属主、
准确版本、与本次候选的差异及后续处置，不把未升级实例写成已承接。

- 本地提交：<准确提交与显式路径文件集；未提交内容及归属>
- 推送与远端CI：<远端引用、准确窗口/提交、结果；未推送保持未推送>
- 合入：<目标分支、PR/合入提交及检查；未合入保持未合入>
- 本地同步：<逐仓main及工作分支与已确认远端的关系；核对时点/证据>
- 工作树/副本：<逐个分支、HEAD、用途、归属、保留或清理决定及真实结果>
- 未跟踪文件：<逐项归属、纳入/归档/保全/待核；未知归属不删除>
- 暂存区：<逐项归属及处置；他人staged内容是否原样保全>
- stash：<逐仓记录的归属、内容去向和保留理由；不能仅看当前工作树>
- 分支与保护：<本地/远端分支、保护规则现状、消费者pin、在途工作及保留/删除依据>
- 过程材料：<日志/截图/探针/备份的归属、保全、归档材料ID及必要校验值>
- 运行资源：<进程/端口/容器/卷/网络/临时库逐项归属；保留或清理证据>
- 遗留与交接：<未决事项、下一负责人/入口、阻碍及影响；不从清理推出交付完成>
```
