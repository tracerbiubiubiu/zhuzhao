# 审计执行卡模板

> 用途：在执行前明确范围、基线与操作边界，接续时核对新增改动；读者：执行者与接手者。输入：当前任务授权、仓库状态及可用环境；输出：本地轮次执行卡。状态：空白原件，不代表环境或范围已确认。权威：[审计方法§2](../../review/audit-playbook.md#2-启动先建执行卡与覆盖清单)。

填写后的实例放本轮本地隔离工作区；原件随Git，不纳入真实账号、凭据或日志。收尾按[生命周期](../../documentation.md#6-可复用工作资料与执行生命周期)提炼正式结论并归档必要原始证据。准备项区分已确认、待确认及影响。下方 SHA 是完整 Git 提交标识，SSOT 是设计的唯一权威来源，`pin` 是调用方固定使用的版本；“覆盖游标”指上轮查到哪一项、下一项从哪里开始。

```markdown
# <轮次>审计执行卡

## 目标与范围
<首次全量/阶段/专项/复审、当前交付范围、未来参照、明确排除项及失去的保证>
<当前会话授权、允许操作、禁止项与待确认项；不从写报告推导修代码或推送权限>

## 基线与来源
<逐仓路径/分支/完整SHA、工作区状态、在途归属；增量起止与逐笔提交>
<本地HEAD、远端已确认状态、发布tag、锁文件、replace/workspace及消费者实际固定的版本（pin）>
<设计SSOT、有效/被替代决策、历史报告、债务及后续规划入口>
<运行二进制/前端资源/镜像来源与准确版本，未核项及下一步>

## 环境与材料
<环境与资源属主、隔离DB/Redis/对象存储/端口、账号策略及清理边界；不填秘密值>
<轮次工作区、证据分类、Git归属、正式报告目的地、归档材料ID和恢复信息>
<静态准备与动态准备分别列确认状态/证据/下一步，网络或首拉故障保留原始记录>

## 覆盖与批次
<阶段顺序、每批主题/负责人或会话/占号时间、发现编号前缀、出口及排除理由>
<逐能力/场景：设计阅读深度、实现入口、装配配置、上下游、数据权限、测试/动态证据>
<状态：未审/进行中/已审/受限/范围外；原因、影响和剩余盲区>

## 进度与接续
<已完成及证据、未决设计、发现去重与状态、覆盖游标、下一步和依赖>
<接续/总报告前各仓最新HEAD和相对基线差集；逐项决定纳入或排除>

## 收口
<正式结论、独有输入与失败/限制的承接；原材料ID、必要SHA256与本地索引>
<实际清理资源及保留项，Git状态与未完成项；提交/CI/合入/发布/部署分别记录>
```
