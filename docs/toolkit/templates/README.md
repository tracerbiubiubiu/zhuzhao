# 空白模板

> 用途：复用结构而非复用某轮结论；读者：维护者与审计协作方。范围：执行卡、正式报告、修复与复验、能力交付讲解试行；状态：可供填写的原件，未代表任何实际执行。权威：[审计方法](../../review/audit-playbook.md)及[文档维护约定](../../documentation.md#6-可复用工作资料与执行生命周期)。

- [审计执行卡](audit-execution-card.md)：在开始前明确范围、准确基线、允许操作、环境和证据位置；填写后的实例默认属于本地过程材料。
- [审计报告](audit-report.md)：保留覆盖、发现、原失败和验证边界；只有需长期追溯的正式结论进入review/reports，一般过程报告仍留本轮本地工作区。
- [修复提交与复验](fix-and-reverification.md)：按真实修复填写提交正文，提交后另记完整 Git 提交标识（SHA）再复验；提交与发现关闭分别留证。
- [能力交付评审](capability-delivery-review.md)：配合[系统理解与交付计划](../../planning/system-understanding-and-delivery-plan.md)，在前三批试行系统如何工作的讲解、个人贡献核对，以及各工作树和运行副本的收尾检查；不新增正式门禁，填写后的实例归本地过程材料。

复制时替换所有占位符。未知内容写待确认及影响，不以模板预填项宣称完成。完整日志、截图、账号和个人路径不放回原件。发现字段或方法需要改进时，更新对应唯一原件及其权威依据。
