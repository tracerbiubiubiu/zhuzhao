## 2. API 限流扩展（必做）

### 2.1 现状

- Phase 1：登录等公开路由限流（AuthService，Redis Lua 原子计数，fail-close 503）——见 [phase1/02-auth](../phase1/02-auth.md)、[architecture §5](../design/architecture.md)。
- Phase 3：扩展为 **API 级限流**（按用户/按 IP/按路由维度）。

### 2.2 设计

```yaml
rate_limit:
  enabled: true
  default:
    rps: 20            # 每用户每秒
    burst: 40
  routes:
    /api/v1/auth/login: { rps: 3, burst: 5 }   # 登录更严
    /api/v1/notifications: { rps: 30, burst: 60 } # 轮询可放宽
```

- 维度：`user_id`（登录后）+ `ip`（匿名/登录）双键。
- 存储：Redis Lua（与 Phase 1 同款，跨实例共享，W1 后天然多实例一致）。
- 超限返回 429 + `Retry-After`；⚠️ 全局阈值 vs 每用户阈值待拍板。

## 3. CORS AllowAll 收紧（必做，B7）

- 现状：`gin-contrib/cors` AllowAll（Phase 1 开发便利）。
- 收紧：配置化白名单（`cors.allowed_origins`），仅放行实际前端域名；上线检查单纳入。
- ⚠️ 若本次不含前端，可暂留开发配置但必须在对外暴露前收紧（记录为上线项）。

---

## 4. 密码过期策略（🚦 触发条件驱动）

- 触发：合规要求（如等保/内控要求定期改密）。
- 现状：`users` 表**无密码过期字段**（roadmap 预留扩展）。
- 设计（若启用）：
  - `users` 表加 `password_changed_at` + 策略配置（`security.password.max_age_days`，默认 0=关闭）；
  - 登录时校验过期 → 要求改密（可配合 Phase 2 auth-enhance 的密码策略）。
- ⚠️ 迁移影响：新增列需迁移；是否启用由你决定。

---

## 5. 异地登录检测（🚦 触发条件驱动）

- 触发：多地域/高安全要求。
- 设计：
  - 登录时记录 `ip` + 地理位置（第三方 geo 库，⚠️ 数据源待选）；
  - 新设备/新地域首次登录 → 站内/邮件通知（依赖 W2 通知能力）或二次验证；
  - 阈值与是否阻断由策略配置。
- ⚠️ 依赖通知能力（7b）就绪；优先级低于 API 限流。

---

## 6. 验证码（🚦 触发条件驱动）

- 触发：登录/敏感操作存在暴力破解或自动化风险。
- 设计：图形/滑块验证码，登录失败 N 次后触发（与 Phase 1 锁定叠加）。
- ⚠️ 引入外部验证码服务（⚠️ 选型）或自研简易方案；低优先，按风险决定。

## 8. 验收用例

|---|---|---|
