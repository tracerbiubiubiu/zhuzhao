# 17 - M-UAA：统一认证与岗位权限治理接入

> **2026-11-12现行修订**：所有者再次明确首次内网部署必须接公司UAA，并提供岗位权限治理指南重新核验。本里程碑不是纯SSO。现行合同以[UAA认证与权限治理接入](../design/uaa-governance-integration.md)为准；本页保留立项、历史估算和迁移承接。**未实施、未真实接入验收。**
>
> 原“对后续phase影响零”“纯加法/判定零改动”“六场景全部本地自管”“换config即可”“停同步永久冻结授权”“弃用零功能损失”不再作为保证。三层鉴权及独立部署方向保留，具体来源、会话和同步治理须建设并验证。

## 0. 范围和边界

对接范围包括统一登录、资源目录上报、账号同步、用户角色关系、角色资源关系、条件适用的数据范围治理和权限配置回传。指南对自研类系统提供资源上报、中央创建角色及绑定的路径，默认按此接入，不擅自简化为“认证统一，所有分配仍由本地自由管理”。

本地继续执行L1接口权限、L2资源可见性和L3动作/状态约束。中央管理授权的分配结果与本地执行授权是两个职责：本地受管绑定是执行投影，不是第二个分配权威。角色、菜单和配置页面需展示来源并限制写入，不能以UI只读代替后端约束。

## 1. 原六件与三路数据面校准

| 原对接件 | 现行承接 |
|---|---|
| SSO登录 | 授权码方向保留，实际协议/安全校验和身份映射按E01-UAA-C核验；本地签JWT/RT，mock IdP同例，不能凭一个LoginURL/ExchangeCallback签名宣称完整支持 |
| MQ基建 | 私有adapter连接企业MQ并可靠投递公共治理入口；不要求所有公共/mock部署都运行企业MQ |
| 资源上报器 | 核心/扩展稳定资源目录导出和差异，私有侧向中央注册；先确认目录、再激活关系，不能空目录覆盖 |
| 账号消费者 | 与HR逐字段划分权威，复用本地领域提交及会话吊销；稳定外部身份加别名映射，不以工号/邮箱直接并号 |
| 原“角色关系消费者” | 明确拆为**用户-角色**与**角色-资源**两个集合流；作用范围分别是账号和角色，不能整应用清空；审批关联结果按需可靠回调 |
| 数据权限配置回传 | 关系/业务动态属性本地管理；稳定通用属性满足指南条件时由中央管理范围值、本地执行；配置回传最小化，格式/频次待核验 |

资源的新增、变更、停启与退役分别映射，不同对象的动作枚举不能混用。未知码、缺失范围或不完整全量均不得解释为“删除全部授权”。工单门户待办外推仍是候选扩展，随实际待办接口单列，不能因有MQ就视为已接通。

## 2. 认证、治理与业务数据权限

统一认证解决身份，中央岗位权限治理解决申请、批准、变更和回收；本地保留业务数据范围、参与关系、状态约束及审计。通用数据属性是否纳管按具体使用方式判定：组织关系过滤与按角色配置组织范围不是同一件事。不能因为旧指南摘要表写“自管”就忽略后续条件纳管规则。

独立模式是正式支持的完整运行模式，不限于开发或mock：不接UAA时保留原有本地账号、角色、菜单授权与权限管理，也不需要公司adapter或MQ即可启动使用；菜单目录继续按现有迁移规则维护。企业模式在迁到内网后通过私有adapter接入，按来源接管纳管授权。两种模式共用公共核心，分别验收，不能因接入UAA而删除独立管理能力。企业模式的本地入口、应急账号和权限例外需要受控政策，禁止中央故障自动放开所有员工账密或永久保留最后一次授权。退出中央管理须有批准的授权/凭据接管和验证，不再承诺只关开关即零迁移恢复。

## 3. 实现前必须补的基础

- **来源闭合**：`roles`/`user_roles`/`role_menus`加source的历史方向仍保留，但有效角色还包含组织赋角和继承；具体模型须覆盖完整来源链，防止撤权后从另一条路径重新授予。
- **身份和幂等**：账号/人员/组织身份及source管辖区分，消息去重与领域提交同事务。已有工号部分唯一索引不保证空值、软删、重放或改号的完整语义。
- **安全生效**：停用不只写DB；当前JWT/RT/PAT/会话及后续委托需按约定失效。按已选拓扑验证策略重载及会话失效；采用多实例前Casbin和缓存须可靠收敛，不能仅刷新消费者所在进程。
- **受限映射**：中央同名admin/superadmin不自动映射本地内置管理员；组织/虚拟组的owner也不是系统超管。
- **可恢复交付**：目录确认、三路feed、依赖等待、乱序/空集、回执及对账分别可恢复；broker ACK与审批“业务生效成功”分开。

## 4. 历史决定与估算

2026-10-09立项：认证授权码、权限MQ数据面、三层本地判定。2026-10-20所有者已选来源列延伸方案a；**拍板不等于迁移已执行**。本轮保留该方向并补完整来源路径，不预分配迁移号，实施前查实际占用和[迁移地图](../review/11-project-control.md)。

历史SSO件2–3人日、MQ数据面13–21工日、全含15–24工日（曾表述3–5周），均为旧范围粗估，不是本轮重审后的固定工期。本轮E01现有3–6日也不能吸收全套UAA；与D06/X01/X02按子件扣重复估，外部申请/等待单列，不叠算或换算成已承诺日历。

## 5. 新排期和激活门

- **E01-UAA-C / P6.0**：指南到逐字段/能力管理权、资源码、三源授权、条件数据范围、撤权/应急和待验合同；新增设计投入初估2–3工日。D06/X01-C/X02-F涉及身份/授权部分先过此门，不阻塞无关mock。
- **E01-UAA-P / P6.1**：核心公共port、受限领域投影和合成IdP/三路feed/回执，正反例及来源/撤权验证。实际投入待C出口拆重估算。
- **E01-UAA-R / P6.1起独立联调**：私有企业协议映射、影子/目录确认、小范围启用、真实撤权/恢复及测试报告；**企业模式首次正式激活硬门**，若上线早于P7则前移。风险/HR真实provider通过不能替代UAA。

P6–P9业务方向继续承接，身份/权限合同和对应工程投入必须调整，不再写“对phase6影响零/排期待定”。实际依赖及未计价项见[总账](../review/planning-backlog.json)、[执行排期](../review/execution-schedule.md)。本轮没有开始真实接入。
