# 部署、备份与故障处理

按任务选择入口，命令的执行目录与目标环境以各页开头为准。部署文件仍在仓库 `deployments/`，本目录集中维护说明。

| 任务 | 文档 | 操作前先确认 |
|---|---|---|
| 本地联调 / 单栈与三栈部署 | [deployment.md](deployment.md) | 资源归属、密钥配对、显式迁移与种子顺序 |
| 排障、测试账号、验收隔离、会话交接 | [运行手册](runbook.md) | §4 账号台账与 §7 在途占用 |
| 备份、独立恢复、PITR、对象与JSONL | [backup.md](backup.md) | 实际备份已启用且恢复验证可用 |
| 审计归档定时任务切换及回滚 | [切换审计归档触发器](cron-migration.md) | 一次只留一个触发器，等待在途结束 |
| 端口取号与冲突处理 | [port-allocation.md](port-allocation.md) | 固定/动态端口及现有监听 |

运行手册中的事故和结果有日期；不能用过去容器名、PID或镜像直接替代当前来源核验。新命令先在自有隔离环境验证，再把有效知识回填。

[运维工具构建与扫描](tools/README.md)集中维护migrate/rclone的源码锁、构建、扫描和功能验证步骤；实际Dockerfile及依赖锁仍在deployments/tools，不因说明归位改变运行行为。

这些页面涉及可独立查用的流程，继续随 Git 维护。例如部署页给出组件的接线顺序，端口表还被 Compose 文件引用。恢复时分别使用数据库、对象和导出审计的步骤。即使审计归档切换文档源自 Phase 4，两类触发器互斥、后台执行资格和回退顺序今天仍可用于运维。 [保留判断](../documentation.md#2-什么应进入-git)
