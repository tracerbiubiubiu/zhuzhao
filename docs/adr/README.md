# 架构决策记录（ADR）

> Architectural Decision Records

## 什么是 ADR

每个 ADR 记录一个独立的架构决策，包含：背景、决策、理由、后果。

## 与 design-decisions.md 的区别

| | `design-decisions.md` | `adr/` |
|---|---|---|
| 定位 | 讨论过程的完整记录 | 决策的最终结论摘要 |
| 内容 | 方案对比、推理细节、Q&A | 背景 + 决策 + 理由，1 页以内 |
| 粒度 | 一个主题可能涉及多个决策 | 一个文件 = 一个决策 |
| 编号 | 无 | 顺序编号（ADR-001, ADR-002...） |

## 何时使用

- **开发阶段**：讨论记录写入 `design-decisions.md`
- **决策固化**：从讨论中提取关键决策，形成独立 ADR
- **Phase 1**：暂不需要，目录预埋

## 模板

```markdown
# ADR-XXX: 决策标题

## 日期
YYYY-MM-DD

## 状态
已采纳 / 已废弃 / 已替代（被 ADR-YYY 替代）

## 背景
为什么需要做这个决策？遇到了什么问题？

## 决策
最终选择了什么方案？

## 理由
为什么选这个方案？关键 trade-off 是什么？

## 后果
- 正面影响
- 负面影响 / 风险
- 需要后续跟进的事项
```
