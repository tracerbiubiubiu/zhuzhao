# ADR-005：统一能力接缝与AL源变更事实责任

日期：2026-11-13。状态：**新增需求驱动的设计候选，未实施**；只提交阶段快照，准确schema/迁移/容量及增量估算留对应设计门。细节权威为[能力调用合同](../design/capability-invocation-contract.md)，分期在[增量范围册](../review/capability-interconnect-supplement.json)。

## 背景

所有者要求核心和插件的产品能力均可受权对外调用，并有内部共同调用通道；工单任务结果、定时更新AL及AL变化触发任务要形成闭环。现有I01/X01、C03/R01/D12可以承接大部分方向，但不能仅靠编译期动作表、进程内尽力Hook或网页操作后的事件补发宣称数据全部互通。

ADR-003历史收敛要求AL不感知事件、由主仓调用成功后发布。这能描述主仓某次业务操作，不能证明AL直接API、定时写、导入等全部数据变化被捕获。新增需求改变了该覆盖前提，需要限域修订。

## 设计方向

1. 共同能力描述和逻辑调用合同覆盖核心、插件及薄连接器；本地仍用领域Port，跨服务HTTP，长任务可靠异步。现有API保留，不强制全部绕HTTP或一个RPC入口。
2. 静态能力用`capability_id + contract_version`；OpenAPI `operationId`只是接口定义别名；动态`operation_id`保留效果幂等语义。旧wire/action_id先做映射，不能改名造成重复副作用。
3. AL只在数据写事务内产最小变更凭证/outbox或可证明完整的变化feed。主仓管理订阅、权限/因果预算、路由与任务；TR负责已批准的业务调度。AL不依赖TR、不复制IAM、不构造第二业务事件总线。
4. 命令、事实、结果receipt和通知分型；统一公共元数据及完成语义，不合并领域状态机。MCP适配选定的同一能力和授权路径。

## 保留与覆盖的边界

保留ADR-003的独立服务、独立PG数据库、统一网关、服务签名和薄动态数据平台定位。覆盖“只在调用方成功后发事件足以捕获全部AL变化”的旧保证；不恢复Change Stream平台、字段历史库、独立权限产品或通用编排引擎。

源事实写入是AL自身事务的责任，不是让主仓连接AL库；跨库仍不声称一笔事务。旧代码没有该能力，当前接口、表和部署不因本ADR自动变化。

## 代价与验证门

AL源事实、受权任务adapter、订阅和共同准入有新增工程量，不默认包含原I01/R06。先核写入口覆盖、批量粒度、幂等/完整性、重放、回调认证及自触发预算，再复估和排程。

P6.0/1先合同/最小门面，P6.3先工单任务结果，P7交AL双向代表链，P8/9按实际需要扩展。D12不反依完整I01，避免循环。无实际变化、乱序/重复、任务写回AL再触发自身、队列满和旧worker恢复均需正反例；未执行这些验证不得称互通已交付。
