# Phase8 — 领域智能体与既有能力消费

> **2026-11-14交付边界**：见[基础先行](../design/foundation-release-boundaries.md)。模型API、知识检索、外部Agent与领域host按实际场景分开交；一条只读接入不应被未来MCP、定时任务和完整host一起前置。A05–A07整包依赖在相应开工前按所消费的身份/查询/ACL/持久状态子出口拆清，当前不为缩排期盲删安全依赖；保留双轨方向，不一次建设完整智能体平台。

> **2026-11-13承接原则**：Agent、SOAR及报告继续消费[共同能力调用合同](../design/capability-invocation-contract.md)，共用当前授权、操作/结果与适用预算；新增入口不另写一套业务实现。继承[生态一致性](../design/ecosystem-consistency-contract.md)，按真实场景扩展，不要求现在冻结全部远期schema或改造全部存量。

> 2026-11-11重规划；尚未实施。模型仅调用已有服务；大量mock保留。专业平台优先，领域Agent限本平台特有业务。唯一工作项与估算见[总账](../review/planning-backlog.md)。

## 1. 双轨智能体

A05支持已有企业Agent连接和本平台领域Agent配置：模型/外部Agent版本、工具/skill允许集、业务上下文、数据域、预算、确认与启停。A06调用已有知识平台的受权检索与引用，不重建知识采集和向量库。A07使用成熟组件的最小受控host，有限工具循环、可信skill、运行证据和暂停恢复；不建设通用Agent开发站或技能市场。

本地场景围绕风险、工单、受权查询和计划任务；专业研判、资产、情报仍取现有平台结论。外部Agent运行图与记忆归其服务，本地只存调用引用与效果；领域Agent保存自身必要恢复状态。配置发布不授予执行权限，skill不授予工具权限。

## 2. 专业执行与协同

R04双向接SOAR和企业Agent：它们可受权调用平台Action，平台可触发其workflow并消费权威run状态；每链唯一编排和重试主。R03先复用已有脚本/执行平台，只为明确缺口补有界胶水与隔离，包审批与逐次执行批准分开。模型部署和专业执行器均不在本平台建设范围。

工单动作面板、结果、日志和工件继承D12/I01–I03，不再重复开发result列。凭据引用和目标授权在执行时复验，非幂等动作效果未知先对账。

## 3. 原自动化旅程与渐进扩充

R03明确管理员提交/登记制品→发布审批→不可变版本/预构建→工单或U08表单受权运行→结果/日志/工件/历史；先一成熟SOAR/runner供给，后增Actions。平台只保必要引用/批准证据和入口，上传/构建/隔离可由外部承载；有确证胶水缺口才另立有限runner，不以供给调查代替旅程完成。

E04先一套固定周/月报和白名单运营查询，产出Word/PDF，经TR定时或终态事件生成并分发/对账；先用已有报告API，缺供给有限模板兜底，后扩模板/订阅。E06先外部通报收文→内部分责处置→回复稿/回执，不能等价替换成incident。内容权威仍归专业平台。

双向SOAR与企业Agent消费同一受权目录/运行合同；新AI不吞掉旧手动/脚本入口，也不把所有旧可选池当必做。详见[全项目演进](../design/project-evolution-strategy.md)。

## 4. 条件项的本阶段去向

E03在P6.3完成审批/日历等场景裁决，P8消费现有供给或补限定业务策略；E04在P6.E冻结首个报告/受众/供给，P8交固定报告，高级视图/SSE按价值另定；E06消费TIP/SOC/知识/通告与演练供给，只保留生命周期需要的引用和证据。不能看到旧候选列表就整包立项。

## 5. 出口和待决

按所选方向分别验收：领域Agent旅程验证受权取数→证据/草案→精确确认→业务效果/任务→可恢复回执；选择外部Agent或SOAR时交其一条mock合同链，具备环境者另做真实互操作。首条纵切不要求三轨齐备，未选方向保留后继范围。预算耗尽、注入、撤权、重复确认、陈旧结果、取消竞争与崩溃恢复按实际启用组合回归。

开工前比较现有企业Agent能力、同语言SDK与有限状态实现，明确本地host增量；不预定框架，不新增模型基础设施。知识API不提供范围授权时限制共享集合或受权深链，不以prompt隔离数据。

规范见[AI能力设计](../design/ai-capabilities.md)和[平台演进](../design/platform-evolution.md)。旧“完整自建脚本中心/强制后续迁回”的实现形式由总账提出更小替代，业务价值尽可能承接，历史研究不作为当前必建清单。

## 双模式及企业授权继承

本阶段沿用[UAA与独立模式合同](../design/uaa-governance-integration.md)。独立模式不依赖公司UAA配置；企业模式按纳管来源和当前有效授权执行。Agent/知识/skill/专业执行、后台恢复及扩展不能用仍有效的配置或grant绕过已撤权/过期投影。各入口在本阶段开工和验收时复用合成反例，不反向成为P6.1双模式基础交付的前置，不另建UAA专属阶段。
