# 06 · 发散功能建议清单

> 性质：发散研究稿（见目录 README）。所有者原话："我的描述可能还是不全，看看你有什么建议的功能"。本清单按"安全部门每天会碰到什么"发散，每条给价值 / 业界出处 / 粗量级 / 依赖 / 建议归属波次。量级为单人周，仅供排序参考。

## 波次约定

- **W-A（phase7 核心）**：接入扩源（SOC / 日志告警入口站、路由、维护窗）+ 自动化地基（Action 注册表、service account、调度分工、资产门面、可观测）。（SOAR 接入归 phase8——2026-10-20 双审计 D24 修正波次漂移，原"+ SOAR 作为调用方接入"以 07 §4.3 为准删除）
- **W-B（phase8–9 核心）**：phase8 = SOAR 能力迁移（脚本沙箱 / 预定义任务 / 连接器 / 工单动作面板 / 自助任务门）；phase9 = 处置闭环深化 + 自研编排引擎 MVP。phase10（编排迁移与 SOAR 退役）/ phase11（智能面）在行内直接标注。
- **W-C（随行小件）**：可塞进任一批次的 ≤1 周件。
- **W-D（触发驱动）**：有明确触发条件再做。

## 推荐的最小可感知组合（"第一口能吃到的"）

若 phase7–8 只能先做四件，建议：**F3 Action 注册表（phase7 地基）→ F4 脚本库（含 runner）→ F6 工单动作面板 → F18 自助任务门（三者 phase8）**。理由：这四件让安全同事在**现有工单页**上立刻获得"跑一个富化/巡检/处置并把结果贴回来"的体验，不需要等 playbook 画布；叠加 F21 的"SOAR 调我们 Action"后，过渡期 SOAR playbook 也能直接消费这些能力；它们同时是后续 F5（phase10 编排迁移）与 F12（phase11 AI）的地基。

## 与既有规划的衔接提示

- F1/F13/F14 是地基型，建议作为 phase7 的前置批（可与 phase6 并行穿插）。
- F2/F20 随 phase7（接入扩源）；**F21 归 phase8**（SOAR 双向集成——D24 修正）；F4/F6/F18 构成 phase8 主体（SOAR 能力迁移）；F9/F10/F11 构成 phase9 主体（处置闭环），F16/F17 是其随行；F5/F22 归 phase10（编排迁移与 SOAR 退役）。
- F7/F8/F10/F11/F15/F19 都是 ≤1 周小件，适合作为各 Wave 的"收口填充"。
- S7（AI 助手）复活形态 = F12 + phase11 本体（范围后置讨论）；本清单让其"工具面"提前就位。
