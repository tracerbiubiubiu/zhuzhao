## 背景与坐标

平台现状 = 自研 IAM + 资源级工单 + 任务执行（taskrunner）+ 风险模块规划中（phase6）。使用方 = **安全部门**，对接生态 = 资产管理、日志平台、SOC、SOAR、威胁情报、公司 UAA/HR/统一消息。所有者 2026-10-20 定调：**平台在逐渐统合各个分散平台的能力（安全运营、风险管理、渗透测试等），把分散的能力与数据打通、聚合到一起**；终态还包括对接 AI 智能体平台（双向）。本研究以"安全部门的日常到底长什么样"为坐标重估平台蓝图，**允许突破既有能力边界、允许提议修改已实现架构**。

## 十三条核心主张（速览）

1. **统一 Action 抽象是全局钥匙**：内部 handler、外部连接器、脚本节点、AI 工具、工单动作，统一为带 JSON Schema 输入/输出的 Action。业界殊途同归（XSOAR 的 app/action、MCP 的 tool），我们已有雏形（taskrunner action_id、capability_registry 定稿方案），缺的是"类型化 I/O + 注册表升格"。见 03-A1。
2. **脚本即 Action**：脚本节点不另造协议，用与连接器同一份 manifest 契约（05 号文档），注册进能力目录后，编排、工单动作、AI 工具调用消费的是同一个东西。
3. **脚本契约的业界共识八条**：声明式 manifest、类型化 I/O schema、数据与日志通道分离、secret 注入不进参数、工件目录、退出码语义、超时/取消、大小上限。05 号文档给出完整规范与两个可跑样例。
4. **脚本执行面应为独立第二执行端**（sandbox-runner——容器池+子进程起步、每运行一容器为二档，与 03-A2 对齐；三审勘误 E-D5），这正是 capability_registry 定稿时预留的触发条件——所有者这条愿景输入直接命中它。见 03-A2。
5. **告警聚合的落点已在 phase6**：原始告警接入 → 归一化 schema → 指纹去重 → 以风险单为聚合实体（R1 已设计）→ R3 联动整改工单。缺的是接入面（webhook 入口站）与归一化 schema，不是处置模型。见 02-G2、03-A7/A8。
6. **资产面由外部资产平台提供，平台只做查询接入**（所有者 2026-10-20 补充）：安全场景处处需要"告警 → 资产 → 责任人 → 部门"的解析链，但资产真相源在另一平台，我们不建台账——只做查询连接器 + 统一解析门面（按配额/时延决定是否加读穿缓存），并在自有实体上存外部资产引用与解析时快照。见 02-G1。
7. **编排分阶段、终态迁回平台**（2026-10-20 晚两次口径）：Stage 1 由公司 SOAR 承担任务编排、其脚本调用平台提供的能力（任务），平台先做能力提供方（Action + 脚本沙箱 + 连接器，phase7–8）；**Stage 2 是既定排期而非触发驱动**——phase9 自研轻 DAG 引擎 MVP 先跑平台自有链路，phase10 playbook 设计器 + SOAR playbook 逐个迁回 + 双跑期 + SOAR 退役。工单流程与任务流程 = 一套画布 + 一套节点词表 + 两套执行语义，引擎不合并（D22）。见 07-§4.3–4.5、03-A5。
8. **事件面建议"持久化域事件表（outbox）"中间态**：这是对"不建 event bus"既有边界的**翻案提案**——不引 broker，用 PG 表 + 拉模式订阅，换 SOC 接入/playbook 触发/通知/审计的可重放性。见 03-A3。
9. **非人身份与委托链要提前进 IAM**：playbook 执行、连接器、AI 代操作都需要"以谁的身份、能做什么、怎么审计"。建议 on-behalf-of 委托链 + 审计标记。见 03-A6。
10. **若公司已有统一 SOAR，playbook 域归属必须先拍**：我们的平台定位是"治理 + 工单 + 跨系统任务自动化 + 台账"，还是再造一个 SOAR——这决定 phase7 的形态与体量。见 02-§5。**（已答，2026-10-20 晚：公司有 SOAR → 过渡期协同模式、能力先迁、编排终态迁回平台——D3 / D1）**
11. **先定完整形态、核心先搭、处置渐进**（所有者 2026-10-20 口径）：07 号给目标态能力地图与九条跨阶段不变量；每阶段分核心切片 / 补全切片，接入先于处置；手动处置（既有工单）第一天可用，所以"慢慢做"不留空窗。
12. **统一接入层推/拉皆备，从 phase6 第一天按通用形态建**：首源 = 漏扫结果平台（推两入口 + http-pull / db-pull / file-pull 水位拉取；推拉进同一指纹，去重即对账），phase7 的 SOC / 日志告警直接复用；整改跟踪走工单（R3）+ **人工复测在工单填写、关单按结论联动风险单**（D13；暂不对接扫描器做自动复测）。db-pull 对应"曾需主动去对方库拉"的特殊情况，安全边界见 D12。
13. **终态还包括对接 AI 智能体平台（双向）**（所有者 2026-10-20 补充）：平台可调用智能体能力作为输入 / 任务，智能体也可调用平台能力——两个接口面已被 A1（智能体 = 能力来源 / Action 暴露）与 A7（智能体产出 = 事件源）天然覆盖，登记为触发驱动段（D17），届时零架构改动。这也是"统合分散能力、打通数据"定位的自然延伸：智能体只是又一个被统合的能力源。
